# 생성엔진 품질 검증 1차 계획

## 목적

다음 두 문제를 분리해서 확인한다.

1. PDF에서 실제로 배울 가치가 있는 내용을 제대로 고르는가?
2. 확정된 지식 덩어리마다 현재 앱에서 가장 적합한 문제 방식을 고르고, 채점 가능한 문제를 만드는가?

문제를 많이 만드는 것은 성공 기준이 아니다. 현재 앱의 네 방식으로 제대로 훈련할 수 없는 내용은 억지로 문제로 만들지 않는 것이 성공이다.

## 자료별 기대 결과

### 1. 말하기 패턴

학습 목표:
인물 묘사 질문을 받았을 때 공통 답변 흐름을 떠올리고, 말하려는 의미에 맞는 영어 패턴의 변수 자리를 바꾸어 직접 말할 수 있다.

반드시 포함:

- 인물 주제와 이름 소개
- 관계·배경과 나이 설명
- 외모 묘사로 전환
- 좋아하는 이유 설명
- 처음 알게 된 계기
- 이후 관계 변화
- 인물에 대한 최종 평가
- 전체 답변 흐름과 문맥에 맞는 변수 치환

제외:

- 학교 동기·이웃·배우·건강한 사람의 완성 스크립트를 각각 독립 핵심으로 추출하는 것
- 이름·나이·외모 등 예시용 고정 정보
- 반복되는 전체 한국어 해석
- 쉐도잉 절차와 학습 독려 문구

기대 판단:
한국어 의미 또는 발화 의도에서 영어 표현을 만들어내는 방향이 기본이다. 네 완성 스크립트를 전부 외우게 하지 않고 일곱 개의 재사용 가능한 발화 기능을 뽑아야 한다. 전체 답변 순서는 구조복원으로 보조할 수 있지만, 개별 영어 표현은 플래시카드가 더 적합하다. 현재 네 문제 방식은 실제 말하기 수행을 완전히 대신하지 못한다는 한계도 남겨야 한다.

### 2. 기술 개념: 데드락

학습 목표:
데드락의 개념과 네 발생 조건을 설명하고, 자원 할당 그래프와 시스템 상태를 보고 데드락 가능성을 판단하며, 예방·회피·탐지/복구의 차이를 구분할 수 있다.

반드시 포함:

- 데드락의 정의
- 상호 배제, 점유 대기, 비선점, 순환 대기
- 요청 간선과 할당 간선의 의미
- 자원 인스턴스 수에 따른 사이클 해석 차이
- 예방·회피·탐지/복구 비교
- 안전 상태와 불안전 상태의 차이

제외:

- 첫 장 제목과 마지막 요약의 단순 중복
- 예시 그림에만 붙은 식별자 자체
- 학습 목표 문장 자체를 별도 암기 대상으로 만드는 것

기대 문제 방식:
정의는 플래시카드, 조건과 잘못된 판단은 OX, 방법 비교와 그래프 해석은 객관식이 적합하다. 관계나 처리 흐름이 분명한 경우에만 구조복원을 쓴다.

### 3. 역사·사회: 권리장전

학습 목표:
반연방주의자의 요구, 매디슨의 제안, 최종 권리장전 사이에서 권리와 정부 권한 제한이 어떻게 이어지고 바뀌었는지 구분할 수 있다.

반드시 포함:

- 세 문서의 시대적 순서와 역할
- 종교·언론·집회 등 개인의 권리
- 수색·압수, 적법절차, 배심재판 관련 보호
- 연방정부에 위임되지 않은 권한의 유보
- 제안 단계와 최종 채택 내용의 차이

제외:

- 고어 문장을 통째로 암기시키는 문제
- 날짜·문구를 학습 목적 없이 잘게 쪼갠 문제

기대 문제 방식:
권리와 제한을 구분하는 객관식·OX가 중심이다. 문서 변화의 순서를 묻는 경우에만 구조복원이 가능하다.

### 4. 과학·오개념: 달의 위상

학습 목표:
태양·지구·달의 상대적 위치로 달의 위상이 생기는 이유를 설명하고, 지구 그림자나 구름이 원인이라는 오개념을 구분할 수 있다.

반드시 포함:

- 달의 밝은 면은 항상 태양 쪽을 향함
- 달의 공전과 관찰 위치가 보이는 밝은 부분을 바꿈
- 지구 그림자가 위상의 일반 원인이 아니라는 점
- 관찰 가능한 시간과 위상 사이의 관계

제외:

- 수업 진행자의 말하기 대본
- 준비물과 교실 운영 지시
- 활동 참가자 역할 자체

기대 문제 방식:
오개념 교정 OX와 원인 판단 객관식이 중심이다. 실제 순서 관계가 확인되는 내용만 구조복원으로 만든다.

### 5. 규칙·조건: 재난 대비

학습 목표:
재난 전 중요 기록을 어떻게 복사·보관해야 하는지, 재난 뒤 어떤 정보와 절차를 확인해야 하는지 판단할 수 있다.

반드시 포함:

- 개인·금융 기록의 복사와 분리 보관
- 전자 자료 백업
- 방수·내화 보관과 신속한 반출 준비
- 재난 후 채권자·보험사 등과 연락할 때 필요한 조치
- 재산 목록과 손해 기록

제외:

- 비어 있는 계좌번호 입력표
- 기관 소개와 일반 홍보 문구
- 구체적인 개인 정보를 문제로 생성하는 것

기대 문제 방식:
상황별 올바른 행동을 고르는 객관식과 명확한 안전 규칙 OX가 중심이다.

### 6. 현재 앱에 맞지 않는 수행형: 미적분 문제집

검증 목표:
직접 계산, 그래프 작성, 증명이 필요한 자료를 현재 네 문제 방식으로 모두 훈련할 수 있다고 잘못 판단하지 않는지 확인한다.

기대 결과:

- 문제 수를 채우기 위해 계산 문제를 사실 암기카드로 바꾸지 않음
- 자료가 주로 직접 풀이를 요구한다는 점을 감지
- 현재 지원이 부분적이거나 미지원임을 표시
- 별도의 개념 설명이 없는 문제를 원문 밖 지식으로 임의 해설하지 않음

현재 엔진이 반드시 네 방식 중 하나를 고르게 되어 있다면 이 자료는 실패할 가능성이 높다. 이 실패는 프롬프트 문제가 아니라 `현재 미지원` 판단 기능이 필요한 근거로 기록한다.

## 실행 순서

### 1단계: 중요한 내용 선별

각 자료를 `Analyze → Plan → Prepare`까지 두 번 실행한다.

확인 항목:

- 반드시 포함할 내용의 누락
- 제외할 내용의 유입
- 같은 의미의 중복 지식 덩어리
- 하나의 지식 덩어리에 여러 능력이 섞인 경우
- 개수를 채우기 위한 저가치 내용 추가
- 원문에 없는 지식 추가

통과 기준:

- 핵심 내용 포함률 90% 이상
- 제외 대상 포함 0건
- 원문 밖 사실 0건
- 의미상 중복 10% 이하
- 최소 개수를 맞추기 위한 억지 생성 0건

### 2단계: 문제 방식 추천

사람이 확인한 지식 덩어리를 고정하고 추천 단계만 세 번 실행한다.

확인 항목:

- 지식 덩어리마다 개별 판단하는가
- 추천 이유가 학습자가 해야 할 행동을 설명하는가
- 특정 형식으로 쏠린 이유가 내용상 타당한가
- 단순 다양성을 위해 부적합한 형식을 섞지 않는가
- 적합한 형식이 없을 때 미지원으로 판단하는가

통과 기준:

- 적합한 추천 90% 이상
- 명백히 부적합한 추천 0건
- 추천 이유와 실제 문제 방식 불일치 0건

### 3단계: 실제 문제 생성

확정한 지식 덩어리와 선택한 문제 방식을 고정하고 문제 생성만 세 번 실행한다.

공통 통과 기준:

- 정답 오류 0건
- 원문 밖 사실 0건
- 자동 채점 불가능 0건
- 같은 질문 또는 같은 정답의 중복 10% 이하
- 가벼운 표현상 결함 10% 이하

형식별 기준:

- 플래시카드: 한 문제에 한 기억 대상, 질문과 짧은 답이 명확함
- OX: 애매하지 않고, 단순 부정문 변환이 아니며, 실제 혼동 지점을 다룸
- 객관식: 정답은 하나뿐이고 오답끼리 겹치지 않으며 모두 같은 범주의 선택지임
- 구조복원: 실제 순서·계층·관계가 있으며 문장을 억지로 조각내지 않음

## 피드백 개선 반복

실패가 발견되면 최초 발생 단계만 수정한다.

```text
중요 내용 선별 실패 → Plan 또는 Prepare만 수정
문제 방식 추천 실패 → 추천 단계만 수정
실제 문항 실패 → 해당 문제 형식의 생성 규칙만 수정
```

수정 후에는 같은 입력과 같은 기준으로 다시 실행해 이전 결과와 비교한다. 한 개선안이 다섯 번 연속 통과 기준을 만족하지 못하면 자동 수정을 중단하고 다음 내용을 보고한다.

- 반복된 실패 유형
- 어느 단계에서 처음 발생했는지
- 시도한 변경
- 좋아진 항목과 나빠진 항목
- 사용자 판단이 필요한 선택

## 이번 단계에서 하지 않는 것

- 자료 주제별 하드코딩 규칙 추가
- 문제 유형을 골고루 만들도록 강제
- AI가 자기 프롬프트를 무제한으로 수정
- 점수 하나만 보고 변경 사항 자동 반영
- 실험 중 발견한 장기 기능을 즉시 모두 구현

## 다음 실행 전 필요한 승인

여섯 PDF의 실제 내용을 OpenAI API로 전송해 기준 실험을 수행하기 전에 사용자 승인을 받는다. 승인 후에는 1단계부터 순서대로 진행하고, 앞 단계 결과가 확인되기 전에는 뒤 단계 품질을 고치지 않는다.
