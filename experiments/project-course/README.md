# 프로젝트 코스 실험 (D 스레드, 2026-10-28)

AI와 함께 소프트웨어를 만들되, 그 과정에서 배운 원리를 직접 검증하고 다른 문제에도 적용할 수 있게 훈련하는 코스의 시제품이다. 앱(`src/`)과 따로 돌고, 잘되면 최종 발표 때 앱에 붙인다.
근거: `협업/인계_D_프로젝트코스실험_20261028.md`, `협업/설계와논의/GPT평가_공부범위확장_20261028.md`.

## 켜는 법

`프로젝트코스 실험.cmd`(이 폴더)를 더블클릭한다. 브라우저에 **http://127.0.0.1:4100** 이 열린다. 창을 닫으면 실습 서버도 같이 꺼진다.

- Node.js 22.13 이상이 필요하다. 설치할 패키지는 없다(Node 내장 `node:http`·`node:sqlite`, 타입 제거 실행).
- 포트: 코스 화면 4100, 학습자 실습 서버 4101, 검사용 서버 4102. 앱(3000)·엔진 실험(3002)은 건드리지 않는다.
- AI(코스 정하기 대화, 힌트 1·2단계)는 앱과 같은 ChatGPT 로그인을 쓴다(`src/lib/assist/model.ts`를 읽기만 한다). 로그인이 안 되어 있거나 한도(20회)를 넘으면 정해진 질문과 준비된 힌트로 이어 간다. `PC_AI=off`로 끌 수 있고, `PC_AI_LIMIT`로 한도를 바꾼다.
- 진도·대화·기록 후보·실습 폴더는 `.data/`(깃에 안 올라감).

## 흐름

1. **코스 정하기**: 채팅과 문답으로 목표·수준·써 본 언어·시간·AI와 나누는 방식을 묻고, 확인 문제 6개를 푼다. 계획(어느 단계부터, 어느 단계를 빠르게, 전이 과제 여부)은 **코드가 정한다**(`lib/intake.ts`의 `makePlan`). AI는 대화만 하고, 준비된 코스 밖의 것을 원하면 "아직 없다"고 말하고 요청으로 적어 둔다. 학습자는 계획 카드에서 단계별로 직접/빠르게/건너뛰기를 바꾼 뒤 시작한다.
2. **단계마다** (게시판 API 6단계 + 전이 과제 메모 API)
   - 작업 폴더 만들기 → VS Code로 열기 → 서버 켜기(로그 보기, 게시판 화면 열기)
   - ① 결과 예측 (처음 고른 답이 기록됨)
   - ② 없애 보기: 그 단계의 핵심 줄이 빠진(또는 준비된 버그가 든) 지금 코드에 실제 요청을 보내 기대와 실제를 본다. 직접 요청 보내 보기(A·B 두 사용자 쿠키 유지)도 있다.
   - ③ VS Code에서 고치기: 부품 카드, 힌트 1(방향)·2(위치)는 AI 또는 준비된 글, 3(정답 줄)은 준비된 정답 차이
   - ④ 재검사: 이번 단계 + 이전 단계(회귀) 검사를 모두. 결과는 "요청 / 기대 / 실제 / 파일:줄 후보(+ 서버 오류 로그의 위치)"
   - ⑤ 내 말로 설명하기 (채점 안 함, 메모로 남김)
   - ⑥ 학습 기록 후보 (파일로만)
3. **결과**: 단계별로 "직접 통과 / 도움 받아 통과 / 빠르게 넘어감"과 지식별 기록 후보.

## 구조

| 경로 | 하는 일 |
|---|---|
| `courses/board-api/course.json` | 코스 데이터 전부: 지식 17개, 부품 카드 10개, 단계 7개(예측·없애 보기·고칠 것·설명 질문·준비된 힌트·요청 예시), 검사 33개, 확인 문제 6개 |
| `courses/board-api/template/` | 기준 프로젝트 하나. 표식(`// <from N>`, `// <until N>`, `// <swap N> 완성 // <start> 시작 // </swap>`, 첫 줄 `// @from N`)으로 단계별 시작 상태를 만든다 |
| `courses/board-api/memo-overlay/` | 전이 과제: 게시판 완성본 위에 덧씌우는 메모 API |
| `lib/stagegen.ts` | 표식 처리, 작업 폴더 쓰기(옛 파일은 `.recaller/backup/`) |
| `lib/checker.ts` | 검사기: 작업 폴더의 서버를 검사용 포트·검사용 DB로 따로 띄워 실제 HTTP 요청 + SQLite 상태 확인. 기대값은 데이터, 판정은 코드 |
| `lib/proc.ts` | 실습 서버 켜기·끄기, 포트 확인, 코스 서버가 꺼질 때 정리 |
| `lib/intake.ts` | 코스 정하기 (AI 대화 / 대본, 진단, 계획) |
| `lib/learn.ts` | 단계 진행, 기록 후보 만들기, 힌트, 실습 서버, VS Code 열기 |
| `lib/ai.ts` | 앱 모델 호출 다리 + 20회 한도 (`.data/ai-usage.json`) |
| `lib/store.ts` | 진도(`runs.json`), 기록 후보(`records/<run>.jsonl`) |
| `server/main.ts`, `web/` | 코스 서버와 화면 |

새 코스는 `courses/<id>/`에 `course.json`과 템플릿을 두면 된다(코드 수정 없음). 지금 화면의 코스 정하기는 `board-api` 하나만 고른다.

### 기록 후보 (지식 저장소에 붙일 모양)

`records/<run>.jsonl` 한 줄 = 기록 하나. `kind`는 지식 저장소의 `KEventKind`(met·asked·wrong·hint·correct·note)와 같은 말이다.

```json
{"knowledgeId":"k-ownership","knowledgeName":"자원 소유권 검사","kind":"correct","detail":"5단계: 직접 고쳐 검사 통과 (통과 전 검사 실패 1번, 힌트 1번)",
 "evidence":{"activity":"check","independent":true},"source":{"kind":"project","title":"게시판 API 만들기 5단계 · 작성자 권한 검사","ref":"board-api:k-ownership"}, ...}
```

규칙: 단계 시작 → 만남. 예측(처음 답) → 맞힘/틀림. 힌트 → 힌트. 재검사 전부 통과 → 정답 줄(힌트 3)을 안 봤으면 맞힘, 봤으면 메모("앎으로 치지 않음"). 빠르게 넘어감 → 메모. 설명 → 메모(채점 안 함).

## 된 것 / 확인한 방법

- 7단계 모두: 시작 상태는 그 단계의 없애 보기 검사에서 실패하고 이전 단계 검사는 통과, 푼 상태는 그 단계까지 검사를 모두 통과 — 실제 서버를 띄우고 실제 요청으로 확인(`npm test`, `test/course.test.ts`). 6단계의 준비된 버그는 2단계 회귀 검사 하나도 깨뜨린다(데이터의 `breaks`에 적어 둠 — 회귀 검사가 버그를 먼저 잡는다는 걸 보여 주는 장면).
- 계획 규칙(`test/plan.test.ts`).
- 브라우저(Playwright)로 처음부터: 코스 정하기 대화 → 확인 문제 → 계획 카드 → 시작 → 5단계 예측(하나 틀림) → 없애 보기(B가 A의 글을 고치면 200·지우면 204, 위치 후보 `posts.ts:35`·`:44`) → 서버 켜고 요청 예시로 같은 장면 재현 → 힌트 1 → (고친 파일을 써 넣고) 재검사 통과 "직접 통과" → 설명 → 결과 화면. AI는 가짜 응답(`PC_FAKE_AI=1`)으로 확인.
- API로: 힌트 1·2·3 뒤 통과는 "도움 받아 통과", 전이 과제(메모 API) 시작·실패 3개·고친 뒤 통과, 대본 모드 코스 정하기, 예측 없이 빠르게 넘어가기는 거절.
- 진짜 AI 경로: 앱의 모델 모듈을 불러오고, 로그인이 없으면 "로그인이 필요해요"로 대본/준비된 힌트로 넘어가며 횟수를 세지 않음(클라우드에서 확인).
- 유료 호출: 0회.

## 확인 못 한 것

- **Windows에서 실제로**: `프로젝트코스 실험.cmd`, VS Code 열기(`code` 명령), Windows에서 실습 서버 끄기·DB 파일 잠금, CRLF로 쓴 작업 파일. 클라우드와 데스크톱 셸(Linux)에서만 돌렸다.
- **진짜 AI 대화와 AI 힌트의 질**(로그인된 PC에서 몇 번 써 봐야 함, 20회 안).
- 사람이 직접 VS Code에서 고쳐 보는 것(완료 기준: 1~5단계 중 2개 이상을 처음부터 끝까지).
- VS Code의 타입 표시: 작업 폴더에 앱의 `node_modules/@types/node`를 복사해 넣는다. 앱에 그 패키지가 없으면 VS Code가 `node:http`에 빨간 줄을 긋는다(실행은 된다).

## 최종에 붙일 때 필요한 것

- 기록 후보 → `src/lib/knowledge/api.ts`(B): 코스 지식을 `saveMany`로 한 번 만들고(폴더 "게시판 API"), 기록마다 `recordEvent(지식id, kind, detail, source)`. 같은 이름의 기존 지식과의 중복은 B의 중복 판정에 맡긴다.
- 복습 문제: 지식 essentials와 예측 문제·설명 메모로 "코드 없이 묻는" 문제를 만든다(앱의 복습 흐름).
- 화면: 이 화면을 앱의 공부 화면 탭 하나로 옮기거나(`/study`), 지금처럼 따로 띄우고 앱에서 링크. 실습 서버를 앱 서버가 띄우는 것은 프로세스 정리·포트 문제가 있어 따로 두는 쪽을 권한다.
- 코스 늘리기: `course.json` 형식을 그대로 쓴다. 검사 기대값과 버그 버전은 사람이 준비한다(AI가 즉석에서 만들지 않는다).
