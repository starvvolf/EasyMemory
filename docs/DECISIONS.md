# 제품·연결 결정

사용자가 확정한 동작이나 공용 연결 방식을 바꿀 때만 짧게 기록한다. 구현 메모나 아직 정하지 않은 선택지는 여기 넣지 않는다.

## 2026-09-29 · 되짚기 생성 흐름 (아래 "앱 전체 흐름"으로 일부 대체됨)

- 학습목표 5개 중 2개를 체크하면 **그 2개에서만** 문제를 만든다. 화면의 선택은 참고 표시가 아니라 출제 범위다.
- 첫 버튼은 학습목표 설계까지만 요청한다. 문제 만들기 버튼은 그 결과를 재사용해 다음 단계로 이어간다.
- 새 문제는 담당 AI가 검사하고 출제 편집틀에 기록한 뒤에만 학습 목록에 나타난다. 요청 저장만으로 AI 실행이나 문제 저장이 끝난 것으로 표시하지 않는다.
- 현재 MCP 요청은 PDF만 받는다. 붙여 넣은 글의 생성 연결은 별도 결정 전까지 지원한다고 표시하지 않는다.

근거: `협업/작업지시_05_되짚기_엔진연결.md`와 사용자 확정. 구현은 `src/app/study/DejipgiStudy.tsx`, `src/lib/mcp-experiment-requests.ts`, `tools/study-forge-mcp/chatgpt-parity.ts`에서 확인한다.

## 2026-09-29 · 앱 전체 흐름

- **사용자 화면은 되짚기(`/study`) 하나다.** 원래 메인 앱, `/mcp-personalization`, `/mcp-runs`는 개발·실험 도구로 둔다. 첫 화면(`/`)은 `/study`로 보낸다.
- **새 자료는 PDF → 짧은 질문(목적, 할 수 있어야 할 것, 범위) → "이렇게 만들게요" 확인 → 바로 읽기** 순서다. 질문 답은 요청의 학습 목적 문장이 된다.
- **읽기는 문제를 기다리지 않는다.** 요청을 올리면 곧바로 원문을 읽을 수 있고, 문제는 AI 작업이 끝나면 붙는다.
- **요청은 한 번이다.** 목표를 앞에서 고르는 단계는 없앤다. AI가 전체 범위를 끝까지 만들고, 사용자는 필요 없는 목표를 나중에 뺀다. 이 결정은 위 항목의 "체크한 목표만 출제"와 "첫 버튼은 학습목표 설계까지"를 대체한다. 고른 목표만 다시 만드는 기능은 "다시 만들기"에 쓴다.
- **생성은 담당 AI가 MCP로 한다.** 담당 AI 대화에서 한 번 요청하면 5단계와 출제 편집틀 기록까지 끝내는 것을 목표로 한다. 앱이 API로 직접 생성하는 경로는 지금 만들지 않는다. *(2026-09-30 "ChatGPT 계정으로 생성"으로 대체)*
- **문제는 한꺼번에 붙인다.** 쪽이나 목차 단위로 나눠 먼저 붙이는 방식은 실제 실행 시간을 재 본 뒤 필요할 때만 한다.
- **품질 검사에 걸린 문항은 빼고 보여 준다.** 뺀 문항 수는 자료 화면에 표시한다. 기록된 문서 전체를 숨기지 않는다.
- **풀다가 "이 문제 이상해요"로 신고할 수 있다.** 신고한 문항은 복습에서 빠지고 신고 기록은 품질 근거로 남는다.
- **홈은 오늘 할 것만 보여 준다.** 복습 차례, 이어서 읽기, 새 자료, 만드는 중인 자료
- **지금 하지 않는 것**: ~~앱의 API 직접 생성~~(2026-09-30 대체), 답 칸 종류 확대(순서 맞추기 외), ~~질문 창 답변 연결~~(2026-09-30 "모르는 것 노트"로 대체), 여러 기기 동기화

## 2026-09-30 · 되짚기 엔진 입력·근거 계약

- 화면에서 고른 다섯 가지 ‘할 수 있어야 할 것’은 수정 가능한 목적 문장에서 추측하지 않고 요청의 `abilities` 목록으로 별도 전달한다. 다시 만들기·재시도에도 유지한다.
- 새 학습 설계의 `sourceText`에는 PDF 실제 문구를 넣고 요약은 `content`에 둔다. 여러 인용은 `||`로 구분한다. 대조할 때 공백·줄바꿈·하이픈을 정리한다. 글자가 없는 쪽은 실패 대신 `원문 글자 없음`으로 표시한다. 과거 기록은 바꾸지 않는다.
- 원문 그림 `crop`은 좌상단 원점의 페이지 비율(0~1)이다. 범위를 벗어난 사각형은 오류다. 이 결정은 화면의 원문 그림 표시 구현을 뜻하지 않는다.
- 요청의 다섯 단계 완료와 출제 기록 완료는 별개다. 현재 `/study`는 출제 문서가 기록되어야 준비됨으로 본다. 출제를 요청의 여섯 번째 단계로 넣는 변경은 이번에 하지 않는다.

## 2026-09-30 · ChatGPT 계정으로 생성

- **생성은 앱이 직접 한다.** 사용자가 "ChatGPT로 로그인"(Sign in with ChatGPT, OAuth)하면 앱이 그 사용자의 토큰으로 Responses API를 호출하고, 사용량은 사용자의 ChatGPT 플랜에서 나간다. 별도 API 키를 쓰지 않는다. 담당 AI가 대화에서 요청을 처리하는 MCP 경로는 대안·실험용으로 남긴다.
- **모델 호출은 한 함수로 모은다.** 공급자는 바꿀 수 있게 한다: ChatGPT 토큰(기본), Codex(기존 로컬 방식), 가짜 모델(테스트). 가짜 모델로 전체 흐름을 비용 없이 자동 확인한다.
- **단계마다 필요한 입력을 명시적으로 넘긴다.** 대화방(스레드)의 암묵적 기억에 기대지 않는다.
- **토큰은 서버에만 둔다.** 화면·로그·기록에 남기지 않는다. 호출은 요청한 사용자의 토큰으로 한다.
- **사용량 한도는 실패가 아니다.** 플랜이나 앱 주간 한도에 걸리면 "사용량 한도" 상태로 멈추고 나중에 이어서 한다. 자료당 호출 수와 재시도 수에 상한을 둔다.
- 대상 모델, PDF 파일 첨부 가능 여부, 오픈소스 흐름 등록 조건은 공식 문서로 확인한 뒤 확정한다. 확인 전에는 결정으로 쓰지 않는다.


## 2026-09-30 · 생성 실험실

- **생성 과정을 보는 실험실을 만든다.** 단계별로 어떻게 돌았는지(상태, 시간, 모델, 재시도), 무엇이 나왔는지(단계에 맞는 읽기 좋은 모양), 모델을 단계마다 바꿔 돌린 결과를 한 화면에서 본다. 한 단계씩 멈추며 확인할 수 있다.
- **같은 앱 안의 `/lab` 화면이다.** 로컬 실험 모드에서만 열린다. 자동 실행기, ChatGPT 연결, PDF 등록·보기를 그대로 쓴다. 실험실 실행 1개는 생성 요청 1개이고, 실험실 설정은 실행기 상태에 붙인다.
- **실험실 결과는 `/study` 연습 목록에 섞지 않는다.**
- **실제 모델 호출은 화면에서 확인을 누를 때만 한다.**
- 기획·화면 설계는 Claude가 하고(`협업/작업지시_08_생성실험실.md`, `협업/실험실/화면시안.html`), 구현은 GPT가 한다.
- **지금 하지 않는 것**: 기대 목록·자동 채점, 단계 구성 바꾸기(엔진 계약 결정 필요), 두 실행 나란히 비교·중간부터 갈라 다시 돌리기·되짚기로 보내기(2차)

## 2026-09-30 · 모르는 것 노트 (읽기 중 물어보기)

- **읽다가 모르는 것을 드래그해 바로 물어본다.** 단어, 문장, 절차, 개념 모두 대상이다. 답은 그 쪽의 원문을 함께 넘겨 **이 자료에서의 뜻**으로 받는다. 원문에 없는 설명은 "원문 밖 설명"으로 구분해 표시한다.
- **한 번 물어본 답은 자료별 노트에 남는다.** 원문에는 점선 밑줄로 표시하고, 다시 누르거나 같은 문구를 다시 고르면 저장된 답을 AI 호출 없이 바로 보여 준다.
- **다시 본 횟수가 약점 신호다.** 같은 것을 여러 번 다시 보면 약점으로 올리고 연습에서 떠올리기 문제로 낸다. 사용자가 약점을 따로 표시하지 않아도 된다.
- **질문 창은 남기고 노트와 잇는다.** 답 카드는 고른 글자 하나를 콕 집어 묻는 곳이고, 질문 창은 지금 쪽 전체를 두고 대화하는 곳이다. 둘은 이렇게 연결한다.
  - 카드에서 이어 묻기가 길어지면 [질문 창에서 계속]으로 대화를 들고 넘어간다.
  - 질문 창이 열려 있을 때 드래그하면 [질문 창에 넣기]로 인용한다.
  - 질문 창의 대화도 노트에 남는다. **대화 한 번이 노트 항목 하나**이고, AI가 짧은 제목을 붙인다. 카드에서 넘어온 대화는 그 카드 항목에 이어 저장한다.
  - 이 결정은 2026-09-29의 "질문 창 답변 연결은 지금 안 함"을 대체한다.
- **노트는 로컬 서버(`.study-forge-data/`)에 저장한다.** AI 사용량을 써서 얻은 답이라 브라우저 기록 삭제로 잃지 않게 한다.
- UX 기준은 `협업/모르는것노트/화면시안.html`이다. 드래그 → 작은 메뉴 → 오른쪽 여백에 원문과 선으로 이어진 답 카드가 뜬다. 카드는 한 번에 하나다. 좁은 화면에서는 아래에서 올라오는 판으로 뜬다.
- **지금 하지 않는 것**: 스캔 쪽(글자 없는 쪽)의 영역 선택과 그림 물어보기, 노트를 생성(학습 설계)에 반영하기, 여러 자료를 모은 전체 노트

## 2026-10-02 · 개념 구조 제출 검사와 재실측
