## 2026-10-26 · 코드 문제 받아오기

- 정한 사람: 사용자와 같이
- 결정:
  1. 받아오기는 백준식(표준 입출력)부터 한다. 함수형(프로그래머스·LeetCode처럼 함수 하나만 채우는 문제)은 나중에 하며, 먼저 AI가 백준식으로 바꿔 받고 그 뒤에 언어별 감싸는 코드를 붙인다.
  2. 입력 종류(문제 글 통째·예제 없는 설명·사진·강의 글·주제 한 줄)마다 길을 따로 만들지 않는다. 하나의 문제 명세(설명·입출력 형식·예제·정답 풀이·숨은 테스트 3개 이상)와 하나의 검사 흐름으로 간다. 칸마다 원문에서 온 것인지 AI가 만든 것인지 표시하고, 근거가 약할수록(원문 예제 없음) 검사를 세게 한다.
  3. 정답 풀이 검사: 원문 예제가 있으면 정답 풀이가 원문 예제 출력과 같아야 한다. 원문 예제가 없으면 느리지만 단순한 풀이를 따로 만들어 작은 입력에서 답을 교차 확인한다.
  4. 검사를 통과하지 못한 문제는 저장하지 않고 어디서 왜 막혔는지 보여 준다.
  5. 답이 여러 개이거나 소수점 오차를 허용하는 문제는 당분간 거절한다.
- 이유: 지금은 기대 출력이 모두 AI 모범 풀이에서 나와, 모범 풀이가 틀리면 틀린 정답으로 채점되고 그 결과가 학습 기록(몰랐음·앎·복습)까지 오염된다. 국내 코딩테스트는 함수형이 많지만 현재 채점기(`src/lib/code/run.ts`)는 입력 글자를 넣고 출력 글자를 비교하는 백준식만 지원한다.
- 근거: `docs/CURRENT_STATUS.md` 코드 절 "모범 풀이 자체가 틀리면 막을 장치가 없다 · 외부 문제 가져오기 없음", `src/lib/assist/code-ai.ts` `makeProblem`(모범 풀이 출력을 기대 출력으로 씀).

## 2026-10-12 · 생성 엔진 구조 (3단계, 목차 단위)

사용자와 Claude가 문답으로 확정했다. `협업/논의정리_20261008_방향.md` 9장의 1·2·4번 결정과 3번 일부(목적 종류)를 대신한다.

- **세 단계로 한다.** 활동 설계·카드 단계는 되짚기 경로에서 없앤다. 옛 5단계·MCP 경로는 그대로 남기고, 새 엔진은 **따로 만든 새 경로**다(`src/lib/study/gen/`).
  1. **자료 파악**: AI가 고른 쪽 전체에서 목차를 한 번 뽑는다(PDF 책갈피는 쓰지 않는다). 목차마다 내용을 성격으로 분류한다(핵심 지식 · 재사용 패턴 · 예시 · 설명 · 학습 지시 · 연습문제 · 부가 정보), 각 항목에 원문 인용과 쪽을 붙인다.
  2. **학습 설계**: 목차마다 목적 규칙으로 고르고 목표를 정한다. 목표 하나 = **떠올릴 것 하나**. 같은 패턴의 예시들은 패턴 하나로 묶는다. 예시·연습문제는 목표가 아니라 문제의 상황·수치 소재로 쓴다. 노트 약점·신고를 받을 입력 칸은 두되 지금은 비운다.
  3. **출제**: 앞 목차부터 차례로, 호출 한 번에 목차 하나. AI는 블록 종류와 순서, 응답 형식만 정하고 배치·좌표·출처는 코드가 채운다.
- **처리 단위는 목차**다. 자료 파악과 학습 설계는 목차별로 동시에 돌린다.
- **사용자 확인은 한 번**: 설계가 다 끝나면 목표 목록을 보고 빼거나 더한 뒤 출제한다. 출제는 앞 목차부터라 첫 목차가 끝나면 공부를 시작할 수 있다.
- **목적 네 가지**가 고르는 기준이다: 그냥 읽기(문제 없음, 자료 파악까지) / 이해(개념·관계·이유 위주로 적게, 설명형) / 핵심 암기(핵심 지식만) / 통암기(핵심·패턴·사실 전부). "할 수 있어야 할 것" 선택은 목적으로 합친다. 계산·절차 문제 여부는 내용 성격으로 AI가 정한다.
- **원문**은 쪽별 추출 글자로 넘긴다. PDF 직접 입력은 나중에 추가한다.
- **응답은 JSON 스키마(structured output)로 받는다.** ChatGPT 계정 연결에서 지원되지 않으면 JSON 모드로 한 번 다시 보내고 그 사실을 호출 기록에 남긴다.
- **검사는 세 갈래**다.
  1. 형식(칸, 번호, 정해진 값): 스키마가 막는다.
  2. 원문에 없는 내용, 끊긴 연결, 풀 수 없는 문제(정답 노출, 정답 누락, 한 칸 여러 요소): 걸린 것만 다시 시킨다. 한 번 더 걸리면 **그 항목만 빼고** 진행하며 "문제 없음"으로 표시한다.
  3. 품질 아쉬움(보기 길이 차이, 티 나는 오답, 비슷한 문제): 경고로 표시만 한다.
- **구현 순서**: 1차 엔진·가짜 모델 테스트·실험실 연결 → PC 실측 → 2차 `/study` 화면(목적 선택, 목표 확인, 목차별 진행).

## 2026-10-12 · 제품의 최종 경험 (사용자 확정)

> 자료를 보다가 막히면 그 자리에서 묻고, 문제를 만들어 풀고, 그 모든 과정이 **따로 정리하지 않아도 저절로 정리된 기록**으로 남는다. 약한 부분은 약한 부분대로, 전체 내용은 전체대로 모여 있어서 공부 시간이 압도적으로 줄어든다.

- **시간이 줄어드는 이유**: 노트를 따로 쓰지 않는다(질문·답·문제·풀이가 공부하면서 정리된다). 복습할 곳을 고르지 않는다(약점만 모인다). 다시 찾지 않는다(기록마다 원문 위치가 붙어 있다).
- **구조 원칙: 모든 기록은 목표 하나에 꿰인다.** 새 엔진의 목표(무엇을 보고 → 무엇을 떠올리나)에 원문 쪽·인용, 문제가 이미 붙어 있다. 여기에 모르는 것 노트의 질문과 답, 풀이 기록(혼자 맞힘 / 도움받음 / 틀림), 신고, 현재 상태(안 봄 · 헷갈림 · 익힘)를 같은 목표 ID로 매단다.
- **이 하나의 기록에서 나오는 화면**
  1. 자료별 정리 노트: 목차 → 목표 → 핵심 인용 → 내가 한 질문 ("전체 정리")
  2. 약점 모음: 틀림·도움받음·여러 번 물어본 목표 ("약한 부분"), 바로 연습으로 연결
  3. 오늘 할 것: 복습 차례와 약점을 섞은 짧은 목록 (학습 에이전트의 시작)

- **순서**: 새 엔진 안정화 → `/study` 연결 → 학습 기록을 서버에 목표 ID로 통합(브라우저에만 있는 풀이·신고 포함) → 정리 노트·약점 화면 → (선택) 내보내기, 오늘 할 것.
- 관련: `협업/논의정리_20261008_방향.md` 6~7장(학습 에이전트, 학습자 상태)

## 2026-10-12 · 장기 방향: 자료 범위와 MD 하네스 (방향, 구현 시점 미정)

- **자료 범위**: PDF에서 시작해 블로그·장문 글·영상 자막까지, 읽는 것은 무엇이든 내 지식으로 만든다. 엔진은 "글자 + 위치"로 돌므로 위치를 쪽에서 문단·시간 구간으로 넓히면 된다. 장문 글에는 "인사이트" 목적(주장·근거·반례·적용, 설명형 문제, 한 줄 요약 저장)이 필요하다. 입구는 한 번이어야 한다(주소 붙여넣기 → 브라우저 확장·공유하기).
- **MD 하네스**: 텍스트로 의미가 담기는 것(목적, 자료 종류별 읽는 법, 분류 기준, 출제 규칙과 예시, 질문 창 답변 방식, 정리 노트 요약 방식)은 전부 MD 파일로 두고, 파일을 고쳐 자연스럽게 커스터마이징한다. `출제기준/`이 첫 사례다.
  - 코드에 남는 것: 응답 구조(스키마), 안전 검사(원문 대조, 정답 노출), 저장·재시도·호출 상한. MD를 바꿔도 이 검사는 그대로 작동한다.
  - 새 목적·자료 종류는 파일 추가로 늘린다. 새 문제 형식(화면·채점이 필요한 것)은 코드가 있어야 한다. 파일은 자기가 쓰는 형식 범위를 밝히고, 엔진이 모르는 것을 쓰면 알린다.
  - 층: 기본 → 자료 종류 → 목적 → 개인 설정(`내설정/`) 순으로 덮어쓴다.
  - 공유된 MD는 모델 지시가 되므로 공유 기능을 만들 때 확인 단계를 둔다.
- 순서: 새 엔진 재실측 → `/study` 연결 → 학습 기록 통합을 먼저 한다. 그 뒤 남은 의미(목차 규칙, 분류 기준, 목적 목록)를 MD로 빼고 "인사이트" 목적을 첫 파일 추가 사례로 삼는다.

  - 시범의 결과 예측이 틀리거나 "모르겠어요" → 틀림 + 실제 출력
  - 튜터 문제의 문제 화면에서 AI 힌트·드래그 설명 → 힌트 + AI가 한 말 앞부분 300자

- AI 힌트의 "지난번에도"는 그 문제 패턴의 기억에서 읽는다(`tutor/links.ts`).
