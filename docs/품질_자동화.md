# 품질 자동화: 공부하면서 고치는 앱 (2026-10-15)

앱 자체가 에이전트다. 앱이 열려 있는 동안 **학습 유도**(docs/학습흐름_자동화.md)와 **자체 개선**(이 문서)을 같이 한다.
자체 개선은 두 고리로 나눈다. 공부하는 그 자리에서 내 문제를 고치는 **빠른 고리**(비용 0, 지금 동작), 쌓인 근거로 출제기준·학습규칙을 바꾸는 **느린 고리**(유료 비교, 사람 승인, 시험 뒤).

```
 공부 ─▶ 신호(버튼 한 번) ─▶ 빠른 고리: 그 자리에서 고침(덧씌우기·내 조정) ─▶ 품질 장부 한 줄
                                                                   │
                     코치 카드 ◀── 같은 원인이 문턱 이상 ◀──────────┘
                        │
                        ├─ 다음 자료 메모에 넣기 (비용 0, 바로 다음 출제부터)
                        └─ 개선 후보로 올리기 ─▶ 느린 고리: 후보 기준 → fork 비교 → 승인 → 변경기록
```

## 1. 빠른 고리: 신호 → 그 자리의 처리 (모두 비용 0)

| 어디서 | 학습자 신호 | 앱이 바로 하는 일 | 되돌리기 | 장부 원인 |
|---|---|---|---|---|
| 결과 화면 | "내 답도 맞아요" | 이번 풀이를 맞음으로, "정답에 추가" 제안 → 누르면 다음부터 정답 | 기록 탭 "고친 것" | 인정답안누락 |
| 결과 화면 | 같은 문제에서 그게 [카드전환-제안]번째 | "카드로 바꾸기" 제안(표기가 여럿인 답은 카드, 단답-1) | 기록 탭 "고친 것" | 형식선택 |
| 결과 화면 | "너무 지엽적" | 그 목표를 빼고, 같은 자료의 비슷한 목표를 함께 뺄지 묻기 | 기록 탭 "연습에서 뺀 것" | 지엽 |
| 결과 화면 | "너무 쉬움" | 가장 긴 복습 간격(35일) | 다음 풀이에서 틀리면 원래대로 | 너무쉬움 |
| 자동 | 서로 다른 날 [쉬움-연속]번 연속 혼자 맞힘 | 가장 긴 간격으로(한 번만) | 같음 | 너무쉬움 |
| 결과 화면 | "이 문제 이상해요"(사유) | 연습에서 빼기(기존) | 기록 탭 | 정답오류·애매함·원문불일치·기타 |
| 읽기·정리 | 목표 "빼기" | 빼고 비슷한 목표 제안([비슷한목표-기준]%, 강의 운영 안내끼리) | 기록 탭 | 목표설계 |
| 풀이 끝 | 분량 "많았어요 / 딱 좋아요 / 더 할 수 있어요" | 하루 시간 ∓15분(내 조정) | 오늘 할 것 아래 "기본값으로" | 분량 |
| 풀이 끝 | 간격 "아는 게 자꾸 나와요 / 금방 잊어요" | 복습 간격 ×1.25 / ×0.8 (0.5~2배) | 같음 | 간격 |
| 풀이 끝·정리 | 내용 "너무 꼼꼼·지엽적" | 그 풀이에 나온 자료를 "핵심만"(보조 목표 제외) | 정리 탭 자료의 "핵심만" 단추 | 지엽 |
| 풀이 끝 | 내용 "빠진 게 많아요" | 정리 탭에서 **문제가 없는 쪽**을 보여 주고, 누른 쪽을 기록 | — | 빠뜨림 |

원칙
- **원래 출제 문서는 바꾸지 않는다.** 문제 수정은 덧씌우기(`study-quality/patches.json`)로 남고, 문제 ID가 그대로라 풀이 기록이 이어진다.
- **학습자 설정은 학습규칙 위에 얹는다.** 하루 시간, 간격 배율, 자료별 "핵심만", 다음 자료 메모는 `__plan.prefs`(풀이 기록과 같이 동기화)에 있고 학습규칙 파일은 그대로다.
- 누를 때마다 무엇이 바뀌었는지 그 자리에서 한 줄로 말한다.

## 2. 품질 장부 (`study-quality/장부.md`, 데이터 폴더)
```
- 2026-10-15 14:03 | 그래픽스 02 · q-s4-o9 | 내 답도 맞아요 → 이번 풀이를 맞음으로 | 원인: 인정답안누락 [단답-1] | 내 답 "(1, 2)" / 정답 "(1,2)"
```
- 한 줄이 사건 하나, 앱은 덧붙이기만 한다. `[ ]` 안은 그 원인이 바꿀 기준(출제기준 ID 또는 학습규칙).
- `GET /api/study-quality` → 덧씌우기, 장부, 원인별 개수.

## 3. 코치 (앱 안의 에이전트, `src/lib/study/coach.ts`)
오늘 할 것 아래에 카드 몇 장. 규칙으로만 만든다(모델 호출 없음). 닫으면 다시 안 나오고, 장부 원인은 문턱을 한 번 더 넘으면 다시 나온다.

| 카드 | 조건 | 단추 |
|---|---|---|
| 시험 전날 | 과목이 final 단계 | 한 장 정리, 약점 풀기 |
| 밀린 양 | 규칙대로 필요한 시간 > 하루 시간 × 1.3 | 하루 n분으로 |
| 약점 더미 | 과목 약점 15개 이상 | 약점부터 풀기 |
| 목표 확인 대기 / 시험일 없음 / 과목 없는 자료 | 해당 있음 | 시험일 넣기, 과목 고르기 |
| 개선: 원인 n번 | 장부의 같은 원인 ≥ [후보-문턱] | **다음 자료 메모에 넣기**(지엽·너무쉬움·빠뜨림), **개선 후보로 올리기** |

"다음 자료 메모에 넣기"는 비용 0으로 바로 효과가 나는 개선이다: 다음에 자료를 만들 때 메모 칸에 미리 들어가고(고칠 수 있음), 엔진 v2가 그 메모를 설계·출제에 쓴다.

## 4. 느린 고리 (시험 뒤, 사람 승인)
1. 장부에서 "개선 후보로 올림" 줄과 원인별 개수를 읽는다.
2. Claude가 후보 기준(`출제기준-후보`)을 쓴다. 신고·고친 문제는 나쁜 예의 재료가 된다.
3. GPT가 회귀 세트(고정 자료)에서 fork로 전후 비교: 점수표, 판정단, **장부에 있던 그 유형이 다시 나오는지**.
4. 사용자가 채택하면 `출제기준/변경기록.md`에 버전을 남긴다. 떨어진 후보는 `개선후보.md`에 이유와 함께.
5. 학습규칙도 같은 방식: 간격 배율·하루 시간 조정이 반복되면 그 값을 학습규칙 기본값 후보로.

시험 기간에는 1(쌓기)만 한다. 기준이 바뀐 문제와 예전 문제가 섞이면 비교도 공부도 흔들린다.

## 5. 앞으로 앱 안에서 더 할 수 있는 것 (유료, 예산 필요)
- 신고한 목표를 세션 사이에 자동으로 다시 만들기(하루 호출 상한, 학습규칙/에이전트.md 확인-1).
- 새 자료가 끝나면 작은 모델 판정단으로 자동 점검 → "확인 필요" 표시.
- 물어봄이 몰린 목표에 보충 설명 카드.
- "빠진 쪽" 기록이 모이면 그 쪽만 다시 만들기.
