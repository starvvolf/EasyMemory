# Gold Reference 초안: 운영체제 데드락

## 1. 문서 목적

이 문서는 운영체제 데드락 강의자료 `lecture8.pdf`를 학습자료로 변환할 때, 좋은 결과가 충족해야 할 의미적 조건을 사람이 검토하기 위한 gold/reference 초안이다.

이 자료는 OPIc 자료처럼 여러 예시에서 하나의 말하기 템플릿을 추상화하는 유형이 아니다. **개념 정의, 성립 조건, 그래프 해석 규칙, 상태 간 관계와 처리 전략의 차이**를 정확하게 이해하고 인출하는 개념·판단형 자료다.

따라서 다음을 평가의 중심에 둔다.

- 핵심 개념과 관계를 빠뜨리지 않았는가
- 필요조건과 충분조건, 가능성과 확정을 혼동하지 않았는가
- 그래프나 상태를 보고 올바른 결론을 내릴 수 있는가
- 비슷한 처리 전략의 목적과 전제 차이를 구분할 수 있는가
- 예시의 고유한 프로세스·자원 이름보다 일반적인 판정 원리를 학습하게 하는가

대표 카드의 정확한 문구와 카드 개수는 고정하지 않는다. 원문 의미와 학습 목표를 보존하면서 하나의 명확한 인출 대상을 제공하면 자연스러운 표현 차이를 허용한다.

## 2. 원자료 분석

- 자료: `lecture8.pdf`
- 주제: 운영체제의 데드락
- 분량: 14페이지
- 자료 유형: 개념 설명, 조건 분류, 그래프 해석, 전략 비교와 상태 판정

### 페이지 구성

- 1~2페이지: 장 제목, 명시된 학습 목표와 목차
- 3페이지: 데드락 정의와 세마포어 예시
- 4~5페이지: 시스템 모델과 데드락의 네 가지 필요조건
- 6~7페이지: 자원 할당 그래프와 사이클 판정
- 8~9페이지: 세 가지 처리 전략과 데드락 예방
- 10~12페이지: 데드락 회피, 안전 상태와 자원 할당 그래프
- 13페이지: 탐지와 복구
- 14페이지: 전체 요약

## 3. 학습 목표 분석

### 원자료가 명시한 목표

2페이지는 다음 세 가지 목표를 직접 제시한다.

1. 데드락의 개념을 설명할 수 있다.
2. 데드락의 발생 조건을 설명할 수 있다.
3. 데드락의 처리 방안을 설명할 수 있다.

### 이 reference에서 구체화한 학습 성과

좋은 학습 결과라면 학습자가 다음을 할 수 있어야 한다.

1. 데드락을 단순한 "멈춤"이 아니라 프로세스 집합 사이의 자원 보유와 대기 관계로 설명한다.
2. 데드락 발생에 필요한 네 조건을 나열하고 각 조건의 의미를 구분한다.
3. 자원 할당 그래프의 노드와 간선 방향을 해석한다.
4. 사이클과 데드락의 관계를 자원 유형별 인스턴스 수에 따라 다르게 판단한다.
5. 예방, 회피, 탐지·복구의 개입 시점과 전제를 비교한다.
6. 예방이 네 필요조건 중 하나 이상을 성립하지 못하게 하는 방식임을 설명하고 조건별 방법을 연결한다.
7. 안전 상태와 불안전 상태를 구분하고, 자원 요청을 승인할지 판단하는 회피 원리를 설명한다.
8. 탐지 후 사용할 수 있는 프로세스 종료와 자원 선점 방식의 복구 방법을 구분한다.

### 적절한 인출 형태

이 자료에는 한 가지 카드 방향만 적용하지 않는다.

- 용어 → 정의: 데드락, 안전 상태와 같은 개념 설명
- 조건 또는 상황 → 판정: 사이클, 안전·불안전 상태, 자원 요청 승인 여부
- 전략 → 핵심 원리: 예방, 회피, 탐지·복구
- 방지하려는 조건 → 구체적인 예방 방법
- 그래프 표기 → 관계 의미
- 비교 질문 → 서로 혼동하기 쉬운 개념의 차이

단순히 슬라이드 문장을 다시 읽게 하기보다, 정의를 설명하고 조건을 적용해 판단하게 하는 형태를 우선한다.

## 4. 필수 의미 범위

아래 범위는 카드 문구의 exact match가 아니라 의미적 포착 여부를 평가한다. 하나의 의미 범위를 여러 적절한 LearningUnit으로 나눌 수 있지만, 서로 독립적인 내용을 한 카드에서 모두 답하게 하거나 같은 사실을 표현만 바꾸어 반복해서는 안 된다.

### A. 데드락의 개념과 발생 구조

#### LU-D01. 데드락 정의

- **지위**: 필수
- **학습 대상**: 차단된 프로세스 집합에서 각 프로세스가 자원을 보유한 채, 집합 내 다른 프로세스가 보유한 자원을 기다리는 상태
- **학습 의도**: 데드락의 핵심인 상호 자원 대기 관계를 설명한다.
- **원문 근거**: 3페이지
- **주의**: 단순히 "프로세스가 멈춘 상태"라고만 하면 자원 보유와 순환 대기라는 핵심 관계가 빠진다.

#### LU-D02. 데드락의 네 가지 필요조건이 동시에 성립해야 함

- **지위**: 필수
- **학습 대상**: 상호 배제, 점유 대기, 비선점, 순환 대기가 동시에 성립할 때 데드락이 발생할 수 있다.
- **학습 의도**: 조건 하나의 존재만으로 데드락을 확정하지 않고 네 조건의 결합 관계를 이해한다.
- **원문 근거**: 5페이지, 14페이지
- **주의**: 네 조건은 데드락의 필요조건이다. "네 조건 중 하나만 만족하면 데드락" 또는 "네 조건을 외우기만 하면 모든 상태를 확정할 수 있다"고 바꾸지 않는다.

#### LU-D03. 상호 배제

- **지위**: 필수
- **학습 대상**: 한 시점에 하나의 프로세스만 해당 자원을 사용할 수 있다.
- **학습 의도**: 공유 불가능한 자원이 데드락 조건에 기여하는 방식을 설명한다.
- **원문 근거**: 5페이지

#### LU-D04. 점유 대기

- **지위**: 필수
- **학습 대상**: 프로세스가 하나 이상의 자원을 보유하면서 다른 프로세스가 보유한 추가 자원을 기다린다.
- **학습 의도**: "보유"와 "추가 대기"가 동시에 존재해야 하는 조건임을 설명한다.
- **원문 근거**: 5페이지

#### LU-D05. 비선점

- **지위**: 필수
- **학습 대상**: 자원을 보유한 프로세스가 자발적으로 해제할 때만 자원을 회수할 수 있다.
- **학습 의도**: 운영체제가 자원을 강제로 빼앗을 수 없는 조건을 설명한다.
- **원문 근거**: 5페이지

#### LU-D06. 순환 대기

- **지위**: 필수
- **학습 대상**: 각 프로세스가 다음 프로세스가 보유한 자원을 기다리고 마지막 프로세스가 다시 첫 프로세스의 자원을 기다리는 순환 관계
- **학습 의도**: 대기 관계가 닫힌 고리를 이루는 구조를 설명한다.
- **원문 근거**: 5페이지

### B. 시스템 모델과 자원 할당 그래프

#### LU-G01. 자원 사용 생명주기

- **지위**: 권장 기초 단위
- **학습 대상**: 프로세스의 자원 사용은 `request → use → release` 순서로 이루어진다.
- **학습 의도**: 이후 요청 간선과 할당 간선의 의미를 이해할 기초를 마련한다.
- **원문 근거**: 4페이지

#### LU-G02. 요청 간선과 할당 간선

- **지위**: 필수
- **학습 대상**:
  - `Pi → Rj`: 프로세스 `Pi`가 자원 유형 `Rj`의 인스턴스를 요청한다.
  - `Rj → Pi`: 자원 유형 `Rj`의 인스턴스가 프로세스 `Pi`에 할당되어 있다.
- **학습 의도**: 간선 방향을 보고 요청 관계와 보유 관계를 구분한다.
- **원문 근거**: 6페이지
- **주의**: 방향을 반대로 해석하면 이후 사이클 판단 전체가 틀어진다.

#### LU-G03. 사이클과 데드락의 관계

- **지위**: 필수·중대한 판정 단위
- **학습 대상**:
  - 사이클이 없으면 데드락이 아니다.
  - 자원 유형마다 인스턴스가 하나뿐일 때 사이클이 있으면 데드락이다.
  - 자원 유형에 여러 인스턴스가 있을 때 사이클은 데드락 가능성을 뜻하며, 데드락을 확정하지 않는다.
- **학습 의도**: 그래프의 사이클을 자원 인스턴스 수와 함께 해석한다.
- **원문 근거**: 7페이지
- **중대한 오류**: "사이클이 있으면 항상 데드락"이라고 일반화하는 것

### C. 데드락 처리 전략

#### LU-H01. 예방·회피·탐지 및 복구의 차이

- **지위**: 필수 비교 단위
- **학습 대상**:
  - **예방**: 네 필요조건 중 하나 이상이 성립하지 못하게 해 데드락 상태 진입을 막는다.
  - **회피**: 프로세스의 최대 자원 사용 등에 관한 사전 정보를 이용해 안전 상태를 유지하도록 할당을 결정한다.
  - **탐지 및 복구**: 데드락 진입을 허용한 뒤 탐지하고 복구한다.
- **학습 의도**: 세 전략을 모두 "데드락을 막는 방법"으로 뭉뚱그리지 않고 개입 방식과 전제를 비교한다.
- **원문 근거**: 8페이지, 14페이지
- **주의**: 한 카드에 세 전략의 모든 세부 구현을 장문으로 요구할 필요는 없다. 비교표, 구분 카드 또는 전략별 카드로 나눌 수 있다.

### D. 데드락 예방

#### LU-P01. 예방의 기본 원리

- **지위**: 필수
- **학습 대상**: 네 가지 필요조건 중 적어도 하나가 성립하지 못하도록 보장한다.
- **학습 의도**: 예방 기법들을 하나로 묶는 공통 원리를 설명한다.
- **원문 근거**: 8~9페이지

#### LU-P02. 상호 배제 조건 제거의 한계

- **지위**: 필수 경계 조건
- **학습 대상**: 본질적으로 공유할 수 없는 자원에는 상호 배제를 부정하는 방식의 예방을 적용할 수 없다.
- **학습 의도**: 네 조건을 모두 같은 방식으로 쉽게 제거할 수 있다고 오해하지 않는다.
- **원문 근거**: 9페이지

#### LU-P03. 점유 대기 방지 방법

- **지위**: 필수
- **학습 대상**: 프로세스가 실행 전에 필요한 모든 자원을 한꺼번에 요청하고 할당받도록 한다.
- **학습 의도**: 자원을 보유한 상태에서 추가 자원을 기다리는 상황을 차단한다.
- **원문 근거**: 9페이지

#### LU-P04. 비선점 조건 방지 방법

- **지위**: 필수
- **학습 대상**: 프로세스가 즉시 할당받을 수 없는 추가 자원을 요청하면 현재 보유한 자원을 모두 해제하고, 기존 자원과 새 자원을 다시 확보할 수 있을 때 재시작한다.
- **학습 의도**: 자원 회수를 허용해 비선점 조건을 깨는 방식을 설명한다.
- **원문 근거**: 9페이지

#### LU-P05. 순환 대기 방지 방법

- **지위**: 필수
- **학습 대상**: 모든 자원 유형에 전체 순서를 부여하고 프로세스가 증가하는 순서로만 자원을 요청하게 한다.
- **학습 의도**: 자원 요청 방향에 일관된 순서를 강제해 순환 고리를 차단한다.
- **원문 근거**: 9페이지

### E. 데드락 회피

#### LU-A01. 안전 상태의 의미

- **지위**: 필수
- **학습 대상**: 모든 프로세스가 어떤 순서에 따라 최대 필요 자원까지 할당받고 완료할 수 있어 데드락을 피할 수 있는 상태
- **학습 의도**: 단순히 "현재 데드락이 없음"이 아니라 안전 순서가 존재하는 상태로 설명한다.
- **원문 근거**: 10페이지

#### LU-A02. 안전 상태와 불안전 상태의 비대칭

- **지위**: 필수·중대한 판정 단위
- **학습 대상**:
  - 안전 상태이면 데드락이 없다.
  - 불안전 상태이면 데드락 가능성이 있지만, 불안전 상태 자체가 곧 데드락은 아니다.
- **학습 의도**: 안전성 판정과 실제 데드락 발생을 구분한다.
- **원문 근거**: 10페이지
- **중대한 오류**: "불안전 상태는 이미 데드락 상태다"라고 설명하는 것

#### LU-A03. 자원 요청 승인 기준

- **지위**: 필수 적용 단위
- **학습 대상**: 즉시 할당한 뒤에도 시스템이 안전 상태에 남는 경우에만 요청을 승인한다.
- **학습 의도**: 현재 자원이 사용 가능하다는 이유만으로 요청을 승인하지 않고, 할당 이후 상태를 평가한다.
- **원문 근거**: 10페이지, 12페이지

#### LU-A04. 회피 그래프의 간선 전이

- **지위**: 필수
- **학습 대상**:
  - claim edge: 프로세스가 미래에 자원을 요청할 수 있음을 나타내는 점선
  - 실제 요청 시 claim edge → request edge
  - 할당 시 request edge → assignment edge
  - 해제 시 assignment edge → claim edge
- **학습 의도**: 자원 요청·할당·해제에 따라 그래프 관계가 어떻게 바뀌는지 설명한다.
- **원문 근거**: 11페이지

#### LU-A05. 자원 인스턴스 수에 따른 회피 알고리즘

- **지위**: 필수 경계 조건
- **학습 대상**: 자원 유형에 여러 인스턴스가 있으면 Banker 알고리즘을 사용한다.
- **학습 의도**: 단일 인스턴스용 자원 할당 그래프 판정을 모든 경우에 그대로 적용하지 않는다.
- **원문 근거**: 11페이지

### F. 데드락 탐지와 복구

#### LU-R01. 탐지의 기본 원리와 범위

- **지위**: 필수
- **학습 대상**: 시스템이 데드락 상태에 들어가는 것을 허용하고, 주기적으로 그래프의 사이클을 찾는 탐지 알고리즘을 수행한다.
- **학습 의도**: 탐지·복구가 예방이나 회피와 달리 사후 대응임을 설명한다.
- **원문 근거**: 13페이지
- **경계 조건**: 여러 인스턴스가 있는 자원 유형에는 더 복잡한 탐지 알고리즘이 필요하다.

#### LU-R02. 프로세스 종료를 통한 복구

- **지위**: 필수
- **학습 대상**:
  - 데드락된 프로세스를 모두 종료한다.
  - 사이클이 제거될 때까지 프로세스를 하나씩 종료한다.
- **학습 의도**: 프로세스 종료 방식의 두 선택지를 구분한다.
- **원문 근거**: 13페이지

#### LU-R03. 자원 선점을 통한 복구

- **지위**: 필수
- **학습 대상**: 일부 프로세스의 자원을 선점해 다른 프로세스에 주고 데드락 사이클을 끊는다.
- **학습 의도**: 프로세스를 종료하지 않고 자원 재배치로 복구하는 방식을 설명한다.
- **원문 근거**: 13페이지

## 5. 권장 적용·진단 단위

다음은 핵심 개념을 실제 상황에 적용하는 능력을 확인하는 데 유용하지만, 예시 자체의 고유한 기호를 암기하는 것은 필수가 아니다.

### 세마포어 순서 역전 예시

- **지위**: 권장 적용 단위
- **원문 근거**: 3페이지
- **학습 의도**: `P0`가 `S`를 보유하고 `Q`를 기다리며, `P1`이 `Q`를 보유하고 `S`를 기다릴 때 왜 서로 진행할 수 없는지 설명한다.
- **평가 기준**: `P0`, `P1`, `S`, `Q`라는 이름을 외우는 것이 아니라 반대 순서의 자원 획득이 순환 대기를 만드는 원리를 설명해야 한다.

### 자원 할당 그래프 판정 예시

- **지위**: 권장 적용 단위
- **원문 근거**: 7페이지
- **학습 의도**: 그래프에서 사이클을 찾고 자원 인스턴스 수를 함께 고려해 데드락 여부를 판단한다.
- **평가 기준**: 슬라이드의 세 그래프 모양을 통째로 외우기보다 새로운 그래프에도 판정 규칙을 적용할 수 있어야 한다.

### 요청 승인·거절 예시

- **지위**: 권장 적용 단위
- **원문 근거**: 12페이지
- **학습 의도**: 요청을 할당하면 사이클과 불안전 상태가 생기는 경우 요청을 거절하는 이유를 설명한다.
- **평가 기준**: `P2`와 `R2`라는 기호보다 "할당 이후 안전 상태 유지 여부"를 판단 근거로 사용해야 한다.

## 6. 카드화하지 않거나 중복을 줄여야 할 내용

### 문서 메타데이터

- **분류**: `metadata`
- **대상**: 장 제목, 페이지 번호, 목차용 영어 항목
- **제외 이유**: 개념 학습과 직접 관련이 없다. 단, 목차의 핵심 주제가 실제 내용에서 누락됐는지 확인하는 용도로는 사용할 수 있다.

### 요약 페이지의 반복 문장

- **분류**: `redundant_summary`
- **원문 위치**: 14페이지
- **제외 이유**: 앞 페이지에서 이미 다룬 정의와 전략을 표현만 바꾸어 중복 카드화하지 않는다.
- **사용 방식**: 핵심 범위 누락 여부를 확인하는 체크리스트로 사용한다.

### 예시 그래프의 고유 기호와 배치

- **분류**: `example_specific_detail`
- **대상**: 7페이지와 12페이지의 특정 `Pi`, `Rj` 번호와 화면상 위치
- **제외 이유**: 고유 기호와 그림 배치를 외우는 것이 목표가 아니라 그래프 판정 규칙을 적용하는 것이 목표다.

### 슬라이드 문장의 기계적 분할

- **분류**: `low_learning_value_fragment`
- **대상**: 하나의 정의나 절차를 줄바꿈 단위로 잘라 만든 불완전한 카드
- **제외 이유**: 슬라이드의 줄바꿈은 의미 단위 경계가 아니다. 필요한 조건과 결과를 함께 유지해야 한다.

### 같은 개념의 한영 중복 카드

- **분류**: `redundant_translation`
- **제외 이유**: 현재 목표는 운영체제 개념 이해와 적용이다. 영어 문장과 한국어 번역을 각각 별도 핵심 카드로 만들어 카드 수를 늘리지 않는다.
- **예외**: 시험 목표가 영문 용어 자체의 인출을 요구하면 핵심 용어의 한영 대응은 별도 목표로 둘 수 있다.

## 7. 대표적으로 허용 가능한 카드 예시

아래는 좋은 인출 형태를 보여주는 예시이며 고정된 정답 목록이 아니다. 같은 의미 범위를 더 명확한 카드로 구현하거나, 필요한 맥락을 유지하면서 적절히 분할할 수 있다.

### 예시 1. 데드락 정의

- **앞면**: 운영체제에서 데드락은 어떤 자원 대기 상태인가?
- **뒷면**: 차단된 프로세스 집합의 각 프로세스가 자원을 보유한 채, 집합 내 다른 프로세스가 보유한 자원을 기다려 서로 진행하지 못하는 상태다.
- **근거**: 3페이지

### 예시 2. 네 가지 필요조건

- **앞면**: 데드락 발생에 필요한 네 조건은?
- **뒷면**: 상호 배제, 점유 대기, 비선점, 순환 대기이며 네 조건이 동시에 성립해야 한다.
- **근거**: 5페이지
- **주의**: 각 조건의 의미를 별도 카드로 확인하는 구성도 허용한다.

### 예시 3. 자원 할당 그래프의 간선

- **앞면**: 자원 할당 그래프에서 `Pi → Rj`와 `Rj → Pi`는 각각 무엇을 뜻하는가?
- **뒷면**: `Pi → Rj`는 요청, `Rj → Pi`는 할당 또는 보유를 뜻한다.
- **근거**: 6페이지

### 예시 4. 사이클 판정

- **앞면**: 자원 할당 그래프에 사이클이 있으면 언제 데드락을 확정할 수 있는가?
- **뒷면**: 각 자원 유형에 인스턴스가 하나뿐일 때다. 여러 인스턴스가 있으면 사이클은 데드락 가능성만 뜻한다.
- **근거**: 7페이지

### 예시 5. 처리 전략 비교

- **앞면**: 데드락 예방, 회피, 탐지·복구는 개입 방식이 어떻게 다른가?
- **뒷면**: 예방은 필요조건 하나 이상을 깨고, 회피는 사전 정보를 이용해 안전 상태를 유지하며, 탐지·복구는 데드락 진입 후 찾아서 복구한다.
- **근거**: 8페이지

### 예시 6. 순환 대기 예방

- **앞면**: 순환 대기 조건을 깨기 위해 자원 요청에 어떤 제약을 두는가?
- **뒷면**: 자원 유형에 전체 순서를 부여하고 각 프로세스가 증가하는 순서로만 자원을 요청하게 한다.
- **근거**: 9페이지

### 예시 7. 안전 상태

- **앞면**: 데드락 회피에서 안전 상태란 무엇인가?
- **뒷면**: 모든 프로세스가 어떤 순서에 따라 최대 필요 자원까지 할당받고 완료할 수 있어 데드락을 피할 수 있는 상태다.
- **근거**: 10페이지

### 예시 8. 불안전 상태의 의미

- **앞면**: 불안전 상태는 이미 데드락이 발생했다는 뜻인가?
- **뒷면**: 아니다. 불안전 상태는 데드락 가능성이 있는 상태이며 현재 데드락 상태와 동일하지 않다.
- **근거**: 10페이지

### 예시 9. 회피의 할당 결정

- **앞면**: 사용 가능한 자원 요청을 즉시 승인하기 전에 회피 알고리즘이 확인해야 하는 것은?
- **뒷면**: 요청을 할당한 뒤에도 시스템이 안전 상태에 남는지 확인해야 한다.
- **근거**: 10페이지, 12페이지

### 예시 10. 탐지 후 복구

- **앞면**: 탐지된 데드락을 복구하는 두 가지 큰 방법은?
- **뒷면**: 데드락 프로세스를 종료하거나 일부 자원을 선점해 사이클을 끊는다.
- **근거**: 13페이지

## 8. 중대한 오류 조건

다음 오류는 카드 문구의 자연스러움과 무관하게 핵심 개념을 왜곡하므로 중대한 실패로 본다.

- 데드락을 단순한 프로세스 정지로만 설명하고 자원 보유·대기 관계를 누락한다.
- 네 필요조건 중 하나만 성립해도 데드락이라고 설명한다.
- 요청 간선과 할당 간선의 방향을 반대로 설명한다.
- 자원 인스턴스 수와 관계없이 사이클이 있으면 항상 데드락이라고 설명한다.
- 불안전 상태를 현재 데드락 상태와 동일하게 설명한다.
- 예방과 회피를 같은 전략으로 설명한다.
- 회피가 사전 자원 사용 정보를 필요로 한다는 점을 누락하거나 반대로 설명한다.
- 탐지·복구가 데드락 진입 자체를 허용하지 않는다고 설명한다.
- 여러 인스턴스가 있는 상황에 단일 인스턴스용 그래프 판정을 그대로 일반화한다.
- 원문에 없는 알고리즘 세부사항이나 장단점을 사실처럼 추가한다.
