설계안 16장 1번(기존 구현 조사) 결과다. 설계안의 장마다 지금 코드에 무엇이 있고, 무엇을 고치고, 무엇을 새로 만드는지 적는다. 코드는 모두 `experiments/project-course/` 기준.

## 0. 한 줄 결론

지금 코드는 설계안의 **"미리 만든 대본 하나를 따라가는 특수한 경우"**다. 버리지 않고, 대본을 학습 진행 엔진의 **기본 길**로 두고 그 위에 엔진(세션 · 학습 사건 · 임시 학습 스택 · 행동 선택)을 올린다. 코스는 지금도 AI가 만들고 자동 관문(`test/course.test.ts`, `test/lessons.test.ts`)으로 걸렀으므로, 코스 생성은 그 과정을 학습자 앞에서 자동으로 돌리는 일이 된다.

## 2. 학습 진행 엔진 설계 (설계안 16장 2번)

### 2.1 원칙
- **상태는 코드, 문장은 LLM** (설계안 17장 셋째). 세션 · 임시 학습 스택 · 사건 · 레벨은 코드가 바꾸고, LLM은 받은 행동과 틀 안의 문장만 쓴다.
- **대본은 기본 길.** 대본이 있는 단계는 걸음을 그대로 따른다(AI 0회, 바로 넘어감). 엔진은 정해진 순간에만 끼어든다.
- **강제하지 않음.** 확인 질문은 선택, "알아요 · 넘길게요"를 늘 존중(설계안 8.1).

### 2.2 걸음 종류 ↔ 행동

| 대본 걸음 | 행동 |
|---|---|
| say(읽기) · map(훑어보기) | EXPLAIN |
| say 중 요청 보내기 · DB 보기 · 코드 조각 돌려 보기 | DEMO |
| predict(예측) | VERIFY (선택적 이해 확인) |
| fix(고치기) | GUIDE |
| 자동 검사 | VERIFY (기능) |
| 검사 실패 · 막힘 | DIAGNOSE |
| 질문 · 이건 뭐예요 · 덩어리 설명 | 임시 학습 시작(NAVIGATE) + EXPLAIN/DEMO |
| 하던 거로 돌아가기 · 다음 단계 | NAVIGATE |
| explain(내 말로) · 정리 | SUMMARIZE |

### 2.3 끼어들기 규칙 (설계안 4.2 우선순위를 코드로)

| 신호 | 엔진 행동 |
|---|---|
| 학습자의 명시적 요청(질문 · 넘기기 · 만들어 주세요) | 그대로 따름 (우선순위 1) |
| 질문 | 임시 학습 스택에 넣음(돌아갈 걸음 기억). 깊이 3 넘으면 "목표를 다시 잡을까요?" |
| 같은 검사 3번 실패 · 5분 조용 | DIAGNOSE: 다른 가설 · 작은 재현 · 되돌리기 · 같이 해요 중 제안 (설계안 7.3) |
| "알아요" | 그 개념 설명 생략, 사건 `self_report` |
| 임시 학습 끝 | NAVIGATE: 돌아갈 걸음으로, 사건 `explanation`(습득 아님) |

### 2.4 데이터 (설계안 11장 초안을 지금 저장소에 맞춤)
- `.data/sessions/<run>.json`: `LearningSession` — goal, currentStep(단계 번호), currentActivity(type · target · status), detourStack[{topic, reason, returnBeat, at}], level(내부, DECISIONS 11/3), status.
- `.data/events/<run>.jsonl`: `LearningEvent` — 진행 중 바로 덧붙임(꺼져도 안 사라짐). type(question · confusion · explanation · demo · code_edit · execution · self_report · application · verify), actor(user · agent · system), stage, beat, concept(코스 개념 id 또는 후보 이름), detail, evidence(메시지 id · 파일:줄).
- 지식 후보(`records`)와 앱 동기화는 그대로 두고, 나중에 사건에서 후보를 만들도록 옮긴다(설계안 9.2 "단계·세션 끝에 정리").

## 3. 순서

1. **(지금) 엔진 기반:** 세션 · 사건 · 임시 학습 스택 · 행동 대응을 만들고 수업(`lesson.ts`)에 연결. 화면에 "질문 중 · 돌아갈 곳" 표시.
2. **끼어들기 규칙:** 실패 반복 → DIAGNOSE, "알아요", 레벨로 과제 크기.
3. **재개:** 사건으로 "지난번에는…".
4. **지식 연동:** 사건 → 후보 정리, 앱 검색(P1·P2)으로 관련 지식 주입.
5. **OpenCode 작업 지시:** "만들어 주세요"를 작업 지시 형식으로(범위 · 제외 · 검증), 관문 통과한 결과만.
6. **코스 생성:** 목표 → 목차 → 첫 단계만 바로 생성 · 관문(시작 실패 · 정답 통과 · 일부러 틀린 정답을 검사가 떨어뜨림) → 뒤 단계는 뒤에서.
7. **평가:** 초보 HTTP 서버 시나리오로 목표 · 구현 · 오류 · 임시 학습 · 재개까지.
