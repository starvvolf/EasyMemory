## 한 줄

NPC는 **아는 조각만** 가져요. 코드(연출가)가 그 조각으로 갈 수 있는 **풀이 길**을 고르고, AI는 그 길을 코드와 말로 옮겨요. 모범 풀이는 채점할 때만 써요.

## 조각 나눔

| 조각 | 누가 | 하는 일 | AI |
|---|---|---|---|
| **명세** | 데이터(JSON) | 이 학습자가 가진 조각, 성격 | 없음 |
| **풀이 조각 지도** | AI 한 번 + 코드 검증 | 이 문제를 푸는 길들과, 길마다 필요한 조각. 길의 판정은 실제 채점으로 잼 | 문제마다 1번 |
| **연출가** | 코드 | 가진 조각으로 갈 길을 고르고, 빠진 조각 자리에서 막히게 하고, 배우면 다시 계획 | 없음 |
| **입과 손** | AI (작은 호출) | 연출가가 정한 길을 코드와 질문으로 씀. 허용된 조각만 받음 | luna · terra low |
| **검사** | 코드 + 채점기 | 쓴 코드의 판정이 그 길의 판정과 같은지, 모르는 문법을 쓰지 않았는지 | 없음 (의심될 때 싼 판정 1번) |
| **정답지** | 코드 | 어느 길로 갔고, 어느 조각이 없어서 어디서 막혔는지 | 없음 |

## 1. 학습자 명세

v1과 같아요. 달라진 건 두 가지예요: 아는 것의 항목이 **풀이 조각**과 같은 이름을 쓰고, 성격에 **조합력**이 생겼어요.

```jsonc
{
  "id": "npc_minsu", "seed": 7, "name": "민수", "lang": "python",
  "knows": {
    "base": { "1": "앎", "2": "앎", "3": "애매", "4": "애매", "5": "모름", "6": "모름", "run": "앎" },
    "items": {
      "tool.queue":         { "state": "모름" },                 // 큐를 모름
      "tool.recursion":     { "state": "앎" },
      "idea.mark-visited":  { "state": "잘못 앎", "belief": "한 번 본 곳을 표시하지 않아도 언젠가 끝난다" },
      "syntax.py.2d-list":  { "state": "모름" }
    }
  },
  "traits": {
    "invent": 0.5,        // 조합력: 조각은 다 있는데 "이걸 이렇게 엮으면 되겠다"를 떠올릴 확률 (v2에서 더함)
    "switch": 0.4,        // 새 조각을 배웠을 때 더 나은 길로 갈아탈 확률 (v2에서 더함)
    "askEarly": 0.3, "guess": 0.4, "helpRungs": 0.5, "copyTutor": 0.2, "confirm": 0.3,
    "patience": 20, "typo": 0.1, "terse": 0.7
  },
  "learning": { "perExplain": 0.6, "perHint": 0.3, "fromOwnFix": 0.5, "forgetPerDay": 0.03 }
}
```

- 상태 네 가지(앎 · 모름 · 잘못 앎 · 애매)는 그대로예요. **잘못 앎**의 틀린 믿음은 "틀린 조각"으로 풀이에 들어가요(2번).
- **조합력**을 넣은 이유: 조각을 가졌다고 풀이가 저절로 나오지 않아요. "방법 고르기(6층)에서 막힘"은 조각이 없어서가 아니라 엮지 못해서 생기는 경우가 많아요.

### 옵션: 기본값에 붙이는 조각

기본 학습자(`default.json`) 하나에 **옵션 조각**을 겹쳐서 사람을 만들어요. 조각은 명세의 일부만 담은 작은 JSON이에요.

```jsonc
// options/문법약함-py.json
{ "id": "문법약함-py", "label": "파이썬 문법이 약함", "patch": { "knows": { "base": { "1": "모름" } }, "traits": { "typo": 0.2 } } }
```

```
node lab/npc/run.mjs --problem 11651 --with 문법약함-py,버티기,설명두번 --seed 3
```

처음에 넣을 조각(약 15개):

| 묶음 | 조각 |
|---|---|
| 아는 것 | 문법약함(언어별) · 읽기약함(3층) · 잇기약함(4층) · 원리모름(패턴 지정) · 방법못고름(6층) · 잘못앎(패턴 + 믿음 지정) · 다른언어에서옴(파이썬은 알고 C#은 처음) · 고수 |
| 성격 | 바로묻기 · 버티기 · 찍어내기 · 힌트의존 · 복붙형 · 확인연타 · 포기빠름 · 말짧음 |
| 배움 | 한번에앎 · 설명두번 · 금방잊음 |

- 겹칠 때는 뒤에 쓴 조각이 이겨요. 숫자는 코드가 0~1로 잘라요.
- 조각끼리 부딪치면(고수 + 문법약함) 실행 전에 알려 줘요.

### 옵션을 AI로 만들기

```
node lab/npc/make.mjs "C#은 처음이고 파이썬은 좀 하는 2학년. 질문을 못 참고, 튜터 코드를 그대로 붙여 넣음"
```

- AI 1번(terra low, 출력은 조각 JSON 하나)이 사람 설명을 조각으로 바꿔요.
- 코드가 모양을 검사해요(Zod). 없는 항목 이름은 버리고, 숫자는 범위로 잘라요.
- 결과를 사람이 읽을 수 있게 다시 풀어 보여 줘요: "1층(C#) 모름, 1층(파이썬) 앎, 바로 묻기 0.9, 복붙 0.8 …". 마음에 들면 `options/`에 저장해서 계속 써요.
- **기록에서 만들기**: 실제 풀이 기록(예: 사용자 본인의 2606 층 검증 표)을 주면 그 사람을 닮은 조각을 만들어요. "나 닮은 NPC"로 내가 겪은 흐름을 다시 돌려 볼 수 있어요.
- **한꺼번에 만들기**: "초보 5명을 서로 다르게"처럼 시키면 조각 여러 개를 한 번에 내요. 코드가 서로 너무 비슷한 것(값 차이가 작은 것)은 걸러요.

## 2. 풀이 조각 지도 (문제마다 한 번, 모든 NPC가 같이 씀)

v1의 "문제 지식 지도"를 바꾼 거예요. v1은 **모범 풀이 하나**가 요구하는 항목을 적었고, v2는 **풀이 길 여러 개**와 길마다 필요한 조각을 적어요.

- **조각**: 풀이를 이루는 생각이나 도구 하나. 설명 한 문장 + 예시 코드 3~8줄 + 층.
- **길**: 조각을 엮은 풀이 방법 하나. 걸음 순서와 필요한 조각 목록.
- **틀린 조각**: 그럴듯하지만 틀린 생각. 지금 있는 재료(`ProblemModel`의 틀린 접근 · 틀린 상태 설계 · 함정)에서 가져와요.
- **길의 판정은 재서 적어요.** AI가 길마다 그 길대로 쓴 코드를 내면, 코드가 **실제 채점기**로 돌려 맞음 · 틀림 · 시간 초과를 지도에 적어요. "이 길은 느릴 것"이라고 짐작하지 않아요.

**예: 2606 바이러스**

| 조각 | 층 | 무엇 |
|---|---|---|
| `shape.edge-list` | 2 | 연결을 (a, b) 쌍의 목록으로 담기 |
| `shape.adj-list` | 2 | 연결을 "번호 → 이웃 목록"으로 담기 |
| `idea.mark-visited` | 5 | 한 번 본 컴퓨터를 표시해 두고 다시 보지 않기 |
| `tool.queue` | 2 · 4 | 넣고, 앞에서 꺼내기 |
| `tool.recursion` | 4 | 함수가 자기를 다시 부르기 |
| `idea.until-no-change` | 5 | 바뀐 게 없을 때까지 전체를 다시 훑기 |
| `frame.bfs` | 4 | 꺼냄 → 이웃 봄 → 표시 → 넣음 순서 |
| `frame.dfs` | 4 | 표시 → 이웃마다 다시 부름 |
| `syntax.py.2d-list` 등 | 1 | 빈 목록 N개 만들기, 입력 읽기 … |
| ✗ `wrong.direct-only` | 6 | "1번과 바로 연결된 것만 세면 된다" |
| ✗ `wrong.no-visited` | 5 | "표시하지 않아도 언젠가 끝난다" |

| 길 | 필요한 조각 | 잰 판정 |
|---|---|---|
| A. BFS | adj-list · mark-visited · queue · frame.bfs | 맞음 |
| B. 재귀 DFS | adj-list · mark-visited · recursion · frame.dfs | 맞음 |
| C. 반복해서 훑기 | edge-list · mark-visited · until-no-change | 맞음 (N ≤ 100이라 통과) |
| D. 바로 연결된 것만 | edge-list · ✗direct-only | 틀림 |
| E. 표시 없이 탐색 | adj-list · queue · ✗no-visited | 끝나지 않음 → 시간 초과 |

- 만들기: AI 1번이 문제 · `ProblemModel` · 모범 풀이를 보고 조각과 길, 길별 코드를 내요. 코드가 길별 코드를 채점기로 돌려 판정을 적고, 조각 예시 코드도 실제로 돌아가는지 봐요. **처음 몇 문제의 지도는 사람이 눈으로 확인해요**(지도가 틀리면 뒤가 다 틀려요).
- 실습도 같아요. 예) 공유 체력: `lock`으로 감싸기 / `Interlocked` 쓰기 / 한 스레드가 순서대로 처리하게 몰기 / ✗"요청이 빨라서 안 겹친다".

## 3. 연출가 (코드, AI 없음)

**길 고르기**
1. 가진 조각으로 **끝까지 갈 수 있는 길**을 찾아요.
2. 여러 개면 성격과 층 기본값으로 하나를 골라요(익숙한 조각이 많은 길, 최근에 배운 조각이 든 길을 더 자주).
3. **조합력 주사위**: 실패하면 길이 있어도 떠올리지 못해요 → "방법을 모르겠음"으로 막혀요.
4. 끝까지 갈 길이 없으면 **가장 멀리 갈 수 있는 길**을 가다가 **빠진 조각 자리에서** 막혀요.
5. 틀린 조각(잘못 앎)을 가졌으면 그 조각이 든 길을 자신 있게 골라요 → 채점에서 틀려요.

**한 판의 흐름**

```
읽기 → 길 고르기 ─┬ 갈 길 있음 → 걸음마다 코드 쓰기 → 예제 실행 → 제출
                  ├ 길을 못 떠올림(조합력) ─┐
                  └ 빠진 조각 자리에서 멈춤 ─┴→ 반응 고르기(성격 주사위)
                                               ├ 혼자 버티며 지어 쓰기   (문법이면 없는 문법을 지어 씀 → 오류)
                                               ├ 틀린 조각으로 메우기    (있으면)
                                               ├ 도움 칸 · 힌트 열기
                                               ├ 튜터에게 묻기 → 배움 판정 → 조각이 생기면 **길을 다시 계획**
                                               └ 포기
제출이 틀림 → (틀린 길이었으면) 반응 고르기 / (실수였으면) 혼자 고치기
맞음 또는 포기 → 나가기 → 풀이 한 장 · 리뷰가 만들어지길 기다림
```

- **배우면 다시 계획**: 튜터가 큐를 가르치면 `tool.queue`가 생겨요. 반복해서 훑던 NPC가 BFS 길로 갈아탈 수도 있고(`switch` 주사위), 하던 길을 그대로 끝낼 수도 있어요.
- **언제 끝나나는 성격이 정해요.** 질문 · 제출을 낮게 묶지 않아요. 상한(질문 20 · 제출 15 · 행동 40)은 끝없이 도는 걸 막는 안전장치예요.
- **배움 판정**: 튜터 답이 어느 조각을 가르쳤는지 싼 AI 1번(luna)이 조각 목록에서 골라요. 가르쳤으면 `perExplain` 주사위로 조각이 생겨요.
- **아는데 하는 실수**(`typo`), **복붙형**(튜터가 준 코드를 그대로 붙임 → 맞혀도 조각은 안 생김)은 v1 그대로예요. 리뷰가 실수를 "모름"으로 잘못 잡는지, 복붙을 "아직 모름"으로 잡는지 보는 미끼예요.
- 같은 명세 + 같은 문제 + 같은 씨앗이면 **길과 막히는 자리가 똑같아요.**

## 4. 입과 손 (AI, 작은 호출)

| 호출 | 모델 | 받는 것 | 내는 것 |
|---|---|---|---|
| **코드 쓰기** | terra low | 문제 + **이번 길의 걸음 + 허용된 조각(설명 · 예시 코드)** + 직전 내 코드 | 코드 한 벌 (빠진 자리는 비워 두거나, 틀린 조각대로) |
| **말 쓰기** | luna | 성격(말투) + 상황("큐를 모름, 이웃을 어디에 쌓을지 모르겠음") | 질문 한두 문장 |
| **배움 판정** | luna | 튜터 답 + 이 문제의 조각 목록 | 가르친 조각 id들 |

- **모범 풀이와 허용되지 않은 조각은 AI에게 보내지 않아요.** v1은 "정답에서 빈틈만큼 틀리게"였고, v2는 "이 조각들로 이 걸음을 써"예요.
- **두 가지 세기**
  - **엄격(기본)**: 코드가 길과 걸음을 정하고 AI는 옮기기만 해요. 다시 돌리면 같아요. 지식 하나를 바꾸는 실험은 이걸로 해요.
  - **느슨(나중, 관찰용)**: AI에게 허용 조각 목록만 주고 길을 스스로 짜게 해요. 지도에 없는 엉뚱한 길이 나올 수 있어 사람다운 모습을 보기 좋지만, 다시 돌리면 달라지고 채점하기 어려워요. 새로 나온 길은 지도에 더할 후보로 모아요.

### 실습은 손이 더 필요해요: 작은 하네스

실습은 파일 여러 개를 고치고 명령을 돌려야 해서, 한 번 부르고 끝나는 호출로는 안 돼요.

- NPC의 손은 **도구 세 개만 가진 작은 에이전트 루프**예요: 파일 읽기 · 파일 고치기 · 명령 실행(작업 폴더 안에서만).
- 연출가가 한 걸음씩만 시켜요: "목표 2의 적용 과제를, 빈틈 `concept.race-condition`(모름) 상태로 해 봐. 최대 6걸음."
- 손이 한 일은 **VS Code 확장이 보내는 것과 같은 모양**으로 실습 서버에 알려요: 저장한 파일, 실행한 명령과 출력(`/api/bridge/state` · `/api/bridge/terminal`), 질문(`/api/bridge/ask`), 대화와 "해 봤어요"(`/api/runs/<id>/lesson/<n>/act`). 실습 서버는 사람인지 NPC인지 몰라요.
- 엔진은 실습 튜터가 쓰는 것과 같은 OpenCode를 창 없이 써요(새로 만들지 않음). 도구 권한은 코드가 걸러요.

- 실습의 손도 허용된 조각만 받아요.

## 5. 검사

1. **길의 판정과 맞는지**: NPC가 쓴 코드를 진짜 채점기로 돌려요. 그 길의 잰 판정과 다르면(맞는 길인데 틀림 = 옮기다 생긴 오류 / 틀린 길인데 맞음 = 길 밖의 지식이 섞임) 버리고 한 번 다시 써요. 두 번 실패하면 정답지에 "재현 못 함"으로 적어요.
2. **문법 누수 (낱말 · 모양)**: 모르는 문법 조각의 모양이 코드에 나오면 다시 써요. **문법에만** 써요.
3. **조각 밖 지식 (생각 · 방법)**: 낱말로는 못 막아요. 그래서 ① 애초에 안 주고 ② 코드가 길을 정하고 ③ 1번 판정 검사로 잡아요. 그래도 의심되면(코드가 걸음 수보다 훨씬 길거나, 길에 없는 반복 구조가 보이면) 싼 AI 1번이 "이 코드가 조각 목록 밖의 것을 쓰나"를 봐요. **완전한 강제는 아니에요.** 표본을 사람이 가끔 확인해요.
4. **다 배운 뒤**: 조각이 다 생긴 NPC의 코드는 맞아야 해요. 안 맞으면 하네스 버그예요.
5. **진짜 사람과 맞춰 보기**: 사용자 본인 기록(2606: 말 34개의 층 분포)과 "나 닮은 NPC"의 분포를 비교해요.

## 6. 두 가지 모드

| 모드 | 방식 | 쓸 곳 | 말할 수 있는 것 |
|---|---|---|---|
| **조합 (기본)** | 아는 조각 → 길 → 코드 | 지식 차이가 풀이 · 막힘 차이로 이어지는지, 튜터 · 리뷰 · 상황 재현이 그걸 따라가는지 | "이런 지식을 가진 학습자는 이런 길로 가다 여기서 막힌다" |
| **심기 (보조, v1 방식)** | 모범 풀이에 정한 실수 하나를 심음 | 리뷰어 · 채점 규칙이 **특정 실수**를 잡는지 반복해서 보는 회귀 시험. 지시문을 고친 뒤 깨진 게 없는지 | "이 실수가 들어오면 잡는다 / 못 잡는다"까지. 우리가 심은 걸 우리가 찾는 것이라 **두 시스템이 맞물리는지만** 확인돼요 |

## 7. 정답지와 채점

```jsonc
{ "t": 0, "route": "C", "why": "tool.queue 없음, tool.recursion 없음" }
{ "t": 4, "stuck": "syntax.py.2d-list", "layer": 1, "state": "모름", "reaction": "지어 씀", "verdict": "RE" }
{ "t": 6, "asked": true, "taught": ["syntax.py.2d-list"], "learned": true }
{ "t": 9, "taught": ["tool.queue"], "learned": true, "switched": "C→A" }
{ "t": 12, "slip": true, "layer": 3, "verdict": "WA", "resolvedBy": "self" }
```

| 채점하는 것 | 어떻게 |
|---|---|
| **리뷰** | 없던 조각이 리뷰에 있나(놓침), 가진 조각을 모른다고 했나(헛짚음), 실수를 "모름"으로 잡았나 |
| **기억** | 없던 조각만 기억이 됐나 |
| **튜터** | 빠진 조각을 가르쳤나, 아래층부터 짚었나, 답을 통째로 줬나 |
| **상황 재현 복습** | 뽑은 빈틈이 정답지의 없던 조각과 맞나. 장면을 다시 풀 때 그 조각을 배운 NPC는 통과, 안 배운 NPC는 또 걸리나 |

## 8. 첫 실험: 2606에서 지식 하나만 바꾸기

성격 · 씨앗 · 나머지 조각을 똑같이 두고, 조각 하나씩만 다르게 한 다섯 명이에요.

| NPC | 다른 점 | 예상 길 | 볼 것 |
|---|---|---|---|
| ① | 다 가짐 | A (BFS) | 한 번에 맞히나 |
| ② | 큐 없음, 재귀 있음 | B (재귀) | 길이 실제로 갈리나 |
| ③ | 큐 · 재귀 없음 | C (반복해서 훑기) | 지도에 있는 "돌아가는 길"이 코드로 나오나 |
| ④ | "표시하기"가 잘못 앎 | E → 시간 초과 → 막힘 | 튜터가 그 생각을 짚나, 리뷰가 [핵심]으로 잡나 |
| ⑤ | 2차원 목록 문법 없음 | A를 가다 문법 자리에서 막힘 | 튜터가 문법만 짧게 알려 주나, 리뷰가 작은 것으로 잡나 |

- 순서: 지도 만들기(AI 1번 + 길 5개 채점) → 사람이 지도 확인 → 가짜 AI로 다섯 명이 끝까지 도는지 → 실제 AI로 실행.
- 판정 기준: **예상 길과 실제 코드의 길이 같은지**(사람이 다섯 개를 읽고 확인), 막힌 자리가 빠진 조각 자리인지.
- 사용량(추정): 지도 약 1.5만 + 다섯 명 약 30만~40만 토큰 → Plus 5시간의 약 5%.

## 9. 비용

AI는 ChatGPT 구독으로 불러서 돈은 안 나가요. 대신 **Plus 5시간 한도**를 사용자와 같이 써요. 아래는 추정이고, 첫 실행의 호출 기록으로 고쳐요.

**알고리즘: NPC 한 명 × 문제 하나** (보통 판: 질문 6번 · 제출 5번쯤 쓰는 경우)

| 쪽 | 호출 | 토큰 (추정) |
|---|---|---|
| NPC | 코드 쓰기 5 (terra low, 허용 조각만 받음) | 약 1.5만 |
| NPC | 말 쓰기 6 + 배움 판정 6 (luna) | 약 1.8만 |
| 제품 (원래 드는 것) | 튜터 답 · 힌트 · 풀이 한 장 · 리뷰 | 약 4만~6만 |
| **합** | | **약 8만~9만 → API로 약 110~140원, Plus 5시간의 약 1.2%** |

- **많이 묻고 많이 내는 판**(질문 15 · 제출 10쯤): 약 18만~20만 토큰(약 2.5%). 상한을 넉넉히 둔 만큼, 비용은 판마다가 아니라 **묶음 토큰 상한**으로 지켜요.
- 실습: NPC 한 명 × 목표 하나에 약 12만~13만 토큰(약 1.7%). 손이 에이전트 루프라 알고리즘보다 커요.

**싸게 만드는 장치**

1. **연출이 코드**: 가장 비싼 "판단"에 AI를 안 써요. NPC 쪽 호출은 전부 짧은 출력이에요.
2. **모델 나눔**: 말 · 판정은 luna(뒤에 검사 있음), 코드만 terra low.
3. **상한**: 판마다 상한은 넉넉한 안전장치(질문 20 · 제출 15)이고, 실제 지킴이는 묶음의 `--max-tokens`예요. 넘으면 새 NPC를 시작하지 않고, 돌던 판은 "나가기"로 정리해요(기록은 남음).
4. **가짜 AI 모드**(`--dry`): AI 0번. 연출가 · 검사 · 정답지 · 드라이버가 끝까지 도는지만 봐요. 하네스를 고칠 때는 이걸로 해요.
5. **기록 다시 쓰기**(`--replay`): 한 번 만든 판(대화 · 제출 · 정답지)을 저장해 두고, 뒤 단계만 바꿔 다시 돌려요. 리뷰 지시문을 고쳐 다시 채점하면 리뷰 호출만 들어요(약 2만 토큰). **튜터까지 다시 돌리는 건 튜터를 바꿨을 때만** 해요.
6. **캐시**: 고정 지시문 · 문제 · 모범 풀이는 앞에, 이번 대본은 뒤에.
7. **기본 묶음은 작게**: NPC 3명 × 문제 하나 = 약 27만 토큰(약 3.6%). 실행 전에 예상 토큰을 출력하고, 실제 값과 나란히 기록해요.

- (v2) 풀이 조각 지도는 문제마다 한 번 약 1.5만 토큰이에요(길별 코드까지 받아서 v1의 지도보다 커요). 길 판정을 재는 건 채점기라 AI가 안 들어요.

## 어려운 곳 · 한계

- **지도의 질이 전부를 정해요.** 지도에 없는 길은 엄격 모드에서 안 나와요. → 길 판정은 재서 적고, 처음 지도는 사람이 확인하고, 느슨 모드에서 나온 새 길을 모아 지도를 넓혀요.
- **생각 · 방법의 누수는 완전히 못 막아요**(5번의 3). 그래서 실험 결과를 읽을 때 코드 몇 개는 사람이 직접 봐요.
- **조합력 · 갈아타기 확률은 우리가 정한 값**이에요. NPC 결과로 "사람도 그렇다"고 말할 수는 없어요. 말할 수 있는 건 "이 조각이 없으면 이 길로 가고 여기서 막힌다"가 시스템 안에서 일관되게 나온다는 것까지예요.
- **조각의 크기**: 너무 잘게 쪼개면 지도가 커지고, 너무 크게 잡으면 "큐는 아는데 앞에서 꺼내는 걸 모름" 같은 차이를 못 내요. 처음에는 층 하나에 조각 하나쯤으로 잡고, 실제 기록(2606의 말 34개)에 대 보며 고쳐요.
- 배움 판정이 후해질 수 있음, 실습의 동시성 재현, 날짜 흉내는 v1과 같아요.

4. 2606 지도의 조각 크기(위 표)가 맞는지 — 실험 전에 한 번 봐 주시면 좋아요.
