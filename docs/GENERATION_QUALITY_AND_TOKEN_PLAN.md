# 생성엔진 품질 개선 및 토큰 절약 실행 계획

작성일: 2026-08-13

## 목적

Study Forge 생성엔진의 두 가지 핵심 문제를 순서대로 해결한다.

1. 독립적으로 묻고 채점할 수 있는 크기로 학습단위를 나눈다.
2. 현재 앱이 제대로 훈련할 수 없는 내용을 억지로 문제화하지 않는다.

토큰 절약은 모델 성능을 먼저 낮추는 방식이 아니라, 성공한 앞 단계 재사용과 중복 입출력 제거부터 적용한다.

## 품질 개선 순서

1. Prepare에서 하나의 LearningUnit에 하나의 독립 학습 행동만 남긴다.
2. 문제 방식 추천과 같은 호출에서 `지원`, `부분 지원`, `미지원`을 판단한다.
3. 자동 흐름은 지원 항목만 생성한다.
4. 직접 선택 흐름은 부분 지원을 기본 제외하되 사용자가 한계를 확인한 뒤 포함할 수 있게 한다.
5. 미지원 항목은 모든 흐름에서 문제를 생성하지 않는다.
6. OPIc와 미적분을 먼저 검증하고, 통과한 뒤 전체 6종 자료를 회귀 검증한다.

## 품질 합격 기준

- 핵심 내용 포함률 90% 이상
- 제외 대상과 원문 밖 사실 0건
- 의미상 중복 10% 이하
- 명백히 잘못된 지원 여부 판단 0건
- 명백히 부적합한 문제 방식 0건
- 정답 오류와 자동 채점 오류 0건
- 두 번의 실행에서 학습단위 경계가 의미상 크게 달라지지 않음
- 데드락과 달의 위상 기존 품질이 낮아지지 않음

같은 목표가 다섯 번의 수정 시도 후에도 기준을 통과하지 못하면 자동 수정을 중단한다. 이때 반복 실패, 최초 실패 단계, 시도한 변경, 좋아진 항목, 나빠진 항목과 사용자 판단이 필요한 이유를 보고한다. 한 번의 시도는 API 호출 한 번이 아니라 하나의 수정안을 적용하고 재검증하는 과정이다.

## 토큰 절약 순서

1. Analyze, Plan, Prepare, 문제 추천, 문제 생성의 실제 사용량을 단계별로 기록한다.
2. 수정하지 않은 앞 단계 결과를 고정하고 실패 단계부터 다시 실행한다.
3. 첫 실행이 기계 검사에서 실패하면 같은 반복 실행을 생략한다.
4. 문제 추천과 문제 생성에 전달되는 중복 데이터를 압축한다.
5. 잘못된 고정 데이터는 API 호출 전에 차단한다.
6. 문제 형식별 축소 출력은 모의 테스트까지 준비하고 실제 API 확인 전에는 활성화하지 않는다.
7. 위 작업 후에도 필요할 때만 추론 강도 변경을 별도 실험한다.

## 모델과 예산 원칙

- Analyze, Plan, 문제 추천, 문제 생성: GPT-5.6 Terra, 추론 강도 `medium`
- Prepare: GPT-5.6 Sol, 추론 강도 `medium`
- Critic: Terra `medium` 설정을 유지하되 비활성화
- 다음 집중 실험의 Sol 목표 호출 수: 최대 5회
- Terra는 Sol 후보 선별과 지원 판단에 우선 사용
- 실제 실행 전 사용 가능한 잔액과 예상 비용을 확인
- 예산 초과가 예상되면 첫 호출 전에 중단

## API 호출 없이 먼저 완료할 작업

- 사용량 파싱과 예상 비용 계산
- 평가 실행계획 dry-run과 예산 차단
- 단계 결과 재사용 계약
- 추천·생성 입력 압축 함수와 크기 비교
- 호출 전 기계 검사
- 축소 출력의 타입·변환 함수·모의 테스트
- 생성 계약, 학습 흐름, 린트와 빌드 검증

## 이번 단계에서 하지 않는 것

- 실제 OpenAI API 호출
- 모델 교체 또는 추론 강도 변경
- Plan에서 PDF를 제거하는 동작 활성화
- 축소 출력 JSON 스키마의 프로덕션 활성화
- Critic 재활성화
- 자료 주제별 하드코딩
- 앱이 운영 중 자기 프롬프트나 코드를 수정하는 기능

## 2026-08-14 실행 결과

### 적용 완료

- Prepare의 모든 개수 정책에 같은 학습단위 기준을 적용했다. 하나의 단위는 독립적으로 질문하고 정답을 판단할 수 있어야 하며, 단순히 개수를 맞추기 위한 병합·분할은 하지 않는다.
- Plan의 `maxLearningUnitCount`는 영역 수가 아니라 영역 안의 독립 학습대상 수도 수용하는 과다 추출 안전선으로 정하게 했다.
- 문제 추천 결과에 `지원`, `부분 지원`, `미지원`, 추천 방식, 한계, 자동 생성 포함 여부를 함께 저장한다.
- 자동 흐름은 지원 항목만 생성한다. 직접 선택 흐름은 부분 지원을 기본 제외하되 한계를 본 뒤 포함할 수 있고, 미지원은 포함할 수 없다.
- 성공한 Plan을 고정한 Prepare 재실행과, Prepare를 고정한 추천·생성 재실행이 실제 호출 경로에서도 작동한다.
- 실행 전 시작·종료 단계, 자료, 반복 수, Sol·Terra 호출 수를 검사하며, 중간 추천 결과도 별도 파일로 남긴다.
- 문제 추천 입력 압축을 제품 경로에 적용했다. OPIc에서는 입력 토큰이 3,965에서 1,752로 56% 줄었고 9개 지원 수준·추천 유형이 모두 유지됐다. 미적분에서는 4,522에서 1,759로 61% 줄었으며, 실제 풀이가 필요한 항목과 규칙 선택 항목을 구분했다.

### 실제 품질 확인

- OPIc Plan 상한은 3에서 9로 바뀌었고, 전체 답변 흐름 1개·독립 발화 패턴 7개·3인칭 문법 1개로 분리됐다. 예문 고유정보와 쉐도잉 방법은 계속 제외됐다.
- 미적분은 실제 계산·유도·증명이 필요한 항목을 부분 지원으로 표시하고, 현재 방식이 대신하지 못하는 능력을 한계로 남겼다.
- 데드락, 권리장전, 달의 위상, 재난 지침에서도 같은 기준으로 관계 복원·판단·실제 수행 능력을 구분했다.
- Critic과 추론 강도는 변경하지 않았고, 자료 주제별 분기나 하드코딩 규칙은 추가하지 않았다.

### 보류

- 문제 생성 입력 압축은 데드락 구형 학습단위에서 정의와 자원 이용 순서 중 하나만 문제화되어 제품 경로에 적용하지 않았다. 새 원자성 기준으로 다시 생성한 자료에서 재검증해야 한다.
- 문제 형식별 축소 출력 스키마는 모의 변환 테스트만 통과한 상태다. 실제 구조화 출력 호환 확인과 생성 입력 압축 통과 전에는 적용하지 않는다.
- 전체 6종의 Plan·Prepare를 모두 새로 재실행하지는 않았다. OPIc·미적분은 새 결과를 사용했고, 나머지 4종은 기존 확정 Prepare를 고정해 추천 회귀검증을 했다.
