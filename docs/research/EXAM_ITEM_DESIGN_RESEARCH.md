# 시험 출제 방법론과 Study Forge 적용 검토

조사일: 2026-09-08

## 0. 이 문서의 범위

교육평가 기관, 대학 교수학습센터, 원저자 자료를 중심으로 출제 설계부터 문제 작성·채점·사후 검증까지 정리했다. 모든 학문 분야의 출제법을 망라한 체계적 문헌고찰은 아니다. 긴 지침서는 관련 부분을 확인했으며, 전체를 완독하거나 최신판 전체를 검증했다는 뜻이 아니다.

- **출처 요약**: 공개 지침이 설명하는 원칙. 해당 부분에 링크를 붙였다.
- **적용 제안·예시**: 위 원칙을 우리 문제에 대입한 판단. 실험으로 검증해야 한다.
- 이번에는 조사 문서만 추가했다. 생성엔진·프롬프트·학습 화면은 변경하지 않았다.

## 1. 핵심 결론

출제의 중심은 ‘문장을 어떤 문제 모양으로 바꿀까’가 아니다.

> 무엇을 배웠는지 확인할 것인가 → 어떤 답변이 그 증거인가 → 그 답변을 요구하는 문제를 어떻게 만들 것인가.

이 흐름은 목표·평가의 정렬과 증거 중심 평가 설계에서 공통으로 찾을 수 있다. 문제 형식은 그 뒤의 선택이다. [CMU 목표와 평가의 정렬](https://www.cmu.edu/teaching/assessment/basics/alignment.html), [ETS 증거 중심 평가 설계 사례](https://www.ets.org/research/policy_research_reports/publications/report/2018/jzuw.html)

**우리에게 주는 결론:** 원문과 정답이 일치해도 좋은 문제라는 보장은 없다. 목표가 영어 문장틀 회상인데 전치사 하나만 묻는 문제라면, 사실 오류가 없어도 목표를 충분히 검사하지 못한다.

## 2. 출제의 대표적인 설계 방법

### 2.1 역방향 설계 — 결과부터 거꾸로 정한다

Understanding by Design은 원하는 학습 결과, 이를 확인할 증거, 학습 활동 순으로 설계한다. 자료를 처음부터 끝까지 같은 비중으로 문제화하는 접근과 다르다. [Wiggins·McTighe / ASCD 설명서](https://ascd.org/ASCD/pdf/siteASCD/publications/UbD_WhitePaper0312.pdf)

적용 예: ‘연쇄법칙을 사용할 수 있다’가 목표라면 공식을 쓰는 문제만으로 끝내지 않고, 합성함수를 실제로 미분하는 과제가 필요한지 본다. 이 이론이 API 호출 세 개를 추가해야 한다는 뜻은 아니다.

### 2.2 목표·학습·평가의 정렬 — 배운 것과 물어보는 것을 맞춘다

목표가 적용인데 평가는 사실 회상만 요구하면 불일치가 생긴다. 설명·연습·평가가 같은 능력을 향해야 한다. [CMU 정렬 가이드](https://www.cmu.edu/teaching/assessment/basics/alignment.html)

적용 예: ‘DFS를 구현한다’와 ‘DFS가 스택을 쓴다고 답한다’는 다른 성취다. 후자는 전자의 보조 지식으로 기록할 수 있지만 구현을 평가했다고 보고하면 안 된다.

### 2.3 증거 중심 설계 — 정답에서 무엇을 추론할지 먼저 정한다

Evidence-Centered Design은 학습자에 관해 판단할 내용, 답변에서 찾을 증거, 이를 끌어내는 과제의 관계를 설계한다. ETS의 학습 지향 평가 사례에서도 이 모델을 사용한다. [ETS 연구](https://www.ets.org/research/policy_research_reports/publications/report/2018/jzuw.html)

적용 예: 보기 없이 네 조건을 답한 것과, 제공된 네 조건을 선택한 것은 제공된 단서가 다르다. 같은 ‘정답’이어도 기록의 의미를 구별해야 한다.

### 2.4 출제계획표 — 범위와 물어볼 행동을 교차해서 배분한다

국내에는 이원목적분류표라는 출제계획 관행이 있다. 확인한 제주교육청 직업계고 안내도 성취기준과 문항 유형의 연결, 중요도·난이도를 고려한 배점, 공동 검토를 설명한다. 이 자료를 모든 학교의 최신 의무 규정으로 일반화하지는 않는다. [제주교육청 안내](https://www.jje.go.kr/index.jje?menuCd=DOM_000000308000000000)

ETS Praxis는 현장 전문가의 영역 정의와 중요도 조사 등을 통해 시험 명세를 구성한다. 핵심은 시험이 필요한 영역을 대표하도록 설계하는 것이다. [ETS 시험 개발](https://praxis.ets.org/states/development-and-adoption/current.html)

**적용용 예시이며 권장 고정 비율이 아님:**

| 학습 범위 | 무엇을 확인할까 | 가능한 문제 | 이 문제로 확인하지 못하는 것 |
|---|---|---|---|
| 데드락 조건 | 네 조건을 기억하는가 | 순서 없는 목록 회상 | 상황에서 조건을 식별하는 능력 |
| 데드락 조건 | 사례에서 어느 조건인지 아는가 | 상황 객관식 | 직접 시스템을 설계하는 능력 |
| 영어 문장틀 | 의미에 맞춰 문장틀을 꺼내는가 | 의미 → 표현 플래시카드 | 실제 발화의 유창성 |
| 연쇄법칙 | 새 함수에 규칙을 쓰는가 | 계산 후 답 입력 | 풀이 과정의 모든 오류 |

따라서 ‘목차 한 개당 무조건 한 문제’도, ‘핵심이면 무조건 세 문제’도 출제의 보편적 정석은 아니다. 목차의 크기와 확인할 행동이 다르기 때문이다.

### 2.5 Bloom 개정 분류 — 무엇을 하게 하는지 점검한다

개정 체계는 기억·이해·적용·분석·평가·창조라는 인지 과정과 사실·개념·절차·메타인지 지식이라는 차원을 구별한다. [UIC 설명](https://teaching.uic.edu/blooms-taxonomy-of-educational-objectives/)

우리 적용 시 주의:

- 여섯 단계를 모두 문제로 만들 필요는 없다.
- ‘객관식=기억, 서술형=고차 사고’로 연결하지 않는다.
- 질문에 ‘분석하라’라는 동사를 붙였다고 실제 분석 문제가 되지 않는다.
- 사고의 복잡성과 실제 정답률은 별개로 확인한다. 생소한 사실을 묻는 회상 문제도 어려울 수 있다.

## 3. 문제 유형별 작성법

아래는 기능 추가 목록이 아니라 출제법 조사다. 일부는 현재 앱의 자동 채점 범위를 벗어날 수 있다.

### 3.1 객관식 — 오답까지 설계해야 한다

질문만 읽어도 과제가 명확해야 하며, 보기는 같은 기준에서 비교할 수 있어야 한다. 정답은 하나의 최선 답으로 분명해야 하고, 오답은 실제 혼동을 반영해야 한다. 길이·문법·반복 단어가 정답을 누설하지 않도록 한다. 부정 질문과 ‘모두 정답’ 같은 장치는 신중히 쓴다. 보기 수를 억지로 채우기보다 그럴듯한 오답을 확보한다. [Waterloo 객관식 작성법](https://uwaterloo.ca/centre-for-teaching-excellence/catalogs/tip-sheets/designing-multiple-choice-questions)

NBME는 보기를 가려도 질문의 답을 생각할 수 있는지 점검하도록 권한다. 의학교육 중심 지침이므로 임상 사례 형식 자체를 모든 자료에 강제할 수는 없다. ‘가장 적절한 것’이라면 최선을 판단할 조건이 제시되어야 한다. [NBME 공개 문항 작성 지침](https://www.nbme.org/sites/default/files/2021-02/NBME_Item%20Writing%20Guide_R_6.pdf)

우리의 오답 작성 후보 — 고정 규칙이 아닌 점검 아이디어:

- 조건과 결과를 뒤집는다.
- 필요조건을 충분조건처럼 바꾼다.
- 비슷한 두 개념의 특징을 서로 바꾼다.
- 적용 조건을 빠뜨린다.
- 실제로 가능한 계산·단위 오류를 넣는다.

단, 모든 오답에 ‘왜 틀린지’를 설명할 수 있어야 한다. 낯선 말이나 우스운 답으로 정답을 돋보이게 만들지 않는다.

### 3.2 OX·복수정답·연결형·빈칸·단답

Waterloo의 유형별 지침을 요약하면 다음과 같다. [문제 유형별 가이드](https://uwaterloo.ca/centre-for-teaching-excellence/catalogs/tip-sheets/exam-questions-types-characteristics-and-suggestions)

| 유형 | 작성의 핵심 | 주의점 |
|---|---|---|
| OX | 한 문장에서 하나의 중심 판단을 요구 | 일부는 참이고 일부는 거짓인 복합문장, 애매한 한정어 |
| 연결형 | 서로 대응 가능한 동질적 항목을 묶음 | 답 재사용 가능 여부와 연결 기준 명시 |
| 빈칸 | 중요한 부분을 가리되 문맥 유지 | 너무 많이 지워 답을 특정할 수 없게 만들지 않기 |
| 단답 | 무엇을 어느 정도 답할지 분명히 함 | 표현이 달라도 맞을 수 있는 답의 처리 |
| 계산형 | 출제자가 먼저 풀어 검증 | 조건·단위·정밀도와 채점 기준 |
| 서술·구술형 | 과업 범위와 평가 기준을 먼저 정함 | 채점 일관성과 응시 조건 |

우리의 추가 적용 판단:

- OX는 무작위 선택으로도 맞을 수 있으므로 한 번의 정답을 깊은 이해의 증거로 삼지 않는다.
- 복수정답형은 ‘모두 고르기’, 정답 개수 공개 여부, 일부 정답의 점수를 먼저 정한다. 단일정답형의 보기만 늘린 것으로 취급하지 않는다.
- 원문 빈칸에서 지운 단어가 학습 대상인지 점검한다. 아무 단어나 지우면 문법·문맥 추측 문제가 되기 쉽다.
- 자유 입력에서 허용 표기와 동의어를 다룰 수 없다면 자동 오답 판정의 한계를 표시한다.

### 3.3 플래시카드 — 앞면이 답의 범위를 정한다

여기는 위 출제 원칙을 학습 카드에 적용한 제안이다.

- 앞면: 기억을 꺼낼 충분한 단서. 원문상의 번호만으로 대상을 지정하지 않는다.
- 뒷면: 앞면이 실제로 요구한 답. 한 표현을 물었으면 여러 단락을 답으로 붙이지 않는다.
- 원문 표현이 학습 대상이면 원문 회상을 허용한다.
- 개념 이해가 목표면 원문을 외웠다는 사실과 구별한다.
- 답 공개 후 ‘알겠음’을 누른 것은 자기평가다. 독립적으로 답을 산출하고 채점한 기록과 동일시하지 않는다.

### 3.4 순서·구조복원 — 배치보다 관계가 중요하다

IHMC 개념도는 개념끼리 연결어를 통해 의미 있는 명제를 만들고, 필요하면 교차 연결을 표현한다. 부분적으로 완성된 전문가 개념도를 학습자가 확장하는 방법도 설명한다. 이것은 단순한 들여쓰기 목록과 다르며, 원래 방법이 모두 고정 정답형이라는 뜻도 아니다. [개념도 구성](https://cmap.ihmc.us/docs/constructingaconceptmap.php), [부분 개념도 활용](https://cmap.ihmc.us/docs/skeletoncmaps.php)

우리의 구조복원 적용 제안:

| 실제 내용 | 보여줄 형태 | 채점해야 할 것 |
|---|---|---|
| 순서 없는 조건 목록 | 고정 제목 아래 여러 빈칸 | 항목의 집합, 중복 여부 |
| 순서가 중요한 절차 | 단계와 방향 표시 | 필요한 선후 관계 |
| 상위·하위 개념 | 부모와 연결을 볼 수 있는 가지 | 부모·자식 관계 |
| 원인·결과 | 관계 이름이 보이는 연결 | 연결 대상과 방향 |
| 대상별 특징 비교 | 행·열 제목이 있는 표 | 해당 대상과 특징의 대응 |

보기 있는 버전은 선택·연결이고, 보기 없는 버전은 직접 회상이다. 단서는 줄일 수 있지만, 어느 관계를 묻는지까지 지워서는 안 된다. 순서 없는 형제 노드의 화면 위치를 정답 조건으로 삼지 않는다.

### 3.5 사례·자료해석·오류수정은 ‘답변 방식’과 별개다

적용용 구분: 사례, 그래프, 코드, 지도, 지문은 **문제에 주는 자료**다. 객관식·단답·서술은 **답하는 방식**이다. ‘사례 문제’라는 이름만으로 적용 능력을 검사했다고 판단할 수 없다.

예: 사례를 길게 붙였지만 마지막 질문이 용어 정의라면 사례가 필요 없는 회상 문제일 수 있다. 반대로 짧은 그래프에서도 조건을 판단하는 과제가 가능하다.

### 3.6 수행·논술·구술 — 조사 범위에는 포함하되 자동화와 구별한다

실제 산출물·발표·논증 등을 평가하려면 평가 항목과 수준별 기준을 명시하는 채점 기준표가 도움이 된다. [CMU Rubric 가이드](https://www.cmu.edu/teaching/assessment/assesslearning/rubrics.html)

적용 판단: 코드 실행, 말하기, 논증은 해당 수행의 증거가 필요하다. 객관식으로 바꾸면 일부 관련 지식을 검사할 수 있지만 원래 수행을 전부 평가하는 것은 아니다. 이번 조사 때문에 서술형 AI 채점 기능을 추가하지 않는다.

## 4. 문제 하나보다 시험 전체를 설계하는 법

시험 준비에는 학습 목표와 범위, 해결 시간, 명확한 지시와 채점 준비가 함께 필요하다. [Waterloo 시험 준비](https://uwaterloo.ca/centre-for-teaching-excellence/catalogs/tip-sheets/preparing-tests-and-exams)

이를 바탕으로 제안하는 세트 점검:

1. 각 핵심 범위가 적어도 어떤 문제와 연결되는지 본다.
2. 같은 사실을 세 번 물은 것을 세 범위의 커버리지로 세지 않는다.
3. 한 문제가 다른 문제의 답을 노출하는지 본다.
4. 공통 지문에 딸린 문제는 앞 문제를 틀려도 다음 문제를 독립적으로 풀 수 있는지 확인한다.
5. 문항 수와 함께 실제로 답해야 하는 하위 항목 수·시간 부담을 본다.
6. 보기 섞기는 답 위치 암기를 줄일 수 있지만 문제의 내용 품질을 높이는 작업은 아니다. 시간순·수치순 보기는 정렬 의미도 고려한다.
7. ‘쉬움 30%, 보통 50%, 어려움 20%’ 같은 비율을 모든 목적에 고정하지 않는다.

## 5. 출제 후 무엇으로 품질을 확인하나

### 5.1 타당성·신뢰성·공정성

평가 표준은 점수의 해석·사용을 뒷받침하는 근거와 공정성을 중요하게 다룬다. 확인한 판본은 AERA·APA·NCME의 2014년판이다. [평가 표준 공개본](https://www.testingstandards.net/uploads/7/6/6/4/76643089/standards_2014edition.pdf)

우리에게 쉽게 적용하면:

- **타당성:** 이 정답을 근거로 정말 의도한 능력을 안다고 말할 수 있는가?
- **신뢰성:** 우연한 보기·채점자·문항 선택 때문에 결과가 과도하게 흔들리지 않는가?
- **공정성:** 배우려는 지식과 무관한 복잡한 문장이나 조작 어려움이 점수를 좌우하지 않는가?

정답 키가 정확하고 데이터 형식 검사를 통과했다는 사실은 위 세 가지 전체를 보장하지 않는다.

### 5.2 실제 응답을 이용한 문항 분석

워싱턴대 안내는 정답률, 다른 문항의 점수와의 관계를 이용한 변별도, 신뢰성 등을 설명한다. 높은 정답률은 통계적으로 쉬운 문항을 뜻한다. 지식 영역이 섞이면 지표 해석에도 주의가 필요하다. [워싱턴대 문항 분석](https://www.washington.edu/assessment/scanning-scoring/scoring/reports/item-analysis/)

우리 적용 제안:

- 어려움: ‘AI가 어려워 보인다고 판단’한 것과 실제 정답률을 분리해 기록한다.
- 오답 선택: 특정 보기에 몰리면 오개념인지 문항 오류인지 확인한다.
- 음의 변별: 정답 오류·모호성부터 검토하되 지표 하나로 자동 폐기하지 않는다.
- 반복학습: 성공하도록 훈련하는 목적에서는 높은 정답률 자체가 결함이 아니다.
- AI 대리 학생은 검수 보조다. 인간의 난이도·학습 효과를 실증한 표본으로 대체하지 않는다.

문항반응이론 같은 통계 모델도 후속 연구 대상이지만, 지금 사람이 푼 데이터 없이 모델부터 붙이는 것은 이 조사에서 제안하지 않는다.

## 6. 시험 출제와 반복학습은 그대로 같지 않다

미국 IES의 2007년 학습 지침은 핵심 내용의 퀴즈 재노출, 분산 학습, 풀이 예시와 직접 문제 해결의 교대 등을 다룬다. 지침 안에서도 권고별 근거 수준은 다르다. [IES 학습 지침](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)

인출학습 연구자들의 안내는 피드백과 다양한 인출 방식을 다룬다. 따라서 ‘객관식은 학습에 쓸모없다’거나 ‘보기 없는 방식만 항상 우수하다’로 단정하지 않는다. [Retrieval Practice 연구자 안내](http://www.retrievalpractice.org/faq)

다음은 우리 적용 판단이다.

| 쟁점 | 시험 중심 판단 | 반복학습에 적용할 때 |
|---|---|---|
| 원문 재사용 | 표현만 외워 맞히는지 주의 | 원문 자체가 목표라면 의도적으로 사용 |
| 정답 노출 | 측정을 방해할 수 있음 | 답을 시도한 뒤의 피드백은 필요 |
| 쉬운 문제 | 측정 목적에 따라 정보가 적을 수 있음 | 초기 회상 연습이나 복습에는 의미 있음 |
| 반복 문제 | 새 영역을 측정하는 것은 아님 | 기억 유지를 위한 반복일 수 있음 |
| 보기·힌트 | 단서의 영향 고려 | 지원을 받았다는 기록을 남기고 활용 가능 |
| 한 번의 정답 | 숙달 전체의 증거로 부족 | 이후 지연 회상·다른 예제로 확인 가능 |

## 7. 자동 문제 생성에서 가져올 수 있는 관점

자동 문항 생성에는 문제의 틀, 바꿀 변수, 허용값과 제약을 이용하는 접근이 있다. ETS 공개 특허 개요에서 이러한 구성을 확인할 수 있다. 이는 기술 접근의 사례이지 해당 특허가 학습 효과를 입증한다는 뜻은 아니다. [ETS 자동 문항 생성 사례](https://www.ets.org/research/policy_research_reports/publications/patent/2012/00511.html)

우리에게 주는 적용 제안:

- 바꾸면 안 되는 핵심 관계와 바꿔도 되는 사례 정보를 구별한다.
- 숫자를 바꾸면 정답도 다시 계산한다.
- 상황을 바꾸면 공식·규칙의 적용 조건이 여전히 성립하는지 검토한다.
- 표현만 바꾼 문제를 새로운 학습 범위를 다뤘다고 세지 않는다.
- 생성 AI의 ‘좋은 문제’ 자기평가만으로 합격시키지 않는다.

## 8. 우리가 겪었던 문제를 이 기준으로 다시 읽기

아래는 과거 사용자 제시 사례에 대한 해석이다. 현재 코드에 동일 결함이 남아 있는지 재검증한 결과는 아니다.

| 사례 | 출제 관점에서의 문제 | 수정 방향 |
|---|---|---|
| 네 조건을 모두 골랐지만 순서 때문에 오답 | 평가하지 않을 배열을 평가함 | 순서 없는 집합으로 채점 |
| 구조를 전부 숨겨 ‘자리 1~7’만 남음 | 정답을 결정할 관계 단서가 없음 | 부모·연결·행열 제목 등 필요한 맥락 유지 |
| 영어 패턴에서 about만 가림 | 목표 표현 대신 작은 문법 요소만 검사 | 목표가 표현이면 의미 있는 표현 범위를 요구 |
| Pattern #1 전체를 말하라 | 번호를 아는 사람만 답 범위를 알 수 있음 | 원문에서 의미·상황 등 단서 확보 |
| 긴 단원 전체를 한 문제로 만듦 | 한 번의 답변 부담과 채점 범위가 과대 | 확인할 관계·행동별로 적절히 나눔 |
| 어려운 수행을 통암기 카드로 바꿈 | 훈련 목표가 달라짐 | 보조 회상임을 구별하거나 지원 한계 표시 |

## 9. 지금 바로 쓸 수 있는 최소 검수표

새 시스템 구조가 아니라 사람이 결과를 읽을 때 사용할 질문이다.

### 목차와 결과물을 나란히 놓고

- [ ] 원문의 주요 구성과 관계를 왜곡하지 않았는가?
- [ ] 선택한 핵심 범위가 최종 문제에서 실제로 다뤄지는가?
- [ ] 문항 수가 아니라 서로 다른 평가 대상의 수를 확인했는가?
- [ ] 각 범위의 문제 방식이 확인하려는 행동에 적절한가?

### 문제 하나마다

- [ ] 무엇을 답해야 하는지 앞면만으로 알 수 있는가?
- [ ] 제시된 정보로 답이 결정되는가?
- [ ] 정답은 맞고, 다른 정답 가능성은 처리되어 있는가?
- [ ] 원문 또는 허용된 근거로 설명할 수 있는가?
- [ ] 정답을 알지 않아도 모양·길이·문법만으로 맞힐 수 있지 않은가?
- [ ] 빈칸·보기·연결이 핵심 내용을 묻는가?
- [ ] 순서·동의어·수치 오차 등의 채점 기준이 내용에 맞는가?
- [ ] 사용자가 실제로 한 행동보다 넓은 숙달을 주장하지 않는가?

## 10. 적용 우선순위와 보류

**추천:** 우선 기존 표본의 목차와 최종 문제를 이 검수표로 다시 평가한다. 발견한 오류를 목표 불일치, 단서 부족, 답 모호성, 채점 불일치 등 원인으로 설명한다. 점수 하나로 뭉개지 않는다.

**그다음:** 반복되는 원인에 대해서만 프롬프트 또는 문제 도구의 작은 변경을 제안한다. 출제 이론의 이름마다 엔진 단계를 추가하지 않는다.

**지금 하지 않는 것:** 모든 분류를 데이터 필드로 저장하기, 정해진 문항 비율 강제, 실제 응답 없는 난이도 보정, 서술형 자동 채점 확대, 생성엔진 전면 개편.

이 문서의 출제 원칙은 검토 근거다. 우리 자료에서 품질이 좋아지는지는 별도의 비교 실험으로 확인해야 한다.
