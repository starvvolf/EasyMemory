# 학습 흐름과 자동화 설계 (2026-10-15)

Recaller의 공부 흐름을 처음부터 끝까지 한 줄로 정리하고, 각 기능을 에이전트가 돌릴 수 있는 단위로 적는다.
**에이전트는 앱 자체다**(사용자 결정 2026-10-15): 앱이 열려 있는 동안 학습 유도(이 문서)와 자체 개선(`docs/품질_자동화.md`)을 한다.
앱 안의 에이전트는 코치 카드, 오늘 할 것, 빠른 고리로 나타나고, 바깥 에이전트(예약 작업·GPT)는 같은 API를 읽는 보조 수단이다.
목표: 학습자는 "자료 올리기, 목표 확인, 풀기, 버튼 한 번 피드백"만 하고, 나머지는 앱이 한다.

## 1. 전체 흐름

```
 자료 올리기 ─▶ 문제 만들기(엔진 v2) ─▶ 목표 확인(사람) ─▶ 과목·시험일에 묶기
      │                                                        │
      ▼                                                        ▼
  바로 읽기 ◀──────────── 오늘 할 것 (매일 아침 계산) ───────────┤
   │  물어보기                │                                │
   │  (모르는 것 노트)         ▼                                │
   └──────▶ 물어봄 ──▶ 풀기: 약점 → 물어봄 → 복습 → 첫 훑기 → 새 문제
                              │ 결과 기록 (study-records)
                              ▼
                약점 모음 · 약점 다시 풀기 · 한 장 정리
                              │
                              ▼
                 학습 메모 MD (과목별, 자동 요약 + 내 메모 + 에이전트 메모)
                              │
                              ▼
          에이전트: 아침 안내 / 밤 정리 / 다음 자료 제안 / 시험 전날 안내
```

| 단계 | 학습자가 하는 일 | 앱이 하는 일 | 에이전트가 할 수 있는 일 |
|---|---|---|---|
| 자료 올리기 | PDF 고르기, 범위·목적 | 등록, 그림 쪽 읽기, 목차·설계 | 시험이 가까운데 문제가 없는 PDF를 찾아 **만들기 제안**(유료, 승인) |
| 목표 확인 | 목표 고르기 | 단원별로 보여 주기 | 기다리는 자료가 있다고 **알림**(확정은 사람) |
| 과목·시험일 | 과목·날짜 입력, 자료마다 과목 | 시험 가까운 순으로 묶기 | 없음(사람이 정함) |
| 오늘 할 것 | "시작하기" | 시험일에 맞춰 하루 분량 계산 | 같은 계산을 `/api/study-plan`으로 읽어 **아침 안내** |
| 첫 훑기 | 처음 보는 핵심 목표를 빠르게 | 혼자 맞히면 7일 뒤로(이미 앎) | 없음 |
| 읽다가 물어보기 | 모르는 말 누르기, 질문 창 | 노트 저장, 그 쪽 목표를 "물어봄"으로 | 물어본 것을 메모에서 읽고 **다음 출제 메모에 반영 제안** |
| 약점 | 다시 풀기 | 마지막 시도로 약점 계산, 과목별 모음 | 새로 생긴 약점을 **밤 정리**에 적기 |
| 한 장 정리 | 가리고 떠올리기, 인쇄 | 목표·떠올릴 것·상태 | 시험 전날 **약점 목록과 바로가기** 보내기 |
| 학습 메모 | "내 메모"에 적기 | 공부 뒤 자동 요약 다시 쓰기 | "에이전트 메모"에 관찰 한 줄씩 |

## 2. 기능 명세 (에이전트가 읽는 단위)

### 2.1 과목·시험일
- 저장: 풀이 기록 묶음의 `__plan` 항목 `{ subjects:[{name, exam:"YYYY-MM-DD"}], of:{ <sourceCatalogId>: <과목> } }`. RecallerData로 두 컴퓨터에 같이 간다.
- 자료는 **등록한 PDF 단위**로 과목에 속한다. 같은 PDF로 다시 만든 자료는 자동으로 같은 과목.
- 에이전트: 읽기만. 바꾸지 않는다(학습규칙/에이전트.md 금지-1).

### 2.2 오늘 할 것 (`src/lib/study/plan.ts` `planToday`)
- 입력: 자료(문제·목표·설계의 중요도·떠올릴 것), 풀이 기록, 과목·시험일, 모르는 것 노트, 학습규칙.
- 분류(문제 하나는 하나에만): 오늘 이미 푼 것(제외) → **약점** → **물어봄** → **복습 차례** → **첫 훑기**(핵심 목표의 첫 문제) → **새 문제**.
- 새 문제 몫: `ceil(아침 기준 안 푼 문제 / (시험까지 남은 날 − 마지막 복습일))`, 상한 `[새문제-최대]`. 시험 없는 과목은 `[시험없음-새문제]`.
- 시험 단계: `learn`(새 문제 나눔) / `final`(D-`[마지막-복습일]` 이하, 새 문제 없음) / `over`(지남, 제외).
- 시간: 문제 형식별 초(`[시간-…]`). 시험이 `[시험-임박]`일 안인 과목의 약점·물어봄·복습은 하루 시간을 넘어도 넣는다. 나머지는 시험 가까운 순으로 하루 시간 안에서.
- 순서: 과목(시험 가까운 순) → 그 안에서 약점 → 물어봄 → 복습 → 첫 훑기 → 새 문제. 한 번에 `[한번에]`개씩 끊어서 푼다.
- 출력 `TodayPlan`: `queue[{deckId,itemId,reason,subject}]`, 과목별 `counts / picked / quota / learnUntil / minutes / phase`, `needMinutes`(규칙대로면 필요한 시간), `notes`(사람에게 보일 안내).
- 같은 코드가 브라우저(화면)와 서버(`GET /api/study-plan`)에서 돈다. 둘의 숫자가 다르면 기록 동기화(1.5초 뒤 저장)를 의심한다.

### 2.3 첫 훑기 (진단)
- 처음 보는 핵심 목표마다 첫 문제 하나. 정답을 보지 않고 맞히면 `[첫훑기-앎-간격]`일 뒤 복습 상자로 바로 간다(이미 아는 것을 반복하지 않는다).
- 틀리면 보통처럼 약점이 되고 내일 다시 나온다.

### 2.4 약점 · 물어봄
- 약점: 문제의 **마지막 시도**가 틀림·모르겠어요·"잘 모름"·정답 먼저 보기. 혼자 맞히면 빠진다. 별도 저장 없음(기록에서 계산).
- 물어봄: 목표의 원문 쪽에 모르는 것 노트(물어본 말, 질문 창 대화)가 있고, 그 뒤 그 목표 문제를 혼자 맞힌 적이 없음.
- 약점 다시 풀기: 과목의 약점 문제를 많이 놓친 순으로 최대 30개, 날짜 무관.

### 2.5 한 장 정리
- 과목 → 자료 → 단원 → 세부 제목 → 목표 + 떠올릴 것(설계 단계의 recall). 점 색: 약점/푸는 중/혼자 맞힘/안 풀어봄, "물어봄" 표시.
- "약점·물어본 것만", "떠올릴 것 가리기"(기록 안 남음), 인쇄.

### 2.6 학습 메모 MD (`study-memory/<과목>.md`, 데이터 폴더)
```
# 컴퓨터그래픽스 학습 메모
<!-- recaller:auto:start -->
## 자동 요약 (날짜 시각)         ← 앱이 공부 뒤마다 다시 씀
- 시험 / 진행
## 약점 목표                    ← [자료 · 목표ID] 목표 — 떠올릴 것 (놓침 n번, 마지막, p.)
## 읽다가 물어본 것
<!-- recaller:auto:end -->
## 내 메모                      ← 학습자. 앱이 건드리지 않음
## 에이전트 메모                ← 에이전트가 날짜와 함께 한 줄씩 덧붙임
```
- 쓰는 때: 한 번의 풀이가 끝났을 때, 자료의 과목을 바꿨을 때(2.5초 모아서).
- 쓰는 사람: 자동 요약은 앱만. 내 메모는 학습자(파일을 직접 열어 쓴다). 에이전트 메모는 `POST /api/study-memory`로만.
- 왜 MD인가: 사람이 그대로 읽고 고칠 수 있고, 에이전트 프롬프트에 그대로 넣을 수 있고, git(RecallerData)으로 변경 이력이 남는다.

### 2.7 학습규칙 MD (`학습규칙/`)
- `오늘할것.md`: 2.2의 숫자들. `- [키] 값` 줄만 읽는다. 새로고침하면 적용. 경고는 오늘 할 것 아래와 `/api/study-rules`에 보인다.
- `에이전트.md`: 에이전트가 혼자 해도 되는 일 / 물어봐야 하는 일 / 하지 않는 일 / 매일 흐름. `- [ID] 내용` 줄이 에이전트 프롬프트에 들어간다.
- 출제기준(`출제기준/`)과 같은 방식: 코드를 고치지 않고 파일로 행동을 바꾼다.

## 3. API (로컬 실험 모드, 같은 출처)

| 메서드·경로 | 용도 | 비용 |
|---|---|---|
| `GET /api/study-plan[?date=YYYY-MM-DD]` | 오늘(또는 그날 아침 8시 기준) 할 것, 과목, 자료 목록, 만드는 중인 자료, 메모 파일 목록, 규칙·경고 | 0 |
| `GET /api/study-memory[?subject=]` | 메모 목록 / 한 과목 MD | 0 |
| `PUT /api/study-memory {subject, auto}` | 자동 요약 교체(앱 전용) | 0 |
| `POST /api/study-memory {subject, agentNote}` | 에이전트 메모 한 줄 | 0 |
| `GET /api/study-rules` | 오늘할것 규칙(파싱 결과·경고), 에이전트 규칙 줄 | 0 |
| `GET /api/study-records` | 풀이 기록 원본(읽기만) | 0 |
| `GET /api/study-quality` · `POST {action:"log"\|"patch"\|"unpatch"}` | 덧씌우기·품질 장부·원인별 개수 | 0 |
| `POST /api/lab/gen` · `…/confirm` · `…/fork` | 자료 만들기·확정·다시 만들기 | **유료, 승인 필요** |

서버 쪽 오늘 할 것은 엔진 v2 자료만 센다(옛 요청 흐름 자료 제외). 시험 자료는 모두 v2라 차이가 없다.

## 4. 자동화 루프

### 앱 안 (기본, 비용 0)
- 앱을 열 때마다: 오늘 할 것 계산, 코치 카드(시험 전날·밀린 양·약점 더미·확인 대기·시험일 없음·개선 제안).
- 풀 때마다: 기록, 약점·물어봄 갱신, 빠른 고리(정답 추가·카드 전환·너무 쉬움·지엽 빼기), 품질 장부.
- 풀이가 끝날 때: 분량·간격·내용 피드백 → 내 조정에 바로 반영, 과목별 학습 메모 MD 다시 쓰기.
- 자세한 표: `docs/품질_자동화.md`.

### 바깥 (선택)
예약 작업(아침·밤)이나 GPT 작업 지시로 돈다. 매번 새로 시작하므로 **상태는 전부 파일과 API에서 읽는다**(대화 기억에 기대지 않는다). 앱이 꺼져 있을 때 알림이 필요할 때만 쓴다.

### 아침 (7~8시)
1. `GET /api/study-rules` → 에이전트 규칙 줄을 프롬프트에 넣는다.
2. `GET /api/study-plan` → 과목별 `picked`, `minutes`, `phase`, `notes`.
3. 학습자에게 3줄: 오늘 문제 수·시간, 시험 직전 과목(있으면 한 장 정리 권유), 기다리는 목표 확인.

### 밤 (22시 이후)
1. `GET /api/study-plan` (오늘)과 `?date=내일`.
2. 과목마다 `GET /api/study-memory?subject=` → 자동 요약의 약점과 어제 에이전트 메모 비교.
3. `POST /api/study-memory` 에이전트 메모: "10-15 약점 +3(회전 부호, FOV), 오늘 42/60, 내일 55문제 약 40분".
4. 시험 7일 안 과목에 등록만 된 PDF가 있으면 만들기 제안(예상 호출 수와 함께, 승인 대기).

### 시험 전날
- 그 과목 메모의 "약점 목표"를 그대로 보내고, 한 장 정리(`/study` 정리 탭, 그 과목)를 권한다.

### 사람이 꼭 하는 것 (자동화하지 않음)
- 목표 확인, 유료 호출 승인, 실제로 풀기, 내 메모.

## 5. 다음 단계 (시험 뒤)
- 약점·물어본 것을 다음 출제의 메모(`note`)에 자동으로 넣기: 메모 MD의 약점 목표를 출제 프롬프트 입력으로(출제기준 `공통.md`에 "학습자 약점" 절 추가).
- MCP 도구로 감싸기(`tools/study-forge-mcp`): `study_plan`, `study_memory_read`, `study_memory_note` — 지금 API 그대로.
- 단원 사이 중복 목표 합치기(엔진).
