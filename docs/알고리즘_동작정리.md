# 알고리즘 파트(PS 튜터) 동작 정리 — 2026-11-12, B

화면에 보이는 이름은 "알고리즘", 안쪽 이름은 `code`다. 이 문서는 처음 보는 사람이 "학습자가 문제 하나를 풀 때 앱 안에서 무슨 일이 일어나는지"를 따라갈 수 있게 쓴다.
그림으로 보는 구조도: `협업/구조도/알고리즘.html`

## 1. 한 장면으로 보기

민수가 백준 2606번 "바이러스"를 풀고 싶다고 하자.

1. **문제 넣기** — 번호 `2606`을 넣는다. 앱이 인터넷 아카이브에서 원문을 가져오고(AI 없음), AI 4개를 동시에 불러 채점할 수 있는 문제로 세팅한다. 숨은 테스트는 코드가 만들고, 코드가 검증한다. 2초면 문제가 열리고, 제출은 15~50초 뒤에 열린다.
2. **혼자 풀기** — 편집기에서 파이썬으로 짠다. 예제 실행·제출은 민수 PC에서 돌고(AI 없음), 맞고 틀림은 출력 비교로만 정한다.
3. **막히면 도움** — 오른쪽 AI 튜터에게 채팅으로 묻거나, 도움 네 칸(1 눈여겨볼 곳 · 2 방법 이름 · 3 계획 · 4 뼈대 코드)을 하나씩 연다. 1~3칸은 미리 만든 글이라 AI 호출이 없고, 4칸만 AI가 뼈대 코드를 만든 뒤 채점으로 검증한다.
4. **끝** — 맞히거나, 그만두거나, 하다가 나가면 "문제 한 장"이 남는다. 앱을 끌 때도 저장한다(저장 중 작은 알림).
5. **돌아보기** — 기억 도서관의 풀이 노트에서 "푼 과정"(대화 요약)과 "총정리"(이야기 + 약점 카드)를 본다. 처음 열 때 AI가 만들고 저장해 둔다.
6. **다음** — 도움을 받은 문제는 하루 뒤 혼자 다시 풀라고 권한다. 다음 문제는 튜터가 고르거나, "문제 찾아오기"로 AI가 웹에서 찾아온다.

## 2. 원칙 (지켜야 하는 것)

- **판정은 코드가 한다.** 맞고 틀림은 실행 결과 비교로만 정한다. AI는 실력을 판정하지 않는다.
- **도움은 작은 것부터.** 혼자 → 막힌 자리에서 작은 도움 → 도움을 받은 문제는 하루 뒤 혼자 다시.
- **기억이 되는 것은 몰랐다가 배운 것만.** 혼자 한 번에 맞힌 것은 기억 카드로 만들지 않는다.
- **약점은 깐깐하게.** 도움 없이 못 넘어갔으면 모르는 것이다. 튜터에게 거의 묻지 않아야 "혼자 풂"이다(대화 1번도 도움 1번으로 센다).
- **약점 카드는 약점을 메워 주는 설명이다.** 드러난 때마다 따로, 작은 건 작게, 핵심은 크게(DECISIONS 11/12, 갈래 공통).
- **공개 저장소:** 문제 원문·학습 기록은 데이터 폴더(비공개 RecallerData)에만 둔다.

모델은 기본 `gpt-6.1-terra` · 강도 low다(사용자 ChatGPT 로그인으로 부름). "heavy"는 같은 terra에 강도 medium이다. 예외는 독립 풀이 하나로, 다른 모델의 눈으로 대조하려고 `gpt-6.1-sol`을 쓴다.

## 6. 총정리는 이렇게 만든다 (v18)

1. 어느 장을 정리할지 고른다: 그 문제의 마지막 장 중 무언가 한 것(제출·질문·AI 힌트가 있거나 끝까지 간 것). 힌트만 열어 보고 나간 장은 건너뛴다.
2. 범위: 앞의 "맞힘·그만둠" 장이 끝난 뒤부터(없으면 12시간 전) 이 장이 끝날 때까지의 대화 장부, 최대 40개.
3. 코드가 센 사실(결과·제출·틀린 종류·연 힌트 칸·물은 수·시간)을 함께 넣는다. 화면 맨 위 사실 칩도 이 숫자다(AI 아님).
4. AI가 쓴다: 상황 · 풀리는 법 · 시간 순서 이야기 문단 · 약점이 드러난 문단에 약점 카드(지금 내 상태 + 메워 주는 설명, small/big) · 다음에 떠올릴 것.
5. 코드가 확인한다: 길이 자르기, 빈 문단 버리기, 종류·크기 값 확인. 받는 중에도 화면에 흘려 보여 준다.

- 채팅 캐시: 앞부분이 고정돼야 캐시가 먹는다(ChatGPT는 같은 앞부분이 1,024토큰 이상이어야 함). 같은 문제는 `prompt_cache_key`·`session_id`를 `recaller-tutor-<문제>`로 묶는다.
