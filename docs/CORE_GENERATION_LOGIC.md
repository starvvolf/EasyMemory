# Study Forge 핵심 생성 로직

> 이 문서는 현재 실험과 실제 생성 경로에서 품질 효과가 확인된 핵심만 고정한다.  
> 화면이나 임시 실험 구조가 바뀌어도 아래 원칙은 별도 결정 없이 약화시키지 않는다.

- 기준일: 2026-08-17
- 기준 코드 상태: 작업 트리 `fda889e` 이후의 미커밋 변경 포함
- 대상: PDF·텍스트에서 학습 문제를 만드는 생성엔진

## 한 문장 요약

자료를 곧바로 문제로 바꾸지 않고, 먼저 **한 문제로 연습할 수 있는 학습단위**로 나눈 뒤 각 단위에 맞는 문제 하나를 만든다.

## 핵심 흐름

```text
PDF·텍스트
  ↓
Analyze: 자료의 구조와 내용을 파악
  ↓
Plan: 학습목표와 범위를 정함
  ↓
사용자: 목차·학습 범위를 선택
  ↓
Prepare: 문제 하나로 연습할 크기의 LearningUnit을 만듦
  ↓
사용자: 포함할 LearningUnit과 문제 방향을 확인
  ↓
Activity Design: LearningUnit마다 문제 설계도 하나를 만듦
  ↓
지원 가능 여부 확인·필요한 보조 문제 결정
  ↓
Cards: 포함된 LearningUnit마다 실제 문제 하나를 만듦
  ↓
사용자 검토 → 저장 → 학습·복습
```

## 단계별 한 문장 책임

| 단계 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| Analyze | 자료가 어떤 구조와 내용으로 이루어졌는지 파악한다. | 문제를 만들지 않는다. |
| Plan | 어떤 범위를 어떤 목표로 공부할지 정한다. | 문제 개수에 맞춰 내용을 억지로 쪼개지 않는다. |
| Prepare | 실제로 연습할 내용을 한 문제 크기의 학습단위로 만든다. | 문제 형식을 고르거나 문제 문장을 쓰지 않는다. |
| Activity Design | 각 학습단위를 어떤 입력·행동·정답으로 확인할지 설계한다. | 한 학습단위를 다시 여러 문제로 불린다거나 합치지 않는다. |
| Cards | 설계도대로 화면에 표시할 문제를 만든다. | 앞 단계의 학습목표를 더 쉬운 암기로 몰래 바꾸지 않는다. |

## LearningUnit의 기준

LearningUnit 하나는 다음 질문에 답할 수 있어야 한다.

1. 학습자가 정확히 무엇을 해야 하는가?
2. 성공과 실패를 한 번의 시도에서 판정할 수 있는가?
3. 정답의 근거가 원자료 어디에 있는가?

현재 핵심 필드는 다음 역할을 가진다.

```text
target             무엇을 익힐지
operation          떠올리기 / 구조복원 / 구별하기 / 적용하기 중 무엇을 할지
successCriterion   무엇을 맞히면 성공인지
reviewedText       사용자가 확인·수정한 최종 학습 내용
source             원자료의 근거 위치
```

## 반드시 지킬 불변조건

1. **LearningUnit 1개 → 문제 설계도 1개 → 최종 문제 1개**를 기본으로 한다.
2. 최대 개수는 안전선이지 채워야 할 목표가 아니다.
3. 한 문제에서 독립적으로 따로 틀릴 수 있는 내용은 가능한 한 학습단계에서 나눈다.
4. 실제 순서·상하관계·묶음 관계가 학습대상일 때만 구조복원을 쓴다.
5. `Apply`와 `Discriminate`는 가능한 한 새 입력을 판단하거나 사용하는 행동을 유지한다.
6. 현재 화면으로 직접 수행·자동채점이 어렵더라도 중요한 학습단위를 삭제하지 않는다.
7. 어려운 핵심은 추가 문제를 덧붙이지 않고, **같은 한 자리**를 자기확인형 플래시카드 같은 가장 가까운 보조 문제로 바꾼다.
8. 보조 문제로 바뀌었으면 완전 지원처럼 표시하지 않는다.
9. 문제 앞면에는 정답이나 정답 순서를 노출하지 않는다.
10. 문제 내용과 정답은 원자료 근거를 벗어나지 않는다.

## 현재 지원하는 문제 화면

| 문제 화면 | 적합한 용도 |
| --- | --- |
| 플래시카드 | 짧은 회상, 직접 말해 본 뒤 자기확인, 현재 자동채점이 어려운 적용의 보조 훈련 |
| OX | 한 문장이나 판단의 참·거짓 확인 |
| 객관식 | 여러 답 중 구별·선택 |
| 구조복원 | 실제 순서, 묶음, 상하관계 복원 |

문제 화면과 학습 행동은 같은 개념이 아니다. 예를 들어 적용 연습도 현재 자동채점이 어렵다면 플래시카드 앞면에서 먼저 수행하고 뒷면으로 확인할 수 있다.

## 실험으로 확인된 효과

### 핵심 로직 단독 실험

- 사회 학생용 자료: 10개 문제단위, 적용 2·구별 2·회상 6
- 과학 학생용 자료: 9개 문제단위, 적용 1·구별 2·회상 5·구조복원 1
- 자료의 중요한 내용을 문제 개수에 맞춰 억지로 늘리지 않고, 문제단위와 행동을 먼저 잡는 방향이 확인됐다.

### 실제 생성엔진 연결 실험

- 사회: LearningUnit 12개 → 문제 12개, 기계 오류 0건
- 과학: LearningUnit 10개 → 문제 10개, 기계 오류 0건
- 실제 `Prepare → Activity Design → Cards` 경로에서도 1:1 대응과 행동 구분이 유지됐다.
- 남은 품질 문제는 사회의 복수 정답 가능 사례와 과학의 서로 다른 관계를 한 구조에 묶은 사례다.

- `eval/local/actual-engine-student-smoke/`

## 핵심에 포함하지 않는 것

다음은 현재 핵심 품질을 만드는 데 필수라고 확인되지 않았거나, 이전 흐름의 잔여물이다.

- Recall Design과 대표 예시 선택
- sample 단계와 sampleFeedback
- Activity Design을 건너뛰는 full 생성 단계
- 꺼져 있는 Critic 호출
- CardContract 중심의 옛 카드 방향 결정
- 지식 유형만으로 문제 방식을 고르는 규칙

이 항목들은 곧바로 삭제한다는 뜻이 아니다. 실제 호출자와 저장 데이터 의존성을 확인한 뒤 정리한다.
