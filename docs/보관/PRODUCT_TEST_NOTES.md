# Study Forge 제품 테스트 기록

사용자가 제품을 직접 확인하면서 말한 문제를 누적하는 작업 문서다.

## 2026-08-18 1차 반영 상태

- 캘린더: 날짜 선택, 날짜별 상세, 학습계획 추가·수정·완료·삭제, 자동 복습·실제 학습 기록 구분을 추가했다.
- 학습자료: 제목·진행률·복습 수만 먼저 보이는 1~2줄 목록으로 줄이고, 나머지는 펼친 뒤 보이게 했다.
- 학습 기록: 최근 세션을 기본 접힘 로그로 바꿨다.
- 자료 생성: 분석·추출·문제 구성·문제 생성 중에는 중앙 진행 화면만 보이게 했다.
- 목차 선택: 카드형 박스 대신 정렬된 체크박스와 행·연결선·글자 굵기로 계층을 표현한다.
- 추출 이후: `PDF 근거 검토 → 문제 생성 설정`을 서로 다른 화면으로 분리했다.
- 부가 설정: 문제 방향은 접어 두고 자동/직접 선택은 짧은 행과 정보 버튼으로 줄였다.
- 생성 결과: 실제 문제 미리보기를 먼저 보여주고, 필요할 때만 `문제 수정`으로 전환한다.
- PDF 근거: 글자 전체를 덮는 면 대신 글자 아래쪽을 강조해 원문 가독성을 높였다.
- 문제 설정: `원문을 최대한 사용 / AI가 학습용으로 다듬기` 선택을 추가했다. 원문 유지 시 문제 설계와 최종 생성 모두 실제 sourceText를 우선하며, 형식별 원문 재사용 규칙을 적용한다.

다음 사용자 검토에서 시각 밀도, 문구, 단계 순서가 실제 기대와 맞는지 다시 조정한다.

## 기록 원칙

- 사용자가 말한 문제를 먼저 기록하고 즉시 구현하지 않는다.
- 비슷한 문제는 같은 항목 아래 합치되 실제 사례는 남긴다.
- 원인이 확인되지 않은 내용은 추측해서 확정하지 않는다.
- `수정 진행` 요청 전까지는 문제 수집과 정리만 한다.
- 수정할 때는 한 번에 전부 처리하지 않고 우선순위를 정해 하나씩 검증한다.

## 수집 중인 문제

### 공통으로 느껴지는 핵심 문제

현재 UI는 사용자가 지금 봐야 할 핵심과 필요할 때만 확인할 세부 정보를 구분하지 않고 한 화면에 대부분 펼쳐 놓는다.

그 결과:

- 화면이 넓고 길게 퍼진다.
- 한 단계에서 집중해야 할 대상이 불명확하다.
- 로그, 설명, 선택지, 진행 방식 같은 보조 정보가 핵심 행동과 같은 비중으로 보인다.
- 기능은 많지만 정리되지 않은 AI 생성 화면처럼 느껴진다.

원하는 공통 방향:

- 처음에는 핵심 정보와 핵심 행동만 보여준다.
- 자세한 내용은 클릭, 펼치기, 별도 화면, 작은 팝업 등으로 필요할 때 확인한다.
- 하나의 항목이 차지하는 기본 높이를 한 줄, 많아도 두 줄 정도로 줄인다.
- 한 단계가 끝나면 다음 단계가 명확한 새 화면이나 집중된 영역으로 이어진다.

---

### 1. 캘린더가 지나치게 가볍다

#### 현재

- 캘린더는 날짜와 간단한 학습·복습 기록을 보여주는 수준이다.
- 날짜별 계획을 직접 구성하거나 자세한 내용을 관리할 수 있는 기능이 거의 없다.

#### 원하는 방향

- 캘린더를 단순 기록 표시가 아니라 학습 전용 플래너로 강화한다.
- 날짜를 누르면 해당 날짜의 자세한 학습 내용을 확인할 수 있어야 한다.
- Google Calendar나 Notion Calendar처럼 날짜별 상세 화면과 사용자 조정 기능이 필요하다.
- 다만 일반 일정관리 기능을 전부 가져오는 것이 아니라 학습에 필요한 기능만 둔다.

#### 아직 정하지 않은 것

- 날짜별로 정확히 무엇을 계획할지
- 자동 복습 일정과 사용자가 만든 계획을 어떻게 함께 표시할지
- 드래그 이동, 반복 일정, 알림 등이 실제로 필요한지

---

### 2. 학습자료와 학습기록이 너무 많이 펼쳐져 있다

#### 학습기록 화면

- 최근 학습 세션은 항상 볼 핵심 정보가 아니라 필요할 때만 보는 로그에 가깝다.
- 현재는 최근 학습 세션이 화면에 전부 펼쳐져 있어 핵심 기록보다 더 많은 공간을 차지한다.

#### 학습자료 화면

- 덱 하나가 넓고 높은 박스 하나를 차지한다.
- 덱 이름, 과목 없음, 혼합 문제, 플래시카드, 상태, 카드 수, 학습 진행 게이지 등이 한 번에 모두 표시된다.
- 정보는 많지만 여러 덱을 빠르게 훑어보기 어렵다.

#### 원하는 방향

- 덱 하나는 기본적으로 한 줄, 많아도 두 줄 높이의 목록으로 표시한다.
- 처음에는 이름과 진행률 등 실제 핵심 정보만 보여준다.
- 덱을 누르면 문제 구성, 상태, 카드 수, 세부 진행률 같은 추가 정보가 나타난다.
- 최근 학습 세션도 접힌 로그 또는 별도 상세 영역으로 이동한다.

#### 병합된 핵심

`항목 전체 정보를 카드 안에 펼쳐 놓는 방식`에서 `짧은 목록 + 필요할 때 상세보기` 방식으로 바꾸고 싶다.

---

### 3. 자료 생성의 단계와 화면이 중구난방하다

#### 입력 화면

- PDF 학습자료, 학습목표, 자료 분석 버튼까지는 현재 흐름을 유지해도 괜찮다.
- 추가 지시와 참고 자료는 첫 화면에서 핵심이 아니므로 숨기거나 제거하는 방안을 검토한다.

#### 분석 진행 화면

- 자료 분석 버튼을 누른 뒤 같은 화면 아래에 `PDF 분석 중`이 붙는 방식은 집중감이 약하다.
- 새로운 진행 화면으로 넘어가거나 화면 중앙의 명확한 진행 애니메이션으로 보여주는 편을 원한다.

#### 분석 결과와 집중 영역 선택

- 두 단계의 내용 자체는 현재도 대체로 괜찮다.
- 다만 시각적으로 박스를 반복해 배치한 형태라 임시 AI 화면처럼 느껴진다.

#### 학습목차 선택

- 현재는 목차 노드를 각각 박스로 만들고 들여쓰기만 달리해 부모·자식을 표현한다.
- 박스를 제거하고 각 내용을 한 줄 또는 두 줄짜리 계층 목록으로 표시하고 싶다.
- 체크박스는 왼쪽이나 오른쪽의 같은 열에 일렬로 정렬한다.
- 부모·자식 레벨은 들여쓰기만 사용하지 않고 폰트 굵기, 크기, 색, 선 등으로 더 분명하고 깔끔하게 구분한다.

#### 병합된 핵심

자료 생성은 `한 긴 화면에 단계가 계속 추가되는 구조`보다 `현재 단계 하나에 집중하고 다음 단계로 이동하는 구조`에 가까워져야 한다.

---

### 4. 학습 내용 추출 이후 한 화면에 너무 많은 기능이 섞인다

#### 학습 내용 추출 결과

- 추출 결과, PDF 근거 검토, 문제 만들기 방향, 문제 생성 방식, 진행 방식 등 모든 요소가 한 화면에 함께 나타난다.
- 무엇부터 확인해야 하는지 알기 어렵고 집중이 분산된다.

#### PDF 근거 강조

- 원문에서 근거를 강조하는 기능 자체는 좋다.
- 현재 반투명 색을 글자 위에 덮는 방식은 검은 글자가 바래고 읽기 어려워진다.
- 글자 가독성을 유지하면서 범위만 분명하게 표시하는 강조 방식이 필요하다.

#### 문제 만들기 방향과 생성 방식

- 추출 결과와 항상 같은 화면에 펼쳐 둘 필요가 없다.
- 다음 버튼을 누른 뒤 별도 단계에서 보여주거나 작은 팝업·미니 패널로 제시하는 방안을 원한다.

#### 문제 생성 진행 방식

- 현재 선택 박스와 설명이 너무 크다.
- 핵심 선택은 짧은 두 줄 이내로 줄이고, 자세한 설명은 정보 버튼이나 마우스를 올렸을 때 확인할 수 있게 하고 싶다.

#### 생성 결과 수정

- 문제 생성 직후 별도의 `생성 결과 수정` 탭에서 모든 문제를 먼저 편집하게 하는 흐름이 번거롭다.
- 기본 흐름은 문제를 확정하고 바로 실제 카드 학습 화면으로 넘어간다.
- 카드를 실제로 보면서 마음에 들지 않는 문제만 별도 수정 기능으로 고치는 방식이 더 자연스럽다.

#### 병합된 핵심

`추출 결과 검토 → 방식 선택 → 진행 설정 → 전체 결과 수정`을 한 화면에 펼치는 방식에서, 필요한 결정을 순서대로 짧게 보여주고 실제 카드를 먼저 경험하게 하는 방식으로 바꾸고 싶다.

---

## 현재까지 합쳐진 제품 방향

아직 구현안이 아니라 사용자가 원하는 느낌을 정리한 것이다.

1. 캘린더는 학습 기록판에서 학습 플래너로 강화한다.
2. 덱과 기록은 카드형 정보 전개보다 압축된 목록과 상세보기 구조를 사용한다.
3. 자료 생성은 한 화면에 기능을 누적하지 않고 단계별 집중 흐름으로 정리한다.
4. 보조 설명과 로그는 기본적으로 숨기고 필요할 때만 연다.
5. 생성 직후 전체 편집을 강요하지 않고 실제 카드 확인을 우선한다.
6. 전체 디자인의 핵심은 기능을 더 보여주는 것이 아니라 필요한 순간에 필요한 정보만 보여주는 것이다.

## 나중에 정리할 항목

- 문제가 발생한 화면 또는 단계
- 사용자가 기대한 동작
- 실제로 발생한 동작
- 반복 여부와 재현 조건
- 서로 같은 원인으로 보이는 문제 묶음
- 수정 우선순위
