# 2026-08-29 Study Forge 작업 기록

## 오늘 작업의 범위

오늘은 기존 Codex App Server 생성 경로를 바꾸지 않고, ChatGPT가 첨부 PDF를 읽고 Study Forge MCP가 자연어 산출물을 앱 데이터로 조립하는 비교 경로를 개선했다.

현재 비교 경로는 다음과 같다.

```text
원문 목차 추출
→ Concept Tree
→ Learning Design
→ Assessment & Activity Design
→ Cards
→ 검증·발행
```

모델은 짧은 자연어 블록을 작성하고 MCP는 ID, 단계 연결, 지원 수준, 카드 JSON, 원문 근거 검증과 저장을 담당한다.

## 수정 전 확인된 문제

오늘 수정 전 기준으로 사용한 첫 실제 데드락 PDF 테스트 결과는 다음과 같았다. 저장 시각은 UTC 기준 2026-08-28이고 한국 시간 작업일은 2026-08-29다.

- 학습대상 9개, Blueprint 14개, 최종 카드 9개
- 실제 카드가 연결된 학습대상은 8/9개
- proxy 또는 unsupported 설계가 제외된 뒤 한 학습대상이 카드 없이 사라짐
- 순서복원과 구조복원이 단계마다 다르게 표현됨
- 순환 순서의 시작·끝에 같은 상태가 등장하면 중복 오류로 거절됨
- Cards 오류가 한 장이어도 전체 카드를 다시 작성해야 함
- 시작 응답을 놓치면 같은 run이 중복 생성될 수 있음
- 완료 run의 시도 횟수와 검증 실패 이력을 결과에서 바로 확인할 수 없음
- 외부 `type`은 모두 `flashcard`이고 실제 유형은 `activityType`에만 있어 외부 통계가 혼동될 수 있음

첫 테스트의 서버 생성시간은 315.905초, 약 5분 15.9초였다. Activity Design 93.011초와 Cards 148.946초가 전체의 약 76%를 차지했다.

## 오늘 구현한 변경

### 1. 학습대상 카드 누락 방지

Activity Design 이후 단순히 설계가 존재하는지만 보지 않고, 각 학습대상에 실제 생성 가능한 exact 또는 scaffold 설계가 하나 이상 있는지 검사한다.

한 학습대상의 설계가 모두 proxy 또는 unsupported이면 해당 목표를 억지로 완전 지원으로 표시하지 않는다. 대신 현재 앱이 지원하는 플래시카드 scaffold 하나로 자동 보정한다.

결과적으로 지원 불가 문제는 제외하면서도 학습대상 전체가 카드 없이 사라지는 문제를 막는다.

### 2. 목표 행동과 문제 행동의 관계 정규화

모델이 학습목표와 다른 확인 행동을 만들면서 관계를 `직접`으로 적어도 전체 Activity Design을 거절하지 않는다. MCP가 이를 `보조(scaffold)`로 정규화하고 이유에 자동 정규화 사실을 남긴다.

### 3. 순서복원과 구조복원 확정

Assessment & Activity Design에서 다음 값을 확정해 Cards 입력으로 전달한다.

- 순서복원: `problemType=순서복원`, `structureKind=sequence`
- 구조복원: `problemType=구조복원`, `structureKind=hierarchy`

내부 렌더러는 계속 `structure_recall`을 공유하지만 Cards 모델이 유형을 다시 해석하지 않도록 했다.

### 4. Cards 부분 재제출

첫 Cards 제출의 각 `CARD n` 블록을 임시 초안으로 저장한다. 검증에서 한 카드가 실패하면 이미 제출한 나머지 카드는 보존하고, 실패한 번호의 카드 블록만 같은 번호로 다시 제출할 수 있다.

단계별 제출 횟수와 실패 오류도 `stageAttemptCounts`, `stageValidationFailures`로 run에 기록한다.

### 5. 순환형 순서복원의 반복 상태 지원

다음과 같이 시작 상태가 마지막에 다시 등장하는 실제 순환 순서를 허용한다.

```text
주장 간선 → 요청 간선 → 할당 간선 → 주장 간선
```

순서복원에서는 같은 표시 이름을 가진 서로 다른 노드를 허용한다. 계층 구조복원은 중복 이름 금지를 유지한다. 학습 화면의 보기 소모 로직도 같은 답 두 개를 한 번에 모두 제거하지 않고 사용한 개수만큼만 제거하도록 수정했다.

### 6. run 중복 방지와 관리

- `clientRequestId`가 같은 시작 요청은 새 run을 만들지 않고 기존 runId를 반환한다.
- `list_chatgpt_pdf_runs`로 active, completed, published, cancelled 상태를 조회한다.
- `cancel_chatgpt_pdf_run`은 미완료 run을 삭제하지 않고 취소 상태로 전환해 진단 기록을 보존한다.

### 7. 실제 카드 유형 노출

과거 덱 호환용 `type`은 유지했다. MCP 결과와 발행 JSON에는 외부에서 바로 읽을 수 있는 `effectiveType`을 추가했고, 실제 문제 형식의 기준은 계속 `activityType`으로 사용한다.

## PDF 원문 재확인과 생성 행동 판정 불일치

데드락 PDF에는 실제 그래프가 있다.

- 6쪽: 요청 간선과 할당 간선의 의미
- 7쪽: 자원 할당 그래프 3개와 데드락 여부 판별
- 11쪽: 주장·요청·할당 간선의 변화
- 12쪽: 요청을 승인했을 때 사이클이 생기는 unsafe state 사례

하지만 계산 문제는 없다. 11쪽에 다중 인스턴스에서는 은행원 알고리즘을 사용한다는 한 줄만 있고, 행렬·수치·계산 절차·계산 예제는 없다.

따라서 `은행원 알고리즘 계산`이나 `그래프 직접 작성`을 필수 학습행동으로 확장하면 원문 범위를 벗어난다. 다만 최종 run을 다시 확인한 결과 AI가 실제로 계산 문제나 그래프 작성 문제를 만들지는 않았다. Activity Design에도 `다중 인스턴스 은행원 계산은 포함하지 않는다`, `그래프 모양 자체는 그리지 않는다`고 명시되어 있었다.

실제로 발생한 불일치는 다음과 같다.

- AI Learning Design은 그래프 사례 판별과 요청 승인 판단을 `적용` 행동으로 분류했다.
- AI Activity Design은 이를 객관식 사례 판별로 설계했다.
- MCP 지원 판정은 현재 `적용 + 객관식`을 직접 지원으로 인정하지 않고 proxy로 판정했다.
- 커버리지 보정기가 해당 설계를 플래시카드 scaffold로 교체했다.

즉, AI가 원문 밖의 계산 문제로 확장한 것이 아니라 AI의 `적용` 행동 분류와 MCP의 객관식 지원 규칙이 맞지 않아 유효한 사례 판별 문제가 더 낮은 회상 문제로 바뀐 것이 실제 문제다. 이 자료에 맞는 활동은 다음 정도다.

- 그래프를 보고 데드락 여부 판별
- 요청 승인·거절 판단
- 간선 변화 순서 복원
- 사이클과 자원 인스턴스 수의 관계 구별

은행원 알고리즘 계산이나 그래프 직접 작성으로 확대하지 않는 원문 범위 규칙은 계속 필요하지만, 이번 최종 run에서 실제로 발생한 실패로 기록하지는 않는다.

## 현재 남은 한계와 다음 개선 후보

1. AI가 `판별` 중심 목표를 `적용`과 `구별` 중 어느 행동으로 분류할지 기준이 아직 흔들린다.
2. MCP는 `적용 + 객관식`을 직접 지원으로 인정하지 않아, 원문에 근거한 사례 판별 문제도 플래시카드 scaffold로 낮출 수 있다.
3. 다음 개선에서는 실제 시나리오를 읽고 판단하는 객관식이 적용 행동을 충분히 확인하는 조건을 정의해야 한다.
4. 목표가 단순한 차이 구별이라면 Learning Design 단계에서 처음부터 `구별`로 확정해 단계 간 불일치를 줄여야 한다.
5. 알고리즘 이름만 언급된 경우 계산 과제로, 그림이 있다는 이유만으로 직접 작성 과제로 확대하지 않는 원문 범위 검사도 유지해야 한다.

## 행동 분류 제거와 재검증

위 불일치를 해결하기 위해 ChatGPT/MCP 자연어 생성 경로에서 `행동`과 `확인행동` 입력을 제거했다.

- Learning Design은 학습내용, 학습목표와 성공기준만 정한다.
- Activity Design은 보여줄 정보, 감출 답, 기대 응답, 채점, 단서와 문제 형식만 정한다.
- MCP 지원 판정은 `회상·구별·복원·적용` 이름을 비교하지 않고 기대 응답과 현재 renderer 기능의 일치 여부로 계산한다.
- 기존 Codex/API 및 저장 계약에 필요한 operation 값은 문제 형식에서 계산하는 내부 호환값으로만 남기고 모델 입출력과 MCP 지원 판정에는 사용하지 않는다.

데드락 PDF를 새 `clientRequestId=deadlock-actionless-20260829-1`로 다시 생성하고 발행했다.

- runId: `chatgpt-request-8fdc086270cf4e04f0581de31d60f2f0`
- deckId: `mcp-run-chatgpt-request-8fdc086270cf4e04f0581de31d60f2f0`
- 학습대상 8개, 문제 설계 9개, 카드 9장, 커버리지 8/8
- 객관식 3장, OX 2장, 구조복원 4장(계층 3, 순서 1)
- 9개 설계 모두 exact/supported, 자동 포함됨
- 상황 판단형 객관식·OX 5개 모두 강등 없이 exact로 유지됨
- 모든 단계 1회 제출, 검증 실패와 재시도 0건
- 서버 생성시간 112.128초, 발행·상태 확인 포함 실측 123.682초

이 재검증으로 위 1~4번 행동 분류 불일치는 해소됐다. 5번의 원문 범위 제한과 실제 미지원 입력 기능 판정은 계속 유지한다.

## 프로젝트 학습트리 연결과 실제 앱 검증

개념트리를 생성 과정의 일회성 중간 결과로 끝내지 않고 프로젝트 학습 상태의 기준 구조로 연결했다.

- Learning Design은 각 학습단위가 포함하는 전체 개념 노드 ID를 저장한다.
- Activity Design은 자연어의 `관련개념: 전체 | 2, 4` 형식으로 해당 문제에 직접 연결할 노드를 고른다.
- MCP는 숫자를 실제 노드 ID로 변환하고, 학습단위 바깥 노드를 참조하면 거절한다.
- Cards는 확정된 Blueprint의 노드 연결을 그대로 상속한다.

### 학습트리 가시성 개선

첫 구현은 2,804px 가로 캔버스를 작은 프로젝트 패널 안에 표시하고 26개 노드를 한꺼번에 펼쳐 루트가 화면 밖으로 밀리고 연결선이 겹쳤다. 이를 다음처럼 수정했다.

- 프로젝트 내부 패널이 아니라 화면 전체 트리 화면으로 표시
- 위→아래 배치에서 좌→우 배치로 변경
- 단일 학습일 때 불필요한 프로젝트 중간 루트 생략
- 처음에는 루트와 최상위 가지 4개만 표시
- 노드의 `+`와 `−`를 눌러 하위 가지를 단계적으로 열고 닫음
- 선택한 가지와 연결선은 선명하게, 나머지는 흐리게 표시
- 노드 폭, 글자 크기, 테두리와 연결선 대비 강화
- 확대, 축소, 화면 맞춤과 빈 배경 드래그 이동 지원

실제 앱에서 기본 5개 노드, 가지 확장 후 6개, 재접기 후 5개를 확인했다. 화면 맞춤과 모달 전체화면이 정상 동작했고 브라우저 콘솔 오류는 없었다.

- 가지를 열면 새 노드와 연결선이 자연스럽게 나타나고 기존 노드는 새 위치로 부드럽게 이동하도록 전환 효과를 추가했다. 접을 때는 하위 가지가 먼저 사라진 뒤 레이아웃을 정리한다.
- `다 열기`와 `다 닫기`를 추가했고 실제 앱에서 5개 → 26개 → 5개 노드 전환, 애니메이션 적용과 콘솔 오류 0건을 확인했다.
- 루트 노드는 하위 가지 배치 계산에서 분리해 왼쪽 중앙 `(120, 260)`에 고정했다. 개별 가지와 전체 트리를 펼친 뒤에도 루트 좌표가 동일하고 콘솔 오류가 없음을 확인했다.
- 실제 AI와 연결되지 않고 입력 문장만 화면에 쌓던 프로젝트 하단 채팅 입력창과 확장 채팅 패널을 제거했다. 프로젝트 자료·학습 목록과 학습트리 기능은 그대로 유지했으며 실제 화면에서 입력창 0개, 트리 버튼과 발행 학습 노출, 콘솔 오류 0건을 확인했다.
- 순환형 순서복원의 시작·끝에 같은 `청구 간선`이 들어갈 때 답 모음 버튼이 문구만 React key로 사용해 중복 경고가 발생하던 문제를 수정했다. 미리보기와 실제 학습 모두 `문구+선택지 위치`를 key로 사용하고, 같은 문구를 하나 사용했을 때 실제 사용 개수만큼만 비활성화하도록 바꿨다. 학습 테스트 52/52, 린트와 프로덕션 빌드가 통과했다.
- 학습 결과는 IndexedDB에 저장됐지만 프로젝트 트리가 받는 세션·시도 React 상태가 학습 직후 갱신되지 않아 색상 피드백이 보이지 않던 문제를 수정했다. 학습 시작·정답 저장 시 상태를 즉시 갱신하고 프로젝트 화면으로 돌아올 때 저장소를 재조회한다.
- 한 문제가 부모·자식 개념에 동시에 연결되면 상위 노드에서 같은 시도를 중복 합산해 1회 정답을 곧바로 `안정`으로 표시하던 문제도 제거했다. 상위 노드는 attempt ID 기준으로 중복을 제거한다. 실제 데드락 문제 1개를 맞힌 뒤 관련 노드 2개와 루트가 `학습 중`으로 즉시 바뀌고 콘솔 오류가 없음을 확인했다.

## 프로젝트 소유 독립 학습트리로 전환

- 학습트리를 덱 내부에만 저장하지 않고 프로젝트 저장소의 독립 `conceptTrees` 컬렉션으로 분리했다.
- 트리마다 자체 ID, 출처 PDF ID, 생성·갱신 시각을 보존하며 같은 ID만 갱신한다. 서로 다른 트리를 자동 병합하지 않는다.
- 덱은 `conceptTreeIds`로 프로젝트 트리를 참조하고, 카드의 `conceptNodeIds`와 함께 학습 결과를 해당 트리 노드에 반영한다.
- 기존 `deck.conceptTree` 데이터는 앱 시작 시 프로젝트 저장소로 자동 이전하고, 이전 성공 뒤 덱에는 참조 ID만 남긴다. 프로젝트나 API 문제가 있으면 기존 트리를 지우지 않는다.
- MCP 발행 덱에도 트리 참조 ID를 함께 기록하도록 변경했다.
- 실제 운영체제 테스트 프로젝트에서 데드락 트리 1개·개념 26개가 새 프로젝트 저장소에 보관되고, 기존 정답 결과가 노드 2개에 `학습 중`으로 표시되는 것을 새 브라우저 탭에서 확인했다. 콘솔 오류는 없었다.
- 검증: 프로젝트 저장소 테스트 1/1, MCP 테스트 14/14, 학습 테스트 52/52, 린트, 프로덕션 빌드 통과. 빌드에는 기존 Codex App Server 동적 파일 추적 경고 1건이 남아 있다.
