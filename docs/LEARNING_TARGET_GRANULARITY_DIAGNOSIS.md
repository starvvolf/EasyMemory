# 학습 대상 단위 크기 문제 브리핑

## 한 문장 요약

Study Forge는 PDF에서 `무엇을 배울지`와 `무엇을 할 수 있어야 하는지`를 추출할 수 있게 되었지만, 여러 항목의 관계를 다루는 자료에서는 하나의 학습 대상이 한 번에 연습하기 어려울 정도로 크게 만들어지는 문제가 남아 있다.

## 1. 지금 만들고 있는 흐름

현재 지향하는 생성 흐름은 다음과 같다.

```text
PDF
→ 사실 기반 목차 구조
→ 관련 내용을 의미 있는 덩어리로 묶기
→ 덩어리별 중요도 판단
→ 실제 학습 대상 추출
→ 학습자가 보여야 할 행동 결정
→ 현재 앱 지원 여부 판단
→ 문제 방식 추천 및 생성
```

각 학습 대상은 다음 세 값을 가진다.

```text
target
무엇을 배워야 하는가

operation
그 대상으로 무엇을 할 수 있어야 하는가

successCriterion
무엇을 하면 배웠다고 판단할 수 있는가
```

`operation`은 다음 네 가지로 제한한다.

```text
Recall
자료 없이 대상 자체를 떠올린다.

Reconstruct
자료에서 배운 고정된 구성·관계·순서를 복원한다.

Discriminate
조건을 보고 맞음·틀림 또는 적절한 대상을 판별한다.

Apply
새로운 입력에 지식이나 규칙을 사용해 달라지는 결과를 만든다.
```

이 구조를 사용하면서 `지식/방법/사례`와 같은 자료 유형 분류는 핵심 판단에서 제외했다.

## 2. 이번에 해결하려고 한 문제

초기 결과에는 한 target이 너무 많은 내용을 한꺼번에 요구하는 경우가 있었다.

예를 들면 권리장전 자료에서 다음과 같은 결과가 나왔다.

```text
수정조항 I부터 X까지를 순서대로 제시하고
각 조항의 핵심 권리를 모두 복원한다.
```

내용상 하나의 체계인 것은 맞지만, 실제 학습 문제 한 번으로 연습하고 성공 여부를 판단하기에는 너무 크다.

반대 문제도 있다. 무조건 작은 단위로 나누면 하나의 구조나 공통 패턴이 의미 없이 조각난다.

예를 들어 OPIc의 Pattern 1~7은 각각 문장 하나이지만, 자료가 익히게 하려는 것은 일곱 문장을 따로 아는 것보다 이들을 조합해 하나의 인물 묘사 답변을 만드는 능력에 가깝다.

따라서 목표는 단순히 작은 target을 많이 만드는 것이 아니다.

> 한 번의 집중된 연습에서 하나의 성공·실패를 판단할 수 있는 가장 큰 의미 단위를 만드는 것

## 3. 적용한 단위 축소 기준

다음 기준을 Prepare 프롬프트와 실험 프롬프트에 추가했다.

- 하나의 target은 보통 한 번의 질문과 답으로 성공 여부를 판단할 수 있어야 한다.
- 서로 독립적으로 성공하거나 실패할 수 있는 결과·규칙·판단은 나눈다.
- 결과 산출과 코드 구현처럼 서로 다른 성공 방법을 `또는`으로 묶지 않는다.
- 여러 요소의 순서·분류·대응 관계 전체가 학습 대상이면 요소 수만 보고 나누지 않는다.
- 긴 장 전체를 한 번에 재현하게 하지 않는다.
- 자료가 실제로 함께 다루는 의미를 보존하면서 한 번에 연습 가능한 가장 큰 단위를 선택한다.

## 4. 실험 구성

기존에 구조화한 다음 일곱 종류의 자료를 사용했다.

1. OPIc 인물 묘사 말하기 자료
2. 운영체제 데드락 강의자료
3. DFS/BFS 알고리즘 자료
4. 미국 권리장전 사료 비교 자료
5. 달의 위상 과학 활동 자료
6. 재난 대비 금융 체크리스트
7. 미적분 문제집

PDF 원문을 다시 전송하지 않고 기존 목차 데이터를 재사용했다. 같은 프롬프트로 반복 실행하여 특정 한 번의 우연한 결과가 아닌지도 확인했다.

중단 조건은 다음과 같았다.

> 동일한 품질 실패가 두 번 발생하면 추가 API 실행과 프롬프트 수정을 중단한다.

## 5. 개선된 결과

### 미적분

기존에는 20개 target이 만들어졌고, 하나의 target이 최대 8개 목차 근거를 함께 사용했다.

단위 축소 후에는 32개 target으로 나뉘었고, 하나의 target이 사용하는 근거는 최대 3개로 줄었다.

다음과 같은 내용이 분리되었다.

```text
미분의 정의로 도함수 구하기
접선 방정식 구하기
함수 그래프에서 도함수 그래프 그리기
연쇄법칙 적용하기
음함수 미분 적용하기
```

문제집처럼 독립적인 풀이 요구가 반복되는 자료에서는 단위를 줄이는 기준이 효과적이었다.

### DFS/BFS

인접 행렬과 인접 리스트를 각각 표현하는 수행이 분리되었다.

반복 실행 중에는 DFS와 BFS의 동작 원리와 코드 구현도 각각 분리된 결과가 나왔다.

```text
DFS의 방문·깊이 진행·되돌아감 구조 복원
재귀 DFS 코드 구현

BFS의 큐 삽입·꺼내기·확장 구조 복원
deque 기반 BFS 코드 구현
```

동작을 설명하는 것과 실제 코드를 작성하는 것이 서로 다른 성공 행동이라는 점을 반영한 결과다.

### 재난 대비 체크리스트

기존 8개 target이 11개로 나뉘었다.

다음처럼 실제로 따로 수행할 수 있는 행동이 분리되었다.

```text
개인 기록 선별
금융 기록 선별
디지털 자료 백업
원본과 사본 분리 보관
채권자 연락
공공서비스 중단 확인
재난 사기 판별
```

### OPIc

작은 단위 기준을 추가했어도 Pattern 1~7을 기계적으로 잘게 나누지 않았다.

```text
새 인물 정보에 맞춰 7개 문장 기능을 연결하여 답변을 만든다.
```

공통 답변 틀 전체가 하나의 수행이라는 의미를 보존했다.

이 결과는 단위 축소가 모든 목록을 개별 항목으로 분해하는 방식은 아니라는 것을 보여준다.

## 6. 반복된 실패

권리장전 자료에서는 큰 target 문제가 두 번 반복되었다.

첫 번째 축소 실행에서는 하나의 target이 최대 11개 목차 근거를 포함했다.

두 번째 실행에서는 최대 12개 목차 근거를 포함했다.

예시는 다음과 같다.

```text
종교·표현·집회·청원·무기·병사 숙영 관련 권리 보장이
반연방주의자 요구
→ 매디슨 제안
→ 수정헌법 제1~3조
로 어떻게 이어지는지 모두 대응시킨다.
```

이 결과는 이전처럼 권리장전 전체를 한 target으로 묶지는 않았다. 자유권, 절차적 권리, 정부 구조처럼 주제별로는 나뉘었다.

하지만 한 주제 안에서 여러 권리와 세 문서의 대응을 한꺼번에 요구하므로 여전히 한 번의 연습 단위로는 크다.

같은 실패가 두 번 발생했기 때문에 설정한 기준에 따라 두 번째 실험 도중 추가 호출을 중단했다.

## 7. 왜 이 문제가 발생하는가

현재 AI는 다음 두 조건을 동시에 지키려고 한다.

```text
관련된 의미를 함부로 쪼개지 않는다.
한 번에 연습 가능한 크기로 나눈다.
```

권리장전처럼 여러 자료의 대응 관계 자체가 중요한 경우 AI는 의미 보존을 더 우선한다.

그 결과 큰 비교 구조를 하나의 target으로 남긴다.

반대로 작은 단위만 강하게 요구하면 다음 문제가 생길 수 있다.

```text
수정조항 하나마다 별도 target 생성
→ 요구·제안·비준의 전체 관계가 사라짐
→ 단순 조항 암기 문제로 변함
```

즉 이 문제는 단순한 프롬프트 문장 부족이 아니다.

> 큰 관계 구조를 보존하는 것과 실제 연습 단위로 나누는 것을 한 번의 AI 판단에서 동시에 처리하고 있기 때문에 발생한다.

## 8. 현재 판단

단위 축소 기준은 문제집, 절차 자료, 체크리스트처럼 독립 수행이 비교적 분명한 자료에는 효과가 있었다.

하지만 여러 문서·시기·조항의 대응 관계가 하나의 의미를 이루는 자료에서는 안정적으로 작동하지 않았다.

또한 반복 실행에서 다음과 같은 흔들림도 있었다.

- OPIc 쉐도잉을 실제 수행인 `Apply`로 잡기도 하고 절차 복원인 `Reconstruct`로 잡기도 했다.
- DFS 동작과 구현을 하나의 수행으로 보기도 하고 별도 target으로 나누기도 했다.
- 같은 자료에서도 중요도 2와 3의 판단이 일부 달라졌다.

따라서 현재 결과를 완전히 안정된 target 생성기로 평가하면 안 된다.

## 9. 지금 더 하지 않는 것

이번 단계에서는 다음 변경을 추가하지 않는다.

- 과목별 단위 크기 규칙 추가
- 권리장전이나 법령 자료만을 위한 예외 프롬프트 추가
- 근거 노드 개수를 기준으로 기계적으로 target 분할
- 최대 글자 수를 넘으면 강제로 분할
- operation마다 고정된 target 크기 지정
- 동일 문제를 해결하기 위한 프롬프트 문장 추가

이런 방식은 현재 실패를 일시적으로 줄일 수 있지만 다른 자료에서 의미 있는 구조를 훼손할 가능성이 높다.

## 10. 다음에 검토할 방향

다음 작업에서는 프롬프트를 더 길게 만드는 것보다 판단을 두 단계로 나누는 방안을 검토할 필요가 있다.

```text
1단계
전체 관계를 보존한 학습 대상 확인

2단계
그 대상을 실제로 연습할 수 있는 하위 과제로 나누기
```

예를 들면 권리장전의 전체 학습 대상은 다음처럼 보존한다.

```text
반연방주의자 요구가 매디슨 제안을 거쳐
권리장전 조문으로 이어진 대응 관계
```

실제 연습 단위는 다음처럼 나눌 수 있다.

```text
종교·표현 권리의 요구→제안→비준 대응
무기 소지 권리의 요구→제안→비준 대응
병사 숙영 제한의 요구→제안→비준 대응
```

이 구조에서는 큰 관계를 학습 목표로 보존하면서도 실제 문제는 작게 만들 수 있다.

다만 이 단계를 바로 추가하면 새로운 구조가 생긴다. 다음 구현 전에는 기존 Prepare가 이 역할을 조금 확장하는 것으로 충분한지, 별도 분리가 정말 필요한지 먼저 판단해야 한다.

## 11. 다음 검증의 합격 기준

다음 접근을 실험한다면 최소한 다음 조건을 만족해야 한다.

- 권리장전의 요구→제안→비준이라는 전체 관계가 사라지지 않는다.
- 실제 문제 하나가 여러 독립 권리를 한꺼번에 요구하지 않는다.
- OPIc Pattern 1~7처럼 하나의 공통 틀을 불필요하게 분해하지 않는다.
- 미적분의 서로 다른 풀이 요구는 독립 target으로 유지된다.
- 같은 자료를 반복 실행했을 때 target 수와 operation이 크게 흔들리지 않는다.
- 자료 주제별 예외 규칙을 사용하지 않는다.
- 현재 앱이 지원하지 못하는 수행을 플래시카드나 객관식으로 완전 지원한다고 과장하지 않는다.

```text
생성 계약 테스트 10개 통과

동일 과대 단위 실패 2회 확인 후 실험 중단
```

## 13. 검수 후 채택한 구조적 판단

반복 실패를 검토한 결과, 현재 `target`이 다음 두 역할을 동시에 맡고 있다는 진단을 채택한다.

```text
역할 1
자료에서 의미적으로 무엇을 배워야 하는가

역할 2
한 문제에서 어디까지 요구하고 성공·실패를 판정할 것인가
```

두 역할의 크기가 비슷한 자료도 있다.

```text
학습 목표
연쇄법칙을 사용하여 합성함수를 미분한다.

한 문제의 요구
주어진 합성함수에 연쇄법칙을 적용해 도함수를 구한다.
```

반면 권리장전처럼 두 역할의 적절한 크기가 다른 자료도 있다.

```text
학습 목표
요구 → 제안 → 비준의 전체 대응 체계를 이해한다.

한 문제의 요구
특정 권리 하나의 요구 → 제안 → 비준 대응을 복원한다.
```

따라서 다음 개념 분리를 실험 대상으로 채택한다.

```text
LearningTarget
자료에서 의미적으로 보존해야 할 학습 목표

PracticeUnit
그 목표를 한 문항에서 독립적으로 연습하고 성공 여부를 판단할 범위
```

관계는 다음과 같다.

```text
LearningTarget 1개
→ PracticeUnit 1개 이상
```

대부분은 `1 → 1`일 수 있으며, 의미 보존 범위와 실제 연습 범위가 다를 때만 `1 → N`으로 나눈다.

## 14. 제안에서 조정한 부분

### LearningTarget을 무조건 가장 크게 만들지 않는다

`의미를 보존하는 가장 큰 학습 단위`라는 표현만 사용하면 한 장·한 과목 전체가 하나의 LearningTarget이 될 수 있다.

LearningTarget은 다음처럼 제한한다.

> 하나의 의미적으로 완결된 학습 목표이며, 왜 이것을 배워야 하는지 한 문장으로 설명할 수 있는 범위

큰 구조를 보존하되 관련된 모든 내용을 무제한으로 합치는 기준으로 사용하지 않는다.

### PracticeUnit을 실제 Attempt와 구분한다

현재 프로젝트에는 학습자가 실제로 문제를 푼 기록인 `StudyAttempt`가 이미 존재한다.

따라서 PracticeUnit을 실제 시도 데이터라고 부르지 않는다.

```text
PracticeUnit
한 문항 또는 한 수행에서 요구할 범위를 정의한 설계

StudyAttempt
학습자가 생성된 문제를 실제로 푼 기록
```

같은 PracticeUnit에서 나중에 여러 문제와 여러 StudyAttempt가 생길 수 있다.

### 두 층에서 같은 필드명을 반복하지 않는다

LearningTarget과 PracticeUnit에 모두 `target`이라는 필드를 두면 어느 층의 목표인지 혼동하기 쉽다.

실험용 최소 구조에서는 다음 이름을 사용한다.

```json
{
  "learningTarget": "요구가 제안과 비준 조문으로 이어지는 대응 관계",
  "evidenceNodeIds": ["..."],
  "practiceUnits": [
    {
      "task": "종교·표현 권리의 세 단계 대응을 복원한다.",
      "operation": "reconstruct",
      "successCriterion": "요구·제안·비준 내용을 정확히 연결한다."
    }
  ]
}
```

`operation`과 `successCriterion`은 LearningTarget이 아니라 PracticeUnit에 둔다. 같은 학습 목표도 서로 다른 행동으로 연습할 수 있기 때문이다.

## 15. 기존 Chunk와의 역할 구분

새 구조를 도입할 때 세 층은 각각 다음 한 문장으로 구분되어야 한다.

```text
Chunk
PDF에서 함께 읽어야 의미가 유지되는 출처 내용 묶음

LearningTarget
그 출처 묶음에서 학습자가 의미적으로 가져가야 할 목표

PracticeUnit
그 목표를 실제 한 문항에서 연습할 범위
```

세 문장을 명확히 구분할 수 없는 결과라면 불필요한 계층이 만들어진 것이므로 구조를 다시 줄인다.

## 16. 첫 구현 범위

논리적 판단은 두 층으로 분리하지만 API 호출을 바로 두 번으로 늘리지는 않는다.

첫 실험에서는 하나의 Plan 또는 Prepare 호출이 다음을 함께 반환하게 한다.

```text
Chunk
→ LearningTarget
→ PracticeUnit[]
```

이 실험의 질문은 다음 하나다.

> 역할을 명시적으로 분리하면 큰 관계를 보존하면서 실제 연습 단위만 안정적으로 줄일 수 있는가?

한 호출에서도 판단이 계속 흔들릴 때만 LearningTarget 추출과 PracticeUnit 생성을 별도 AI 호출로 분리할 근거가 생긴다.

## 17. 기존 제품 계약과의 최소 연결

현재 `LearningUnit`은 Activity Design과 문제 생성이 직접 소비하는 단위다. 실제 역할은 새 구조의 PracticeUnit에 가깝다.

따라서 초기 실험에서 기존 계약 전체를 바로 교체하지 않는다.

```text
새 실험 결과
LearningTarget + PracticeUnit[]

현재 문제 생성 입력
PracticeUnit을 기존 LearningUnit 형태로 펼쳐서 전달
```

이 방식이면 새로운 구조의 효과를 확인하기 전에 저장소·학습 화면·문제 생성 계약 전체를 변경하지 않아도 된다.

실험이 통과한 뒤에만 `learningTargetId`처럼 부모 목표와의 연결을 기존 LearningUnit에 보존할지 결정한다.

## 18. 다음 실험의 핵심 가설

```text
LearningTarget은 의미적 완결성을 기준으로 만든다.

PracticeUnit은 한 문항에서 독립적으로 성공·실패를
판정할 수 있는 수행 범위를 기준으로 만든다.
```

다음 실험은 최소한 아래 결과를 보여야 한다.

### 권리장전

- 요구 → 제안 → 비준의 전체 관계는 하나의 LearningTarget으로 보존한다.
- 개별 PracticeUnit은 특정 권리 또는 한 번에 대응 가능한 권리 묶음만 요구한다.
- 한 PracticeUnit에서 9~12개 조항을 한꺼번에 재현하게 하지 않는다.

### OPIc

- 7개 문장 기능을 연결한 답변 구성을 하나의 LearningTarget으로 유지한다.
- 전체 답변 작성이 한 번의 자연스러운 수행이면 PracticeUnit도 하나로 유지한다.
- 개수를 늘리기 위해 Pattern 1~7을 기계적으로 분할하지 않는다.

### DFS/BFS

- DFS의 동작 원리와 구현 방법을 의미적으로 연결된 LearningTarget으로 보존할 수 있다.
- 탐색 흐름 복원, 새 그래프 방문 순서 계산, 코드 구현은 독립 PracticeUnit으로 나눈다.
- 각 PracticeUnit에 맞는 operation을 따로 부여한다.

### 미적분

- 이미 한 문제로 연습 가능한 LearningTarget은 PracticeUnit 하나와 `1 → 1`로 유지한다.
- 단위 분리를 도입했다는 이유로 정상적인 풀이 목표를 불필요하게 세분화하지 않는다.

### 반복 안정성

- 같은 자료를 반복 실행했을 때 LearningTarget의 의미 범위가 크게 바뀌지 않는다.
- PracticeUnit 수와 operation이 이전 실험보다 안정적이어야 한다.
- 동일 실패가 두 번 발생하면 실험을 중단하고 구조를 다시 검토한다.
