# 지식 저장소 동작 정의와 점검 (2026-10-30)

지식 저장소가 **어떻게 동작해야 하는지**를 "이렇게 하면 → 이렇게 된다"로 정하고, 각각이 **실제로 그렇게 되는지** 확인한 기록이다.

확인 방법(근거 칸):
- **API**: 실제 서버(같은 코드, 빈 데이터 폴더)에 HTTP로 요청해서 확인. 10/30 새벽에 돌렸고, 모델 호출은 하지 않았다.
- **기록**: 실제 앱을 쓰면서 쌓인 데이터(`tmp/review-test-data`, 지식 159개, 같은 지식 판정 247쌍)에서 확인.
- **테스트**: 자동 테스트. 지식·글 지도·일정 테스트 37개가 모두 통과한다.
- **앱 대기**: 앱 서버가 꺼져 있어서 화면에서는 아직 다시 보지 못했다. 서버가 켜지면 확인한다.

## 2. 기록과 상태: 무슨 일이 있었나 → 지금 어떤가

상태는 4가지다. **만남**(본 적만 있음), **몰랐음**, **앎**, **졸업**(앎 + 복습 끝).

| # | 이렇게 하면 | 이렇게 된다 | 결과 | 근거 |
|---|---|---|---|---|
| D8 | 메모, 설명 보기, 만남 | 기록만 남고 상태와 복습 날짜는 그대로다 | ✓ | API |
| D5 | 물어봄·틀림·힌트 | **몰랐음**이 된다. 졸업이 풀리고, 맞힌 날이 초기화되고, 상자 0으로 **내일** 다시 나온다 | ✓ (24.0시간) | API |
| D6 | 맞힘 | **앎**이 되고 상자가 한 칸 오른다. 간격은 10분 → 1일 → 3일 → 7일 → 16일 → 35일 | ✓ (1칸 24시간, 2칸 72시간) | API |
| D7 | 서로 다른 **3일**에 맞힌다(중간에 틀리지 않고) | **졸업**하고 복습에서 빠진다. 같은 날 여러 번 맞혀도 하루로 센다 | ✓ (같은 날 2번 = 1일) / 3일 졸업은 테스트 | API, 테스트 |
| D7 | 몰랐음인 지식을 손으로 졸업시킨다 | 되지 않는다 | ✓ | API |
| D9 | 6시간 안에 "내 답도 맞아요"를 누른다 | 마지막 틀림 기록과 바뀐 복습 날짜가 되돌아가고, 연습 중이면 맞힘이 된다 | ✓ | 테스트 |
| D10 | 복습 목록을 연다 | 만남과 졸업은 빠진다. 날짜가 된 것만, **몰랐음 먼저** 나온다 | ✓ | API, 테스트 |

## 점검하면서 고친 것

- **개념어 목록에 핵심 이름이 또 뜨던 것.**
  - 증상: 「상장지수 펀드」에서 "차익거래", "레버리지 ETF"가 핵심으로 저장됐는데, 개념어 목록에도 "새 개념어"로 또 떴다.
  - 정의와 어긋난 점: 개념어는 누르기 전에는 저장되지 않아야 하는데, 이 둘은 이미 저장된 것처럼 보였다.
  - 고친 것: 핵심과 이름이 같은 개념어는 목록에서 뺀다(`article-map.ts`). 테스트에 이 경우를 더했다.

## 정의와 다르게 남아 있는 것 (예전 데이터)

- **10/28 이전의 웹 글에서 생긴 자유 문구 고리 18개.** "계산에 사용", "주식 수로 나누면", "고려해야 하므로" 같은 문구다. 글 지도 이전의 추출 방식이 만든 것이다. 지금의 경로는 이런 고리를 만들지 않는다. 자동 고리는 포함·씀·조건·먼저와 PDF의 냄·입력으로 씀뿐이다. 데이터를 정리할지는 따로 정한다.
- **「해시」의 쉽게 풀어 보기는 예전 칸 형식이다**(요약·왜·비유 …). 화면은 이것을 문단으로 보여 준다. 다시 누르면 새 형식으로 바뀐다.

## 아직 화면에서 다시 볼 것 (앱 서버가 켜지면)

1. 긴 글 하나로 글 지도를 만든다. 핵심만 저장되는지, 개념어 목록에 핵심 이름이 없는지 본다.
2. 개념어 하나를 "모름"으로 고르고 다시 푼다. 상태가 몰랐음이 되는지, 풀어도 지식이 남는지 본다.
3. 새로 들어온 지식에 4초 뒤 주제·종류, 같은 지식 판정, 층 나누기가 붙는지 본다.
4. "쉽게 풀어 보기"를 두 번 연다. 두 번째에 AI를 다시 부르지 않는지 본다.
5. 드래그해서 묻기(D18).

점검용으로 만든 지식은 확인이 끝나면 지운다.
