# 핵심 문제단위 로직의 실제 앱 연결 점검

- 점검일: 2026-08-17
- 목표: 단독 실험에서 확인한 `문제 하나 크기의 학습단위 → 단위마다 문제 하나` 품질을 실제 `Plan → Prepare → Activity Design → Cards` 경로에서 재현
- 중단 기준: 같은 품질 실패가 수정 후 다시 발생하면 추가 API 실험 중단

## 이번에 확인한 개선

1. 구형 학습단위에 `operation`이 없을 때 무조건 recall로 덮어쓰던 동작을 제거했다.
2. 최신 Plan의 최종 목차를 실제 앱처럼 선택하여 Prepare에 전달하도록 평가 경로를 맞췄다.
3. Plan의 기본 선택 최종 목차 수가 안전선보다 많으면 안전선을 선택 수까지 올려 서로 모순되지 않게 했다.
4. Activity Design이 하나의 LearningUnit 성공 기준을 여러 문제 기준으로 다시 불리지 못하도록 단일 기준으로 제한했다.
5. 적용·판별 설계는 `새 사례` 같은 빈 설명이 아니라 카드에 바로 쓸 수 있는 구체 입력 하나를 만들도록 했다.
6. 숫자 답이나 텍스트 격자라는 이유만으로 전용 입력 기능이 필요하다고 판단하지 않도록 지원 경계를 명확히 했다.

## 반복 실패 이후의 구조적 해결

DFS/BFS의 `연결 영역 수 계산`, `격자 최단거리 계산`이 규칙 암기로 후퇴하는 문제는 프롬프트 수정만으로 해결되지 않았다. 이후 다음 두 가지 고정 사실을 서버 규칙으로 옮겼다.

1. 텍스트 격자와 숫자 답은 전용 입력창이 없어도 플래시카드 앞면에서 먼저 계산하고 뒷면과 비교하는 자기확인 적용 문제로 지원할 수 있다.
2. 숫자 문제는 Activity Design에서 구체 입력과 실제 숫자 정답을 함께 확정해야 하며, 정답 숫자가 없으면 Cards로 넘기지 않는다.

최종 DFS/BFS 결과에서 연결 영역은 새 4×5 격자의 정답 `3`, 최단거리는 새 4×5 격자의 정답 `7`로 생성됐고 두 값을 직접 재검산했다.

재난 체크리스트에서는 순서 없는 최상위 구조 항목이 여러 시작점으로 표현되어 두 번 차단됐다. 학습 화면과 채점기는 이미 같은 `parentId=null` 항목들을 순서 없는 묶음으로 처리할 수 있었으므로, 검증만 실제 기능에 맞춰 여러 최상위 항목을 허용했다. 부모 순환과 존재하지 않는 부모는 계속 차단한다.

## 현재 판단

- `한 문제 크기의 LearningUnit → 한 설계도 → 한 문제` 연결 자체는 실제 앱에서 작동한다.
- 범위가 통째로 사라지는 문제와 복수 설계 문제는 크게 줄었다.
- OPIc와 데드락에서는 단독 핵심 로직과 비슷하거나 더 구체적인 결과가 확인됐다.
- `Apply` 단위의 지원 여부는 AI 표현만 따르지 않고 현재 화면에서 텍스트 입력과 자기확인이 가능한지 서버가 재계산한다.
- 음성 제출, 코드 실행·자동채점, 실제 그림 위 표시는 계속 미지원으로 남는다.
