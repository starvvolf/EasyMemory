## 3. 할 일 순서 (제안 — 사용자와 먼저 정한다)

1. **점검 (읽기만, 호출 없음)**: 엔진 갈래·단계·기능마다 무엇을 하는지, 공부 화면에서 실제로 쓰이는지, 1장의 방향(A1~A4, 유니브 기준, 지식 연결, 만들면서 읽기)과 맞는지 표로 정리한다. 쓰이지 않는 코드, 기본값 불일치 같은 것도 적는다.
2. **실측 (호출 씀)**: 테스트 데이터 폴더에 PDF 1~2개(작게, `삽질방지_노트.md` 3장 방법)를 넣고 기본 엔진으로 만들어 본다. A1~A4가 지금 어느 정도인지 확인한다.
3. 1·2 결과를 "밀어줌 / 보류 / 잘 모르겠음" 표로 사용자에게 보여 준다. 각 줄에 근거(파일·실측)를 붙인다.
4. 사용자가 고른 것만 고친다. 보류는 지우지 않고 실험실 선택지에서 숨기는 정도로(지우는 건 따로 묻는다).
