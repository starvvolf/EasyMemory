## 1. 지금 상태 (10/26~27 기준, `docs/CURRENT_STATUS.md` "지식창고·복습")

- 파일: `src/lib/knowledge/store.ts`(548줄, 저장·찾기·기록·복습), `questions.ts`(AI 없이 만드는 복습 문제), `sources.ts`, `src/lib/assist/knowledge-ai.ts`(AI 쪽), 화면 `workspace/KnowledgeWindow.tsx`, `KnowledgeSidebar.tsx`, API `src/app/api/knowledge/[[...path]]/route.ts`.
- 지식 상태: 만남·몰랐음·앎 + 졸업. 폴더·고리(링크)·합치기.
- 기록(이벤트): 만남·물어봄·틀림·힌트 받음·맞힘·메모. 지식마다 언제 무엇을 했는지 남는다(`readEvents`, `memoryEvents`).
- 복습: 상자(라이트너) 방식 10분·1·3·7·16·35일(`REVIEW_BOXES`). 틀림·힌트·물어봄은 첫 상자로, 다음 날 다시. 날짜가 된 것만 복습에 나온다(`reviewQueue({dueOnly})`).
- AI 없이 만드는 복습 문제: 플래시카드(늘), 객관식(같은 폴더·같은 자료 지식 2개 이상), OX, 빈칸(고리 있을 때). 다른 과목 지식은 보기로 섞지 않는다. 엔진 표기 ⟨받음/냄⟩은 뺀다.
- 들어오는 곳:
  - PDF 연습 결과(맞힘→앎, 틀림→몰랐음, 정답 보고 풂→힌트). "읽은 직후 확인"은 틀림만 남긴다. "내 답도 맞아요"는 되돌린다(`takeBackWrong`). 4쪽 PDF로 직접 확인함.
  - PDF 지식 포인트는 "만남"으로, 폴더는 `자료 이름 / 구역`(`importPoints`, `recordByRef`).
  - 코드 문제: 문제를 열면 확인하는 지식을 만들고(`saveMany`), 풀이 기록은 "이번 풀이"에 모았다가 맞았을 때·문제를 나갈 때·2시간 뒤에 합친다(`src/lib/code/service.ts`).
  - 웹 글: 지식 잡기(용어·주장·고리).
- 결정 근거: `협업/기획결정_20261026_Claude.md`의 "지식" 절, `docs/DECISIONS.md` 10/26 항목들.

## 2. 알려진 문제

- 서로 다른 3일 맞히면 졸업(`GRADUATE_DAYS = 3`)이라 7일 이상 상자까지 거의 안 간다. 졸업 규칙과 상자 단계를 맞출지 **사용자 결정 전**(제안만 했음).
- 예전 데이터(RecallerData의 지식 319개)는 품질이 나빴지만, 사용자가 10/28에 "원래 데이터 필요 없다"고 했다. 지금은 테스트 데이터 폴더를 쓴다. 예전 데이터 정리는 하지 않아도 된다. 다만 **새로 쌓이는 데이터**에 같은 문제(오답 보기가 지식으로 들어감, 본문 `undefined`, 같은 개념 중복)가 생기지 않는지는 확인한다.
- 같은 지식 판단이 글자 비교뿐이다(`similarity`). 뜻이 같고 말이 다르면 못 합친다(웹 글 쪽 D1 임베딩 과제와 연결).
- 예전 카드(덱)는 따로 FSRS로 돈다(지식 복습과 별개).
- 성취도·약점 통합 화면(C3), 잔디(C2)는 없다. 이벤트 기록은 이미 있어서 화면만 만들면 된다.

## 2.5 같은 지식 찾기 — 임베딩 (10/28 사용자와 정함)

- 지금은 이름 글자 비교뿐이라(88% 이상) 띄어쓰기 차이만 잡는다. "이진/이분 탐색", "Binary Search", "DFS"는 따로 생기고, 기준을 낮추면 "깊이/너비 우선 탐색"이 합쳐진다.
- 실측 결과와 방향: `협업/결과보고/결과보고_임베딩비교_Claude_20261028.md`. 요약:
  - 모델은 **EmbeddingGemma**(308M, 다국어 하나로 한·영 같이). 점수 하나로 같음/다름을 가를 수는 없고, 후보 찾기용(5위 안 84%, 10위 안 91%).
  - 흐름: 이름·별칭 정확 비교 → 임베딩으로 후보 5~10개 → AI가 같음/포함/관련/다름 판정. 포함·관련은 고리로 잇는다.
  - 처음엔 자동 합치기 없이 "비슷한 지식" 후보만 보여 준다.
  - 저장할 때 영어 이름·약어를 별칭으로 붙인다.
- 앱에서 돌리는 방법은 정해야 한다: 앱 서버(Node)에서 `@huggingface/transformers` + onnxruntime으로 돌릴지, 화면(브라우저)에서 돌릴지. 패키지 추가는 사용자 확인 후. 모델 파일(8비트 약 300MB)은 처음 한 번 내려받고, 지식마다 벡터를 저장해 둔다(1,000개 × 768차원 ≈ 3MB, 벡터 DB 불필요). 필요할 때만 모델을 불러온다.
