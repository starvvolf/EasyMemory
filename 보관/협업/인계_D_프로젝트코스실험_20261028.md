## 1. 무엇을 실험하나 (근거 문서)

- 고민 정리(사용자·Claude 대화): `협업/설계와논의/고민정리_공부범위확장_20261028.md`
- GPT 평가(받아들일 방향의 기준): `협업/설계와논의/GPT평가_공부범위확장_20261028.md`. 인용된 연구와 숫자는 아직 원문 확인 전이니, 근거로 쓰기 전에 확인한다.

한 문장 목표:
> AI와 함께 소프트웨어를 만들되, 그 과정에서 배운 원리를 직접 검증하고 다른 문제에도 적용할 수 있도록 훈련한다. 결과물은 프로젝트가 아니라 머리에 남는 것이다.

받아들인 원칙 (GPT 평가 + 사용자):
1. **부품 ≠ 지식.** 단위는 프로젝트 → 기능(단계) → 부품(하나의 책임) → 지식(인출·재사용할 원리) → 코드 위치. 부품 하나에 지식 여러 개, 원리 하나가 여러 부품에 걸칠 수 있다.
2. **이해와 구현을 나눈다.** 이해(설명·예측), 적용(새 상황에서 수정·구현), 검증(틀린 걸 찾고 증명)을 따로 본다. AI가 대부분 짜도 되지만 핵심 몇 줄은 학습자가 직접 한다.
3. **검사 통과 ≠ 학습 성취.** 지식 기록은 학습자가 직접 한 활동에서만 나온다(AI가 다 짜서 통과하면 "앎"이 아니다. 원인을 정확히 예측했으면 실패해도 이해의 증거다).
4. **전이로 확인한다.** 코스 끝에 구조가 다른 과제 하나(예: 게시판에서 배운 권한 검사를 메모 API에 적용)를 둔다.
5. **판정은 코드, 해석은 AI.** 테스트 기대값은 사람이 준비하고 코드가 검사한다. AI는 결과 해석과 힌트만 한다. 버그도 AI가 즉석에서 심지 않고 준비된 버그 버전을 쓴다.
6. 대상은 문법은 알지만 혼자 만들어 본 경험이 부족한 초급~초중급.

## 2. 첫 코스 (제안 — 사용자와 먼저 확정)

**게시판 API, Node.js + TypeScript + SQLite, 편집기는 VS Code** (GPT 제안). 6단계:
1. 서버와 HTTP 요청 (라우팅, 상태 코드)
2. 게시물 CRUD·DB (데이터 모델, 영속성)
3. 입력 검증 (잘못된 입력, 중복)
4. 회원가입과 로그인 (비밀번호 해시, 세션)
5. 작성자 권한 검사 (인증과 인가, 401 vs 403)
6. 버그 수정·요구 변경 (디버깅, 회귀 테스트) + 전이 과제(메모 API)

화면은 미리 준비한 간단한 클라이언트로 충분하다(이번 대상은 백엔드).

한 단계의 활동 흐름(5단계 예):
1. 결과 예측: "B가 A의 글을 수정하면 몇이 와야 하나?"
2. 없애 보기: 소유권 검사를 뺀 버전에서 실제로 요청 → 200이 와서 뚫리는 걸 관찰
3. VS Code에서 원인 찾고 고치기: 검사 결과의 "파일:줄"
4. 재검사: 403 + 글 내용이 안 바뀌었는지(DB 상태까지)
5. 지식 기록 후보: 인증과 인가의 차이, 자원 소유권 검사, HTTP 403

## 3. 만들 것 (실험 범위)

모두 **`experiments/project-course/`** 안에. 혼자 돌아가는 Node 스크립트와 파일로 만든다.

1. **코스 데이터**(JSON/MD): 단계, 완료 조건, 활동(예측 문제·없애 보기·수정 과제), 부품·지식·코드 위치 연결
2. **템플릿 프로젝트**: 단계별 시작 상태와 준비된 버그 버전(패치 파일 등)
3. **작업 폴더 만들기**: 템플릿에서 실습 폴더를 만들고, VS Code로 연다(`code 폴더`)
4. **서버 실행·종료**: 실습 폴더의 서버를 켜고 로그를 모음. 포트는 **4100번대**(3000·3001·3002는 앱이 씀). 끝나면 프로세스를 꼭 정리한다.
5. **자동 검사기**: 실제 HTTP 요청 + 테스트용 SQLite 상태 확인. 정상·경계·오류 경우와 이전 단계 회귀 검사. 결과는 "기대 vs 실제 + 파일:줄 후보".
6. **학습 기록 후보**: 활동 결과를 "이런 지식 기록이 나올 것"(지식 이름, 만남/틀림/맞힘/힌트, 근거 활동)으로 **파일에만** 남긴다. 실제 지식 저장소에는 쓰지 않는다(최종에 붙일 때 `src/lib/knowledge/api.ts`로 연결).
7. (가능하면) AI 힌트: 검사 결과 + 관련 코드로 3단계 힌트. 이미 있는 코드 탭 힌트 방식을 참고한다(`src/lib/assist/code-ai.ts`의 `hint`).

완료 기준(실험 성공으로 볼 것): 사용자가 실제로 1~5단계 중 2개 이상을 처음부터 끝까지 해 보고 — 작업 폴더 생성 → VS Code → 서버 → 예측 → 없애 보기 → 수정 → 재검사 통과 → 기록 후보 파일 — "이렇게 공부하면 남겠다"고 판단할 수 있는 수준.
