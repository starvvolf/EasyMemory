# 개인화 V1 웹앱 연결 기록

## 해결하려는 문제

문제를 푼 뒤 무엇을 다시 봐야 하는지 사용자가 기억에만 의존하지 않도록, 실제 제출·정답 공개·자기평가 기록을 학습내용과 문서 버전에 연결한다. 사용자가 요청할 때 복습 후보와 판단 근거를 보여준다.

## 실행 및 소유 범위

통합 checkout `C:/Users/Public/Documents/ESTsoft/CreatorTemp/recaller-integration`에서 `node scripts/run-local-experiment.mjs`로 로컬 실험 모드를 실행하고 `http://127.0.0.1:3000/mcp-personalization`에 접속한다. 로컬 모드는 기본 OFF이며 loopback 전용이다. 일반 Firebase 인증 경로는 유지된다.

개인화 담당 소유 파일은 `src/app/mcp-personalization/**`, `src/app/api/personalization-lab/**`, `src/lib/personalization-lab/**`다. 내비게이션과 기존 출제 렌더러의 이벤트 전송은 화면 담당 소유 파일을 사용하며 개인화 담당이 수정하지 않았다. 원본 PDF 조회 API와 로컬 실험 권한 helper는 하네스 담당 소유다. 구형 독립 `tools/personalization-lab/**`은 보존하되 웹앱 기록 저장소와 연결하지 않는다.

## 데이터 경계

기본 선택 문서는 새 MCP 원천 실행에서 이어진 기하 9문항 `integrated-geometry-sol-20260928-r02/iteration-1`(문서 SHA `d788b7c9517d3171f3be4e593f3a883d4bbf93439dc967aa27e5c7f8abb22d98`)이다. 반도체 5문항 `integrated-semiconductor-sol-20260928-r01/iteration-1`(SHA `8811075330042100831d719c315d8298ed9f6340c632a9562a687a7b802fe6ca`)도 선택 가능하다. 두 문서는 실제 authoring-lab 산출물을 그대로 읽고 SHA를 고정 검증한다. 출제용 패킷은 원천 MCP run과 Cards 입력 SHA를 기록하지만 MCP `cards` 단계 결과 자체로 표시하지 않는다. 기존 기하 4/8문항도 비교용으로 보존한다. 문서 SHA-256, authoring run/버전, 원천 MCP run, 문제 ID, 학습내용 ID, 원본 파일/범위를 기록한다. 다른 run이나 SHA에서 ID 문자열이 같아도 복습 근거를 합치지 않는다.

기하 r02는 기존 r01 iteration-1의 SHA를 부모로 기록한 **새 authoring run**이다. p6의 정규화 좌표와 `h≠0` 이유를 각각 채점할 수 있도록 9문항으로 개정했다. r01의 `iteration-2`로 표시하지 않는다. 기하 p7 원천 개념 메타데이터는 범위가 넓어 이 화면은 해당 문항 제출을 연결된 모든 개념의 습득으로 환산하지 않는다.

기존 렌더러 HTML을 `sandbox="allow-scripts"` iframe에 넣고, 출제 렌더러의 `select`/`input`/`submit`/`reveal` 최소 이벤트만 받는다. 부모는 iframe source, 임의 채널, run ID, 문서 SHA, 질문/응답 ID를 확인한다. 이벤트 payload와 로컬 저장값에는 정답 문자열, 원문 전체, 사용자 인증정보를 넣지 않는다. 저장소는 전용 `localStorage` 키로 분리돼 브라우저·로그인 주체별이며 서버 동기화하지 않는다. 정정은 원판정을 보존한 별도 correction 필드로, 제외는 별도 flag로 표시한다. 정답 공개 후 자기평가는 사용자 보고로 남되 독립 회상 성공으로 계산하지 않는다. 새 시도로 다시 풀기는 iframe과 시도 ID를 새로 만든다.

마지막 선택 자료와 각 문서 SHA별 시도 ID·마지막 문항을 따로 보존한다. 다시 열면 같은 자료와 다음 미제출 문항이 표시되고 `이어하기`가 렌더러의 해당 문제로 이동한다. 자료 왕복 전환과 새로고침은 시도 ID를 바꾸지 않아 이전 정답 공개 이력이 독립 풀이 판정에 계속 적용된다. 공개 이력은 추천 제외 대상으로 제공하지 않으며 이전 기록에 제외 표시가 있어도 독립성 판정에 남긴다. 문서 SHA가 달라지면 이전 진행 위치를 새 문서에 적용하지 않는다. 답안 문자열은 복원하지 않는다.

새 완료 요청의 출제 문서는 별도로 목록에 자동 발견한다. 완료된 `cards` 요청의 run/source와 검증된 run.json SHA·Cards 입력 SHA가 출제 패킷의 원천 정보와 일치해야 한다. 두 허용 PDF 파일명·페이지 범위, 안전한 runs 루트 내부 경로, `record_problem_iteration` 실행 기록, 문서 계약검사를 통과한 최신 iteration만 받는다. 클라이언트가 보낸 파일 경로는 읽지 않는다. 현재 고정 네 문서의 ID와 SHA는 유지한다.

원문 근거 버튼은 허용된 PDF route에서 원본 파일을 받아 해당 페이지를 기존 PDF.js 라이브러리로 그린다. sourceText는 발췌 텍스트로만 표기하며 실제 원문 페이지를 대신하지 않는다.

학습 화면에서는 자료명·문항수·출제 페이지와 문항별 번호·주제·판정·시간을 먼저 보여준다. MCP 실행 ID, 출제 run, 문서·패킷 SHA와 사건별 UUID는 기본 접힌 `생성 기록 상세`/`기록 출처 상세`에서 확인한다. 브라우저에서 두 상세를 열어 출처를 확인하고 닫았으며, 답 제출과 정답 공개 후 자기평가 판정이 접힌 상태에서도 읽히는 것을 확인했다.

- 최종 서버 콜드 재기동(PID 93408→187176, 같은 `127.0.0.1:3000`) 뒤 동일 브라우저로 다시 접속해 방금 만든 기하 새 시도도 확인했다. 기하 9문항은 마지막 위치 2번·다음 3번, 기록 8건이며 새 2번 원점 중심 회전 정답 제출/입력 사건이 그대로 보였다. 고정 반도체 5문항 선택 시에도 별도의 위치 2번·다음 3번, 기록 8건과 2번의 `정답 공개 후` 판정이 유지됐다. 다시 기하로 돌아온 뒤 위치 2번·다음 3번을 확인했다. 이 재검수에서는 제출·초기화·코드수정을 하지 않았다.
- 규칙 테스트 7개, 전용 파일 린트·TypeScript 검사, 통합본 전체 린트·프로덕션 빌드가 통과했다. 전체 린트는 개인화 영역 외 `eval/local/.../build-authoring.mjs`의 미사용 변수 경고 1개, 빌드는 개인화 영역 외 `codex-app-server.ts`의 동적 경로 경고 1개가 남아 있다.

이 확인에서 남긴 사건은 담당자의 **테스트 기록**이며 실제 사용자의 학습 기록이 아니다. 한 차례 인앱 브라우저 탭이 중단됐으나 서버는 HTTP 200을 유지했고 새 탭에서 새 시도와 원문 페이지를 확인했다.

## 현재 한계와 롤백

새 기하 9문항의 출제 범위는 32쪽 PDF 중 2~7쪽이고, 새 반도체 5문항의 범위는 44쪽 PDF 중 16~20쪽이다. 전체 자료를 출제·평가했다고 표시하지 않는다. 추천은 FSRS나 AI 평가가 아닌 결정적 로컬 규칙이며 학습 효과를 입증하지 않는다.

초기 완료 웹 요청 두 개는 `analyze`에서 종료됐다. 이후 별도 신규 `cards` 완료 요청과 이에 대응하는 authoring 기록 1건으로 자동 발견의 실제 등록을 브라우저에서 확인했다. 새 반도체 문서의 범위는 44쪽 중 16~18쪽이며, 16·17쪽 단답 제출은 자동 정답 판정 근거가 아니다.

롤백은 개인화 소유 route/API/규칙 파일과 화면 담당의 `/mcp-personalization` 진입 링크만 제거하면 된다. 기존 덱·학습기록·공유 저장소의 이전이나 수정은 없다. 실험 기록은 해당 브라우저의 전용 키에만 남으며 화면의 초기화 버튼으로 지울 수 있다.
