# 자료에서 복습까지: 완료 기준

사용자 목표: 학습목표를 확인하고, 범위별 체크리스트를 보며, 실제 PDF 학습 사이클을 이어갈 수 있게 한다.

기하변환 32쪽과 반도체 44쪽은 테스트 입력이다. 파일명·쪽수·주제에 맞춘 제품 예외처리로 성공시키지 않는다. 전체 범위를 검토하되 모든 페이지를 같은 수의 문제로 만들지는 않는다.

## 확인할 흐름

| 단계 | 완료를 증명할 실제 동작 | 현재 판정 |
| --- | --- | --- |
| 자료 등록 | 웹에서 PDF를 등록하고 원본·실제 쪽수·파일 식별값이 보존됨 | 두 PDF 실제 웹 등록 성공, 저장 metadata 확인 |
| 자료 구분 | 같은 내용은 중복 구분, 같은 이름의 다른 내용은 별도 자료로 보존 | 미검증 |
| 분석 | MCP가 전체 범위의 목차를 만들고 웹에서 읽기 쉽게 확인 | 기존 분석 있음, 일반 등록 경로 미검증 |
| 학습목표 | 실제 MCP 학습설계 결과의 목표·성공기준·원문 범위 표시 | 전범위 미검증 |
| 범위 확인 | 목차별 학습목표 연결과 제외 이유를 확인, 누락을 완료로 표시하지 않음 | 미검증 |
| 문제 생성 | 목표와 연결된 문제를 실제 MCP 출제 도구로 생성·저장·자동 발견 | 일반 등록/전범위 미검증 |
| 학습 | 답을 보기 전 풀이, 정답 확인, 필요시 자기평가 가능 | 기존 대표 문서에서 확인, 새 경로 미검증 |
| 체크리스트 | 문제 없음·미풀이·복습 필요·자기확인·부분/최근 독립 성공을 구별 | 구현 및 단위검증 완료, 새 전체 실행 연결 미검증 |
| 복습 | 어려웠던 문제를 다시 풀며 이전 시도도 보존 | 새 경로 미검증 |
| 이어하기 | 새로고침·자료 전환·서버 재시작 후 목표/문제/기록/현재 위치 유지 | 기존 대표 문서에서 확인, 새 경로 미검증 |

## 연결 원칙

- 원본 파일의 SHA-256, MCP 실행 ID와 단계 결과 해시, 출제 문서 버전/해시로 연결한다.
- 같은 목표 ID라도 다른 실행/다른 설계의 기록을 자동 합치지 않는다.
- 체크리스트는 저장된 학습설계와 실제 문항 연결에서 계산한다. 별도 수작업 목표로 대체하지 않는다.
- 여러 지식단위를 가진 목표에서 문항 하나의 성공을 전체 목표의 숙달로 처리하지 않는다.
- 정답을 본 뒤의 성공과 독립 풀이 성공을 구분한다.
- 기존 실험 결과와 풀이 기록은 삭제하거나 새 데이터로 덮어쓰지 않는다.
- 실행은 기획팀장 대화 지시 → MCP 테스트담당 실행 → 웹 결과 확인 방식이다.

## 검증 기록

구현 테스트는 구조와 저장 규칙의 근거이며 학습 품질 자체의 증거가 아니다. 최종 검증에는 두 PDF의 실제 MCP 실행, 범위 대비 목표/문항 연결표, 사용자 화면 학습·복습·재시작 확인을 남긴다. 고쳐야 할 경우 자료 전용 규칙보다 같은 실패를 해결하는 제품 규칙을 수정한다.

## 담당 경계

- 하네스: 자료 등록/원본 보존, 실행 요청과 MCP 원본 연결. 공용 registry 단독 소유.
- 화면 담당: `mcp-runs/page.tsx`의 자료 등록/선택 화면.
- 개인화: 학습목표 체크리스트, 기존 문항별 기록의 파생 상태와 학습 화면 연결.
- MCP 테스트담당: 실제 생성 실행과 제품 흐름 검증.
- 기획팀장: 요구사항 유지, 연결 검수, 완료 증거 확인.

현재 상태: 권한 설정 후 재검증 중. 일반 자료 등록·목표 체크리스트 연결을 구현했으나 두 PDF 전체 생성·학습·복습·재시작 검증은 미완료다. 기존 대표범위 MVP 완료를 이번 전체 학습 사이클 완료로 간주하지 않는다.

### 구현 중 확인한 증거

- `objective-checklist.test.ts` 11개 통과: 미출제 목표 표시, 실행/문서 버전별 기록 격리, 정답 열람 구분, 복수 단위의 부분 근거, 별도 세션 복습 후 상태 회복, 저장 입력 재현.
- 전체 `tsc --noEmit` 통과(2026-09-28, 통합 중간 상태). 화면 동작 또는 생성 품질 완료 증거는 아니다.
- `npm run build` 통과. 기존 `codex-app-server.ts`의 동적 파일 추적 경고 1건은 남음.
- 실제 `/mcp-personalization`에서 기존 LD 목표/성공기준/원문쪽 및 전체 목차 41개를 표시함. 구형 실행의 PDF 계보 미확인 안내도 확인. 처음 선택된 반도체 목표와 기하 문제 문서가 달라지는 오류를 발견해 선택 동기화 수정 중.
- 위 선택 혼합 오류 수정 후 실제 화면 검수: 반도체 205f 실행을 선택하면 연결 문제 없음, 문제 iframe 0개. 새로고침 후 같은 실행 선택과 빈 문제 상태 유지. 같은 실행 문서만 선택되며 이전 실험은 별도 경로로 보존한다.
- 저장·요청·체크리스트 통합 검증 18개 통과. 이는 임시 테스트 저장소의 규칙 검증이며 실제 두 PDF의 웹 업로드 검증을 대체하지 않는다.
- 실제 `/mcp-runs` 화면에서 PDF 등록 UI와 전체 44쪽 기본 선택 확인. 파일명 비교 대신 등록 응답 ID로 선택하도록 수정.
- 실제 PDF의 Chrome 파일 선택은 `Not allowed`로 거절됨. 확장 프로그램의 파일 URL 접근 설정을 사용자에게 안내했으며 다른 업로드 경로로 우회하지 않음. 일반 등록 경로의 실자료 검증은 미완료.
- MCP 테스트담당의 이전 분석 보고 전달은 자동 승인 검토가 차단. 사용자에게 작업 간 결과 공유 승인을 요청했으며 미응답 상태. 해당 보고를 다른 경로로 취득하지 않음.

### 재개 순서

권한 후속 확인: 사용자가 파일 URL 접근을 켰다고 알린 뒤 Chrome 재연결, 기하 PDF filechooser 선택 성공 및 실제 웹 POST 실행을 확인했다. 앱에서 `PDF 내용을 읽을 수 없습니다.` 오류가 반환되어 하네스 담당에게 서버 PDF 로딩 원인 수정을 맡겼다. 브라우저 권한 문제는 해소됐다. MCP 테스트담당의 보고도 승인 후 전달받았다.

1. 완료: Chrome 파일 선택 권한 확인 후 두 PDF 실제 웹 등록 성공. 등록 source ID는 각 원본 SHA 앞에 `src_`를 붙인 값이며 실제 쪽수는 32/44로 저장됨.
2. 완료: 테스트담당 → 기획팀장 결과 공유 승인 및 보고 수신.
3. 일반 등록 경로의 원본 SHA/쪽수/중복 구분을 검증하고, 실제 MCP 실행으로 전체 범위의 학습설계와 문제를 생성한다. 검증된 동일 원문의 기존 분석은 재사용할 수 있다.
4. 목표·전체 목차·문항 연결을 검토하고 실제 풀이/복습/새로고침/서버 재시작으로 기록 보존을 확인한다. 그 증거가 모이기 전 목표를 완료 처리하지 않는다.

### 등록 후 연결 검증

- Next 서버 환경에서 PDF 읽기가 실패하던 문제를 하네스 담당이 수정한 뒤, root가 Chrome에서 두 PDF 등록 완료 메시지와 자동 자료 선택을 확인했다. `.study-forge-data/mcp-sources`의 두 metadata도 확인했다.
- 새 등록 자료의 기존 Analyze 재사용 후보가 화면에 표시되지 않는 결함이 발견됐다. 하네스 담당은 실제 원본 동일성 검증을 거친 재사용 후보 계약을, 화면 담당은 해당 후보의 선택 UI를 담당한다. 새 실행의 문항 coverage와 과거 분석 재사용 후보는 구별한다.
- MCP 테스트담당에게 전체 범위의 Concept Tree 및 Learning Design까지 실행을 위임했다. 위 UI 연결 수정 완료 후 진행한다. 생성은 MCP로 수행하며 localhost 제품 요청/claim/progress/finish API 사용은 허용된다. 금지 대상은 외부 유료 모델 API 생성이다.

### 전체 범위 실제 실행

- 재사용 후보 연결 수정 후 root가 웹에서 동일 원본의 과거 Analyze 선택지를 확인했다. 타입 검증도 통과했다.
- 기하 요청 `req_1b2e516cefe500fcdd7811c29584cb92` → 실행 `chatgpt-request-1d661c9570204ca0b12e5e7412f7e0f1`.
- 반도체 요청 `req_e0e2adc1345e1dabeb49736bc60973d4` → 실행 `chatgpt-request-dbfe69de29916e9bbda0f76088bbbd39`.
- 두 요청 모두 등록 source, 전체 페이지 범위, Learning Design 종료 조건으로 저장됐으며, 실제 요청 파일에서 `running`과 Analyze 단계 완료를 확인했다. 후속 학습설계·문제·학습 검증 완료를 뜻하지 않는다.
- 테스트담당이 원본 렌더를 확인한 결과 반도체 p2는 빈 페이지가 아니라 학습목표가 들어간 이미지 슬라이드다. 추출 텍스트가 없다는 이유만으로 학습 범위에서 제외하지 않는다.

### 첫 학습설계 검수 및 개선 실행

- r01은 기하 18개, 반도체 20개 학습목표까지 실제 완료됐다. 웹 학습 화면에서 두 실행 선택지가 보이며 등록 원본/실행/LD 해시 일치 안내, 목표·성공기준·원문 연결, 문제 없음 상태를 확인했다.
- 검수에서 기하의 x/y/z 목표에 z만 확인하는 기준, 독립 능력의 과도한 묶음, 반도체 원문에 없는 공정 역할 요구를 확인했다. 보고: `eval/local/full-study-20260928/EXECUTION_REPORT.md`.
- MCP 공통 지시를 목표·내용·기준의 범위 일치, 독립 능력 분리, 원문으로 학습 가능한 기준이라는 세 원칙으로 보완했다. PDF별 조건이나 정답을 넣지 않았다. root가 관련 MCP 계약검사 11개 통과를 확인했다.
- r02 기하 요청 `req_bc49d772e1edca0076a8b7f7d90b68f3` → `chatgpt-request-edffcc5c6125fdf2f9ca5fc7d8191c90`.
- r02 반도체 요청 `req_7d4982548eb8ff8f7fe37957570707ec` → `chatgpt-request-ecdf7a398e99e1e6279633a5d5d11ae4`.
- 두 r02 요청은 실제 Analyze 재사용 완료 및 running 상태를 확인했다. 새 Concept/LD부터 Cards, 출제 편집틀, 개인화 화면 발견까지 이어서 실행하도록 승인했다. r01 원본은 보존하며 아직 r02 학습·복습 완료로 판정하지 않는다.
