# 로컬 MCP 시험학습 MVP — 통합 진행판

상태: **대화 지시형 로컬 대표범위 MVP 완료(검증 범위와 한계는 아래 명시)**. 이 문서는 이번 통합 작업의 한 곳짜리 상태 기록이다. 기존 덱·학습기록 및 원본 PDF는 변경하지 않는다.

## 다시 여는 방법

통합 폴더의 **`Study Forge 로컬 열기.cmd`를 더블클릭**하면 된다. 이미 켜진 로컬 서버가 있으면 재사용하고, 없으면 시작한 뒤 `http://127.0.0.1:3000/mcp-runs`를 연다. 실제 사용자 환경에서 동일 `.cmd` 실행과 브라우저 열림을 확인했다. 물리적 마우스 더블클릭 자체를 자동화한 시험은 아니며, 로컬 실험 데이터는 같은 컴퓨터·같은 브라우저·같은 `127.0.0.1:3000` 주소에서 이어진다.

## 사용자가 경험할 흐름

**이번 MVP 운영 결정:** 사용자가 이 대화에서 자료·범위·목적과 생성 지시를 내린다 → MCP 테스트 담당이 실제 AI·MCP 5단계를 실행한다 → 사용자가 웹에서 목차·단계 결과·문제를 확인하고 학습한다 → 기록을 바탕으로 이어하기·복습한다. 웹 요청 저장 화면은 입력·상태를 보관할 수 있지만 **버튼만 눌러 무인 AI 실행을 시작하는 기능은 이번 MVP에 넣지 않는다.** 별도 Codex CLI 로그인도 요구하지 않는다. 이는 사용자의 명시적 운영 방식 변경이며, 생성·풀이·기록 등 나머지 목표를 축소한 뜻은 아니다.

사용자는 로컬 앱에서 PDF 두 자료의 전체 목차와 미처리 범위를 확인하고, 대화에서 학습목적·범위를 확정한다. 실행 담당이 만든 **실제 MCP** 분석/개념·목표/문제 설계·출제의 중간 입력·출력을 웹에서 확인한 뒤 문제를 풀고, 정답·해설·원문을 보며, 별도 실험 기록을 저장한다. 같은 브라우저에서는 새로고침·서버 재시작 뒤 이어하고 요청 시 기록 기반 복습을 한다.

기본 학습 목적은 **제공 자료에서 오래 기억할 핵심을 익히기**다. 시험 범위/출제경향은 모르므로 지어내지 않는다. 사용자가 지엽적 내용이나 원문 표현을 요구하면 그 지시를 범위·목표에 반영한다. 전체 PDF를 살펴볼 수 있게 하되 첫 문제 생성은 선택된 작은 묶음으로 한다. 전체 대상, 생성 완료 범위와 아직 만들지 않은 범위를 반드시 구별해 표시한다.

## 의존 순서와 범위

1. **기록 보기**: 저장된 실제 MCP 5단계 `Analyze → Concept Tree → Learning Design → Activity Design → Cards`와 별도 authoring-lab 4/8문항을 출처가 다른 자료로 읽는다. 사용자 지시와 AI 판단, 원문 목차→목표→문항 연결을 보여준다. 32쪽 목표 초안 문서는 **실제 MCP 제출 결과가 아니다**.
2. **로컬 실험 권한**: 기본 OFF 서버 설정 및 127.0.0.1 loopback에서만 Firebase 없는 실험 화면/API 사용. 클라우드 기본 인증 유지. 임의 클라이언트 헤더/쿼리로 우회 불가, 쓰기 요청의 동일 출처 검사, 허용된 자료 경로/분리된 실험 저장소 사용.
3. **실행제어**: 실제 MCP 도구의 입력 수신·제출·검증·보존·도구 기록과 **현재 호스트 AI**를 연결. 웹앱은 실행 요청·상태·결과/학습 화면을 담당한다. 단계별 모델/강도·종료단계·이전 결과 재사용은 실제 호스트 실행 근거가 있을 때만 완료. 재사용은 새 run·출처 run/stage/hash로 보존하고 입력만 재사용했는지 결과 자체를 재사용했는지 표시. 유료 API·별도 Codex App Server 로그인 폴백 없음. 선택 범위의 최하위 목차마다 기본 1문제를 만들고, 핵심을 한 문제로 평가하기 어려운 경우에만 2문제 이상으로 늘린다. 목차 ID와 문제 ID를 연결해 0문제·복수문제의 이유를 확인한다.
4. **풀이/개인화**: 기존 렌더러의 문제를 안전한 iframe에서 사용하고 최소 이벤트만 로컬 실험 기록으로 연결. 같은 문제를 다른 문서/버전의 결과와 혼동하지 않도록 run/artifact/question/learning ID를 기록. 기록 기반 복습은 새 AI 생성 없이 시작한다.
5. **두 자료 실사용 검증**: 전체 PDF를 등록·열람/목차선택 가능하게 하되 두 자료 각각 대표 범위의 실제 MCP 분석·목표·문제 생성과 학습/복구를 끝까지 확인. 미생성 범위를 명시한다. 자료의 그림/수식과 원문 근거를 직접 대조한다.

### 완료 증거 — 운영 검토에서 확인할 세 연결

1. 자료별 `전체 → 선택 → 문제 생성 → 실제 풀이 → 복습 확인` 범위를 **같은 표기**로 앱과 최종 보고에 기록한다. 미생성 목차는 `아직 문제 없음`으로 표시한다. 대표 범위 통과를 전체 시험공부 완료라고 부르지 않는다.
2. 같은 checkout·브라우저의 실제 문항 한 개에 대해 `run ID → artifact SHA → learning/question ID → renderer 제출·공개 이벤트 → 실험 저장값 → 새로고침/서버 재시작 뒤 복습`을 추적한 기록을 이 문서에 연결한다. 신규 반도체 웹 요청→최종 3문항→18쪽 오답·원문 열람→새로고침 뒤 복원까지 [개인화 연결 기록](../experiments/personalization/V1_WEB_INTEGRATION.md)에 남았다. 재시작 후 같은 `127.0.0.1:3000` 브라우저 저장소에서 목록·마지막 자료/문항·기록·복습 후보를 확인했다. 시도 ID 문자열은 화면에 표시되지 않아 직접 대조하지 않았고, 다른 origin/기기 동기화는 시험하지 않았다.
3. 기하와 반도체 각각 하나의 선택 범위에서 `사용자 입력 → 실제 MCP 도구 호출 기록 → 5단계 산출물 → 별도 authoring 문항 → 브라우저 풀이·저장`의 같은 계보를 추적한다. 기존 기하·반도체 5단계와 별도 최종 9/5문항은 확보했다. **추가 신규 반도체 16~18쪽 요청은 같은 웹 요청→5단계→authoring 3문항→브라우저 풀이·저장·새로고침까지 연결**됐다. 기하의 같은 계보 전체와 서버 재시작까지 모두 검증됐다고 일반화하지 않는다.

## 현재 막힘·미결정

- 이 checkout에는 Firebase 필수 설정이 없고, 일반 개발 서버의 127.0.0.1:3000 실제 브라우저에서 AuthGate 누락 오류가 재현되었다. 기본 인증은 유지한다. **로컬모드 진입 막힘은 해소**: 통합 루트의 로컬 실험 서버에서 `/api/local-experiment/status` `active:true` 및 `/api/mcp-runs` 목록·상세 HTTP 200을 확인했다. 신규 반도체 요청의 실제 실행→풀이와 같은 origin의 서버 재시작 뒤 학습기록 복원도 확인했다. **웹 무인 자동 실행은 별도 미완료**다.
- 기존 MCP 서버는 stage 결과 보존은 하지만 단계별 모델/강도 설정·중간 종료·결과 재사용·모델 자동실행을 자체 제공하지 않는다. 실행제어는 별도 최소 연결이 필요하다. 화면의 버튼만으로 완료 처리하지 않는다.
- **실행주체 정정**: 과거 Codex App Server 경로의 `Not logged in`은 이번 MCP/현재 호스트 AI 실험의 선행 로그인 조건이 아니다. 웹앱이 별도 Codex App Server에 로그인하도록 요구하는 방향은 철회했다. 현재 호스트 AI가 두 PDF의 실제 MCP 5단계를 호출·저장한 증거는 확보했다. 웹 요청을 **활성화된 실행 담당**이 claim→MCP Analyze 제출→같은 요청 완료로 연결한 왕복도 확인했다. 첫 웹 요청은 이전 목차 텍스트를 reuse 지정 없이 재제출한 실패였고, 사용자 재승인 후 두 번째 웹 요청에서 원본 32쪽을 새로 확인한 Analyze가 검증됐다. 담당 작업이 끝난 뒤 다음 웹 요청을 누가 자동으로 받아 실행하는지는 입증되지 않았다. MCP 서버만으로 모델 실행·모델 선택이 자동으로 되는 것은 아니다.
- **웹 무인 실행은 사용자 결정으로 이번 MVP에서 제외**: 웹 POST는 durable queue(재시작 뒤에도 남는 대기 요청)를 저장하고 상태를 표시하지만, 요청을 자동 `claim`해 모델을 호출하는 상주 소비자는 없다. 이번에는 사용자가 **대화에서 지시**하고 MCP 테스트 담당이 실제 실행한다. MCP 서버는 도구를 노출할 뿐 스스로 모델 턴을 시작하지 않는다([공식 MCP 서버 설명](https://developers.openai.com/plugins/build/mcp-server)). 웹 단독 실행을 완료라고 표시하지 않되, 이번 합격 기준의 결손으로도 세지 않는다.
- **독립 실행 CLI 조사는 보류된 대안**: 설치된 Codex CLI 0.101.0에는 비대화식 실행·모델/강도·MCP 기능이 있지만, 조사 당시 `codex login status`는 `Not logged in`이었다. 인증파일·키 미열람, 모델호출 없음. [OpenAI Docs의 비대화식 실행 설명](https://learn.chatgpt.com/docs/non-interactive-mode)과 [인증 설명](https://learn.chatgpt.com/docs/auth)은 CLI 실행과 별도 인증을 설명한다. 사용자가 대화 지시 방식을 택했으므로 **추가 CLI 로그인·자동 소비자·유료 API 폴백은 진행하지 않는다.**
- 기존 기하 변환 MCP run은 2~7쪽 선택 leaf 8개에서 6문항을 만들었다. 별도 authoring-lab에서는 같은 8개 leaf마다 직접 묻는 질문 1개씩 8문항을 만들고 검사했으나, **앱의 새 실제 MCP run과 동일한 계보는 아니다**. 전체 32쪽/44쪽 생성 완료로 간주하지 않는다.
- 사용자 확인에 따라 현재 호스트 AI/MCP 환경에서 두 PDF의 **선택 범위 내용을 모델이 읽고 처리**하는 것은 승인 범위다. 기존 두 자료 5단계 실행, 웹 요청의 새 Analyze·명시적 Analyze 재사용→Concept Tree, 신규 반도체 5단계→출제 3문항이 기록됐다. 첫 웹 요청의 **재사용 지정 없는 기존 텍스트 재제출은 실패**로 남기고, 뒤의 명시적 출력 재사용 성공과 혼동하지 않는다. 금지는 별도 외부 서비스 업로드나 유료 API 폴백이다. **웹 요청 저장만으로 새 모델 분석이나 무인 실행이 보장되지는 않는다.**

## 진행 증거 (완료 판정 전)

- 로컬전용 기동 스크립트에서 `/api/local-experiment/status` `active:true`; MCP 실행 목록·상세 API HTTP 200. 일반 Firebase 모드의 로그인 경로는 삭제하지 않았다.
- 모델·추론 강도 경계: 실행 담당 보고에 따르면 Luna의 `ultra` 요청은 API에서 거절되고 화면의 선택 상한도 조정했다. 요청 거절·화면 경계 검사 4/4, 관련 브라우저 확인 및 빌드 통과. 이는 **모델 선택 검증**이지 새 PDF 생성이나 웹 요청 자동 실행 성공 증거가 아니다.
