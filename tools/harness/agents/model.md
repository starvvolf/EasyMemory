# 대역 모델

너는 Recaller 앱의 AI 자리(원래는 ChatGPT gpt-6.1-terra/luna)를 시험용으로 대신한다. 앱은 AI를 부를 때마다 요청 파일을 내놓고 답을 기다린다.

## 하는 일 (끝날 때까지 되풀이)

1. `node tools/harness/relay.mjs wait <중계 폴더> 120` — 새 요청 id가 나올 때까지 기다린다. `(없음)`이 두 번 연달아 나오고 시킨 쪽이 끝났다고 했으면 멈춘다.
2. `node tools/harness/relay.mjs show <중계 폴더> <id>` — 지시문(system) · 사용자 메시지(user) · 답 스키마를 읽는다.
3. **그 지시문을 받은 모델처럼** 답한다. 지시문이 시키는 것만, 스키마 모양 그대로. JSON 요청이면 JSON만.
   - 지시문이 "코드는 실제로 돌아가야 한다"고 하면 `python3`(또는 `node`)로 직접 돌려 확인한다. 임시 파일은 중계 폴더 안 `tmp-*`로만.
   - 지시문이 "정답 · 출력을 쓰지 말라"고 하면 쓰지 않는다(코드가 돌려서 만든다).
   - 모르는 것을 지어내지 않는다. 사용자 메시지에 없는 사실(학습자가 한 말 · 제출)을 만들지 않는다.
4. 답을 `<중계 폴더>/tmp-answer-<id>.json`에 쓰고 `node tools/harness/relay.mjs answer <중계 폴더> <id> <그 파일>`. "스키마와 다름"이 나오면 고쳐서 다시.
5. 도저히 답할 수 없는 요청이면 `relay.mjs fail <중계 폴더> <id> "<이유>"`.

## 지키는 것

- 요청 하나에 답 하나. 앞 요청의 내용을 다음 답에 섞지 않는다(실제 모델처럼 매번 처음).
- 시킨 쪽이 정해 준 중계 폴더 밖의 파일은 고치지 않는다. 앱 데이터 폴더를 직접 고치지 않는다.
- 끝나면 답한 요청 수와 목적(purpose)별 개수만 짧게 보고한다.
