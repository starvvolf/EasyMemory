## 결론

## Claude가 판단할 것 / 비교 실행 전에 결정할 것

1. **현재는 비교용 최소 지원 범위다.** 선택형(4보기)·단답·자기확인으로 먼저 구조를 비교할지 결정한다. 원본 그림 영역을 문제에 직접 넣는 기능, OX·빈칸·구조복원, 기출형 경향 연결은 이번 구현에 없다. 그림 자체 없이는 못 푸는 문제는 만들지 않도록 지시한다. 기출 입력은 명시적으로 중단한다.
2. **동일 모델로 구조 효과부터 비교하는 안을 권한다.** astra는 엔진 이름이며 모델 이름을 강제하지 않는다. 네 단계 기본 모델은 Sol·medium이고 실험실에서 바꿀 수 있다.
3. **한 연습 묶음의 초기 문항 수 한도는 1~3, 호출당 묶음은 최대 16이다.** 설계의 범위값을 실행 가능한 값으로 정한 운영 한도다. 학습 단위를 낱말로 쪼개라는 규칙이 아니다. 실제 결과에서 이 한도가 범위를 왜곡하는지 확인해야 한다.
4. **가짜 검수는 AI 검출 능력의 증거가 아니다.** 경고가 왔을 때 문항을 실제로 보류하는지는 확인했다. AI가 원문에서 조건 누락·정답 노출·이유 누락을 얼마나 잘 찾는지는 다음 실제 비교에서 판단한다.
5. **전체 PDF 반복 입력의 비용은 아직 모른다.** 파일 전달은 구현됐지만, 호출 감소를 토큰 절감이라고 주장하지 않는다. 실제 비교 전 동일 자료·범위·목적과 품질/비용 채택 조건을 고정해야 한다.

## 자세한 내용

### 1. 구현 단계와 입출력

| 단계 | 입력 | 저장되는 출력 |
|---|---|---|
| `astra-plan` 전체 학습 계획 | 전체 PDF, 선택 쪽, 목적, 메모, 사용자 신호 | 원문 단원, 개념·조건·근거, 연습 묶음, 필수/추가, 문항 배분, 불확실 위치 |
| 목표 확인 | 계획을 문항별 목표 자리로 연결한 결과 | v2와 같은 `awaiting-confirm` / `confirmedObjectiveIds`. 자동 확인도 기존 필수/전체 선택 기준 사용 |
| `astra-author` 묶음 출제 | 전체 PDF, 전체 계획, 이번 최대 16목표, 앞서 물은 내용의 짧은 목록 | 문항 본문·답·설명·필수 채점 요소·실제 평가 범위·문항별 근거 |
| `astra-solve` 정답 없는 풀이 | 전체 PDF, 학생에게 보이는 본문·보기·응답 형식 | 독립 답, 부족한 조건, 노출된 관계, 불확실 여부, 근거. 정답·해설·계획의 recall은 전달하지 않음 |
| `astra-review` 전역 검수 | 전체 PDF, 계획, 문항·정답, 독립 풀이, 코드 검사 결과 | 문항별 공개/수정/보류, 연습별 범위 충족, 계획 밖 누락 |
| 한 번의 수정·보충 | 수정 대상·누락 범위와 이전 결과 | 최대 16문항 재출제 → 재풀이 → 전역 재검수. 해결되지 않으면 보류 |
| 기존 문서로 공개 | 최종 검수와 계약 검사를 만족한 문항 | `layoutQuestion → inspectQuestion → sectionDocument`, `problem-authoring-v1` |

수동 선택에서는 미계획 목표를 자동으로 추가하지 않는다. 선택한 과제의 부족한 부분은 수정할 수 있으나 새 범위는 누락 표시로 남긴다. 자동 확인에서는 선택된 단원 안의 미계획 범위를 한 번의 보충 한도에 포함할 수 있다.

### 2. 기존 구조와 맞춘 방법

- `engines`에 astra만 추가했다. 입력 기본값 v2, 공부용 화면, v3 구현은 변경하지 않았다.
- 모든 astra 모델 요청은 runner의 `askParsed → ask → callModel`을 사용한다. `calls/*.json`, 호출 번호·시간·사용량·응답 형식, 로그인/사용량 한도 중단은 같은 코드다.
- PDF는 모든 단계의 `ModelRequest.files`로 넘긴다. 파일 해시를 저장해 재개 중 원본 교체를 감지한다. 원본 부재·50MiB 이상이면 중단하며 글자만으로 바꾸지 않는다. ChatGPT와 가짜 공급자만 허용한다.
- `section.classify.items`에는 지도 개념을 옮겨 두어 고정 재실행의 기존 선행 조건을 충족한다. 새 분류 모델 호출은 없다.
- `section.design.objectives`에는 문항별 목표를 둔다. 연습/개념과의 연결은 `Objective.astra` 및 `GenState.astra`에 남는다. 최종 문항의 실제 질문·답·근거·채점 요소로 목표를 맞춰 판정단이 이전 계획의 답을 정답으로 오인하지 않게 한다.
- `설계부터 다시`는 목차·개념 지도를 코드에서 고정하고 practice만 다시 계획한다. `출제만 다시`는 계획과 목표를 유지하고 묶음·풀이·검수를 새로 만든다. 모델 선택도 astra 단계 키로 전달한다.
- 판정단과 정리 화면이 읽는 기존 문서 형식은 유지한다. 이 연결은 타입·코드로 확인했으며, astra 실제 결과에 판정단을 호출하거나 정리 화면을 브라우저로 조작한 것은 아니다.
- 전역 검수 전에는 단원 문서를 게시하지 않는다. 중간 결과는 상태 파일에 저장해 재개한다. 보류 수와 범위 미충족을 완료 메시지에 구분해 표시한다.

### 3. 공용 코드 변경의 이유

- `types.ts`: 엔진/단계 이름, 기본 모델, astra 선택 필드. 기존 필수 계약을 바꾸지 않는다.
- `runner.ts`: astra 전용 분기, 공용 호출 어댑터, 가짜 공급자 연결, 고정 재실행의 상태 복사와 모델 키 추가. v2/v3 실행 분기는 그대로다.
- `layout.ts`: astra가 명시적으로 요청할 때만 문자열 겹침·복합 단답 추정 오류를 경고로 낮춘다. 계약 오류는 유지하고 의미 판단은 독립 풀이/검수로 보낸다. 옵션 기본값은 꺼져 있어 v2/v3 검사가 바뀌지 않는다.
- `GenLab.tsx`: 엔진 선택과 네 단계 설정, 계획·검수·수정·보류 요약. astra가 쓰지 않는 기존 출제기준 폴더 설정은 숨긴다.
- 의존성 추가, 공부 화면 수정, 기존 기준 문서 수정은 없다. Claude v3 설계 문서와 `v3.ts`는 설계 참고로 읽지 않았다.

### 4. 실제 결함에 연결한 새 시험 하나

파일: `src/lib/study/gen/astra.test.ts`.

관찰 근거는 그래픽스03 `q-s6-o5`의 **알아낼 대응 관계를 질문이 먼저 제공하는 결함**이다. 공개 시험에는 사적 문항을 복사하지 않고 가상의 색–상태 대응을 사용했다.

가짜 풀이가 노출 경고를 내고 첫 검수가 수정을 요청한다. 수정에도 같은 결함이 남지만 두 번째 검수가 근거 없이 ready를 주도록 구성했다. 엔진이 이 상충 상태를 그대로 게시하지 않고 해당 문항을 보류하며 정상 문항만 문서에 남기는지 확인했다. 정답 없는 풀이 입력에 답·계획·정답 보기 인덱스가 전달되지 않는 것도 같은 흐름 안에서 확인했다.

이것은 가짜 응답으로 모델 품질을 통과시킨 시험이 아니라 **경고 미해소 문항의 공개 차단을 검증한 시험**이다. 의미적 결함을 모델이 스스로 찾아내는 성능은 미검증이다. 새 테스트 파일/시험은 이것 하나뿐이며, 연구용 상시 스크립트는 추가하지 않았다.

### 5. 검증 과정에서 확인·수정한 문제

- 첫 새 시험은 합성 근거의 인용이 비어 있어 정상 문항도 기존 출처 계약에서 거부됐다. 텍스트 근거에는 실제 인용이 있어야 하도록 확인하고 합성 원문도 맞췄다. 그림/수식처럼 인용이 없는 근거는 출처에 `인용 아님, 모델 설명`을 표시한다. 요약을 원문 인용으로 위장하지 않는다.
- 계획의 동일 recall을 여러 문항이 그대로 물려받지 않도록 최종 문항별 질문·정답·채점 요소를 연결했다.
- 독립 풀이/검수/범위 연결의 누락·중복, 경고에 대한 해소 설명 누락은 보류한다. 검수 모델의 반박 설명 자체가 타당한지는 여전히 실제 모델 품질 검증 대상이다.
- 수동 목표 선택 뒤 자동 보충으로 선택 범위를 확대하지 않게 구분했다.
- 최초 타입 검사에서 빌드 정보 파일 쓰기 권한 문제가 있어 `--incremental false`로 검사했다. 최종 타입 검사 종료 코드는 0이다.
- 최초 기본 빌드는 작업 폴더의 공유 의존성 junction을 Turbopack이 거부했다. 대체 Webpack 빌드도 기존 PDF worker ESM import 5곳에서 실패했다. 이 파일들은 변경하지 않았다.
- 직접 만든 junction만 대상 경로를 확인해 제거한 뒤, 기존 잠금 파일 그대로 `npm ci --ignore-scripts --no-audit --no-fund`로 독립 설치했다. **최종 기본 Turbopack 빌드는 성공했다.** package.json·잠금 파일·빌드 설정 변경은 없다. 원래 연구 폴더의 의존성은 삭제하지 않았다.
- 남은 빌드 경고 11개는 PDF worker 외부 모듈 처리 및 guide/v3/codex-app-server의 동적 경로 추적이다. 이 작업에서는 해당 코드나 기존 기준을 고치지 않았다.

### 6. 실행 및 아직 확인하지 않은 것

이 브랜치를 사용하는 로컬 앱의 `/lab/gen`에서 `astra (GPT 안, 실험)`을 선택하면 된다. 기존 3000 서버에는 이 브랜치를 반영하거나 서버를 다시 띄우지 않았다.

가짜 모델은 전체 흐름을 무료로 확인한다. 실제 모델로 실행하면 전체 PDF가 계획·출제·풀이·검수에 반복 전송된다. 실제 생성, 실제 사용량 중단 후 재개, astra 고정 재실행의 모델 실측, 브라우저 화면 조작, 유니브 및 v2/v3와의 블라인드 비교는 이번에 하지 않았다. 새 가짜 시험 외에 같은 확인을 반복하는 테스트는 만들지 않았다.

공개 산출물에는 실제 PDF·기출·문항 원문·계정 정보를 넣지 않았다. 비공개 연구 자료와 사용자 기록은 변경하지 않았다.

### 7. 2026-10-19 후속: 원본 반복 입력의 캐싱 조정

- PDF를 처음 한 번만 읽는 방식으로 전환하지 않았다. 계획 → 출제 → 독립 풀이 → 전역 검수의 핵심 흐름은 유지한다.
- astra 요청만 공통 지시·공통 응답 스키마·같은 PDF를 고정하고, PDF 뒤 고정 텍스트에 명시적 캐시 경계를 둔다. 단계별 지시와 데이터는 그 뒤에 전달한다. 캐시 유지 설정은 30분이다.
- 네 단계는 동일한 `result` 응답 틀을 공유하지만 해당 단계 결과만 반환한다. 기존 단계별 검증과 독립 풀이의 정답 비공개는 유지한다.
- 응답에 제공된 `cached_tokens`·`cache_write_tokens`를 호출 기록의 `cachedInputTokens`·`cacheWriteTokens`로 남긴다. 미제공은 0으로 만들지 않는다.
- 계정 경로에서 캐싱 기능이 거부되면 명확히 중단한다. 몰래 캐싱을 끄고 재호출하거나 다른 엔진의 출력 형식 설정을 바꾸지 않는다. 명확한 출력 스키마 거부에 대한 기존 JSON fallback은 유지한다.
- 공용 변경은 선택적 요청 필드·사용량 필드와 provider의 opt-in 분기뿐이다. v2/v3 요청 구성과 공부 화면은 변경하지 않았다.
