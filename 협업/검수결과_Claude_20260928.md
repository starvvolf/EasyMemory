# Recaller 검수 결과 (Claude, 2026-09-28)

`먼저읽기.md`의 요청에 따라 코드는 수정하지 않았다. 판단 근거는 세 가지다. 실제로 실행 중인 로컬 서버(127.0.0.1:3100, `projectRoot`가 이 복사본임을 `/api/local-experiment/status`로 확인), 미리보기 HTML을 헤드리스 브라우저로 직접 풀어 본 결과, 그리고 코드·원문 텍스트(`*-page-text.json`)·문제 문서(`r02-*-authoring-document.json`)의 대조다.

## 요약

- 문제 내용 자체는 대체로 원문에 충실하다. 50문제 정답을 원문과 대조했을 때 사실 오류는 발견하지 못했다.
- 그러나 **풀기 전에 보이는 "근거:" 줄이 대부분의 문제에서 사실상 정답을 알려준다.** 여기에 객관식 정답이 거의 항상 가장 긴 보기라는 단서까지 겹친다. 그 결과 "독립 성공" 기록이 부풀려진다. 기록 규칙은 공개 후 제출을 잘 걸러내지만, 공개 전에 새는 정답은 막지 못한다.
- 주관식 채점(`exact-normalized`)이 지나치게 엄격하다. 맞는 답을 자연스럽게 입력해도 오답 처리되는 경우가 흔하고, 그 오답이 복습 기록에 그대로 남는다.
- 이 복사본에서는 앱 화면 두 곳 모두 데이터를 표시하지 못한다. 대부분 복사본의 한계지만, 원인 중 일부는 실제 코드 구조(하드코딩된 ID 목록, 하나만 실패해도 전체가 실패하는 구조)에 있다.

## A. 사용을 막는 오류

### A1. `/mcp-personalization`이 전부 실패함 (API 500)
- **사용자가 겪을 문제**: 학습목표 체크리스트, 문제, 복습 화면이 "출제 산출물을 읽을 수 없습니다"만 표시하고 아무것도 쓸 수 없다.
- **근거**:
  - `GET /api/personalization-lab` → `500 {"message":"출제 산출물을 읽을 수 없습니다."}` (실제 호출 결과).
  - `src/lib/personalization-lab/artifacts.ts`의 `listArtifacts()`는 하드코딩된 `allowed` 4개 문서와 발견된 문서를 `Promise.all(... loadDescriptor ...)`로 불러온다. 이 중 하나라도 파일이 없으면 `throw`하므로 목록 전체가 실패한다.
  - 복사본의 `tools/problem-authoring-lab/runs/`에는 `integrated-*-full-20260928-r02/source-packet.json` 두 개만 있다. `allowed`가 가리키는 폴더는 하나도 없다.
- **원인 단계**: 저장·조회(개인화 산출물 로더).
- **복사본 한계인가**: 파일이 없는 것은 복사본의 한계다. 하지만 **하나가 없으면 전부 못 보는 구조**는 제품 결함이다. 원본에서도 옛 실험 폴더를 정리하는 순간 같은 증상이 난다.
- **최소 수정안**: `listArtifacts`에서 항목별로 `try/catch`(또는 `Promise.allSettled`)를 쓰고, 실패한 항목은 "읽을 수 없음"으로 표시하며 건너뛴다.

### A2. `/mcp-runs`에 최신 실행 기록이 나타나지 않음
- **사용자가 겪을 문제**: 실행 기록 탐색이 "열람할 실행 기록이 없습니다"로 나온다. 쪽 표시도 "실제 실행 기록이 연결된 쪽 0쪽"이다.
- **근거**:
  - `GET /api/mcp-runs` → `{"runs":[]}`. 그런데 `.study-forge-data/mcp/chatgpt-runs/`에는 `run.json` 6개가 있고, 최신 `edffcc5c…`와 `ecdf7a39…`도 여기에 포함된다.
  - `src/lib/mcp-run-view.ts`의 `roots()`에서 `local-data` 루트의 `ids`는 `[]`이다. 목록은 ① 하드코딩된 `allowedMcpRunId` 및 `newMcpRunIds`(`789ee870…`, `6229f153…`)와 ② 완료된 실험 요청 저장소로만 만들어진다. ②는 복사본에서 제외돼 있다.
- **원인 단계**: 저장·조회(실행 목록).
- **최소 수정안**: 등록된 원본 SHA와 `run.json`의 `config.files[].sha256`이 일치하는 실행은 요청 저장소 없이도 "요청 기록 없음" 표시와 함께 목록에 올린다. ID 허용 목록은 테스트 고정값으로만 남긴다.

### A3. 원본 화면에 서로 모순되는 안내가 함께 보임
- **사용자가 겪을 문제**: 같은 화면에 "기존 완료 실행의 문제 범위는 2~7쪽"과 "실행 기록이 연결된 쪽 0쪽"이 동시에 표시된다.
- **근거**: `src/lib/mcp-source-catalog.ts` 138–140행의 `note`는 실제 기록과 무관한 고정 문자열이다.
- **최소 수정안**: `note`를 `runIds`와 `pages[].recordedRunId`에서 계산한다.

## B. 학습 품질 문제

### B1. 풀기 전 "근거:" 줄이 정답을 노출함 (가장 중요)
- **사용자가 겪을 문제**: 문제 아래 "근거:"를 읽으면 생각하지 않고도 답을 고를 수 있다. 그렇게 맞힌 답이 **독립 성공으로 기록된다**.
- **사례** (`interactiveHtml`에서 풀이 전에 보이는 문구와 정답):

  | 문제 | 풀기 전 "근거:" | 정답 |
  |---|---|---|
  | 기하 21 | z는 고정되고 xy 평면이 회전한다 | …, z′=z |
  | 기하 16 | 결합법칙은 성립하지만 일반적으로 교환법칙은 성립하지 않는다 | (AB)C=A(BC)이지만 보통 AB≠BA |
  | 기하 27 | 기준면에서 0인 변위가 기준면과의 거리에 비례해 늘어난다 | 기준면에서 0이고 떨어진 거리에 따라 증가 |
  | 반도체 7 | 부분 점유 띠·작은 밴드갭·큰 밴드갭이 각각 도체·반도체·부도체의… | 각각 도체·반도체·부도체 |
  | 반도체 13 | np는 ni²와 같다 | 10^5 cm^-3 (공식이 주어짐) |
  | 반도체 20 | …웨이퍼 제조·산화·포토·박막·식각·배선·불량 선별·패키징의 여덟 단계… | 같은 순서 그대로 |

  50문제 중 대략 35개 이상에서 근거 문구가 정답을 직접 말하거나 결정적인 힌트를 준다(전체 목록은 헤드리스 실행으로 추출해 확인함).
- **원인 단계**: Learning Design이 `source.sourceRange`에 **원문 위치가 아니라 지식 요약문**을 채운다. 여기에 렌더러가 이 값을 정답 공개 전에 "근거:"로 표시한다. 하네스(`SKILL.md` 12행)가 "정답 노출 여부"를 검사하라고 요구하지만 걸러지지 않았다. `r02/preview-inspection.json`은 레이아웃 넘침만 검사했다.
- **최소 수정안**:
  1. 렌더러는 공개 전에는 쪽 번호만 보여주고, `sourceRange`와 `knowledgeContent`는 공개 후에만 보여준다.
  2. `validate_problem_document`에 "정답 문자열 또는 핵심 토큰이 공개 전 텍스트에 나타나면 error"라는 규칙을 추가한다.

### B2. 객관식 정답이 거의 항상 가장 긴 보기
- **사용자가 겪을 문제**: 내용을 몰라도 가장 길고 조건이 붙은 보기를 고르면 맞는다. 인출 연습이 되지 않는다.
- **근거**:
  - 객관식 27개 중 **25개**에서 정답이 가장 긴 보기다. 정답 위치는 1~4번에 고르게 분산돼 있어서, 위치 단서는 해결됐지만 길이 단서는 남아 있다.
  - 오답 보기가 명백히 틀린 경우가 많다. 예: 반도체 16 "세 단자는 모두 같은 역할을 한다", 반도체 22 "NPU는 반도체 공정의 산화 단계 이름이다", 기하 26 "반드시 모든 길이가 두 배가 된다", 반도체 19 "두 재료의 이동도·밴드갭·안정성은 완전히 같다".
- **원인 단계**: Authoring. 하네스가 "그럴듯한 선택지"를 요구하지만 강제하는 장치가 없다.
- **최소 수정안**: 검증기에 "정답 길이가 오답 평균의 1.3배를 넘으면 warning" 규칙을 둔다. 오답은 흔한 오개념(부호 반전, 순서 반전, 조건 누락)에서 만들도록 하네스 예시를 추가한다. 기하 9·18·20번은 좋은 예로 쓸 수 있다.

### B3. 주관식 채점이 맞는 답을 오답 처리함
- **사용자가 겪을 문제**: 맞게 풀었는데 "오답"이 뜨고, 그 결과가 복습 필요(`needs-review`)로 기록된다.
- **근거** (미리보기에서 직접 입력해 본 결과, `normalize`는 NFKC·대시 통일·공백 제거·소문자화만 한다):

  | 문제 | 입력 | 결과 |
  |---|---|---|
  | 기하 7 | `-sinθ, sinθ` | 오답 (`+sinθ`만 인정) |
  | 기하 11 | `75` / `75도` | 오답 (`75°`만 인정) |
  | 기하 13 | `T(q)·R(θ)·T(-q)` | 오답 |
  | 기하 15 | `R^-1(θ)SR(θ)` (**PDF 13쪽 표기 그대로**) | 오답 |
  | 기하 21 | `x'=…` (키보드 작은따옴표) | 오답 (`′` 프라임 기호만 인정) |
  | 기하 24 | `이동→정렬→회전→역정렬→역이동` | 오답 (문장 전체 일치 필요) |
  | 기하 5 | `(x,y,1), h≠0` | 오답 (세미콜론만 인정) |
  | 기하 6 | `tx ty` | 오답 |

  반도체 4(`σ=1/ρ; σ는 S/m, ρ는 Ω·m`)와 반도체 20(8단계 순서 문장)도 사실상 정확히 일치시킬 수 없는 답이다.
- **원인 단계**: Authoring(자유 서술형 답에 `exact-normalized` 지정)과 채점 계약(정규화 범위).
- **최소 수정안**:
  1. 여러 요소를 답하는 문제는 빈칸을 요소별로 나누거나(예: 2단계씩), 순서·조합 문제는 순서 배열이나 객관식으로 바꾼다.
  2. 정규화에 `'`→`′`, `·`/`*` 제거, `°`/`도` 제거, `R^-1`↔`R(-θ)` 같은 표기 동치를 추가하거나, 문항별로 인정 답안을 여러 개 작성하게 한다.
  3. 긴 서술형은 `self-check`로 지정한다.

### B4. 같은 계산 문제 중복 (기하 1 ↔ 기하 10)
- **근거**: 기하 1 "(2,-1)에 변위 (-3,4)"와 기하 10 "변위 (2,-1)과 (-3,4)의 합성"은 숫자와 답 `(-1,3)`이 완전히 같다.
- **원인 단계**: Authoring(목표는 다르지만 수치를 재사용함).
- **최소 수정안**: 검증기에서 같은 문서 안에 정답과 입력 수치가 동일한 문제가 있으면 warning을 띄운다.

### B5. 원문 범위 요약 과정의 누락
- **기하 24–29쪽**: 임의축 회전의 유도 과정(단위벡터 u, x축 회전으로 u′=(0,b,c)를 xz평면에 넣기, y축 회전으로 u″=(a,0,d)를 z축에 맞추기)이 6쪽 분량인데, 단계 이름을 외우는 문제 1개(기하 24)로 축약됐다. 출처에는 "24~29쪽의 축 정렬 유도"라고 적혀 있지만 유도 과정은 묻지 않는다. 22쪽의 "좌표축에 평행한 축" 3단계도 따로 다루지 않았다.
- **기하 13·14·15**: 정답이 PDF 표기(`T⁻¹(xf,yf)`, `R⁻¹(45°)`)가 아니라 생성기가 새로 만든 표기(`T(q)`, `T(-f)`, `R(-θ)`)여서, 원문대로 공부한 학생이 불리하다(B3과 연결됨).
- **반도체**: 11쪽(한국은 메모리 IDM에 특화), 13쪽(메모리 시장 성장), 34쪽(초미세화 로드맵)을 제외했다. `EXECUTION_REPORT.md`에 수치와 전망을 의도적으로 제외했다는 설명이 있어 판단 자체는 타당하다. 다만 11쪽의 구조적 주장은 수치가 아니므로 재검토할 만하다.
- **최소 수정안**: 한 목표가 여러 쪽을 근거로 삼는데 문제는 그 일부만 묻는 경우, 연결표에 "부분 출제"로 표시한다(`LEARNING_CYCLE_ACCEPTANCE`의 "범위 대비 목표/문항 연결표" 항목과 같은 맥락).

### B6. 긍정적으로 확인된 부분
- `rule.ts`와 `objective-checklist.ts`: 같은 세션에서 정답 공개 후 제출한 답은 독립 성공에서 제외한다. 오답 후에는 **별도 세션 2회** 성공해야 회복으로 보고, 24시간이 지나면 다시 확인 대상으로 돌린다. 상태 이름도 "숙달"이 아니라 `recent-independent-success`다. "한 번의 정답을 숙달로 과장하지 않는다"는 요구를 코드가 잘 반영하고 있다.
- 50문제의 정답을 원문과 대조했을 때(회전 부호, 반사 좌표, np=ni² 계산, 8대 공정 순서, 페르미 에너지 정의 등) 사실 오류는 발견하지 못했다.
- `EXECUTION_REPORT.md`가 원문을 넘어서는 성공기준(반도체 objective-18)을 스스로 지적한 점도 좋다.

## C. 선택적 개선

- **C1. 공개 후 제출이 "정답"으로 표시됨**: 미리보기에서 정답 공개 후 입력하고 제출하면 "정답"이 뜬다(기하 2로 확인). 기록 규칙에서는 제외되지만 화면 문구는 오해를 준다. 공개 후에는 "정답 확인 후 입력"으로 표시하는 것을 권한다.
- **C2. 정답이 페이지 소스에 포함됨**: `answer-contract` JSON에 인정 답안이 그대로 들어 있다. 개인 학습용이라 심각하지는 않지만, 공유나 배포를 한다면 채점을 서버로 옮기는 것을 고려할 만하다.
- **C3. 수식이 일반 텍스트로 표시됨**: 기하 7·21·22·23은 행렬 원소와 좌표식을 텍스트 빈칸으로 처리한다. 하네스 규칙("독립 수식이나 행렬은 math 블록")을 부분적으로만 따른다.
- **C4. 어색한 빈칸 문장**: 반도체 8 "…농도는 보통 [증가한다]이다."처럼 빈칸 뒤 조사가 자연스럽지 않다.
- **C5. `recommend()`와 `deriveObjectiveChecklist()`의 정렬 차이**: `rule.ts`의 `recommend()`는 이벤트를 시간순으로 정렬하지 않고 `independent.at(-1)`을 사용한다. 반면 `objective-checklist`는 정렬한다. 저장 순서와 발생 순서가 다르면 두 결과가 달라질 수 있다.

앱 화면은 실행 중인 서버에서 데스크톱과 모바일(375px) 크기로 확인했다. 문제 미리보기는 헤드리스 브라우저에서 데스크톱(1100px)과 모바일(390px) 크기로 캡처해 확인했다.

### 좋은 점
- 메인 앱(오늘·프로젝트·기록)은 다크 테마, Pretendard 폰트, 둥근 카드로 절제돼 있고 완성도가 높다. 모바일에서는 사이드바가 하단 탭바로 바뀌고 카드가 한 줄로 쌓인다.
- 문제 카드는 보기 선택 상태와 정답 공개 후 초록 표시가 명확하다. 빈 화면에는 "첫 학습자료 만들기"처럼 다음 할 일을 안내한다.

### 문제점

**D1. 문제 카드 레이아웃이 어색하다 (학습 품질 체감에 직접 영향)**
- **사용자가 겪을 문제**: 한 줄짜리 빈칸 문제도 카드가 약 700px로 길어지고, 문장과 정답 칸 사이가 텅 빈다. 문장 끝의 "이다."가 입력칸과 떨어져 다음 줄에 놓이기도 한다.
- **근거**: 기하 1(`page.height` 606, 빈칸 y=96, 정답 공개 영역 y=464)과 기하 6(데스크톱에서 "이다."가 따로 떨어짐).
- **원인 단계**: Authoring. AI가 블록마다 `frame` 절대 좌표를 지정하고 렌더러가 `position:absolute`로 그대로 그린다.
- **최소 수정안**: 기본은 위에서 아래로 쌓는 흐름 배치로 하고, `frame`은 그림이나 도식에 겹쳐 배치하는 문제에만 허용한다. 빈칸 앞뒤 문장과 입력칸은 한 줄 인라인 요소로 묶는다.

**D2. 수식이 두 번 렌더링된다**
- **근거**: 기하 6에서 정상 행렬 아래에 `100010□□1` 텍스트 행렬이 한 번 더 겹쳐 나온다(데스크톱·모바일 동일). 미리보기의 `href="../../../assets/katex/katex.min.css"`가 `eval/local/full-study-20260928/r02/` 기준으로는 존재하지 않는 경로여서 KaTeX 스타일이 빠지고, 화면용 표기와 접근성용 표기가 동시에 보인다.
- **원인 단계**: 렌더러(미리보기 HTML 생성 시 자산 경로를 상대 경로로 기록). 앱 안에서도 재현되는지는 미검증이다.
- **최소 수정안**: KaTeX CSS를 인라인으로 넣거나 절대 경로·앱 정적 경로를 쓴다. 미리보기 검사(`inspect-preview.mjs`)에 "스타일시트 로드 실패"와 `.katex-mathml` 노출 검사를 추가한다.

**D3. 사용자에게 내부 오류 문구가 그대로 보인다**
- **근거**: 프로젝트 화면에 `서버 인증 설정이 없습니다. 누락된 환경 변수: AI_OWNER_EMAIL`, 학습 만들기 화면에 `저장된 학습을 불러오지 못했습니다: MCP 발행 덱 목록을 불러오지 못했습니다.`가 나온다.
- **최소 수정안**: 로컬 실험 모드에서 쓸 수 없는 기능은 숨기거나 "로컬 모드에서는 사용할 수 없어요"로 안내한다. 환경 변수 이름은 개발 로그에만 남긴다.

**D4. 화면 톤과 이름이 통일되어 있지 않다**
- 메인 앱은 다크 테마인데, `/mcp-runs`, `/mcp-personalization`, 문제 미리보기는 밝은 테마다. 사이드바에서 이동하면 다른 제품처럼 느껴진다.
- 제품명은 Recaller로 정했지만 화면에는 Study Forge로 표시된다.

**D5. MCP 실행 화면이 개발자 도구에 가깝다**
- 원본 SHA-256, "기획팀장 대화에서 실행을 요청하세요", 단계별 모델·추론 강도 선택 칸 5개가 그대로 보이고, 설명 문장도 많다. 실험 도구로는 괜찮지만 학습자용 메뉴와 같은 사이드바에 있으면 혼란스럽다.
- **최소 수정안**: "개발자/실험" 영역으로 분리하거나, 해시와 모델 설정은 접힌 "상세" 안으로 옮긴다.

**D6. 자잘한 겹침**
- 상단 로컬 실험 배너 문구가 오른쪽 "로컬 실험 · 실험" 배지에 가려 잘린다(데스크톱·모바일).
- MCP 화면의 파일 선택 칸이 브라우저 기본 모양이라 "파일 선택 선택된 파일 없음"으로 보인다.
- 모바일 하단 탭 위에 Next.js 개발 표시가 겹치는 것은 개발 모드에서만 생기므로 제외한다.

**미검증(UI)**: PDF 원문 가림 화면(`PdfReviewViewer`), 덱 칸반, 학습 세션 진행 화면은 복사본에 데이터가 없어 보지 못했다.

## 미검증

- **앱 안의 전체 흐름**(목표 체크리스트에서 풀이·복습·재접속 후 저장 유지까지): 복사본에 산출물 등록과 요청 저장소가 없어 A1·A2 때문에 실행하지 못했다.
- **세션 경계**: `sessionId`가 언제 새로 만들어지는지는 확인하지 못했다. 공개 후 새로고침하고 제출했을 때 새 세션으로 잡혀 독립 성공으로 기록되는지 여부는 앱 화면에서 확인해야 한다.
- **새 문제 생성(MCP 실행)**: `실행방법.md`에 따라 실행 주체가 연결되지 않은 상태라 수행하지 않았다.
- **테스트 스위트**(`npm run study:test` 등): 실행하지 않았다.
- **이미지 기반 페이지의 판단**(반도체 1–2쪽처럼 텍스트가 추출되지 않는 쪽): 텍스트 추출본을 기준으로 판단했으며 PDF 그림은 직접 보지 않았다.

## 수정 순서

순서를 정한 원칙은 세 가지다.
1. **학습 기록을 오염시키는 문제부터** 고친다. 기록이 틀리면 복습 추천과 목표 체크리스트가 모두 틀어진다.
2. **재생성 전에 렌더러·검증기를 먼저** 고친다. 그래야 유료 MCP 재생성을 한 번만 하면 된다.
3. **앱에서 직접 확인할 수 있는 상태를 빨리** 만든다. 그래야 미검증 항목을 줄일 수 있다.

### 1단계: 코드만 수정 (재생성 불필요, 기존 50문제에 바로 효과)
| 순서 | 항목 | 이유 |
|---|---|---|
| 1 | **B1** 공개 전 "근거:" 숨김 | 효과가 가장 크고 수정은 렌더러 한 곳이다. 이것만 고쳐도 기존 문제의 "독립 성공" 기록이 신뢰할 만해진다. |
| 2 | **B3-2** 채점 정규화 보강 (`'`↔`′`, `·`/`*` 무시, `°`/`도`, `R^-1`↔`R(-θ)`) | 맞는 답을 오답으로 기록하는 것을 막는다. 기존 문제에도 즉시 적용된다. |
| 3 | **A1** 개인화 목록 항목별 실패 처리 · **A2** 원본 SHA 기반 실행 목록 · **A3** 고정 안내 문구 제거 | 앱에서 풀이·복습·재접속 흐름을 확인할 수 있게 만든다. 미검증 항목을 줄이는 전제 조건이다. |
