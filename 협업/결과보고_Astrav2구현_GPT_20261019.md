# Astrav2 구현 결과 — 2026-10-19

## 결론

- 기존 astra를 유지하고 별도 실험 선택지 `astrav2`를 구현했다.
- 짧은 사실 회상·독립 질문과 의미 있는 관계·순서를 구분하도록 계획과 출제 지침을 수정한다.
- 정상 문항 판정과 연습 범위 부족 경고를 분리한다.
- 실제 모델 호출은 하지 않는다. 오프라인 검증은 연결·차단 동작의 확인이며 생성 품질 개선의 증명이 아니다.

## 변경 근거와 범위

비교 담당의 `협업/결과보고_반도체07_astra_유니브_GPT_20261019.md` 및 비교본 astra 코드를 확인했다. 과목 이름으로 분기하지 않고 관찰된 실패가 시작되는 책임을 수정한다.

| 관찰 | 변경 위치와 방향 |
|---|---|
| s1-o1/o2 등 여러 쌍에서 같은 답 반복 | 계획: 추가 문제에 새로운 인출 대상·적용 상황 요구. 출제·검수: 같은 답 반복 점검 |
| 단순 암기에도 복합 질문 편향 | 계획·출제: 짧은 사실·명칭 회상을 유효한 목표로 인정. 관계 전체는 유지 |
| s1-o4 재출제에서 요청하지 않은 ID 반환 | 출제: 슬롯 ID와 1:1 명시. 잘못된 ID는 추측 연결하지 않음 |
| s3-o8 자체는 ready이나 같은 연습의 partial 때문에 보류 | 공개 관문: 개별 결함과 범위 부족을 분리. 범위 경고는 유지 |
| 객관식의 정상 정답 보기를 노출로 판단한 비교 사례 | 독립 풀이·검수: 본문이 답을 알려주는 것과 정답 보기의 존재 구분 |

원문·문항 전문은 공개 문서에 복제하지 않았다. 관찰 ID는 비교 실행 `gen_8b7deaa73df81b8eb4ca9863d6200f13` 등에 대한 것으로 새 엔진 실측 결과가 아니다.

## 입력과 흐름

PDF 최초 계획 → 작은 묶음 출제 → 정답을 숨긴 풀이 → 묶음 검수·공개 → 전체 검수.

- 최초 계획에만 PDF를 전달하고 이후에는 선택 범위의 글자·그림/표/식 읽기 기록을 사용한다.
- 여기서 1회는 엔진의 계획 호출 기준이다. 공용 통신 계층의 구조화 형식 거부 후 대체 형식 재전송은 유지하므로 실제 HTTP 전송이 반드시 1회인 것은 아니다. 계획 내용 오류를 고치기 위한 별도 PDF 재호출은 추가하지 않았다.
- 범위 제한과 정답 저장 칸 안내는 비교 브랜치의 astra 수정 사항을 반영한다.
- 기존 저장 형식·목표 확인·점진 공개·읽는 위치 우선순위는 공용 연결을 사용한다.
- 기존 astra와는 프롬프트뿐 아니라 원본 전달 정책도 다르다. 단일 변경의 효과라고 해석하면 안 된다.
- 최초 그림 판독 오류는 후속 단계로 전파될 수 있다. 실측에서 별도로 확인해야 한다.
- 공용 저장 칸 `state.astra`와 단계 키 `astra-*`는 호환을 위해 재사용하고, 실행의 `input.engine=astrav2`로 구현·프롬프트를 구분한다. 별도 파일은 기존 astra를 비교 기준으로 보존하기 위한 것이며 범용 엔진 계층을 추가하지 않았다.

신규 테스트 파일은 없다. 기존 `astra.test.ts` 시나리오를 확장하여 가상 자료의 PDF 전달·범위 제한·정상 객관식 공개·범위 부족 경고 분리를 확인했다. 가짜 검수 응답에 올바른 판정을 명시한 시험이므로 모델이 스스로 노출이나 중복을 알아챈다는 증거가 아니다.

`withPdf`는 호출 기록의 논리 요청에 PDF가 포함됐는지 저장한다. 통신 계층의 대체 형식 재전송 횟수를 뜻하지 않는다.

실제 모델 호출: **0회**. 사용자 공부 서버·기록은 변경하지 않는다.
