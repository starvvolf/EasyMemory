# 로드맵 (2026-10-12, 사용자·Claude 논의 기준)

**도착점**(`docs/DECISIONS.md` "제품의 최종 경험"): 자료를 보다가 묻고, 문제를 풀고, 그 과정이 저절로 정리된 기록으로 남아 약점과 전체 정리가 따로 모이고, 공부 시간이 압도적으로 줄어든다. 품질은 사람이 하나하나 보는 대신 **GPT 판정단과 MD 기준 개선 회차**로 올린다.

**역할**
- Claude: 설계·작업지시·검토, 화면 설계.
- GPT(Codex): 구현·실측·반복 실행.
- 사용자: 방향 결정, 승인, 아는 과목에서 가끔 판정단 검증.

**읽는 법**: 단계마다 목적 / 할 일 / 완료 기준 / 담당 / 선행 단계. 앞 단계의 완료 기준을 넘기 전에는 다음 단계를 시작하지 않는다(4와 5는 병행 가능).

## 0. 지금 진행 중: 새 엔진 재실측
- **목적**: 1차 수정(목차 경계, 중복, 보조 목표, 답 다듬기)과 출제기준 v1이 효과가 있는지, 모델 강도가 품질에 주는 영향을 확인한다.
- **할 일**: `협업/새엔진_1차_결과와_실측안내.md` 7장의 A(luna·low), B(설계·출제 sol·medium), C(다른 PDF).
- **완료 기준**: 결과보고 제출, 모델 조합 결정(단계별 기본 모델).
- **담당**: GPT 실측 → Claude 검토.

## 1. 새 엔진 안정화 마무리
- **목적**: 시연과 실사용에 쓸 수 있는 생성 품질과 안정성.
- **할 일**
  1. 재실측에서 나온 문제 수정. 구조 문제는 코드, 판단 문제는 `출제기준/`.
  2. **큰 자료 1회 실측**(반도체 44쪽 또는 기하 32쪽 전체): 목차 수, 병렬 처리, 호출 상한(시작당 60)이 충분한지, 걸린 시간·토큰.
  3. 단계별 기본 모델 확정(예: 목차·분류 luna, 설계·출제 sol).
- **완료 기준**: 2쪽·30쪽대 자료 모두 끝까지 성공, 정답 노출 0, 목차 간 중복 거의 없음, 시간·토큰이 기록됨.
- **담당**: Claude 수정, GPT 실측.

## 2. `/study`를 새 엔진에 연결 (2차)
- **목적**: 사용자가 실제로 쓰는 화면이 새 엔진으로 돈다. 목표 ID가 화면까지 온다.
- **할 일**
  1. 자료 만들기: 목적 4개(그냥 읽기 / 이해 / 핵심 암기 / 통암기) 선택, 메모.
  2. **목표 확인 화면**: 목차별 목표 목록, 보조 목표는 기본 해제, 빼기·더하기.
  3. **목차별 진행 표시**: 첫 목차가 준비되면 바로 읽기·연습 시작, 나머지는 뒤에서 만들어짐.
  4. 문제 묶음 로딩: `study-gen/<id>/sections/<s>/document.json`을 읽는다.
  5. **다시 만들기**: 신고한 목표만 다시 출제하는 새 엔진 경로(설계는 재사용, 해당 목표만 출제).
  6. 옛 경로(5단계·MCP)는 화면에서 숨기고 코드는 남긴다.
- **완료 기준**: 사용자가 실제 PDF 하나로 올리기 → 목적 선택 → 목표 확인 → 첫 목차 공부 → 나머지 목차까지 끊김 없이 진행. 기존 풀이 기록이 깨지지 않음.
- **담당**: Claude 화면 설계·구현, GPT 실측.
- **선행**: 1.

## 3. 판정단 1차 (GPT가 문제를 대신 판정) — 2026-10-12 1차 구현됨(점수표 v0, 평가 실행, 판정단 시험). 실측·검출률 확인 대기
- **목적**: 사람이 하나하나 보지 않아도 품질을 숫자로 잰다. "사람이 헷갈려하는 것"을 행동으로 잰다.
- **할 일**
  1. 판정 역할 구현(실험실 "평가 실행").
     - **공부 안 한 학습자**: 문제만 보고 풀기. 맞히면 노출·찍기 가능.
     - **원문을 읽은 학습자 3명**: 따로 풀기. 답이 갈리면 모호, 다 틀리면 정답 오류.
     - **전문가 체크리스트**: 원문 일치, 목표 일치, 조건 누락에 예/아니오로 답하기.
  2. **점수표**: 노출률, 모호율, 원문 불일치, 형식 분포, 중복, 핵심 덮은 비율, 호출 수·시간. 단계별(분류·설계·출제)로 나눠 본다.
  3. 판정 지시를 `평가기준/` MD로 둔다(출제기준과 같은 방식).
  4. 출제 모델과 판정 모델을 다르게 한다. 점수보다 **전후 비교 판정**을 쓴다.
  5. **결함 심기로 판정단 시험**: 좋은 문제에 알려진 결함(정답 보기만 길게, 조건 빼기 등)을 넣고 판정단이 잡는지 확인한다.
  6. **평가 자료 확정**: 2~3개. 하나는 사용자가 이미 잘 아는 과목. 개선에 안 쓰는 확인용 1개.
- **완료 기준**: 심은 결함의 대부분을 판정단이 잡음. 사용자가 아는 과목에서 판정단과 사람 판단이 대체로 일치(어긋난 3~5개만 사람이 봄).
- **담당**: Claude 설계, GPT 구현.
- **선행**: 1(2와 병행 가능).

## 4. 첫 GPT 개선 회차
- **목적**: "MD 기준을 고치면 품질이 오른다"를 한 번 증명한다.
- **할 일**
  1. **개선 담당 세션 지시문 템플릿**을 쓴다: 개선후보·점수표·나쁜 문제 읽기 → 후보 폴더 수정 → 전후 실행 → 비교 보고.
  2. 재료는 `출제기준/개선후보.md` 1~3(자기 확인 쏠림, 빠뜨린 대안, 반대 방향 중복)과 재실측 결과.
  3. **예시 은행 시드**: 결함 심기로 만든 대비 예시, 규칙별 좋은·나쁜 예(평가 자료 밖에서 만들고 판정단이 일치한 것만).
  4. 사용자 승인 후 반영, `변경기록.md`에 기록.
- **완료 기준**: 고치려던 지표가 개선되고 다른 지표가 나빠지지 않음(확인용 자료 포함).
- **담당**: GPT 개선 세션, Claude 검토, 사용자 승인.
- **선행**: 3.

## 5. 학습 기록 통합 (모든 기록을 목표 하나에 꿰기)
- **목적**: "저절로 정리되는 기록"의 바탕을 만든다.
- **할 일**
  1. 서버 저장: 풀이(혼자 맞힘·도움받음·틀림·읽은 직후), 신고, 모르는 것 노트, 자기 확인 결과를 **목표 ID**로 저장.
  2. 지금 브라우저에만 있는 풀이·신고 기록을 옮긴다.
  3. 목표 상태 계산: 안 봄 · 헷갈림 · 익힘(정직성 규칙: 도움받은 풀이는 독립 성공이 아님).
  4. 노트와 목표 연결: 원문 위치가 겹치는 목표에 질문을 매단다.
- **완료 기준**: 한 목표를 열면 원문 인용, 내 질문과 답, 풀이 이력, 현재 상태가 한곳에 보인다. 기기를 바꿔도 기록이 남는다.
- **담당**: Claude 설계, GPT 구현.
- **선행**: 2.

## 6. 정리 화면 (최종 경험의 핵심)
- **목적**: 따로 정리하지 않아도 전체 정리와 약점이 모여 있다.
- **할 일**
  1. **자료별 정리 노트**: 목차 → 목표(무엇을 보고 → 무엇을 떠올리나) → 핵심 인용 → 내가 한 질문. 원문 위치로 바로 이동.
  2. **약점 모음**: 틀림·도움받음·여러 번 물어본 목표. 바로 그 목표로 연습.
  3. **오늘 할 것**: 복습 차례와 약점을 섞은 짧은 목록(처음엔 규칙 기반).
- **완료 기준**: 시험 전날 이 화면만으로 복습이 된다(사용자 본인 사용으로 확인).
- **담당**: Claude 화면, GPT 구현.
- **선행**: 5.

## 7. 약점을 다음 생성에 반영 (노트 2단계)
- **목적**: 공부한 결과가 다음 문제를 바꾼다.
- **할 일**
  1. 새 엔진 설계 입력의 `signals`(약점, 신고) 칸을 채운다.
  2. 약점 목표에 다른 각도의 문제를 다시 낸다(같은 목표, 다른 cue나 형식).
- **완료 기준**: 약점으로 잡힌 목표에 새 문제가 생기고, 다시 풀어 상태가 바뀐다.
- **선행**: 5.

## 8. MD 하네스 확장
- **목적**: 의미가 담긴 것은 전부 MD로 고칠 수 있다.
- **할 일**
  1. 목차 규칙, 분류 기준, 목적 목록을 MD로 뺀다. 목적은 파일을 추가하면 생긴다.
  2. 질문 창 답변 방식, 정리 노트 요약 방식을 MD로 둔다.
  3. 층: 기본 → 자료 종류 → 목적 → 개인 설정(`내설정/`).
  4. **MD 검사기**: 필수 절, ID 중복, 크기 예산, 엔진이 모르는 형식 사용.
- **완료 기준**: 코드 수정 없이 새 목적 하나를 파일로 추가해 실제로 돈다.
- **선행**: 4(개선 회차 방식이 자리 잡은 뒤).

## 9. 개선 자동화와 실제 학습 신호
- **목적**: 기준이 "그럴듯한 문제"에서 "나에게 효과 있는 문제"로 진화한다.
- **할 일**
  1. 개선 회차를 예약 작업으로 반자동 실행하고, 사용자는 보고서 승인만 한다.
  2. 판정단 확대: 오개념 학습자, 전후 비교 판정 정교화.
  3. 학습 신호 연결: 신고 사유를 규칙 ID에, "내 답도 맞아요"를 인정 답안 규칙에, 기억 유지율(시간이 지나도 맞히는 문제의 특징)을 형식·종류별 규칙에 연결.
- **선행**: 5, 8.
