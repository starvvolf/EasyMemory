# 조사 범위와 비교 기준

조사 기준일: 2026-09-11. 제품·프로젝트 65개를 기록했다. 기존 36개, 사용자가 추가한 목록의 중복 제거 후 11개, 추가 탐색 18개다. 상용 서비스·공개 코드·범용 AI·인접 제품을 포함한다. 인터넷의 모든 서비스를 망라했다는 뜻은 아니다.

이번 결과는 **공개 자료와 일부 코드에 근거한 기능·구조 비교**다. 전 제품에서 실제 문제를 생성한 품질 순위가 아니다. 확인되지 않은 기능은 ‘없음’이 아니라 ‘미확인’으로 기록한다.

## 포함·분리 기준

1. 자기 자료나 주제로 AI 문제·카드를 만들거나, 그 결과를 풀이·복습하는 제품을 포함한다.
2. 교사·한국 시험·기업 교육도 배제하지 않는다. 대상과 자료가 달라 같은 실험으로 비교하기 어려우면 별도 군으로 둔다.
3. 공개 코드는 설치 가능한 프로젝트와 생성·검증·학습 구조를 참고하려고 포함한다. README만 읽은 경우 코드 검증으로 쓰지 않는다.
4. 이름이 같은 서비스는 도메인/저장소로 구분한다. 브랜드 변경은 한 제품으로 묶고, 같은 회사의 별도 제품은 관계를 표시한다.
5. Anki·Scholarcy는 학습/읽기 참고군, Monic은 종료 기록군이다. 신규 AI 출제 제품 수에 그대로 합산하지 않는다.
6. 검색 결과의 광고성 비교 글은 후보 발견에만 사용한다. 기능은 제품 설명·공식 도움말·저장소로 다시 확인한다.

## 확인 수준

- **공식 도움말**: 기능 경로와 조건을 문서에서 확인. 현재 내 계정에서 동작한다는 뜻은 아니다.
- **공식 제품 설명**: 판매자가 제공한다고 설명한 기능. 독립적인 품질 검증으로 취급하지 않는다.
- **README/릴리스**: 프로젝트 작성자의 설명. 구현·실행 성공은 별도다.
- **코드 확인**: 함수·입력·출력·예외 처리를 읽어 확인한 해당 경로만 인정한다.
- **직접 실행**: 기록된 환경·자료·횟수에서 실제 성공/실패. 다른 유형/모델/플랜까지 확대하지 않는다.
- **미확인/상충/종료**: 각각 분리한다. 점수 0으로 대체하지 않는다.

## 목록의 순서와 후속 실험 편입 규칙

인기나 품질 총점을 만들지 않았다. 먼저 사용 장면별로 정렬하고 제품별 근거를 붙였다. 군 안의 순번은 식별 번호이며 우열이 아니다.

- **개인 학습군**: 자료→문제/카드→자기 학습을 주로 제공하거나 주장하는 제품. 임의 자료 생성 경로가 불명확하면 보류한다.
- **교사·수업군**: 학급 응답·수업 자료·교육 기준을 주로 다룬다. 개인 PDF 생성 자체는 동일 입력 실험에 참여할 수 있다.
- **출제·저작군**: 문제 제작·편집·배포/내보내기를 주로 다룬다. 자체 학습 기능도 있는 제품은 별도로 기록한다.
- **한국 시험군**: 국어/영어/사회과학 등 실제 지원 과목 안에서 비교한다. 영어 전용에 운영체제 PDF를 넣고 실패로 채점하지 않는다.
- **공개 코드군**: 실행 비교와 구조 참고를 분리한다. 모델·프롬프트·설치 환경을 고정해야 결과 비교가 가능하다.
- **범용 AI군**: 일반 채팅, 전용 퀴즈 화면, 에이전트/도구 사용을 별도 실험으로 둔다.
- **인접/종료군**: 생성 품질 순위의 대상에서 제외하되 기능 참고 목록에 남긴다.

어떤 제품도 이름값이나 소개 문구만으로 최종 탈락시키지 않는다. 실험 편입에는 (a) 동일 자료/내용 입력 가능, (b) 새 문제 생성 가능, (c) 결과 검토·저장 가능이 필요하다. 계정·비용·언어 제약은 탈락 점수가 아니라 별도 조건이다. 확인 전 편입은 ‘조건부’다. 임의로 10개 같은 상한을 정하지 않는다.

## 실제 문제 품질 비교 규약 — 다음 실험에 적용할 초안

기능 유무와 결과 품질은 별도 표로 평가한다. 아래 가중치는 사용자 확정값이 아니라, 지엽적 사실 보존·능동 인출·문제 형식을 중시한 이번 비교 설계안이다.

| 문항 품질 | 배점 | 판정 기준 |
|---|---:|---|
| 원문·정답 정확성 | 30 | 조건/예외/용어 보존, 근거로 답 입증, 정답 오류 없음 |
| 답의 명확성 | 20 | 단일 정답형의 복수정답/정답 없음, 빈칸의 과도한 다의성 없음 |
| 목표·범위 적합성 | 15 | 선택 범위와 요구한 학습 행동에 맞음 |
| 실제 인출·사고 수준 | 15 | 답 노출 없이 회상/이해/적용을 실제로 요구함 |
| 선지·답안 설계 | 10 | 그럴듯하고 구별 가능한 오답, 허용 답안 기준. 비객관식은 동등한 답안 설계 평가 |
| 읽기·시각 품질 | 10 | 문장·배치·기호·수식·그래프가 명확하고 문제 풀이를 방해하지 않음 |

각 항목은 0/1/2/3/4로 판정하고 배점×점수/4로 환산한다. 0=사용 불가, 1=핵심 수정 필요, 2=상당 수정, 3=작은 수정, 4=그대로 사용 가능. 루브릭은 모든 제품에 동일하게 적용한다.

**중대 오류는 총점으로 상쇄하지 않는다.** 정답 오류, 단일정답 문제의 복수정답, 핵심 원문 왜곡, 답을 노출한 문제는 각각 표시한다. 원시 점수와 함께 ‘중대 오류 없이 사용 가능한 문항 비율’을 보고한다.

세트 단위로 범위 커버리지·중복·문항 사이 정답 누설·문제 종류 준수도 별도 기록한다. 문항을 많이 만들면 점수가 오르게 설계하지 않는다.

## 공정한 실행 방식

1. 텍스트 위주 강의자료, 영어 문장 암기자료, 그래프/표 포함 자료를 별도 시험 묶음으로 만든다. 한국 시험 서비스에는 공통 영어 지문과 국어 지문을 따로 쓴다.
2. PDF 원본·동일 추출 텍스트를 각각 준비한다. PDF 미지원 서비스의 붙여넣기는 허용하되 사람이 들인 시간으로 기록한다.
3. 범위·목적·언어·요청 개수·난이도를 고정한다. 지원하지 않는 유형은 미지원으로 기록하고 다른 유형으로 몰래 대체하지 않는다.
4. 첫 생성 결과를 모두 보존한다. 수정 기회를 줄 때는 같은 오류 설명·같은 횟수로 추가 실험한다.
5. 단 한 번의 성공 사례로 순위를 정하지 않는다. 우선 자료당 3회 정도의 탐색 실험을 제안하며, 이는 통계적 우열을 보장하는 표본 수가 아니다.
6. 제품명을 가린 문제를 같은 기준으로 검토한다. LLM 평가만으로 확정하지 않고 정답·모호성은 원자료를 보고 확인한다.
7. 오류율·사용 가능 비율·수정 횟수·사용자가 쓴 시간·처리 시간·실제 지출/제한을 함께 보고한다.
8. 긴 문서에서 빠진 범위, 그림·수식의 실제 정합성, 채점이 허용해야 할 표현을 별도 점검한다.
9. 반복학습 효과는 생성 결과 점수로 주장하지 않는다. 지연 회상/재학습 시간을 비교하려면 별도 기간을 둔 사용자 실험이 필요하다.

이번 조사에서는 신규 유료 결제나 65개 전수 생성을 수행하지 않았다.

# 교차 확인으로 드러난 차이

## 1. 생성 형식과 학습 형식을 따로 봐야 한다

ClassPoint의 전체 상호작용에는 그림·음성 응답 등이 있지만, AI 생성 안내는 객관식·단답·빈칸 3종이다. Shiken도 스토어에 보이는 유형 전체를 AI가 만들 수 있다고 단정하지 않았다. [ClassPoint AI](https://www.classpoint.io/ai-quiz-generator), [Shiken 스토어](https://app.shiken.ai/store?page=6).

## 2. ‘복습’의 구현이 서로 다르다

Studley는 카드 숙련도를 표시하지만 FAQ에서 복습 시점은 사용자가 정한다고 설명한다. Quizzer는 SM-2 스케줄을 코드로 관리한다. 이 둘을 모두 ‘복습 지원’ 한 칸으로만 표시하면 차이가 사라진다. [Studley FAQ](https://www.studley.ai/flashcard-maker), [Quizzer 코드](https://github.com/suncloudsmoon/quizzer/blob/main/src/quizzer/learner_state.py).

## 3. OpenTutor: 검사와 수정은 있으나 경로 차이가 있다

읽은 파일: apps/api/services/parser/quiz.py. 업로드 내용의 문제 추출 경로는 검증 오류가 있으면 LLM repair를 시도하고 다시 검증한다. 중복을 제거하며 살아남은 문제가 너무 적으면 배치를 거부한다.

같은 파일의 prepare_generated_questions는 검증·중복 제거를 수행하지만 이 함수 안에서 같은 repair를 호출하지 않는다. 모든 문제 생성 경로에 동일한 수정 루프가 있다고 말할 수 없다. repair에 넣는 원문은 content[:3000]으로 제한돼 있다. 긴 내용에서는 관련 근거가 그 안에 있는지 점검할 필요가 있다. 이는 코드에서 도출한 점검 항목이며 실제 오류 발생을 관찰했다는 뜻은 아니다.

FSRS 파일/호출 검색에서는 forgetting_cost·urgency가 확인된다. FSRS/지식 그래프를 쓴다는 사실은 장기 기억 향상의 실증 결과가 아니다. [문제 처리 코드](https://github.com/zijinz456/OpenTutor/blob/377286db8182806407faa76bb62f64fc0aa7f14c/apps/api/services/parser/quiz.py), [FSRS 코드](https://github.com/zijinz456/OpenTutor/blob/377286db8182806407faa76bb62f64fc0aa7f14c/apps/api/services/spaced_repetition/fsrs.py).

## 4. Studium: LLM critic이 있지만 원문 사실 검증에는 한계가 보인다

읽은 파일: services/ingestion/app/services/quiz_generator.py. 본문 조각에서 최대 2개 개념을 고르고 개념당 객관식·OX·빈칸을 요청한다. 구조 검사 후 별도 LLM이 품질 점수를 매기고 0.6 미만을 제거한다. 이후 의미 중복 검사와 저장이 이어진다.

그러나 평가 함수가 보내는 것은 질문·유형·정답·학년이며 원문 조각과 객관식 선지는 포함하지 않는다. 따라서 이 호출만으로 원문 충실성이나 오답 선지의 타당성을 충분히 검증한다고 볼 수 없다. 평가 JSON 오류/예외 때는 문항을 유지한다. ‘검사기 있음’과 ‘검증 실패 결과를 차단함’이 다르다.

또한 파일 맨 위 설명은 조각당 5문항이지만 실제 프롬프트는 개념별 3변형이다. 설명보다 실제 호출을 확인해야 하는 사례다. [코드](https://github.com/EmaadAkhter/Studium/blob/main/services/ingestion/app/services/quiz_generator.py). 실행하거나 품질 점수를 재현한 것은 아니다.

## 5. Quizzer: theta라는 이름만으로 정교한 능력 추정은 아니다

읽은 파일: learner_state.py 및 quiz_creator.py. theta 갱신은 이전 값에 정오답의 이동평균을 적용한다. question_difficulty는 이 갱신식에 직접 반영되지 않고 기록되며, 이후 가까운 난이도 문항을 고르는 데 theta를 사용한다. 엄밀한 문항반응이론 모델이라고 소개하면 과장이다.

반면 SM-2 간격 갱신과 정오답×자신감 점수 매핑은 실제 코드에서 확인됐다. PDF 페이지 이미지→분류/요약→질문 생성 구조는 대용량 입력의 호출량과 비용을 따로 측정해야 한다. [학습 상태 코드](https://github.com/suncloudsmoon/quizzer/blob/main/src/quizzer/learner_state.py), [생성 코드](https://github.com/suncloudsmoon/quizzer/blob/main/src/quizzer/quiz_creator.py).

## 6. MK-QuizFlow: 무료 동작과 AI 동작을 나눠 측정해야 한다

공식 저장소는 브라우저의 규칙 기반 Quick 생성과 외부 모델 AI 생성을 구분한다. Quick 결과를 AI 품질로 평가하거나, 외부 모델 사용 모드까지 모든 데이터가 기기 밖으로 나가지 않는다고 설명하면 안 된다. 이번에는 README/소스 검색까지 확인했고 전체 호출·실행 검증은 하지 않았다. [공개 설명 파일](https://github.com/mk-knight23/MK-QuizFlow/blob/b56763bb33fad1dfffb94bbf2e38dee5a8573fdc/public/llms.txt).

## 7. 국내 제품도 과목과 작업 범위가 다르다

PlanA·페듀는 영어 시험 제작 측면을 먼저 비교해야 한다. 문항공방은 시험 유형별 생성·출력·검토 가이드가 구체적이다. 똑스는 사회·과학 내신과 다양한 AI 도구를 안내하며, 운영사 큐레아는 별도 QGen/Pullim 제품 구조도 설명한다. 이것들을 하나의 ‘전 과목 PDF 생성기’로 묶지 않았다. [PlanA](https://plana-ai.com/guides/tools), [페듀](https://www.pedu.co.kr/faq), [문항공방](https://munhang.co.kr/guide), [똑스](https://www.dokdok.co/teacher), [큐레아](https://curea.co/).

## 8. 그래프/그림 기능은 최소 네 가지로 구분해야 한다

자료 속 그림을 읽는 것, 기존 이미지를 문제에 넣는 것, 도식/개념도를 만드는 것, 수학적으로 정확한 새 그래프를 만드는 것은 별개다. easy-quiz.ai의 Image Quiz는 무료 소스 이미지 매칭이라고 설명한다. Algor는 개념도·마인드맵을 제공한다. 두 기능을 수능 수학 그래프 출제로 환산하지 않았다. [easy-quiz.ai](https://easy-quiz.ai/), [Algor](https://www.algoreducation.com/en).

## 9. 가격·유형 수·운영 상태에도 불확실성이 있다

Quiz-Maker FAQ의 무료 일일 제한 문구가 상충한다. 문항공방의 유형 수는 가이드/가격 페이지가 다르다. PrepAI는 접근 오류가 있어 운영 종료라고 단정하지 않았다. Monic은 공식 종료일이 있어 신규 실행 비교에서 분리했다. [Quiz-Maker](https://www.quiz-maker.com/AI-Quiz-Generator), [문항공방 가격](https://munhang.co.kr/pricing), [Monic 공지](https://monic.ai/).
