## 1. 제품 핵심(사용자와 합의한 이해)
- 요약기가 아니라 "자료 → 학습목표 → 정답이 새지 않는 인출 문제 → 정직한 기록 → 간격 복습"으로 이어지는 학습 설계 도구다.
- **정직함이 핵심 원칙이다.** 정답을 본 뒤 맞힌 것은 독립 성공으로 세지 않는다. 한 번 맞힌 것을 숙달로 과장하지 않는다. 원문 표기와 세부 내용을 함부로 바꾸거나 빼지 않는다.
- 사용자 선호: 단순하고 복잡하지 않은 UI, 과한 장식 없음, 원문 중심 화면.

## 3. 최신 평가: 3101번 `/mcp-personalization` (22:20 기준, 원본 저장소 서버)

**반영 확인됨**

**남은 문제(우선순위 순)**
1. 최신 전체 범위 실행(기하 28목표 `chatgpt-request-edffcc5c…`, 반도체 22목표 `…ecdf7a39…`)에 문제 묶음이 연결되지 않아 앱에서 풀 수 없다(작업지시 03).

## 4. 되짚기(Claude의 비교용 시제품) — 사용자가 가장 중요하게 보는 결과물
- **최신 코드와 상세 설명은 `협업/되짚기/README.md`와 `협업/되짚기/되짚기_최신_v9.html`에 있다.** 이 절은 요약이다.
- **링크**: https://claude.ai/artifact/6SoZ7pnUgAAWehvdNSp8TM (사용자 계정 전용, 버전 9). 목적은 Recaller를 대체하는 게 아니라, 같은 코어를 가볍게 만들었을 때 무엇이 좋아지고 무엇이 빠지는지 비교하는 것이다.
- **구조**: 단일 HTML.
  - Claude 호출은 페이지 안에서 한다(`sample`).
  - 기록은 사용자별 개인 저장소 `data/users/<id>/`(`db`)에 둔다.
  - 원본 PDF는 파일 저장소(`assets`)에 둔다.
  - PDF는 pdf.js 3.11.174(cdnjs)로 읽고 그린다.
- **흐름**: 자료 만들기(목표 설계 1회 호출 → 목표 5개씩 문제 작성 → 자동 검사와 1회 수정) → 읽기 → 연습 → 기록.
- **사용자가 좋게 본 점**: 흐름이 단순하고 UI가 복잡하지 않다.
- **사용자가 직접 요청해 반영한 것**
  - 읽기 화면을 원문 중심으로 바꿈. 원문을 맨 위에 두고, "이 쪽에서 익힐 것"은 원문 아래로 옮겨 원문 시작 위치가 흔들리지 않게 함.
  - PDF를 화면 폭과 기기 배율에 정확히 맞춰 그려 선명도를 개선함.
  - 16:9 슬라이드는 폭 가득 크게 보여주고 "크게 보기"를 추가함.
  - 쉬운 풀이 기능은 없애고, 떠 있는 반투명 질문 창 하나로 대체함. 창은 끌어 옮기고, 모든 가장자리로 크기를 바꾸고, 접기와 크게를 할 수 있다. 추천 질문 칩이 있고, 지금 보는 쪽 원문을 근거로 답한다.
- **기록 규칙**
  - 정답 공개, 결과 화면을 본 뒤의 재시도, 연습 중 원문을 열거나 질문한 쪽의 문제는 모두 "도움받은 풀이"로 기록한다.
  - "이 쪽 문제 풀기"로 읽은 직후 푼 결과는 "읽은 직후"로 따로 기록하고, 복습은 다음 날부터 시작한다.
- **알려진 약점(사용자와 합의, 출제 품질은 일단 보류)**
  - 목표 상한 18개와 "핵심만 미리 선택" 때문에 범위가 누락된다(기하 32쪽 중 13쪽만 출제됨).
  - 계산 문제가 없고 카드와 순서 문제로 치우친다.
  - 순서 형식은 정답 노출 검사가 빠져 있다.
  - 단어 답이 값 쓰기 형식으로 나와 "반시계" 같은 답이 오답 처리된다.
- **미검증**: 실제 PDF 위 형광펜 위치, 실제 KaTeX 조판, 실제 Claude의 질문 창 답변 품질(작업 환경에서 pdf.js와 cdnjs를 받을 수 없어 가짜 PDF와 가짜 응답으로만 확인함).
