# GPT 작업 규칙 (2026-10-12)

모든 GPT 작업 지시에 이 규칙이 붙는다. 지시문에 따로 적지 않아도 지킨다.

## 역할
- **Claude**: 화면·사용 흐름, 엔진 구조, 출제기준·프롬프트 문구, 결과 판단.
- **GPT**: Windows 테스트·린트·빌드, 실제 호출 실측과 대조, 반복 점검, 지시가 파일·함수·완료 기준까지 정한 작은 코드 수정.
- **사용자**: 방향 결정, 실제 호출 승인, 실제 공부.

## 범위
1. 지시에 적힌 파일과 일만 한다. 지시에 없는 기능·화면·문구·데이터 구조·의존성은 바꾸지 않는다.
2. 애매하거나 지시대로 하면 이상한 결과가 나올 것 같으면 **멈추고** 보고서의 "Claude가 판단할 것"에 적는다. 스스로 설계를 바꾸지 않는다.
3. 엔진(`src/lib/study/gen/`)·`출제기준/`·`평가기준/`은 지시가 있을 때만 고친다.
4. 시작 전 `git status`를 확인하고, 사용자의 기존 변경을 되돌리지 않는다.

## 실제 호출
5. 실제 모델 호출은 지시에 적힌 **묶음마다 한 번** 사용자에게 확인받는다(예상 호출 수를 같이 말한다). 지시의 상한을 넘기지 않는다.
6. 사용량 한도·로그인 문제로 멈추면 다시 시도하지 말고 그대로 보고한다.

## 검증
7. 코드를 받거나 고치면 테스트·`npm.cmd run lint`·`npm.cmd run build`를 돌리고 결과를 숫자로 적는다. 테스트가 없는 부분은 "테스트 없음"이라고 쓴다.
8. 확인하지 못한 동작은 추측으로 쓰지 않는다.

## 보고서
`협업/결과보고_<주제>_GPT_YYYYMMDD.md`, 아래 순서를 지킨다.

```
# 제목
## 결론 (5줄 이내)
## 핵심 표 (하나)
## Claude가 판단할 것 (없으면 "없음")
## 자세한 내용
```

- 결론과 표만 읽어도 다음 행동을 정할 수 있게 쓴다.
- 실행 ID·호출 수·시간·토큰은 표에 넣는다.
- 판정·결과에 동의하지 않는 부분은 "Claude가 판단할 것"에 근거와 함께 적는다.
- 키·토큰·환경 변수 값은 쓰지 않는다.
