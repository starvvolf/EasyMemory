# 작업지시 09: 학습 설계의 쪽 근거 없는 목표를 제출 때 막기

- **브랜치**: `claude/local-state-20260928` (PR starvvolf/EasyMemory#1)
- **영역**: 생성 엔진(`tools/study-forge-mcp/chatgpt-parity.ts`). `docs/GENERATION_ENGINE_BOUNDARY.md`의 경계를 따른다.
- **작업지시 08과 별개**다. 작은 수정이라 08보다 먼저 해도 된다.

## 현재
- 학습 설계는 "개념: 번호"로 개념 구조의 개념을 가리킨다. 쪽은 가리킨 개념들의 쪽 근거에서 가져온다.
- 개념 구조에서 **맨 위 개념(자료 전체)은 쪽 근거 없이도 통과**한다. 하위 개념만 쪽이 필수다(`materializeConceptTreeArtifact`).
- 학습 설계가 맨 위 개념만 가리키면 쪽을 찾을 수 없다. 그러면 **`sourcePage: sourceRef?.pageNumbers[0] ?? 0`으로 0쪽을 넣고 그대로 저장**한다(`materializeLearningDesignText`, 현재 1303줄 부근).
- 원문 인용 검사(`checkLearningEvidence`)도 쪽이 없으니 경고만 남긴다.

## 문제 (실제 실행 `req_439de8…`)
- 03_Three Dimensional Viewing.pdf 44쪽에서 학습 설계가 "개념: 1"(맨 위 개념)만 가리킨 목표 1개를 냈다.
- 0쪽으로 저장됐고, 활동 설계와 카드 단계는 그대로 진행됐다.
- **5단계가 모두 끝난 뒤** 출제 패킷(`packetFromCompletedRequest`)에서야 "선택 범위에 0쪽 없음"으로 막혔다. AI 호출 7번이 결과 없이 끝났다.
- 제출 때 막았다면 자동 실행기의 단계 재시도가 이전 답과 오류를 보고 그 자리에서 고쳤을 것이다. 재시도에 이전 답을 보여 주는 기능은 이미 들어가 있다.

## 변경
1. `materializeLearningDesignText`에서, 학습 설계 블록이 가리킨 개념들에 **쪽 근거가 하나도 없으면 오류**로 거부한다. `?? 0` 대체값을 없앤다.
   - 오류 문장은 모델이 읽고 고칠 수 있게 쓴다. 예: `3번 학습 설계는 쪽 근거가 있는 개념을 가리켜야 합니다. 맨 위 개념(1) 대신 실제 내용이 있는 하위 개념 번호를 쓰세요.`
2. 같은 규칙을 단계 지시문(learning-design의 `instructions` 또는 `format`)에 한 줄 더한다: "맨 위 개념 하나로 자료 전체를 묶지 않는다."
3. 테스트
   - 맨 위 개념만 가리킨 제출은 거부된다.
   - 하위 개념을 함께 가리키면 통과하고, 쪽은 하위 개념의 쪽이다.
   - 기존 통과 예시(`scripts/study-forge-mcp-chatgpt.test.ts`의 deadlock 흐름)는 그대로 통과한다.

## 지금 하지 않는 것
- "범위에 비해 목표가 너무 적음" 같은 개수 기준 검사는 하지 않는다. 실험실(작업지시 08)의 경고로 먼저 보고 정한다.
- 과거 실행 기록은 고치지 않는다.
- 단계 구성 변경(활동 설계·카드 생략)은 하지 않는다.
