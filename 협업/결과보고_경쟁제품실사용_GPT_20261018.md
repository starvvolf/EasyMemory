# 경쟁제품 실사용 비교 · 2026-10-18

## 결론 (5줄 이내)

유니브·RemNote·NotebookLM에 동일한 자체 작성 BFS 기초 텍스트를 넣고 실제 생성·학습 화면을 조작했다.
유니브는 다양한 문제와 후속 연습, RemNote는 문서와 복습 계획의 연결, NotebookLM은 출처 옆에서 바로 푸는 흐름이 강했다.
문제·카드 생성 자체는 차별점이 아니다. Recaller는 범위 누락을 알 수 있고, 틀린 내용을 다음 공부로 자연스럽게 이어주는 경험을 입증해야 한다.
이번에는 짧은 텍스트·데스크톱 관찰이다. PDF·태블릿·장기 기억 효과·동일 입력의 Recaller 품질 우열은 미검증이다.
3000 서버와 사용자 학습 데이터를 조작하지 않았고 제품 코드도 수정하지 않았다.

## Claude가 판단할 것

1. **다음 공부를 명확히 제시하기:** 결과 화면에 통계만 두지 말고, 이번 오답 다시 보기와 다음 복습을 구분하는 것이 우선인가? NotebookLM의 오답 재풀이와 RemNote의 취약 개념 안내는 실제로 확인했다.
2. **생성 중 시작과 총량 안내:** 유니브처럼 먼저 풀게 할 수 있지만 총 문항 수가 변하면 진행률을 오해하기 쉽다. Recaller도 준비된 단원과 아직 생성 중인 범위를 별도로 보여줄 필요가 있다.
3. **설명은 필요할 때 펼치기:** 답 확인 순간에는 짧은 정답이 중심이고, 긴 설명·출처·질문은 선택해서 열도록 할지 검토한다. 새 화면·계층을 추가하자는 제안은 아니다.
4. **원자료와 추가 예시 구분:** AI가 만든 예시를 원자료 예시처럼 보여주지 않아야 한다. RemNote의 요약에서 원래 그래프와 다른 연결이 등장했다. Recaller도 같은 기준으로 확인해야 한다.
5. **차별화 주장 보류:** PDF를 문제로 바꾸기·오답 재풀이·카드 자기 판정은 경쟁 제품에서도 제공한다. 시험 범위와 원문 근거를 유지하며 반복 공부까지 이어지는 신뢰성이 실제 우위인지 별도로 검증해야 한다.

## 자세한 내용

### 비교 조건과 선정 이유

- 유니브: 자료를 빠르게 퀴즈·카드로 바꿔 시험 공부를 시작하는 직접 경쟁 흐름.
- RemNote: 문서 정리와 카드·복습 계획을 연결하는 반복 학습 경쟁 흐름.
- NotebookLM: 소스 중심 읽기·질문과 생성 학습 자료를 같은 공간에 둔 경쟁 흐름.
- 자료는 직접 작성한 BFS 기초 텍스트 하나다. 큐/FIFO, 방문 처리, 동일 가중치 최단 경로, 복잡도, 작은 그래프, 연결 요소, DFS와 차이를 포함했다. 개인 PDF·기출·노트는 전송하지 않았다.
- 각 서비스에 연구용 문서만 새로 만들었다. 기존 개인 문서는 수정하지 않았다. 유료 상품 구매나 구독 변경은 하지 않았다. 서비스의 기존 AI 사용량은 소모될 수 있다.
- RemNote 입력 과정에서 줄바꿈 자동 조작이 안정적이지 않아 본문을 한 문단으로 입력했다. 의미는 같지만 레이아웃은 다르다. 이 현상을 제품 자체의 결함으로 집계하지 않는다.

### 유니브에서 확인한 점

10문항은 객관식 3개·OX 3개·단답 2개·빈칸 2개였다. 생성이 끝나기 전에 풀 수 있었고, 풀이 중 총 문항 수가 늘었다. 기다림을 줄이는 장점과 진행량이 불명확해지는 단점이 함께 있었다.

퀴즈 종료 후 취약 주제와 유사 문제 5개를 만드는 버튼이 나타났다. 이 후속 생성은 실행하지 않았다. 플래시카드는 별도로 10개가 만들어졌고 모름/앎을 각각 한 번 선택했다. 카드 홈으로 돌아왔을 때 생성한 카드 묶음이 남아 있는 것을 확인했다. 다음 날의 실제 예약 동작은 확인하지 않았다.

문항 대부분은 입력 내용과 맞았으나 결과 조언의 '가중치가 1이 아닌 그래프'라는 표현은 부정확한 일반화 소지가 있었다. 모든 간선 가중치가 동일한 2인 경우에도 BFS의 최소 간선 경로는 최소 비용 경로다. 본문 문제 자체의 '가중치가 서로 다른 경우'와 조언을 구분해 평가해야 한다.

### RemNote에서 확인한 점

사전 지식 수준을 선택한 뒤 학습 계획이 생겼고, 요약 읽기·카드·퀴즈로 이어졌다. 요약에는 별도 짧은 답변 질문도 있었지만 이번에는 답하지 않았다. 카드 3개 판정 후 문서로 돌아오니 14개 복습 대상과 취약 개념 안내가 표시됐다. 현재 문서에서 다음에 무엇을 할지 연결하는 방식이 가장 분명했다. 날짜를 실제로 넘겨 예약 유지까지 확인한 것은 아니다.

요약의 그래프 예시는 입력에 없던 C-D·D-E 연결이 포함된 다른 예시로 바뀌었다. 새 예시 자체가 알고리즘적으로 틀렸다는 뜻은 아니지만, 원자료 예시와 추가 예시의 경계가 불명확했다. 입력에 없던 Dijkstra 설명도 추가됐다. 원자료 충실성이 중요한 시험 공부에서는 별도 검토할 지점이다.

### NotebookLM에서 확인한 점

소스·채팅·Studio가 나뉘어 있고 퀴즈는 Studio에서 열렸다. 생성 설정에서 문제 수·난도·이미지 포함·문제 유형 등을 선택할 수 있었다. 기본 설정으로 단일 선택 7개·복수 선택 3개, 총 10문항이 생성됐다.

선택 후 보기별 설명을 바로 제공하며, 결과에서는 오답만 기본적으로 모아 보여줬다. '퀴즈 다시 풀기' 메뉴 안에 '틀린 문제 다시 풀기'가 있는 것까지 확인했다. 후속 퀴즈 생성은 실행하지 않았다. 이번 화면에서 간격 복습 계획은 확인하지 못했으며, 이것을 서비스 전체에 해당 기능이 없다는 증거로 삼지 않는다.

방문 순서와 최단 간선 수 문제는 입력의 A-B, A-C, B-D, C-E 그래프와 일치했다. 연결되지 않은 정점 관련 문항은 서로 가까운 내용을 반복했다. 보기 일부는 명백히 관련 없는 선택지여서, 정답률만으로 이해를 측정하기는 어렵다.

### 확인 범위 및 남은 일

- 완료: 세 서비스 동일 의미 텍스트 등록·실제 AI 생성·학습 화면 조작. 유니브/NotebookLM 퀴즈 종료, RemNote 카드 판정과 후속 안내.
- 미실행: RemNote 퀴즈, 각 서비스 추가 생성, PDF/OCR, 태블릿 비교, 다음 날 재방문, 장기 기억 효과, 같은 텍스트의 Recaller 생성 비교.
- 서비스 내부 호출 수·토큰·정확한 지연은 노출되지 않아 미측정. 카드 개수나 많은 기능을 품질 우위로 환산하지 않았다.
- 근거는 로그인된 실제 화면과 접근성 상태 관찰이다. 이번 보충 실험의 화면 캡처 파일은 아직 보존하지 못했으므로 캡처 첨부 완료로 쓰지 않는다.
- 연구용 탭은 사용자가 직접 확인할 수 있도록 유지했다. 제품 코드를 고치거나 사용자 저장소를 동기화하지 않았다.
