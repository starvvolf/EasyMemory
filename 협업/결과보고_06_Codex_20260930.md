# 작업지시 06 결과 (2026-09-30)

## 결론

되짚기 요청의 선택 능력을 생성 엔진에 전달하고, MCP 5단계 결과를 출제 입력 패킷으로 연결하는 경로를 마련했다. **실제 한마디 요청으로 AI가 끝까지 생성해 `/study`에 준비됨으로 나타나는 전체 실행은 아직 검증하지 않았다.** 유료 MCP/API 재생성은 실행하지 않았다.

## 반영한 흐름

`/study`가 만든 요청 → 담당 AI가 대기 요청 조회·점유 → 원문 읽기 도구로 등록 PDF의 선택 쪽을 읽기 → 원문 목차·개념트리·학습 설계·활동 설계·카드의 5단계를 제출하고 요청에 기록 → 완료 요청을 출제 패킷으로 고정 → 문제 출제 실험실에서 작성·검사·기록. 마지막 기록이 있어야 화면에서 준비됨으로 판정한다. 이 흐름은 MCP 안내문과 도구 설명에 넣었으며, 별도의 상주 자동 실행기를 만든 것은 아니다. 요청 완료와 출제 기록 사이의 공백은 그대로 존재한다. 이를 요청의 여섯 번째 단계로 바꾸려면 계약 변경이 필요하다. 글자가 추출되지 않는 스캔 쪽은 읽기 도구가 빈 글자를 반환하므로 현재 경로에서 AI가 내용을 추측해서는 안 된다.

다시 만들기는 기존 학습 설계를 재사용하고 `selectedObjectiveIds`를 활동 설계·카드·출제 패킷에 유지한다. 패킷 변환 테스트에서 선택한 목표만 남는 것을 확인했다. 원본 5단계 실행과 문제 출제 실험실의 실제 연속 호출은 미검증이다.

## 사용자와 결정한 계약

| 결정 | 반영 내용 |
| --- | --- |
| 학습 능력 | `abilities`를 요청의 선택값 목록으로 추가했다. 화면의 다섯 선택지를 그대로 보존하며 활동 설계 입력과 충족 경고에 사용한다. 목표 문장에서 다시 추측하지 않는다. |
| 원문 그림 좌표 | `SourceAssetRef.crop`은 페이지 폭·높이에 대한 0~1 비율로 정하고 범위를 검사한다. 실제 PDF 잘라 보여 주는 화면은 이번 범위가 아니다. |
| 원문 근거 | 새 학습 설계의 `sourceText`에 실제 PDF 문구를 사용한다. 여러 인용은 `||`로 구분한다. 공백·줄바꿈·하이픈을 정리해 등록 PDF의 해당 쪽 글자와 대조한다. 글자가 없는 쪽은 `원문 글자 없음` 경고, 등록 PDF가 없는 구형 결과는 `원문 PDF 없음`으로 표시한다. 구형 기록은 수정하지 않았다. |

## 검사와 기존 자료 결과

- 선택 능력 검사: 계산·적용을 골랐지만 직접 해결할 문항 설계가 없으면 경고한다. 절차 쓰기는 절차형 학습 내용인데 순서 복원이 없을 때만 경고한다. 단순 공식 자료까지 절차형으로 오판하지 않는다.
- 원문 검사: 실제 인용, 여러 인용, 공백·하이픈 차이, 원문 불일치, 글자 없는 쪽을 단위 테스트로 확인했다.
- 기존 r02 문서의 새 품질 검사 결과(경고·오류의 *발견 개수*, 자동 수정 건수 아님):

| 자료 | 긴 주관식 답 | 절대 배치 | 정답 길이 단서 | 불가능한 오답 표현 | 기타 |
| --- | ---: | ---: | ---: | ---: | --- |
| 기하 변환 | 7 | 16 | 6 | 3 | 중복 문항 1, 원문 표기 누락 1 |
| 반도체 | 3 | 6 | 12 | 7 | 정답 최장 비율 1 |

두 기존 문서는 새 선택 능력이나 등록 PDF 원문 인용 필드를 갖춘 요청이 아니므로, 그 두 검사의 과거 문서 점수인 것처럼 해석하지 않는다. 품질 검사는 기존 문서를 읽기만 했으며 결과물은 재생성하지 않았다.

## 출제 하네스

선택지의 길이·문체를 맞추고 오개념에서 오답을 만들도록 지침을 보완했다. 긴 복합 답은 개별 빈칸·순서 배열·자기 채점으로 분리하고, 원문 표기는 인정 답안에 먼저 넣도록 했다. `sourceRange`는 위치, `knowledgeContent`는 요약으로 구분했다. 그림을 겹치지 않는 문항은 흐름 배치를 기본으로 렌더링하도록 변경했다. 화면 캡처는 브라우저의 로컬 파일 접근 제한과 헤드리스 브라우저 실패 때문에 만들지 못했으므로 데스크톱·모바일 육안 검증은 남았다.

## 실행한 검증

- 관련 단위 테스트 55개 통과.
- `mcp:study-forge:test` 20개 통과.
- 린트: 오류 0개, 기존 경고 21개.
- 프로덕션 빌드: 성공. 기존 동적 파일 접근 경고 2개.
- 변경 파일 공백 검사: 통과.
- 저장된 완료 요청 2건을 읽기 전용으로 패킷 변환해 각각 22개, 28개 목표·출제 단위 연결을 확인했다. 이 작업은 새 문제 생성이 아니다.

실제 모델 호출을 하지 않았으므로 전체 처리 시간은 측정하지 못했다. 목차·쪽 단위로 분할할지 여부도 이 결과만으로 결정할 수 없다. 다음 검증은 유료 실행 승인 후 요청 하나를 처음부터 출제 기록까지 처리하고, `/study` 준비됨·다시 만들기·데스크톱/모바일 문항 배치를 함께 확인하는 것이다.
