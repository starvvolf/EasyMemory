# ChatGPT 로그인 경로의 프롬프트 캐시 — 실측 (D, 2026-11-03)

ChatGPT 로그인으로 모델을 부르는 모든 곳(앱 `src/lib/ai/chatgpt-provider.ts`, 프로젝트 코스 튜터)에 해당한다. 사용자 요청으로 조사·실험했고, API 키 호출은 사용자가 허락한 비교 실험에서만 썼다.

## 한 줄 결론

ChatGPT 로그인(Codex 백엔드)은 **`session-id` 헤더가 없으면 캐시를 거의 다시 쓰지 않는다.** 헤더를 붙이고 **앞 요청의 메시지를 그대로 둔 채 뒤에 덧붙이면** 같은 경로에서도 캐시가 맞는다(실험 97%, 실제 튜터 질문 약 40%).

## 실측

모델 gpt-6.1-terra, 입력 약 5,100토큰. 숫자는 응답 원문 `usage.input_tokens_details.cached_tokens`.

| 실험 | ChatGPT 로그인, 헤더 없음 | ChatGPT 로그인 + `session-id` | API 키 |
|---|---|---|---|
| 같은 요청 두 번 | 대개 0, 여러 번 반복하면 가끔 거의 전부 | — | 두 번째 1,754 / 1,757 |
| 대화 이어 쓰기(앞 요청 전체 + 답 + 새 질문) | 0 (0초~60초 쉬어도) | **4,992 / 5,149** | 5,103 / 5,149 |
| 메시지 하나 안에서 끝만 다르게 | 0 | 0 (가끔 4,992) | 앞부분(지시문 + 도구) 1,301 |
| 실제 튜터 질문(질문마다 새로 조립, 헤더 없음) | 24번 넘게 전부 0 | — | — |
| 실제 튜터 질문(이어 쓰기 + `session-id`) | — | 7번 중 3번 적중, 입력 토큰의 약 39% | — |

- 앱의 PDF 생성 엔진(같은 로그인, `session-id` 없음) 기록도 약 4,700건 중 190건쯤(4%)만 캐시가 맞았다.
- 요청 본문을 비교하면 모델 · 도구(이름 · 순서 · 정의) · 지시문 · 추론 설정 · `prompt_cache_key`가 같았고, 고정 앞부분이 1,757토큰(최소 1,024 이상)이었다. 본문 문제가 아니었다.
- 로그인 토큰은 매번 같았다(해시로만 비교). OpenCode의 사용량 보고도 원문과 같았다(보고 오류 아님).
- 캐시 진단(`prompt_cache_options.comparison_response_id`)은 이 경로에서 `unavailable`로 온다(`store: false`가 필수라서로 보임).

## 지키면 되는 것

1. **`session-id` 헤더**(우리는 `session_id`도 같이)를 같은 대화마다 같은 값으로 붙인다. `prompt_cache_key`만으로는 안 된다. OpenCode가 붙이는 `x-session-id` · `x-session-affinity`도 이 헤더를 대신하지 못한다.
2. **덧붙이기만 한다.** 캐시는 메시지 끝에서 끊긴다. 앞 요청의 `input` 항목들이 다음 요청에 바이트 그대로 남아 있어야 한다. 질문마다 맥락을 메시지 하나로 다시 조립하면, 헤더를 붙여도 거의 안 맞는다.
3. **바뀌는 것은 뒤에.** 지시문 · 도구 · 고정 설명이 앞, 상태 · 파일 · 질문은 맨 뒤의 새 메시지로.
4. **너무 길어지면 그때만 압축.** 요약을 들고 새 대화로 간다. 그 한 번만 캐시가 안 맞는다(튜터는 입력 24,000토큰 기준, `PC_COMPACT_TOKENS`).
5. **그래도 보장은 없다.** 같은 요청도 서버 배정에 따라 맞거나 안 맞는다(아래 openai/codex #33821). 실제 튜터에서는 7번 중 3번만 맞았다.

## 확인하는 법

- 응답 원문의 `usage.input_tokens_details.cached_tokens`를 남긴다. 튜터는 `experiments/project-course/.data/prompts/usage.jsonl`의 `raw`에 남긴다.
- 프로젝트 코스 서버의 `POST /api/debug/cache-probe`: 마지막 튜터 요청을 변형해 두 번씩 보내 비교한다. AI 사용량이 든다. 변형 이름은 `lib/cacheprobe.ts`에 있다. `headers: {"session-id": …}`로 헤더 실험, `apiKey: true`로 API 키 비교(사용자 허락 필요)를 할 수 있다.

## 다른 영역에 대한 메모(고치지 않았다)

- 앱 `chatgpt-provider.ts`는 `session-id` 헤더를 보내지 않는다. PDF 생성(C)처럼 같은 앞부분을 여러 번 보내는 곳은 실행 하나마다 같은 `session-id`를 붙이면 캐시가 늘 수 있다. 주인 영역이라 손대지 않았고, 붙인다면 호출 기록(`토큰 사용량 보기.cmd`)으로 전후를 비교한다.
