## Claude가 판단할 것

### P0 — 공부를 시작하기 전에 호출 상한으로 막힘

원문 목차 응답(호출 53번)부터 이미 모든 쪽을 1쪽짜리 항목 52개로 나눴다. 서버가 나중에 자동으로 52개로 자른 것이 아니다. 표지·수업안내·교재안내·QUIZ도 각각 분류와 설계 호출을 받는다. 호출은 목차 수에 비례하는데 목차 단위가 페이지 제목 수준으로 잘게 잡혀, 모든 설계를 끝내기 전 60회 제한에 도달한다.

이번 A는 이미지 52회 + 목차 1회 + 분류 31회 + 설계 28회 = 총 112회. 나머지 분류 22목차·설계 24목차만 해도 최소 46회가 추가로 필요하다. 재시도·출제를 빼도 승인 잔여 18회를 넘는다. 목차를 얼마나 묶을지와 전체 설계 완료 전 학습을 막는 현재 정책을 판단할 필요가 있다. GPT는 목차·프롬프트·단계를 수정하지 않았다.

### P0 — ‘이어간다’는 안내와 `/study`의 다시 시작 연결이 다름

멈춤 화면은 “다시 시작하면 멈춘 곳부터 이어가요”라고 안내하며 `다시 시작` 버튼을 보여 준다. 그러나 `src/app/study/DejipgiStudy.tsx`의 `builder.restart`에서 새 엔진 ID에 대해 `startGen(...)`을 호출한다. 이는 `/api/lab/gen`에 새 실행을 POST하는 함수다. 기존 ID의 `/continue`를 호출하는 경로가 아니다.

따라서 버튼을 누르면 기존 그림 읽기·목차·분류·설계를 이어 쓰는 대신 새 실행을 만들 위험이 있다. **코드 경로에서 확인한 문제이며, 버튼을 눌러 실제 중복 호출을 발생시키지는 않았다.** 남은 예산 안에서 안전하게 시험할 수 없어서 미검증으로 남긴다.

### P0 — 사용자 승인 상한과 엔진 내장 상한이 다름

`runner.ts`는 한 번 실행할 때 그림 읽기를 제외한 60회만 제한한다. 이미지 쪽 읽기에는 쪽당 최대 2회 시도가 있고, 실행 전체/자료 전체의 130·80회 예산을 입력하거나 강제하는 계약은 없다. 화면에도 누적 호출 수가 바로 보이지 않는다.

B는 그림 대상 32쪽 + 일반 호출 최대 60회 = 재시도 없는 경우에도 최대 92회가 가능하다. 이미지 재시도까지 고려한 이론상 첫 실행 최대는 124회다. 승인된 전체 80회 상한을 안전하게 보장할 방법이 현재 `/study`에 없어 **B는 실제 실행하지 않았다**. 예산을 임의로 늘리거나 그림 읽기를 끄거나 범위를 줄여 다른 실험으로 대체하지 않았다.

### P1 — 안내문을 외우는 목표로 오인

아래는 완성 문제가 아니라 **중간 학습목표**다. 아직 출제되지 않아 문제 ID는 없으며 목표 ID와 실제 PDF 쪽을 남긴다. 원문 5·6·8쪽 이미지를 직접 렌더링해 확인했다.

- **`s5-o1`~`s5-o5`, PDF 5쪽:** 원문은 ‘기업윤리의 개념과 중요성을 이해하고 설명할 수 있다’ 등의 교과 학습목표를 안내한다. 생성 결과는 ‘교과의 첫 번째/두 번째/… 학습 목표를 말할 수 있다’이고 외울 답도 안내 문장 자체다. 분류 단계에서 안내문을 `핵심 지식`으로 지정한 뒤 설계가 이를 암기로 바꿨다. 학습내용의 실패는 출제 전부터 시작됐다.
- **`s6-o1`, PDF 6쪽:** 원문은 수업의 진행 방식 ‘도입사례 → 이론강의 → 사례분석 → 학습요약 → 퀴즈’다. 분류는 `학습 지시`로 맞게 했지만, 설계에서 ‘한 회차 수업의 진행 단계를 순서대로 말하기’를 핵심 목표로 만들었다.
- **`s8-o1`, PDF 8쪽:** 원문의 성적 반영 안내 ‘시험(지필고사): 70%’를 핵심 암기 대상으로 지정했다. 분류는 `학습 지시`인데도 설계에서 70%를 외우게 했다. 명시적인 오리엔테이션 암기 요청이 없는 핵심 암기 시험공부에서는 우선 대상으로 보기 어렵다.

숫자·인용은 원문과 일치한다. **원문 충실성 통과가 학습 가치 통과를 뜻하지 않는 사례**다. 위 3쪽은 문제 원인 확인을 위해 골라 본 표본이지, 지시한 ‘목표 확인에서 무작위 3개 확인’을 수행한 것으로 세지 않는다.

### P2 — 중간 결과의 실패·검증 범위를 사용자가 알기 어려움

- 호출 57번(`design`, `s1`)은 “ChatGPT 응답이 완료되지 않았어요”로 기록됐다. 최종 중단 이유는 이 오류가 아닌 호출 상한이다. 사용량 한도·로그인 실패는 기록되지 않았다. 이 오류가 사용자 화면에서 별도 드러나는지 확인하지 못했다.
- `/study`에서는 그림 완료 수와 현재 목차가 보이지만 누적 112회 호출, 남은 설계량·예산은 실험실을 열어야 알 수 있다. 화면의 ‘약 6분 더’는 그림 읽기 추정이며 전체 생성 완료 예상 시간이 아니다.
- 첫 목차가 끝나면 학습할 수 있다는 구현이 있어도 이번에는 **모든 목차의 설계가 끝나야 출제 단계로 가는 조건** 때문에 그 이점을 확인하지 못했다.

### 호출·토큰 수치의 해석

실제 기록 합계 입력 188,515 + 출력 30,419 = **218,934토큰**. 응답 미완료 1건의 usage는 반환되지 않아 이 합계는 확인 가능한 usage만 합친 값이다. 해당 실패가 무료였다고 간주하지 않는다. 캐시·추론 세부 토큰 및 결제 비용은 현 기록만으로 채우지 않았다.

모델 호출 시간 합은 966.616초지만 그림·분류/설계가 병렬로 돌아 실제 벽시계 시간은 462.965초였다. 호출 수에는 기록된 실패 1건이 포함된다. 재시도 기록과 오류 여부는 구분해야 한다(예: 분류 30목차에 31회 시도).
