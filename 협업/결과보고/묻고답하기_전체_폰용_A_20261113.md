## 1. 자료(PDF) 엔진

**Q. PDF를 통째로 한 번에 넣으면 왜 안 되나?**
- 입력이 커진다 (50쪽 = 글+그림 수만 토큰)
- 출력이 한 줄로 길어져 **느리다**
- 슬라이드에는 사실로 확인된 "느리다"만 씀

**Q. 그래서 어떻게 했나?**
- 먼저 **줄기 계획** 1번: 어디서 어디까지 한 덩어리인지
- 덩어리마다 카드 쓰기를 **동시에**
- 쪽마다 그림을 미리 그려 두고, 그 덩어리 쪽만 보냄

**Q. 나누면 카드 품질은?**
- 덩어리 호출마다 줄기 계획(전체 흐름 · 앞뒤 이름)을 같이 줌
- 끝에 흐름 · 합치기 · 확인 호출
- 코드 검사: 근거 쪽 번호, 빈 칸, 중복

**Q. 덩어리 크기가 다르면?**
- 내용 단위로 나눠서 다를 수 있음
- 큰 덩어리는 쪽 · 카드가 많을 뿐
- 동시에 돌아서 가장 큰 덩어리가 전체 시간을 정함

**Q. 07 카드에 왜 주사선 그림이? 여러 장은 안 되나?**
- 예전엔 카드당 그림 **1장**만 골라서 먼저 보인 그림이 붙음
- 11/13: **최대 3장**, 가장 맞는 것 먼저 → "그림 1/N"으로 넘겨 봄
- 참고: 고러드 셰이딩은 밝기를 주사선 따라 보간 → 아주 엉뚱하진 않았음

**Q. PDF에 유튜브 영상 넣으면 재생되나?**
- 보통 안 됨. 링크 누르면 브라우저로 열림
- 영상은 PPT에 파일로 넣거나 따로 띄우기

## 2. 알고리즘 — 문제 가져오기

**Q. 백준 번호를 넣으면 원문은 어떻게?**
- 앱 서버가 직접 받음. AI 안 씀
- 백준이 2026년 4월 종료 → **인터넷 아카이브 저장본**에서
- 순서
  1. `acmicpc.net/problem/번호` 주소 만듦
  2. 아카이브에 가까운 저장본 묻기 (없으면 저장본 목록에 한 번 더)
  3. 툴바 없는 원래 페이지 받기
  4. 칸 이름표로 제목 · 문제 · 입출력 · 예제 잘라냄
- 글자 그대로. 2~6초, 20~25초면 포기
- 저장본 없는 문제는 못 가져옴

**Q. 크롤링인가?**
- 엄밀히 **스크래핑**
- 크롤링은 아카이브가 함
- 우리는 번호 넣을 때 한 장만 받아 칸을 잘라 옴

**Q. 웹 검색으로 찾은 문제는?**
- AI는 주소만 찾음, 원문은 코드가 받음
- 백준 → 아카이브
- 다른 사이트 → 그 페이지 (막히면 아카이브)
- 블로그 → 그 글이 다룬 백준 문제의 원문 먼저

**Q. 번호 넣으면 전체 흐름은?**
1. 같은 문제 있는지 (즉시) → [열기]/[새로 만들기]
2. 원문 받기 (2~6초)
3. 바로 열림: 읽기 · 코드 · 예제 실행 가능, 제출만 잠김
4. 뒤에서 채점 준비 (AI 4개 동시, 15~50초) → 제출 열림
5. 난이도 표시 (AI 1번, 처음만)

**Q. AI가 문제 고르기에 영향을 주나?**
- 백준 번호: 학습자가 고름 → 영향 없음
- 튜터 추천: 코드 규칙 → 영향 없음
- 주제로 찾기: AI 웹 검색 1번 → 영향 있음
- 그래도 원문 · 채점은 똑같이 검증 (없는 문제면 실패)
- 수준에 맞는지는 코드가 검사 안 함

**Q. 웹 검색은 어떻게 후보를 고르나?**
- 넘기는 것: 최근 5문제, 푼 목록(30), 학습자 기억, 다음 패턴 3개, 요청
- 기준: 실제 문제만, 백준 먼저, 표준 입출력만, 틀렸으면 쉽게 · 잘했으면 한 단계 위
- 코드가 걸러 **최대 3개**

**Q. 웹 검색 API는 입출력이 어떻게?**
- 보냄: 지시문 + 기록 요약 + 웹 검색 도구 + 답 형식
- 모델이 검색어를 정해 여러 번 검색
- 받음: 후보 목록 JSON (검색어 · 본 페이지는 저장 안 함)
- 공개 웹은 거의 다, 로그인 필요한 곳은 못 봄

**Q. "검색 결과가 입력 토큰"이란?**
- 모델은 인터넷을 직접 못 봄 → 검색 결과가 글로 붙음
- 보낸 건 1천 토큰이어도 실제 읽는 건 1만+
- 실측: 입력 약 12,800 · 9.3초 → 느리고 비쌈

**Q. 튜터 추천은?**
- 코드 규칙, AI 안 씀
- 바킹독 단원별 문제 · 패턴 44개 순서
- 고르는 순서
  1. 어제 도움 받고 푼 문제 혼자 다시
  2. 다시 볼 날 된 패턴 복습 (최대 2)
  3. 지금 패턴 다음 단계 (시범 → 알아채기 → 설계 → 구현)
  4. 섞어 풀기
- 막히면 한 단계 물러남

**Q. 시작 전 패턴 점검을 뺐는데 추천이 의미 있나?**
- 처음 배우는 사람: 있음 (푼 결과로 정함)
- 잘하는 사람: 약함 (아는 것도 처음부터)
- 보완안 "풀어서 증명하면 건너뛰기" — 미정

**Q. 문제 고르기를 어떻게 설명하나?**
- 구조도에서는 **"문제 가져오기" 하나**로 묶음

## 3. 알고리즘 — 채점 준비

**Q. 채점 준비가 뭔가?**
- 백준 서버가 하던 두 가지를 내 PC에서 대신
  - 숨은 테스트 → AI가 **테스트 만드는 프로그램**을 쓰고 코드가 돌려 확인
  - 채점 서버 → Windows 작업 개체 + PC 속도 보정
- 보안 격리는 일부러 낮춤 (내 코드를 내 PC에서)
- AI가 쓴 코드는 환경 변수 비운 별도 프로세스

**Q. AI 4개는 각각?**
- 세팅: 모범 풀이 + 단순 풀이(완전탐색)
- 테스트 생성기: 입력 만드는 `gen` + 제약 보는 `check`
- 틀린 풀이: 흔한 실수 3~5개
- 독립 풀이: 다른 모델이 문제 글만 보고

**Q. 코드는 무엇을 확인하나?**
1. 입력 최대 60개, 제약 어긴 것 버림
2. 모범 풀이가 원문 예제를 맞혀야 함
3. 작은 입력 수백 개에서 단순 풀이와 같은 답
4. 독립 풀이와 모든 테스트에서 같은 답
5. 틀린 풀이를 잡는지 점수, 못 잡으면 반례 추가
- 어긋나면 다시 (최대 3번)
- 문제당 15~50초, 약 $0.04

**Q. 테스트 생성기는 정확히?**
- **입력만** 만듦. 정답은 모범 풀이가 냄
- 종류 × 크기로 나눔 (예: "1번이 고립", "최대 · 한 줄로 길게")
- 흔한 실수를 노림. 같은 시드면 같은 입력

**Q. 틀린 풀이는 왜?**
- 테스트가 쉬우면 틀린 코드도 통과함
- 일부러 틀린 풀이를 돌려 잡는지 봄
- 안 잡히면 반례를 테스트에 영구 추가

**Q. 모범 · 독립 풀이가 같은 실수를 하면?**
- 다른 모델 (terra / sol), 서로 안 봄
- 원문 예제가 기준, 단순 풀이와도 대조
- 남는 구멍: 둘 다 같은 조건을 놓치면 못 잡음 → 100% 보장은 아님

**Q. 숨은 테스트 용량은?**
- 10만 글자 넘는 입력은 **만드는 방법만** 저장 (종류 · 크기 · 시드)
- 제출할 때 다시 만들고 메모리에 둠
- 상한: 문제당 60개, 합계 40MB

**Q. 40MB는 너무 크지 않나?**
- 저장 크기가 아니라 만들 때 **안전선**
- 디스크엔 보통 수십~수백 KB (실측 전)

## 4. 알고리즘 — 내 PC에서 채점

**Q. 보정은 어떻게?**
- 처음 알고리즘 탭 열 때 한 번 (10~20초, AI 없음)
- 30일 지나거나 컴파일러 바뀌면 다시

**속도 배율**
- 계산 · 메모리 읽기 · 정렬을 3번씩
- 기준 PC와 나눈 비율의 기하평균
- 5% 안쪽 차이는 1로

**언어별 기본 몫**
- 빈 프로그램의 CPU · 메모리
- Python 61MB · 62ms, JS 19MB, C# 9MB, C++ 0.6MB

**채점 예 (1초 · 256MB, Python, 배율 1.2)**
- 한도: CPU 약 1,622ms, 메모리 약 343MB → 넘으면 OS가 멈춤
- 되돌리기: CPU 1,262 → 1,000ms, 메모리 141 → 80MB
- 조금 넘으면 "PC 차이로 봐줬어요"

**한계**
- 진짜 백준 속도는 이제 모름 → 만든 사람 PC가 기준
- 계산 종류마다 PC 차이가 다름 (봐주는 몫이 흡수)
- 노트북은 전원 모드에 따라 흔들림, Windows에서만

## 5. 알고리즘 — 푸는 중 · 리뷰

**Q. 푸는 중 코드는 어디에 남나?**

**Q. 실행 기록의 두 코드(길이 다름)는 둘 다 맞나?**

  - `key=lambda p: (p[0], p[1])` → 맞았습니다 41/41

  - `key=lambda p: (p[1], p[0])` → 맞았습니다 42/42

## 6. 실습 — 튜터가 코드 보는 법

**Q. 실습은 어떻게 두고, OpenCode는 무슨 역할?**
- 왼쪽 **편집기**(VSCodium)
- 가운데 **OpenCode**: 코딩 에이전트 엔진 (파일 읽기 · 명령 실행)
- 오른쪽 **학습 시스템**: 목표 · 판정 · 막힌 순간 · 기록
- OpenCode에 학습용 도구 몇 개를 더 줌

**Q. "공식 문서 6곳 · 짚어 주기 · 코드 조각 돌려 보기"는?**
- 튜터 도구
- 공식 문서 6곳: 찾아볼 문서 사이트를 정해 둠
- 짚어 주기: 편집기에서 그 파일 그 줄을 열어 줌
- 코드 조각: 짧은 예시를 따로 4초까지 실행
- 발표 그림에선 "· · ·"로

**Q. 상태를 굳이 도구로 바꾸는 이유?**
- 목표를 대화 글에만 두면 코드가 믿고 쓸 수 없음
- 튜터가 도구로 정하면 **데이터로 남음**
- 판정 · 기록 · 화면은 코드가 그 값으로 처리
- "AI는 돕고, 판정 · 기록은 코드" 원칙

**Q. 튜터가 파일을 왜 안 읽나?**
- 아예 안 읽진 않음 (시뮬에서 6번)
- "됐다"고 하면 안 읽음
  - 터미널 출력으로 충분하다고 봄
  - 지시가 "필요하면 읽어라", 강도 low
- 놓친 예: lock 밖에서 값 읽는 실수 (출력이 맞게 나옴)

**Q. low와 medium 차이?**
- 아마 medium이 도구를 더 부름 (장담은 못 함)
- 대신 느려짐 → 채팅마다 학습자가 고름, 기본 low

**Q. 열린 파일을 코드로 바로 보내면?**
- 통째로 매번 보내면
  1. 같은 코드가 계속 쌓임
  2. 열린 파일이 고친 파일이 아닐 수 있음
  3. 상관없는 질문에도 끼어듦
- 그래서
  - 지난번 뒤 **바뀐 파일만**
  - 열린 파일 + 그 사이 저장된 파일
  - 150줄 이하 통째, 크면 바뀐 줄만

**Q. Ctrl+S 안 해도 아나?**
- 보고 있는 파일 하나는 앎 (1.2초 뒤 보냄)
- 다른 탭의 저장 안 한 파일은 모름
- 실행은 저장된 파일로 → "저장 안 함" 표시해서 튜터가 짚게

**Q. 다른 도구(Claude Code · Cursor · Codex · OpenCode)는?**
- 대부분 도구로 불러서 읽음
- 자동으로 붙는 건 파일 이름 · 고른 줄 정도
- 우리는 Claude Code 쪽: 바뀐 코드는 코드가 알려 주고, 나머지는 튜터가 읽음

**Q. 터미널도 들어가나?**
- 들어감. 연결 확장이 명령 · 출력을 보냄
- 지난 차례 뒤 최대 5개가 맥락에 붙음
- 판정 · 막힌 순간에도 씀

**Q. 시연 때 코드가 맞는데 튜터가 "애매하다"고 한 이유?**
- 서버 출력은 **서버를 끌 때(Ctrl+C)** 넘어갔음
- 튜터는 "이번 클라이언트 결과" + "한 번 전 서버 로그"를 짝지음 → 숫자가 안 맞음
- 한 번은 고치기 전 서버가 그대로 돌아 실제로 틀림 (15·5 받고 10씩 깎음)

**Q. 서버 안 끄고도 볼 수 없나?**
- 11/13 고침 (연결 확장 0.9.7)
- 명령 하나 끝날 때마다 아직 도는 서버 로그도 같이 보냄
- 노트북에서 확인: 서버 켠 채 클라이언트 → 튜터가 서버 로그로 답함

**Q. `.class`가 깨진 글자처럼 보이는데?**
- 컴파일된 바이너리라 원래 그럼
- `.java`를 열면 됨

## 7. 실습 — 화면과 목표 흐름

**Q. 버튼마다 의미가 있나?**
- 홈 버튼 하나
- 도움 다이얼: 스스로 · 같이 · 빨리 만들기 ("빨리"면 튜터가 파일 고치기도 허락)
- 모델 · 생각 강도는 학습자가 고름
- [기록]은 개발자 모드에서만

**Q. 탑다운 · 바텀업 질문은 빼도 되나?**
- 됨. 튜터가 말과 수준을 보고 고름

**Q. 튜터가 "이 버튼 누르세요"라고 하는 이유?**
- 11/5~6 지시가 있었고, 11/8에 뺌
- 지금은 "버튼 누르라고 안내하지 않는다"

**Q. 버튼 배치 (11/13)**
- [이해했어요 → 적용하기] · [해 봤어요] · [다음으로]를 채팅창 위로
- "도움"은 제목처럼 보이게
- "배운 것 · 부족했던 점" 칸은 빼고 기억 도서관 리뷰로

**Q. 선행은 뭐였나? 필요한가?**
- 목표마다 붙던 바탕 지식 3~5개 (알아요/몰라요)
- 시뮬에서 거의 안 쓰임, 비는 곳은 대화 · 판정에서 드러남
- → **선행 전체를 뺌** (11/12~13)

**Q. 목표 · 완료 조건 · 이해 · 적용은?**
- 완료 조건: "끝냈다고 칠 장면" 한 문장
- ① 이해: 튜터가 설명 → [이해했어요]는 학습자가 누름
- 넘어갈 때: 튜터가 작은 과제 하나 (완성 코드 X)
- ② 적용: [해 봤어요] → 판정 AI가 맞음 · 일부 · 틀림 · 근거 부족
  - 맞음일 때만 "적용 ✓"
  - 일부 · 틀림은 부족함 원장에
- [다음으로]: 언제든, 안 했으면 "건너뜀"

**Q. 지도 = 로드맵?**
- 같은 것 (코드 `map`, 화면 "로드맵")

**Q. [너무 어려워요] 보충은?**
1. 이유 고르기 (안 골라도 됨)
2. [이걸로 도와줘요] → 코드가 기록, 이유별 "채우는 법"을 튜터에게
3. 튜터가 보충 단계 1~4개
4. 단계마다 이해 → 적용
5. 막힌 목표에서 한 걸음 나아가면 원래 로드맵으로
- 또 막히면 더 쉽게, 3번째쯤엔 목표를 낮추자고 제안

**Q. 적용 과제 질은?**
- 15개 중 의미 있음 6 · 쓸 만함 4 · 사실상 "다시 실행" 5
- 원인: 조건이 "실행하고 확인", 코드가 이미 완성, 기대 출력을 적어 줌
- → "코드가 있으면 조건 하나 바꾼 변형, 정답 · 기대 출력 금지"

**Q. 시연에서 과제를 원하는 대로 나오게 하려면?**
- [이해했어요] 누르기 전에 계획을 말하면 그대로 냄
- 예: "적용은 공격력을 메시지로 받아서 5랑 15 보내는 걸로 해볼게"
