# 정리: 풀이가 끝나면 AI가 리뷰를 쓰게 한 과정 (알고리즘 B, 11/12)

실습(D)에 넘기는 정리다. 알고리즘 문제를 다 풀거나 그만두면 AI가 그 풀이를 리뷰하는데, 이걸 어떻게 만들었고 최종적으로 어떤 모양이 됐는지 적었다.
지시문 전문은 같은 폴더의 `지시문_AI학습리뷰어3차_B_20261112.md`에 있다.

## 한 줄 요약

**코드가 재료를 모으고(문제 · 센 사실 · 대화 원문 · 제출 코드) → AI 1번이 마크다운 글로 리뷰를 쓰고 → 코드는 머리글 두 개만 검사 → 화면이 머리글로 잘라 카드로 보여 준다.**
판정(맞음/틀림, 몇 번 물었나)은 코드가 세고, AI는 "무엇을 몰랐고 어떻게 이해하면 되나"를 쓰는 일만 한다.

## 1. 지나온 길 (11/11~11/12)

| 판 | 무엇을 바꿨나 | 왜 (사용자 말) |
|---|---|---|
| v12~13 | 발상 → 구현 마디 틀. 구현·문법 단계에는 그때 내 코드와 고친 코드를 붙임 | "구현이 발상 느낌으로 나왔는데 구현은 코드를 보여 줘야" |
| v14 | 시간 순서 이야기 + 약점이 보인 곳에만 상자(지금 내 상태 + 정성스러운 설명) | "흐름을 스토리처럼 가면서 약점이 보이면 박스로" |
| v15 | 상자 길이는 필요한 만큼 | "강의책급이라고 무조건 길게 갈 필요 없어, 친절하고 디테일하게" |
| v16 | 깐깐하게: 도움 없이 못 넘어간 건 모르는 것 | "어쨌든 모르는 거잖아… 깐깐하게" |
| v17 | 묶지 않고 드러난 때마다 따로, 작은 건 작게 큰 건 크게 | "묶는 것보다는 타임라인으로 분리… 작은 건 작게 큰 건 크게" |
| v18 | 예는 자유롭게(학습자 코드가 좋으면 그대로, 아니면 새 예·일반 예) | "지금 상황이 설명하기 좋으면 그대로… 문법은 제너럴하게도" |
| 실험실 | `/lab/review`에서 대화 범위 · 모델 · 강도 · 지시문 · 출력(JSON/글)을 바꿔 가며 비교 | "단위 작게… 프롬프트랑 모델 조정하면서 뭐 나오는지" |
| 글 출력 | JSON 대신 머리글 있는 글 | "JSON으로 꼭 해야 함?" → 가이드라인을 잘 주는 걸로 |
| 리뷰어 1차 | 사용자가 GPT와 만든 "AI 학습 리뷰어" 지시문 + 틀은 Claude가 잡음 | 사용자가 지시문을 가져옴 |
| 리뷰어 2차 | + 해설 규칙(실제 시도에서 출발) + 깐깐하게 + 실행 재현 · 작은 오류 누적 · 끝났을 때 상태 · 역량 중심 | 사용자 해설 규칙, GPT 피드백 1회차 |
| **리뷰어 3차 = v19 (제품)** | + 중복 제거 7가지 + 사실 확인([결과] 줄을 근거로) · 끝났을 때 상태 3줄 · "자잘하게 막힌 것"은 있을 때만 | GPT 피드백 2회차 |
| 11/13 | 재료에 제출한 코드도 | AI에게 안 묻고 제출만 한 풀이도 무엇을 고쳤는지 보이게 |

> 방향이 한 번 바뀌었다. v14~18은 **시간 순서 이야기 + 약점 상자**였고, v19는 **주제별 리뷰**(관련 사건을 묶어 학습 주제로)다.
> 3차 지시문은 "시간순으로 다시 나열하지 않는다"고 쓰지만, 11/12 약점 카드 정책의 핵심(깐깐하게 · 작은 건 작게 큰 건 크게 · 예는 자유롭게 · 다시 봤을 때 이해 쏙쏙)은 그대로 들어 있다.
> 크기는 주제마다 `[핵심]` / `[작은]` 표시로, 자잘한 건 "자잘하게 막힌 것"에 한 줄씩 남긴다.

## 2. 비교 실험 숫자 (2606 바이러스, 34번 물은 풀이 하나로)

| 지시문 | 시간 | 출력 토큰 | API였다면 |
|---|---|---|---|
| v18 (JSON, 이야기+약점 카드) | 111초 | 5.9k | $0.040 |
| 제품 지시문을 글 출력으로 | 88초 | 4.7k | $0.034 |
| 리뷰어 1차 | 50초 | 2.6k | $0.024 |
| 리뷰어 2차 | 63초 | 3.4k | $0.028 |
| **리뷰어 3차** | **57초** | **3.0k** | **$0.027** |

다른 문제(7576)에서 3차는 52초, $0.020. 제품에 넣은 뒤 2606을 다시 만들었을 때 58초 · 출력 3.1k. 입력은 약 11.7k 토큰(대화가 길어서).
JSON을 버리니 같은 내용이 짧아지고 빨라졌다. 따옴표 · 이스케이프 · 칸 이름이 출력에서 빠지고, 코드 블록이 JSON을 깨뜨리는 일도 없어졌다.

## 3. 최종 모양

**재료 (코드가 모음, AI 없음)**
- 문제 글 앞 1,200자, 이 문제가 보는 방법(패턴 이름)
- `[결과]` 한 줄: 끝(맞힘 · 그만둠 · 나감) · 제출 수와 판정별 수 · 예제 실행 수 · 연 힌트 칸 · AI에게 물은 수 · 걸린 분. **채점 기록에서 코드가 센 사실**이다.
- 대화 장부: 이번 풀이 범위에서 AI와 주고받은 원문 최근 40개. 각 항목에 그때 채점 결과와 그때 코드 앞 1,000자.
- 제출한 코드(11/13): 같은 코드는 빼고, 6개가 넘으면 첫 제출 · 판정이 바뀐 제출 · 마지막 제출.

**AI 1번 (gpt-6.1-terra · low, 스트리밍)**
- 고정 지시문(리뷰어 3차) + 출력 형식을 앞에, 재료를 뒤에 둔다(프롬프트 캐시).

**출력 (마크다운, 머리글 고정)**
```
# 학습 총평            3~5문장
# 끝났을 때 상태        스스로 한 것 / 도움 받아 한 것 / 아직 확인 안 된 것 — 세 줄
# 핵심 학습 리뷰
## 1. 주제명 [핵심]     **어려웠던 것** / **제대로 알기** / **정리**
## 2. 주제명 [작은]     (같은 틀, 짧게)
# 자잘하게 막힌 것      (있을 때만) `그때 코드나 말` → 이렇게 해요
# 다시 확인할 것        2~4줄
```

**코드 검사**: 머리글 `# 학습 총평`과 `# 핵심 학습 리뷰`가 있고 200자 이상이면 통과. 내용 판단은 하지 않는다.

**화면**
- 맞힌 직후 문제 화면에 진행 카드가 뜬다: "AI 튜터가 이번 풀이를 리뷰하고 있어요 · N초". 받는 중인 글의 머리글을 보고 지금 어느 칸을 쓰는 중인지 체크리스트로 보여 준다(단계 글을 지어내지 않음).
- 다 되면 "리뷰 보기 →"가 기억 탭의 풀이 노트로 연다. 만드는 중에 풀이 노트를 열어도 같은 작업에 붙어서 이어 받는다(서버가 진행 중인 글을 들고 있음).
- 풀이 노트는 머리글로 잘라 학습 총평 · 끝났을 때 상태 · 주제 카드(`[핵심]` 큰 카드, `[작은]` 작은 상자) · 자잘하게 막힌 것 · 다시 확인할 것으로 보여 준다.

## 4. 해 보며 알게 된 것

- **지시문은 원칙 + 금지 + 틀**로 나누면 잘 듣는다. 특히 금지 사항("시간순으로 나열하지 않는다", "형식적인 칭찬으로 채우지 않는다", "기록에 없는 행동을 만들지 않는다")이 품질을 크게 올렸다.
- **"깐깐하게"는 맨 위 우선 규칙으로 따로 둬야 지킨다.** 원칙 사이에 섞어 두면 "아마 낯설었을 수 있어요"처럼 흐려진다.
- **사실은 코드가 센 걸 따로 한 줄로 넣고, 그 줄을 근거로 쓰게 한다.** GPT 검토가 "제출은 맞았지만"을 지어낸 말이라고 했는데, 실제로는 `[결과]` 줄에 맞힘이 있었다. 대화에는 채점 결과가 안 나올 수 있다.
- **중복이 제일 흔한 결함이다.** 같은 오류를 주제 세 곳에서 되풀이하고, 전체 정답 코드를 여러 번 붙였다. 3차의 중복 제거 7가지와 "다 쓴 뒤 다시 읽고 정리"가 이걸 줄였다.
- **칸을 다 채우라고 하면 억지로 채운다.** "내용이 없으면 그 머리글을 쓰지 않는다"를 넣었다.
- **대화를 줄이지 않는다.** 처음엔 대화를 잘라 넣었는데, 리뷰의 근거는 학습자가 실제로 한 말과 코드라서 원문을 그대로 넣는 게 낫다.

## 5. 실습에 옮길 때

| 알고리즘 | 실습에서는 |
|---|---|
| `[결과]` (채점 기록) | 목표 판정 결과 · 해 봤어요/이해했어요 · 걸린 시간 · 연 도움 |
| 대화 장부 (그때 코드) | 튜터 대화 + 막힌 순간(`moments.ts`) + 그때 바뀐 파일 |
| 제출한 코드 | 저장본 차이 · 터미널에서 돌린 것과 출력 |
| 문제 글 | 목표 설명 · 이 실습에서 배우려는 것 |

- 지시문 본문은 거의 그대로 쓸 수 있다. "코드 · 실행 재현" 부분만 실습 말(파일 · 명령 · 화면 출력)로 바꾸면 된다.
- 출력 머리글을 그대로 두면 알고리즘 화면 부품(`ReviewView.tsx`의 `parseMdReview` · `MdReviewView`, `ReviewProgress.tsx`)을 같이 쓸 수 있다.
- 실험실(`/lab/review`)은 알고리즘 기록만 읽는다. 실습 기록으로 비교하려면 재료 함수만 바꿔 끼우면 된다.
