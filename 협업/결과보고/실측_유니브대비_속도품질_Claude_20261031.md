# 유니브 AI 대비 속도·품질 실측 (2026-10-31, Claude)

같은 PDF를 유니브 웹(univai.co.kr)에 올리고 페이지 안에서 시간과 데이터를 기록했다. 문항 원문은 싣지 않는다.

## 1. 결론

1. **속도는 비슷하다.** 유니브는 요약 첫 글자가 약 10초로 빠르고, Recaller는 첫 문제가 11~12초로 빠르다. 다 만드는 시간은 둘 다 1분 안팎이다.
2. **품질 차이는 "생성물의 짜임새"다.** 유니브는 모든 주장·문항에 쪽과 원문 인용이 붙고, 문항마다 힌트와 보기별 해설이, 개념마다 정의·비유·핵심 3줄·혼동 포인트가 있다.
3. **유니브는 요약만 자동이고 나머지는 버튼으로 하나씩 만든다.** 학습자가 고르는 손잡이(문제 유형·난이도·문항 수·집중 영역·쪽 범위·"심층" 검토)가 많다.
4. **유니브는 같은 파일을 다시 올리면 AI를 부르지 않고 예전 결과를 복사한다.**
5. Recaller가 앞서는 곳은 문제 수(24개 vs 10개), 복습 날짜, 지식으로 쌓기다. 유니브에서는 날짜 간격 복습을 보지 못했다(암기 탭의 "외움 0/37" 체크만 있음).

## 3. 생성물 구성

| 항목 | 유니브 | 비고 |
|---|---|---|
| 요약 | 소제목별 본문 + 소제목마다 "쉬운 설명"(비유), 표·수식, 문장마다 쪽 표시. 데드락: 약 5,200자·쪽 표시 50번·2~14쪽 전부. 그래픽스: 소제목 9개·약 1만 자·44쪽 중 43쪽 표시 | 끝에 "핵심 정리" |
| 개념 | 카드 필드 `title, importance, definition, explanation(비유), keyPoints(3), pitfalls(혼동), sourceRef(쪽)`. 데드락 8개, 그래픽스 26개. 카드마다 "이 개념으로 퀴즈/플래시카드 생성" | Recaller B1 개념 정리 탭의 기준으로 쓰기 좋다 |
| 퀴즈 | 10문항 기본(객관식 3·OX 3·서술 2·빈칸 2). 문항 필드 `question, options, correctAnswer, hint, optionExplanations, explanation, sourceQuote, sources[{page, quote}]` | 모든 문항에 힌트, 객관식·OX는 보기마다 해설 |
| 퀴즈 설정 | 문제 유형, 난이도(쉬움·보통·어려움), 생성 방식(기본·심층: "한 번 더 검토"), 문항 수, 집중 영역, 쪽 지정, 출력 언어 | 문서별 저장 |
| 암기 | 그래픽스 37개, 항목마다 쪽 표시, "외움 n/37"·"못 외운 것만" | 날짜 간격 복습은 아님 |
| 플래시카드 | 10장 `front/back/sourceQuote` | |
| 마인드맵 | 루트 1 + 가지 8 | |

계산 문항: 데드락 기본 퀴즈에는 뱅커 알고리즘 계산이 없었다. 그래픽스 10/18 퀴즈는 10문항 거의 전부가 수치 계산이었는데(세계→보기 변환, 원근 투영 좌표, 뷰포트 변환), 10/26 실측 때 "계산 위주로" 같은 요청을 넣어 만든 것으로 보인다(기록 확인 못 함). 오늘 기본 설정으로 다시 만든 그래픽스 퀴즈는 개념 확인 위주에 간단한 수치 몇 개였다. 즉 유니브는 **요청하면** 다단계 계산을 낸다.

## 4. 따라잡을 방법 (제안, 고르기 전)

| # | 할 일 | 영역 | 기대 |
|---|---|---|---|
| 1 | 문항 형식에 `hint`, 보기별 해설, 원문 인용 + 쪽을 필수로 | C (엔진) | 유니브 문항과 같은 짜임새. 검사에서 "인용이 원문에 있나"도 코드로 확인 가능 |
| 2 | 개념 카드를 `정의·비유·핵심 3줄·혼동 포인트·쪽·중요도`로 | C → B | B1 개념 정리 탭 그대로 |
| 3 | 첫 화면을 스트리밍으로: 지도 완성(35초)을 기다리지 않고 쪽 설명을 글자 단위로 먼저 | C·공부 화면 | 첫 글자 10초대 |
| 4 | 퀴즈 손잡이: 유형·난이도·문항 수·집중 영역·쪽 범위, "꼼꼼히(한 번 더 검토)" | C·공부 화면 | A2 방향 지시 반영과 같은 목표 |
