# 실측: 튜터가 학습자 답을 바르게 판정하나 (D, 2026-11-08)

사용자 요청(11/8): 코딩 에이전트 모델 · 추론 강도 조사(ChatGPT 임시 채팅, MRBench · MathTutorBench · OpenAI 추론 가이드 등)를 바탕으로, 아주 작은 단위 시험을 실제 AI 호출로 반복. 하드코딩 없이 일반 모델로.

## 일반 모델: 튜터 한 차례 = 판정 → 행동

학습자의 마지막 말이 직전 질문 · 과제의 답이면, 질문과 완료 조건이 요구한 것에 비추어 **맞음 · 일부만 맞음 · 틀림 · 판단 근거 부족**(답이 아니면 질문 · 요청)으로 먼저 판정하고, 판정마다 같은 행동을 한다.
- 맞음 → 짧게 확인하고 이어 감
- 일부만 맞음 · 틀림 → "맞아요"로 시작하지 않음. 맞은 부분은 구체적으로 인정, 빠지거나 틀린 곳은 정답을 통째로 주지 않고 질문 · 힌트로
- 판단 근거 부족 → 맞다 · 틀리다 하지 않고 무엇을 뜻하는지 되묻기
- 요구한 것을 하나라도 빠뜨렸거나 뭉뚱그렸으면 일부만 맞음(v2에서 더함)

## 시험 방법

- 코드: `experiments/project-course/lib/evals.ts`, 문항 `evals/judge-cases.json`(20, 규칙을 고칠 때 본 것) · `evals/judge-cases-holdout.json`(12, 검증용 · 질문/힌트 요청 2 포함), 실행 `POST /api/dev/eval/judge`, 결과 `.data/evals/`
- 튜터 호출은 근사: 지금 튜터 지시문(CHAT_SYSTEM) + 목표 맥락 + 직전 튜터 말 + 학습자 답(도구 · 긴 대화 없음). 모델 gpt-6.1-terra
- 채점: 다른 호출(medium)이 문항 key와 튜터 답을 보고 accepted(맞다고 받아들임) · pointed_gap(빠진 곳 짚음) · leaked(정답 통째로) · handled(질문에 응함)
- 문항 · gold는 제가 썼다. 검증 세트 두 문항(오버라이딩 "자식 것이 쓰여요", 브랜치 "따로 작업하려고요")은 gold(일부만 맞음 · 근거 부족)가 너무 깐깐했다 — 판정 호출도 "맞음"으로 봤고 질문에 대한 답으로는 맞다고 볼 만하다

## 읽은 것

- 추론 강도를 medium으로 올려도 판정은 안 좋아졌다(조사의 "더 생각한다고 늘 낫지 않다"와 같음). 차이를 만든 건 **판정 → 행동 규칙**이다.
- 규칙 v2 한 줄이 판정 호출(2번)과 같은 효과를 호출 1번으로, 더 빠르게 냈다. 답이 짧아져 오히려 빨라짐.
- 가장 큰 변화는 **정답을 통째로 주는 비율**(65~70% → 0~25%, 검증 50~58% → 0~17%). 맞는 답을 깎는 일(너무 깐깐함)은 없었고, 질문 · 힌트 요청에는 판정하지 않고 응했다.
- 한계: 튜터 호출이 실제 대화의 근사(도구 · 긴 기록 없음), gold와 채점이 모델 · 제 판단, 문항 32개.

## 목표 정리 호출 low vs medium (`POST /api/dev/eval/record`)

실제 대화 9목표(시연 · 한 바퀴 점검 · 시연 전 보관본)를 같은 입력으로 다시 정리하고 채점 호출이 부족한 점을 스스로 찾아 비교. low: 찾은 부족함 3/3 포함, 근거 없는 항목 0, 5.6~6.5초 / medium: 1/3, 근거 없는 항목 0, 5.3~8.2초. 표본이 작지만 medium이 나을 근거는 없음 → low 유지.
