# 유니브 요약은 어떤 구조로 만드나: 4개 자료와 원본 PDF 대조 (C, 2026-11-02)

## 1. 공통 뼈대 (네 자료 모두)

1. 맨 위 개요 1~2문장(학습 목표 쪽 근거).
2. 주제마다: **본문** → 접힌 **쉬운 설명**.
3. 본문 끝에 **그 주제 한 줄 정리**(쪽 표시 없음, "시험 핵심:"으로 시작하기도 함).
4. 맨 끝 **핵심 정리**(끝 요약 쪽을 근거로).
5. 쪽 표시는 문단·줄 끝에 `p.N p.M`처럼 여러 개. 내용 쪽 인용률: 데드락 13/13, 그래픽스 03 43/43, 04 51/51, 반도체 37/39.

## 2. 자료 종류에 따라 본문 틀이 바뀐다

- **개념·산업 자료(데드락, 반도체):** `##` 큰 주제 + `###` 작은 주제, 본문은 "이름: 한 문장. p.N" 줄 3~9개. 숫자가 많은 쪽(시장 규모, 공정별 장비·소재 표)은 숫자를 줄에 그대로 옮기고 표로도 만든다.
- **수식·알고리즘 자료(그래픽스 03·04):** 주제를 한 단계로만 나누고, 문단으로 유도 순서를 따라가며 정의 → 식 → 조건 → 예제 순으로 쓴다. 행렬·식을 LaTeX로, 알고리즘은 코드와 의사코드로 다시 쓴다. 경우 나누기(Sutherland–Hodgman 네 경우)는 표로.
- 같은 날(10-31) 만든 데드락과 그래픽스 03이 서로 다른 틀이므로, 날짜(버전)가 아니라 자료 성격으로 틀을 고르는 것으로 보인다.

## 3. 쉬운 설명의 틀

- **데드락·반도체(개념형):** 다섯 칸이 매번 같다. "한마디로, …" + 질문 / 생활 장면 한 문단 / **"쉬운 한 줄 제목: 비유·예 2~3문장"을 본문 줄마다** / "흔한 오해는 …"(학습자가 할 법한 생각) / 마무리 한 줄. 장면 비유는 모든 주제에 있다(데드락 8/8, 반도체 17/17 표본 확인). 줄마다 칸의 제목은 용어가 아니라 쉬운 문장이다.
- **그래픽스 03(수식형):** 생활 장면(사진 찍기, 책상 위 물건, 운동장) 한 문단 → 식의 뜻을 문장으로 풀기 → 기호 대응 목록($P_0$: 카메라 위치 …) → **비유의 한계** 한 줄("사진 비유는 큰 흐름용, 조명까지 같다는 뜻은 아님") → 마무리.
- **그래픽스 04(알고리즘형):** 비유보다 **작은 수치 예**("한 칸 갈 때 0.4씩 늘면 0.4, 0.8, 1.2 → 반올림")와 "이 예는 이 경우만"이라는 한계 문장.
- 즉 "늘 비유"가 아니라 **개념형은 비유, 수식·알고리즘형은 장면 한 번 + 기호 풀이 + 작은 수치 예**로 바꾼다.

## 4. 원본 PDF와 대조해서 찾은 것

| 자료 | 빠진 것 | 틀린 것 | 쪽 표시 |
|---|---|---|---|
| 데드락 | p.12 그림의 구체 간선(어느 요청이 어떤 사이클을 만드는지)은 일반론만 | **p.7 그래프 (a)를 "순환은 있으나 교착 아님"으로 씀. 그림 (a)는 P1→R1→P2, R2→P1, R2→P2로 순환이 없다.** (c)와 설명이 겹침 | 맞음 |
| 반도체 07 | **p.19 장비 6분류**(Wafer 제조·Mask 제조·FAB·Wafer 검사·Package·PKG 검사 장비) 없음 | 못 찾음 | **이미지 쪽에서 어긋남:** p.15 내용을 p.14로, p.26 내용을 p.24로, p.46(CMP Slurry) 내용을 p.45로 표시 |
| 그래픽스 03 | 이미지로 된 큰 행렬(p.26 원근 투영 행렬, p.28 대칭 절두체 관계식, p.34 일반 정규화 행렬)은 말로만 | 못 찾음 | 맞음 |
| 그래픽스 04 | (원본 PDF가 이 PC 연결 폴더에 없어 쪽 대조 못 함) | - | 2~52쪽 모두 인용 |

- 빠뜨림보다 **쪽 표시 오류**가 이미지 위주 자료에서 눈에 띈다. 글자 층이 없는 쪽을 그림으로 읽으면서 쪽 번호를 하나둘 밀린 것으로 보인다. 우리 엔진은 쪽마다 [p.N] 라벨을 붙여 보내고 인용 쪽을 코드로 검사하므로 이 부분은 우리가 강하다.
- 그림 판정 오류(데드락 p.7)는 한 자료에서 한 번. 우리 terra 유니브식 실행은 같은 그림을 맞게 읽었다.

## 5. 화면에서 보이는 것 (요약 글 밖)

- 원문 그림을 요약 안에 그대로 넣는다("원문 · N쪽", 확대 버튼).
- 작은 도식: 구조도(처리 방법 세 갈래), 흐름도(탐지 → 복구, 제조 → 검사).
- 표, 수식(KaTeX), 코드 블록.

## 6. 우리 프롬프트에 옮길 것

1. 자료 성격으로 틀 고르기: 개념형(이름: 한 문장 줄) / 수식·알고리즘형(문단 + 식 + 표 + 의사코드). 목차를 쓸 때 모델이 함께 고르게 한다.
2. 쉬운 설명도 성격별로: 개념형은 다섯 칸 + 줄마다 "쉬운 한 줄 제목: 비유·예 2~3문장", 수식형은 장면 한 번 + 기호 풀이 목록 + 작은 수치 예 + 비유의 한계 한 줄.
3. 주제 끝 한 줄 정리("시험 핵심").
4. 용어는 한국어(영어) 병기, 주제 첫 문장으로 주제를 먼저 말하기.
5. 자료 쪽의 숫자·표는 숫자 그대로, 경우 나누기는 표로.
6. 원문 그림·도식은 화면 쪽 일(정리 탭 시안과 함께).
