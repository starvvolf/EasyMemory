# AI 학습 서비스 10개의 사용자 흐름

확인일: 2026년 10월 12일

앞서 선정한 10개 제품에서 사용자가 무엇을 넣고, 무엇을 선택하며, 어떤 결과를 받아 다음 행동으로 이어가는지 정리했다. 기능 목록과 이용 규모는 [제품 비교](AI_LEARNING_READING_APPS_20261012.md)에 있다.

**이 문서는 실제 계정으로 10개를 모두 실행한 체험기가 아니다.** 공식 도움말의 단계별 절차와 공개 제품 안내를 확인했다. 버튼·순서가 확인된 것은 그대로 적고, 공개 안내에만 있는 기능은 그렇게 표시했다. 확인하지 못한 화면을 상상해서 연결하지 않았다.

## 확인 수준

| 표시 | 의미 |
|---|---|
| 절차 확인 | 공식 도움말에 사용 순서·버튼·결과가 구체적으로 명시됨. 현재 계정에서의 실행 성공까지 보증하는 뜻은 아님 |
| 개요 확인 | 공식 제품 안내에서 기능과 큰 흐름 확인. 버튼별 순서나 세부 동작은 미확인 |
| 미확인 | 설명이 부족해 이번 조사에서 확정하지 못함 |

자료를 넣는 단계에서 일부만 처리하는지, 결과를 사용자가 수정할 수 있는지, 다음에 돌아왔을 때 무엇이 남는지를 구분했다. 학생의 복습 일정, 시험의 재응시, 읽었던 문장의 재노출은 서로 다른 기능이다.

## 한눈에 보는 시작과 끝

| 제품 | 시작하는 사람과 상황 | 대표 흐름 | 흐름의 도착점 | 확인 수준 |
|---|---|---|---|---|
| Wayground | 교사가 학생에게 풀릴 활동 준비 | 출제 → 검토 → 배포 → 학생 풀이 → 교사 리포트 | 다음 수업·피드백의 판단 자료 | 절차 확인 |
| StudyFetch | 학생이 자기 강의자료로 시험 준비 | 공부 묶음 → 자료 → 계획·문제 → 시험 → 문항별 질문·재응시 | 같은 자료에서 다음 학습으로 이동 | 절차 확인 |
| 유니브 AI | 학생이 강의 녹음·자료를 정리 | 녹음·자료 → 자막·요약 → 암기·퀴즈·질문 | 강의 내용을 공부 자료로 보관 | 개요 확인 |
| Quizlet | 학습자가 카드 또는 AI 시험으로 연습 | 세트 → 카드·Learn, 또는 자료 → AI 시험 → 결과 | 학습 자료와 시험 검토 | 절차 확인 |
| RemNote | 학습자가 원문을 구간별로 공부 | 자료 → 익숙함 설정 → 구간 학습 → 카드·퀴즈 → 숙달 확인 | 노트·카드·구간 진도와 복습 | 절차 확인 |
| Gizmo | 학습자가 가볍게 암기 반복 | 덱 → 자료 가져오기 → 카드 확인 → Memorise → 반복·보상 | 결과에 맞춰 다시 나오는 카드 | 절차 확인 |
| Readwise Reader | 독자가 책·기사·PDF 읽기 | 저장 → 읽기·밑줄 → 설명 → 보관 → 밑줄 다시 보기 | 읽은 흔적을 나중에 재사용 | 절차 확인 |
| Gemini Notebook | 사용자가 모은 자료 이해 | 노트북 → 자료 → 대화·결과물 → 카드·퀴즈 → 재학습 | 출처와 생성 자료·카드 진행 | 절차 확인 |
| SciSpace | 학생·연구자가 논문 이해 | 논문 → 질문 → 답·중요 구절 → 노트 저장 → 다시 읽기 | 논문별 이해와 연구 노트 | 절차 확인 |
| Elicit | 연구자가 여러 근거 조사 | 연구 질문 → 범위 확인 → 조사 → 인용 검토 → 수정·저장·내보내기 | 근거가 연결된 연구 결과 | 절차 확인 |

아래 대표 경로는 가능한 사용 방식 중 하나다. 앱 전체가 반드시 이 순서로만 동작하거나 모든 결과물을 자동 생성한다는 뜻은 아니다.

## 1 Wayground

**교사가 만들고 운영하고, 학생이 참여하는 두 사람의 흐름이다.**

| 단계 | 사용자가 하는 일 | 받는 결과 또는 다음 행동 |
|---|---|---|
| 1 교사 출제 시작 | Create → Assessment 또는 Quiz → Generate with AI → Document | 문서로 문제를 만드는 경로 진입 |
| 2 자료와 조건 | 파일 업로드·Drive 가져오기 후 문항 수·과목·학년·언어 선택 | Generate Quiz로 생성 요청 |
| 3 검토 | 생성한 질문·유형·보기·미디어를 확인하고 수정 | Publish로 저장하고 배포할 준비 |
| 4 배포 | 실시간 활동 또는 숙제로 운영 | 학생들이 교사가 운영하는 활동에 참여 |
| 5 학생 풀이 | 배포받은 활동의 문제에 응답 | 활동 결과가 리포트로 집계 |
| 6 교사 확인 | Reports에서 해당 활동 열기 | 학생·문항별 결과를 보고 이후 지도 판단 |

1~3은 [문서 기반 AI 출제 절차](https://help.wayground.com/support/solutions/articles/158000405091-wayground-ai-generate-assessments-from-prompts-documents-videos-more), 4~5는 [수업 운영 안내](https://help.wayground.com/support/solutions/articles/158000403991-what-is-wayground-), 6은 [리포트 안내](https://help.wayground.com/support/solutions/articles/158000404058-reports-on-wayground) 기준이다.

**범위 제한:** 해당 문서 출제 도움말은 파일을 한 번에 하나씩 올리고 처음 16,000자만 처리한다고 명시한다. PDF 전체를 빠짐없이 출제한다는 뜻이 아니다. 생성 후 교사 검토도 요구한다. Publish의 공개 범위·학생 참여 설정은 실제 배포 때 따로 확인해야 한다.

**저장되는 것:** 저장한 활동과 실행별 리포트. 여기서 학생 개개인의 장기 복습 일정이 자동 완성된다고는 확인하지 않았다.

## 2 StudyFetch

**공부 묶음 안에서 자료·계획·시험·설명이 이어진다.**

| 단계 | 사용자가 하는 일 | 받는 결과 또는 다음 행동 |
|---|---|---|
| 1 묶음 만들기 | My Sets → Create Study Set, 이름 입력 | 과목·목적별 공부 공간 생성 |
| 2 자료 넣기 | Upload에서 파일 추가. 강의계획서 안내가 나오면 넣거나 Skip and Upload Documents | 선택한 공부 묶음에 학습자료 추가 |
| 3 계획 보기 | Study Plan 열기. 필요하면 강의계획서·시험 날짜 추가 | 단원·주제 순서와 Covered·Mastered 진행 확인 |
| 4 시험 만들기 | Practice → Test → New Test | 기존 자료 또는 카드에서 출제할지 선택 |
| 5 조건 정하기 | 자료 선택 → 문제 유형별 개수 → 이름·언어·선택 지시 설정 | Create test로 시험 생성 |
| 6 풀기 | 보기 선택·답 입력. 한 문제씩 또는 전체 보기 선택 | 답한 문항 표시. 제출 전 수정 가능 |
| 7 결과 보기 | Submit Test → View Answers | 점수·정오답·주제별 결과 확인 |
| 8 이어 공부 | Chat About This Question 또는 Retake | 그 문항을 맥락으로 설명받거나 다시 시험 |
| 9 재방문 | My Sets 또는 최근 묶음 열기 | 같은 공부 공간에서 자료·기존 시험·계획에 재접근 |

근거: [묶음 만들기와 재접근](https://www.studyfetch.com/docs/docs/6a542d542911612bb96214ee), [자료 넣기](https://www.studyfetch.com/docs/docs/6a542e364aad29a96f070b20), [학습 계획](https://www.studyfetch.com/docs/docs/6a519349893cd6f616be1054), [시험 생성](https://www.studyfetch.com/docs/docs/6a63bfe5ee9569d818eecc3c), [풀이와 결과 검토](https://www.studyfetch.com/docs/docs/6a63c0556f4e994396e156e0).

**확인된 세부 동작:** 시험 생성은 4단계로 나뉜다. 기본 유형은 객관식·OX·빈칸·단답·자유 응답·공통 지문 계열을 안내한다. 한 문제씩 볼 때 답을 선택하면 다음 문항으로 넘어가며 제출 전 되돌아갈 수 있다. 모든 문항에 답하면 제출 버튼이 활성화된다고 설명한다.

**분기:** Study Plan은 선행 진단·주제 건너뛰기·학습 깊이 조절을 지원한다. Mini Apps는 별도 생성 경로이며 이 기본 시험 경로의 필수 단계가 아니다.

**아직 확정하지 않은 것:** 한국어 자유 응답 채점의 정확도, 카드별 다음 복습 날짜를 정하는 알고리즘, 우리의 PDF를 실제로 넣었을 때의 전체 범위 보존.

## 3 유니브 AI

**강의를 들으며 남긴 자료를 시험공부 도구로 바꾸는 흐름. 버튼별 절차는 개요 수준으로만 확인했다.**

| 단계 | 공식 안내에서 확인한 행동 | 받는 결과 |
|---|---|---|
| 1 입력 | 강의 녹음 시작 또는 PDF·PPT·Word·사진·메모·링크 추가 | 공부할 원자료 확보 |
| 2 강의 기록 | 녹음 중 생성되는 자막 확인 | 놓친 구간을 자막에서 찾아 다시 듣기 |
| 3 정리 | 자료의 요약·핵심 개념·암기 포인트 보기 | 내용을 읽고 공부할 부분 확인 |
| 4 연습 | 자료 기반 퀴즈·해설·플래시카드 이용 | 이해한 것과 헷갈리는 개념 점검 |
| 5 질문·연결 | 전공 튜터에 질문하거나 마인드맵 보기 | 추가 설명 또는 개념 관계 확인 |

근거: [공식 공개 제품 안내](https://univai.co.kr/). 녹음 경로와 파일 업로드 경로는 서로 다른 시작점이다. 요약을 반드시 읽어야 퀴즈로 넘어갈 수 있는지는 확인되지 않았다.

**보존 안내:** 웹·앱 간 동기화를 안내한다. **미확인:** 퀴즈 생성의 실제 설정 화면, 문항별 제출·채점 순서, 오답만 다시 풀기, 다음 날 자동 복습 목록, 진행 상태의 정확한 저장 단위. 화면에 없는 버튼 이름이나 ‘자동 약점 보완 루프’를 덧붙이지 않았다.

## 4 Quizlet

**카드로 공부하는 경로와 AI 시험을 만드는 경로를 나누어 봐야 한다.**

### 카드로 공부

| 단계 | 사용자 행동 | 결과 |
|---|---|---|
| 1 세트 열기 | 계정 로그인 후 공부할 카드 세트 열기 | 용어·정의 카드 이용 |
| 2 모드 선택 | Flashcards 선택 | 앞뒤 카드 화면 |
| 3 회상·확인 | 카드를 눌러 뒤집고 앞뒤 화살표로 이동 | 정답 내용을 직접 확인 |
| 4 분류 | Options에서 정렬 기능 켜기 | Still learning·Know 그룹으로 카드 구분 |
| 5 추가 연습 | Learn 선택 | 카드 내용을 여러 질문 형태로 연습 |

근거: [Flashcards 절차](https://help.quizlet.com/hc/en-ca/articles/360030988091-Studying-with-Flashcards), [Learn 안내](https://quizlet.com/features/learn). 카드 분류는 자동 채점 결과와 구분한다.

### AI 시험 생성

Generate → Practice test → 카드 세트 선택 또는 노트 입력·업로드 → Start transforming → 문항 수·유형·시간 조절 → Take this test → 답하기 → Submit test → 점수·시험 검토. 저장한 시험은 Library의 Practice tests에서 다시 찾는다. [AI 시험 절차](https://help.quizlet.com/hc/en-us/articles/25946589648013-Studying-with-Practice-Tests)

**이용 조건:** 공식 AI 시험 안내는 영어·지원 국가·연령 조건을 두며 한국은 국가 목록에 없다. 따라서 한국 계정에서 이 경로가 열린다고 전제하지 않는다. 일반 카드 학습이 불가능하다는 뜻은 아니다.

## 5 RemNote

**자료의 구간마다 이해·인출·진도 확인을 연결한다.**

| 단계 | 사용자 행동 | 결과 또는 다음 행동 |
|---|---|---|
| 1 시작 | 자료 업로드 후 Learn PDF | Guided Learn 진입 |
| 2 기준 설정 | 처음 배움·기본 이해·복습 중 선택 후 생성 | 구간별 학습 계획 |
| 3 읽기 | 구간 요약 확인, 필요하면 Read PDF/Document | 원문 해당 페이지로 이동 |
| 4 이해 보완 | 문장·개념 선택 또는 AI Tutor 질문 | 맥락 안에서 설명 |
| 5 인출 | 구간 카드 생성·연습 또는 퀴즈 생성 | 카드 저장, 형식·난이도 조절 |
| 6 평가 | Study Mode 또는 Test Mode로 풀기 | 즉시 확인 또는 끝난 뒤 점수·검토 |
| 7 진도 확인 | Mastery Tracker 보기, 필요하면 주제 제외 | 연습 결과에 따른 구간 진도 |
| 8 확장·재방문 | 다음 구간 생성 또는 Existing Quizzes 열기 | 큰 자료를 이어 공부하거나 기존 퀴즈 재접근 |

근거: [Guided Learn 단계별 안내](https://help.remnote.com/en/articles/15724936-guided-learn-mode), [PDF Reader](https://help.remnote.com/en/articles/6690975-learning-from-pdfs-and-files-with-the-remnote-reader).

**중요한 구분:** 익숙함 설정은 요약과 카드 중 무엇을 먼저 보여줄지 바꾼다. 같은 자료의 내용 자체를 달리 생성하는 설정은 아니다. 큰 자료는 모든 구간을 한 번에 생성하지 않고 다음 구간을 추가 생성한다.

**보존과 복습:** 생성 카드는 자료 아래에 저장해 수정·추가·삭제할 수 있다. 카드 간격 복습도 제공한다. 퀴즈 진도 점수를 실제 지식 숙달의 객관적 증명으로 간주하지 않는다. [간격 복습 설명](https://help.remnote.com/en/articles/6022755-getting-started-with-spaced-repetition)

## 6 Gizmo

**덱을 만든 다음 짧은 문제 풀이를 반복하고, 결과가 다음 출제 간격과 보상으로 이어진다.**

| 단계 | 사용자 행동 | 결과 또는 다음 행동 |
|---|---|---|
| 1 입력 | 덱 → Add → Magic Import → 자료 종류 선택 | PDF·노트·녹음 등의 자료로 카드 생성 |
| 2 확인 | 가져온 덱 검토, 누락 카드 필요 시 추가 | 초록색 핵심 단어가 질문 대상으로 표시 |
| 3 연습 | Memorise에서 퀴즈 풀기 | 카드 유형·설정에 맞는 질문 |
| 4 보완 | AI Tutor에 설명이나 추가 질문 요청 | 이해를 보완하고 다시 연습 |
| 5 반복 | 계속 풀이 | 정답 카드는 더 늦게, 오답은 더 빨리 재등장하도록 조정 |
| 6 동기 | XP·레벨·연속 학습 확인. 선택적으로 Gizmo Live | 공부 흔적 확인 또는 친구와 대결 |

근거: [자료 가져오기 절차](https://help.gizmo.ai/en/articles/15647624-what-is-magic-import), [복습 동작](https://help.gizmo.ai/en/articles/15647638-what-is-spaced-repetition), [튜터·게임·보상](https://help.gizmo.ai/en/articles/14472668-how-does-gizmo-work).

**형식과 조건:** 텍스트 카드·객관식·짝짓기·순서·OX를 안내한다. 짝짓기·순서는 현재 Magic Import 경로로만 제공한다고 명시한다. 일반 앞뒤 카드의 뒤집기 옵션과 핵심 단어를 묻는 퀴즈를 구분해야 한다. [카드 형식](https://help.gizmo.ai/en/articles/16527223-what-types-of-flashcards-can-i-make)

가져오기 도움말은 큰 자료를 작은 구간으로 나눠 넣고 생성 덱을 확인하도록 권한다. 무료 가져오기에는 대기 시간이 있다. 전체 PDF의 모든 내용을 한 번에 빠짐없이 바꾼다고 주장하지 않는다.

## 7 Readwise Reader와 Readwise

**읽기 → 밑줄·질문 → 보관 → 다시 보기의 흐름이며, 시험 제출이 필수인 제품은 아니다.**

| 단계 | 사용자 행동 | 결과 또는 다음 행동 |
|---|---|---|
| 1 모으기 | 확장 프로그램·모바일 공유·파일 업로드 | 기사·책·PDF 등을 Reader에 저장 |
| 2 읽기 | 문서 열기, 글자·테마 등 보기 설정 | 읽기 화면에서 계속 읽기 |
| 3 흔적 남기기 | 문장에 밑줄·메모 | Readwise 라이브러리로 동기화 |
| 4 질문 | 문서 옆 Ghostreader에 질문 | 읽는 자료의 설명·요약 등 |
| 5 여러 자료 연결 | 웹·데스크톱의 Global Ghostreader에서 질문 | 라이브러리 검색 답변과 구절별 인용 |
| 6 검증 | 인용에 마우스를 올리거나 클릭 | 근거 미리보기 또는 해당 원문 위치 이동 |
| 7 다시 보기 | Readwise의 Daily Review | 저장한 밑줄을 재노출하고 문서별 빈도 조절 |

근거: [입력·읽기·주석](https://docs.readwise.io/reader/docs), [문서 대화·전체 라이브러리 대화](https://docs.readwise.io/reader/guides/ghostreader/global), [밑줄 복습](https://docs.readwise.io/readwise/docs/faqs/reviewing-highlights).

**조건:** 전체 라이브러리 대화는 설정에서 활성화해야 할 수 있고 웹·데스크톱에 한정된다. 모바일의 개별 문서 대화와 다르다. Daily Review의 문서별 재노출 빈도와 정답 여부를 반영한 문제 복습을 혼동하지 않는다.

**남는 것:** 저장 문서·밑줄·메모·대화 기록. AI가 정리 작업까지 하게 하면 밑줄 생성·태그 변경 등의 쓰기 작업에는 별도 권한 설정이 적용된다.

## 8 Gemini Notebook 구 NotebookLM

**노트북에 자료를 묶어두고, 그 자료에서 필요한 설명이나 학습 도구를 꺼내 쓴다.**

| 단계 | 사용자 행동 | 결과 또는 다음 행동 |
|---|---|---|
| 1 자료 공간 | 새 노트북 생성 또는 기존 노트북 열기 | 같은 주제의 자료를 모을 공간 |
| 2 입력 | 사용할 자료 추가 | 자료 기반 대화·결과물 생성 준비 |
| 3 이해 | 질문하거나 Studio의 결과물 선택 | 설명·노트·요약 등. 모든 유형 생성은 필수 아님 |
| 4 문제 생성 | Studio → Flashcards 또는 Quizzes, 필요하면 연필 아이콘 | 난이도·초점 등의 조건을 지정하고 생성 |
| 5 연습 | 카드 또는 퀴즈 풀기, Explain으로 설명 요청 | 결과 확인과 추가 이해 |
| 6 자기 확인 | 카드에 Got it·Missed it 표시 | 카드 진행 기록 |
| 7 재학습 | 끝에서 재연습하거나 놓친 카드만 선택 | 같은 묶음에서 반복 |
| 8 재방문 | 같은 노트북의 카드 열기 | 이전 카드 진행을 이어가기 |

근거: [노트북과 자료 공간](https://support.google.com/gemininotebook/answer/16206563?hl=en), [카드·퀴즈의 실제 절차](https://support.google.com/gemininotebook/answer/16958963).

**조건:** 카드·퀴즈를 생성·삭제하려면 노트북 편집 권한이 필요하다. 카드 진행 보존은 확인되지만 ‘며칠 뒤 무슨 문제를 복습할지’ 정하는 전용 일정 기능은 이번에 확인하지 못했다. 카드의 자기 표시와 퀴즈 결과도 구분한다.

## 9 SciSpace

**논문을 읽다가 막힌 부분을 질문하고, 필요한 설명을 연구 노트로 남긴다.**

| 단계 | 사용자 행동 | 결과 또는 다음 행동 |
|---|---|---|
| 1 시작 | 로그인 → Chat with PDF → Upload PDF | 기기 또는 라이브러리의 논문 열기 |
| 2 큰 내용 파악 | 주요 결과·방법·결론 등 질문 | 논문에서 관련 내용을 찾아 답변 |
| 3 깊게 읽기 | 특정 부분이나 연구 한계를 질문하고 중요 구간 표시 | 이해 보완과 중요한 근거 보관 |
| 4 저장 | Save To Notebook | AI 답변·정보를 노트에 보관 |
| 5 정리 | 연구 주제별 폴더로 구분 | 논문 공부 기록 축적 |
| 6 재방문 | 대시보드에서 기존 PDF·대화 이력 열기 | 이전 이해를 바탕으로 질문 계속 |

근거: [Chat with PDF 단계별 도움말](https://scispace.com/help/en/articles/10660595-how-does-chat-with-pdf-work-chat-with-pdf-interacting-with-research-papers-using-ai). 수식·표·그림 설명 기능은 [제품 안내](https://scispace.com/chat-pdf)에서도 확인된다.

**조건:** 해당 도움말은 100MB 이하의 텍스트 기반 PDF를 전제로 하며, 스캔 이미지는 OCR 없이 분석할 수 없다고 안내한다. 모든 표·수식을 정확히 읽는다는 검증은 아니다.

**흐름의 끝:** 설명과 노트 축적이다. 여기서 자동 시험·오답 기록·날짜 복습까지 이어진다고는 확인하지 않았다.

## 10 Elicit

**연구 질문에 필요한 근거를 찾고, 비교 결과를 계속 다듬는 흐름. 시험공부용 문제 풀이가 중심이 아니다.**

| 단계 | 사용자 행동 | 결과 또는 다음 행동 |
|---|---|---|
| 1 경로 선택 | Research Agent·Research Report·Systematic Review 중 선택 | 자유 조사·보고서·구조적 문헌 검토의 구분 |
| 2 질문 | Agent에 연구 질문과 원하는 결과·범위 입력 | 필요하면 추가 확인 질문 |
| 3 자료 범위 | 파일 추가 또는 Library·컬렉션 사용 범위 지정 | 내 자료와 더 넓은 검색 범위 구분 |
| 4 조사 | Agent의 진행 확인 또는 완료 후 돌아오기 | 자료를 찾아 비교한 결과 |
| 5 확인 | 인용 클릭, 근거 문서 확인 | 주장의 출처 검토 |
| 6 다듬기 | 추가 질문·조건 변경·표·보고서 등 요청 | 같은 세션에서 후속 분석 |
| 7 보관·활용 | 논문을 Library에 저장, 표의 인용 내보내기·결과물 확인 | 다음 연구에서 재사용할 근거와 산출물 |

근거: [경로 선택과 최신 통합](https://support.elicit.com/en/articles/14757543-getting-started-with-elicit-which-workflow-should-i-use), [Agent 사용 절차와 결과 활용](https://support.elicit.com/en/articles/14756886-elicit-s-research-agent).

**분기:** Research Report는 질문에서 인용이 붙은 보고서를 만들고 PDF·Word로 내보내는 경로다. Systematic Review는 논문 모으기 → 포함·제외 선별 → 정보 추출 → 보고서로 이어지며 Pro 이상 조건이 있다.

**조건:** Agent의 노력 수준 조절은 제한된 베타다. 모든 계정에서 선택할 수 있다고 쓰면 안 된다. 자료를 저장하고 다시 조사하는 기능과 학습자의 기억 수준을 추적하는 기능도 구분한다.

## 조사로 확인된 차이

| 구분 | 실제로 다른 점 | 비교할 때 주의할 점 |
|---|---|---|
| 누가 다음 행동을 정하는가 | Wayground는 교사, 카드 앱은 학습자, StudyFetch·RemNote는 학습 계획이 일부 안내 | 모두 같은 ‘AI 공부 앱’ 흐름으로 설명하면 차이가 사라짐 |
| 입력 범위를 얼마나 처리하는가 | Wayground의 해당 경로에는 문자 제한, RemNote는 큰 자료를 구간 추가 생성 | 파일을 올렸다는 사실이 전체 범위 처리의 증거는 아님 |
| 생성 후 무엇을 하는가 | 교사가 수정·배포하거나, 사용자가 바로 풀거나, 설명만 읽음 | 문제 생성 지원과 학습 완료를 구분 |
| 무엇이 저장되는가 | 활동·점수, 카드·진도, 문서·밑줄, 논문·연구 결과 등으로 다름 | 저장 지원을 모두 학습 기억 기능으로 부르면 안 됨 |
| 왜 다시 들어오는가 | 숙제, 오답·복습, 보상, 읽을 자료, 이어 하던 연구 | 실제 재방문 동기가 제품 성격을 보여줌 |

**남은 검증:** 공식 절차의 존재는 확인했지만 실제 한국 계정에서의 접근, 우리 PDF의 생성 품질, 채점 정확도, 재접속·기기 변경 시 보존은 직접 실행으로 검증해야 한다. 이번에는 그 검증을 했다고 표시하지 않았다. 특히 유니브 AI는 세부 흐름의 확인 수준이 낮으므로 다른 제품과 동일한 버튼 수준의 확정 설명으로 쓰지 않는다.
