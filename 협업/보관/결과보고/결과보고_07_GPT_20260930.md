# 작업지시 07 — GPT 담당 결과 (2026-09-30)

## 0. 공식 OpenAI 문서 확인

- **오픈소스 등록**: 첫 연결에서 `client_id=dynamic_agent_client`로 동적 등록하고, 돌아온 발급 `client_id`를 저장한다. 클라이언트 비밀키·별도 API 키는 필요 없다. 호스트마다 안정적인 `ext_agent_host_id`가 필요하다. OAuth 승인 주소는 `https://auth.openai.com/api/accounts/authorize`, 교환 주소는 `https://auth.openai.com/api/accounts/oauth/token`이다. 콜백은 `http://127.0.0.1:<port>/...`를 사용하며 `localhost`로 바꾸면 안 된다. 요청 범위는 `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`. [등록·로그인](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [개요](https://developers.openai.com/siwc/token-sharing-open-source)
- **대상**: 이 공개 흐름은 오픈소스·로컬 호스팅 앱용이다. 원격 유료/상용 호스팅은 별도 참여 절차가 안내되어 있다. 따라서 이번 구현은 로컬 실험 모드의 127.0.0.1에서만 열었다. [개요](https://developers.openai.com/siwc/token-sharing-open-source)
- **모델·추론**: 자격 있는 요청은 사용자가 승인한 `chatgpt.tokens.use.direct` 토큰으로 `POST /v1/responses`에 보낸다. `store:false`, `stream:true`가 필수이고 `response.completed`를 받아야 성공이다. 모델은 고정된 전체 목록이 아니라 로그인한 계정의 `GET /v1/models` 결과에 따라 달라진다. 따라서 현재 저장된 `gpt-6-sol`·`gpt-6-astra`·`gpt-6-luna`가 이 사용자의 계정에서 모두 되는지는 실제 로그인 전에는 확인할 수 없다. `reasoning.effort`와 JSON 모드는 코드에 연결했지만 이 로그인 경로에서의 해당 모델별 조합은 실제 호출 전 미검증이다. [모델·추론](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)
- **PDF 첨부**: 선택 모델이 지원하면 Responses 입력으로 파일을 넣을 수 있지만, 이 경로에서 Files 업로드 API는 지원하지 않는다. 이번 자동 실행기는 기존처럼 PDF의 쪽별 추출 글자를 단계 입력에 보낸다. PDF 원본 바이너리 첨부로 바꾸지 않았다. [제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)
- **오류**: 한도는 HTTP 429의 `subscription_sharing_usage_limit_exceeded` 또는 스트림 내부 `response.failed`로도 올 수 있다. 인증 문제는 401·권한 코드, 일시적 사용량 확인 실패는 `subscription_sharing_usage_unavailable`(503)이다. 본문이 항상 표준 `error` 객체라는 보장은 없다. 갱신 토큰의 `invalid_grant` 등은 재로그인이 필요하다. [오류·복구](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery), [토큰](https://developers.openai.com/siwc/token-sharing-open-source/token-reference)

## 구현 범위

- `POST /api/auth/chatgpt/start`: 서버에서 state·nonce·PKCE를 만들고 동적 등록/재로그인 주소를 반환한다. 브라우저에는 HttpOnly 임시 쿠키만 준다.
- `GET /api/auth/chatgpt/callback`: state·임시 쿠키·등록 client ID·ID 토큰 서명/issuer/audience/nonce/만료를 검증한 뒤 서버에 자격증명을 보관한다. 승인 범위가 없으면 로그인은 남아도 생성 준비는 false다.
- `POST /api/auth/chatgpt/logout`: 갱신 토큰 원격 해지를 시도한 뒤 로컬 토큰을 제거한다. 원격 해지 실패 여부만 반환한다.
- `src/lib/ai/model.ts`의 `chatgpt` 공급자: 해당 호출자의 토큰을 만료 전 갱신하고, `instructions`와 독립 `input`으로 Responses API를 스트리밍 호출한다. 완료 전 끊김은 성공으로 처리하지 않는다. 입력/출력 토큰 수를 반환한다. 한도·로그인·지원 불가·일시 오류를 분리한다.
- 토큰·PKCE 임시 상태는 `.study-forge-data/chatgpt-auth/`에 `0o600`으로 쓰고, Windows/프로덕션에서는 `STUDY_FORGE_CHATGPT_ENCRYPTION_KEY`(32바이트=64자리 16진수)로 AES-256-GCM 암호화하지 않으면 연결을 막는다. 현재 호스트 경로가 Public 아래이므로 Windows 파일 모드만 믿지 않는다.
- 화면 파일은 수정하지 않았다. Claude가 로그인 버튼을 달 경우 위 시작/로그아웃 URL을 사용한다.

## 검증과 남은 것

- 가짜 OAuth/JWKS/Responses 스트림으로 서명·nonce 거부, 동적 client ID, 토큰 보관/암호화/갱신/로그아웃, 공급자의 `ready=true`, 한도 코드, `response.completed` 필수 조건을 검사했다. 실제 OpenAI 호출은 0회다.
- 새 공급자 테스트 4/4, `src/lib/study/*.test.ts` 17/17, 로컬 경계 테스트 3/3 통과. 린트 오류 0개(기존 경고 21개), 프로덕션 빌드 통과.
- 실제 로그인 뒤 `GET /api/study-executor`의 `model.ready=true`, 해당 계정의 모델 목록, 1~2쪽 실생성 시간·호출 수·사용량은 **아직 확인하지 않았다**. 사용자 확인을 받은 뒤에만 실제 호출한다.
- 이 구현은 로컬 단일 활성 ChatGPT 계정을 대상으로 한다. 다중 계정 선택과 원격 배포는 이번 결과로 지원한다고 표시하지 않는다.
