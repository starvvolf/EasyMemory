- **멈출 때**: 실패를 발견하면 고칠 수 있는 것(작은 버그)은 고치고 기록에 "고침"으로 적는다. 판단이 필요하면 고치지 말고 "질문"으로 적고 다음 단계로 간다.

## 1. 작업지시 09 + 실패 기록 재생 (비용 0)
- 09를 반영한다. 학습 설계가 쪽 근거 없는 개념만 가리키면 제출 단계에서 거부하고, `?? 0`을 없앤다.
- 로컬에 남은 실제 실패 실행 두 개의 **실제 모델 답**을 지금 검사기에 다시 넣는다.
  - 개념 구조 쪽 누락
  - `req_439de8…`: 44쪽 → 목표 1개 → 0쪽
- 확인: 둘 다 **해당 단계 제출에서** 걸리는가. 오류 문장이 모델이 고칠 수 있는 말인가.
- 재생 테스트는 실제 답을 그대로 고정 자료로 저장소에 넣는다(`src/lib/study/fixtures/`). 개인 정보나 토큰이 없는지 확인한 뒤 넣는다.

## 2. 원문 입력 점검 (모델 없이)
- 대상: `eval/corpus/user-test-pdfs/*.pdf`, 그리고 로컬에 있는 `03_Three Dimensional Viewing.pdf`. 44쪽 자료는 저장소에 넣지 않는다.
- 자료마다 표 한 줄을 채운다: 쪽 수, 글자 없는 쪽, 쪽당 글자 수(최소/중간/최대), 전체 범위로 요청할 때 60,000자 제한에 잘리는 쪽.
- 이 표는 "큰 자료를 나눌지" 결정의 근거로 쓴다. 결론은 쓰지 말고 숫자만 적는다.

## 3. 화면 전체 흐름 (가짜 모델, 넓은 화면 + 390px)
- **되짚기**: 자료 올리기 → 생성 → 준비됨 → 연습 1문제 → "이 문제 이상해요" → 다시 만들기 → 준비됨
- **모르는 것 노트**: 드래그 → 물어보기 → 밑줄 다시 열기(호출 없음 확인) → 이어서 묻기 2번 → 질문 창에서 계속 → 노트 서랍
- **실험실**: 한 단계씩 → 모델 바꿔 다음 단계 → 재시도 시나리오 → 출제
- 각 흐름에서 화면 캡처 1~2장을 남기고, 콘솔 오류는 0이어야 한다.

## 4. 고장 상황 (가짜 모델)
- 상황별로 "멈춤 → 다시 시작 → 이어서 완료"가 되는지, 사용량(호출 수)이 두 번 나가지 않는지 본다.
  - 사용량 한도
  - 로그인 만료
  - 연결 끊김(transient)
  - JSON 아닌 답
  - 생성 중 서버 재시작
- 노트: 한도 또는 로그인 오류일 때 카드에 안내와 버튼이 나오는지 본다.

## 5. 실제 호출: 실험실 실측 (승인 후)
- 조합: 자료 3개(2쪽, 10쪽 안팎, 44쪽 자료의 한 장) × 모델 2개(`gpt-6-luna`·low, `gpt-6-sol`·medium). **한 단계씩 끄고** 끝까지 돌린다.
- **한도**: 기록 맨 위 승인 칸의 숫자를 넘지 않는다. 넘을 것 같으면 그 자리에서 멈추고 기록한다.
- 쓸 수 없는 모델이면(지원 안 됨 오류) 그 칸은 "불가"로 적고 넘어간다.
- 실행마다 표 한 줄을 채운다. **품질 판단은 쓰지 말고**, 사람이 볼 곳만 실험실 실행 ID와 단계로 적는다.
