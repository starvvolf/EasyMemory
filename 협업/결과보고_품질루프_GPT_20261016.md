## Claude가 판단할 것
- 확인용 기업윤리 02 실행은 102개 설계 목표 중 1개만 골라 다시 만든 실행이다. 판정 경로 테스트에는 충분하지만 과적합 검출용 고정 시험지로는 범위가 좁다. 다른 실행으로 변경할지는 Claude 확인이 필요하다. Codex는 임의 변경하지 않았다.
- 나머지 2개 기준점을 측정한 뒤에야 0번 준비 완료로 볼 수 있다. 현재 STOP을 해제하거나 자동 루프를 켜면 안 된다.
- 이번에는 판정 POST → 완료 조회 → 점수표 GET 및 저장만 실제 검증했다. 실제 생성/fork API는 호출 계약을 확인했으며, 실제 모델을 이용한 전체 개선 바퀴는 아직 검증하지 않았다.

## 자세한 내용
- 기준 코드: `origin/claude/local-state-20260928`의 `e0f3d33`. 사용자 브랜치에는 변경을 합치지 않았다.
- 전용 작업 공간에 잠금 파일 기준으로 의존성을 설치했다. 패키지나 스키마 변경 없음.
- `.env.local`은 전용 폴더에만 두고 공유 데이터와 기존 로컬 로그인 저장소를 참조한다. 키/로그인 파일을 복사하거나 공개 저장소에 넣지 않았다.
- 모델 호출 기본 경로는 로컬 서버 API다. 변경 요청에 서버와 같은 Origin 및 JSON Content-Type을 사용한다. 출제 POST, design/author fork POST, judge POST, score GET의 계약을 비공개 상태.md에 기록했다.
- 설치된 CLI에는 `--full-auto`가 없다. 사용자가 이 대화에서 지속 권한 설정을 별도로 승인한 후 `--approve-for-me`와 공유 데이터 폴더의 `--add-dir`로 교체했다. 승인 검토와 sandbox를 우회하는 옵션은 사용하지 않았다.
- 사용자 실행 폴더에서 실수로 실행하는 것을 막는 검사와, Codex 비정상 종료 시 무한 반복하지 않는 분기를 추가했다.
- 3개 기준점 묶음 호출은 안전 검토에서 별도 승인이 필요해 시작되지 않았다. 사용자가 이후 "일단 1회 동작 테스트", "모델쓰는거로"라고 요청하여 확인용 1문항의 판정만 수행했다.
- 실제 결과·문항별 판정·점수표는 RecallerData의 `품질루프/baseline-smoke.json`에만 저장했다. 공개 보고서에는 원문 인용과 학습자 답을 넣지 않았다.
- 실제 판정 시각: 2026-10-16 03:58 KST. 재시도 없이 5개 호출 모두 성공. 맨손 학습자도 맞혔지만 이는 노출 판정과 별개이며, 전문가가 오답 보기 품질을 지적했다.
- 품질 기준/프롬프트/평가 기준의 내용은 변경하지 않았다. 채택·기각·규칙 버전 증가도 없다.
- STOP은 준비 미완료를 나타낸다. 반복 실행을 시작하려면 남은 기준점을 측정하고 결과 및 확인용 적합성을 검토해야 한다.
