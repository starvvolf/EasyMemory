**기록 위치**: `.study-forge-data/study-gen/<gen_id>/`
- `state.json`: 상태, 목차, 분류, 목표, 출제 결과
- `calls/<n>.json`: 호출마다 지시문, 입력, 응답, 시간, 토큰, 응답 형식
- `sections/<s>/document.json`: 목차별 문제 문서(`problem-authoring-v1`)

**검사 세 갈래**
- 형식: 스키마
- 원문 없음·끊긴 연결·풀 수 없음: 걸린 것만 한 번 다시 시킨다. 또 걸리면 그 항목만 빼고 표시한다.
- 품질: 경고만 남긴다.

옛 엔진의 120개 검사는 새 경로에서 쓰지 않는다.

## 2. 확인한 것과 못 한 것
- **통과**:
  - 새 테스트 20개(엔진 9, 공급자 4 포함). 확인한 흐름은 끝까지 실행, 확인 대기 후 고른 목표만 출제, 그냥 읽기, 인용 불일치 재시도 후 제외, 정답 노출 문항만 재시도 후 제외, 한도 멈춤 후 이어하기, 실제 호출 확인 없이는 시작 안 함이다.
  - 타입 검사(`tsc`), 바뀐 파일 린트도 통과했다.
- **환경 탓 실패 17개**(코드와 무관): 검증한 곳이 PC의 격리 리눅스 환경이라 PDF 글자 추출 라이브러리(Windows용 설치본)가 안 돌아 11개, 복사에서 뺀 고정 자료 때문에 6개가 실패했다. Windows PC에서 `시작하기.md` 6절 명령으로 다시 확인할 것.
- **미검증**:
  - `npm run build`
  - 실제 PDF로 가짜 모델 실행
  - 실제 모델 호출
  - ChatGPT 계정 연결에서 JSON Schema가 받아들여지는지. 첫 실측의 호출 기록 "형식" 칸으로 확인한다.

## 3. 첫 실측 방법 (PC)
1. GitHub Desktop에서 이 브랜치를 Pull 한다.
2. `Study Forge 로컬 열기.cmd`로 켜고 `http://127.0.0.1:3000/lab/gen`을 연다.
3. **먼저 가짜 모델로 한 번 돌린다.**
   - 자료는 Cornell 2쪽이다(없으면 "예제 PDF 등록").
   - "가짜(비용 없음)", "목표 확인 없이 끝까지"를 고르고 시작해 "완료"와 "문제 보기"를 확인한다.
   - 실제 PDF 글자 추출부터 화면까지 무료로 확인된다.
4. **실제 모델 1회.**
   - 같은 Cornell 1~2쪽, 목적은 핵심 암기, 모델은 전 단계 luna·low로 둔다.
   - "실제 모델을 호출합니다"에 체크하고 시작한다. 예상 호출은 목차 1 + 2쪽 분량의 목차 수 × 3이다.
   - 목표 확인 화면에서 목표를 보고 "이 목표로 문제 만들기"를 누른다.
5. **볼 것**
   - 호출 기록의 **형식** 칸: `json_schema`면 structured output이 된다는 뜻이다. `json_object`면 계정 연결이 거부해 대체 경로로 간 것이다.
   - 실패한 호출은 행을 눌러 응답을 본다.
   - 목표가 "떠올릴 것 하나"로 잘렸는지, 근거 인용이 맞는지, 문제에 정답이 보이지 않는지 본다.

## 4. 옛 엔진 카드 단계 버그 (참고)
- 10/1 실측에서 카드 2번은 근거를 학습 단위 근거와 똑같이 옮겼다(두 구절을 `||`로).
- 그런데 카드 검사는 쪽 표기 `(PDF 2쪽)`이 낀 저장 문자열 전체와 비교해서 틀렸다고 판정했다. 10/8 수정(카드에 쪽 원문을 안 보냄)으로는 풀리지 않는 원인이었다.
- 이제 학습 설계 검사와 같은 규칙으로 구절별로 대조하고, 어긋난 구절과 고치는 법을 오류 문장에 넣는다.
- 옛 경로만 쓰는 사람을 위한 수정이고, 새 엔진에는 카드 단계가 없다.
