- **미검증**:
  - `npm run build`
  - 실제 PDF로 가짜 모델 실행
  - 실제 모델 호출
  - ChatGPT 계정 연결에서 JSON Schema가 받아들여지는지. 첫 실측의 호출 기록 "형식" 칸으로 확인한다.

## 3. 첫 실측 방법 (PC)
1. GitHub Desktop에서 이 브랜치를 Pull 한다.
2. `Study Forge 로컬 열기.cmd`로 켜고 `http://127.0.0.1:3000/lab/gen`을 연다.
3. **먼저 가짜 모델로 한 번 돌린다.**
   - 자료는 Cornell 2쪽이다(없으면 "예제 PDF 등록").
   - "가짜(비용 없음)", "목표 확인 없이 끝까지"를 고르고 시작해 "완료"와 "문제 보기"를 확인한다.
   - 실제 PDF 글자 추출부터 화면까지 무료로 확인된다.
4. **실제 모델 1회.**
   - 같은 Cornell 1~2쪽, 목적은 핵심 암기, 모델은 전 단계 luna·low로 둔다.
   - "실제 모델을 호출합니다"에 체크하고 시작한다. 예상 호출은 목차 1 + 2쪽 분량의 목차 수 × 3이다.
   - 목표 확인 화면에서 목표를 보고 "이 목표로 문제 만들기"를 누른다.
5. **볼 것**
   - 호출 기록의 **형식** 칸: `json_schema`면 structured output이 된다는 뜻이다. `json_object`면 계정 연결이 거부해 대체 경로로 간 것이다.
   - 실패한 호출은 행을 눌러 응답을 본다.
   - 목표가 "떠올릴 것 하나"로 잘렸는지, 근거 인용이 맞는지, 문제에 정답이 보이지 않는지 본다.

## 7. 재실측 (모델 조합을 나눠 비교)
1차는 전 단계 luna·low였다. 목차 겹침·보조 목표는 구조 문제라 모델과 무관하지만, 답의 언어·구체성은 모델 강도 영향일 수 있어 조합을 나눠 본다.

| 실행 | 자료 | 목적 | 모델 | 목표 확인 | 예상 호출 |
|---|---|---|---|---|---|
| A | Cornell 1~2쪽 | 핵심 암기 | 전 단계 luna·low (1차와 같은 조건) | 끝까지 자동 | 약 7 |
| B | Cornell 1~2쪽 | 핵심 암기 | 목차·분류 luna·low / 설계·출제 sol·medium | 끝까지 자동 | 약 7 |
| C | 다른 PDF 4~6쪽 (반도체 `ilovepdf_merged.pdf` 등. 기하 r02는 출제기준 예시에 쓰여 평가에서 뺀다) | 핵심 암기 | A·B 중 나은 조합 | 확인 화면 사용 | 10~15 |

**주의**: 재실측부터 학습 설계·출제 규칙은 `출제기준/` 폴더(v1)에서 읽는다. v1은 옛 출제 지침(객관식·단답·관계 구조 규칙, 기하 r02 사례)을 합친 것이라 1차 프롬프트보다 규칙이 많다. 그래서 A와 1차의 차이에는 코드 수정과 기준 정리 효과가 함께 들어 있다. 호출 기록의 "기준" 칸에 기준 버전이 남는다.

볼 것: A와 1차 비교로 수정 효과(중복·보조 목표), A와 B 비교로 모델 효과(답 언어·구체성·목표 선별), C로 다른 자료에서도 되는지. 각 실행의 시간·토큰도 같이 적는다.

## 8. 앞 단계 고정 재실행 (2026-10-12, Claude)
A·B는 분류를 각자 새로 돌려 분류 결과부터 달랐다. 그래서 모델 효과와 분류의 우연을 나눌 수 없었다(`결과보고_새엔진1차_GPT_20261012_B.md`).

- 실험실에서 끝난 실행(또는 목표 확인 대기 실행)을 열면 **"앞 단계 고정 재실행"**이 있다.
  - **설계부터 다시**: 목차·분류는 기준 실행 것을 그대로 쓰고, 학습 설계·출제만 다시 부른다.
  - **출제만 다시(같은 목표)**: 목표와 고른 목표까지 그대로 쓰고, 출제만 다시 부른다. 출제 모델이나 `출제/` 기준 비교용.
- 다시 돌 단계의 모델과 출제기준 폴더를 바꿀 수 있다. 목표 확인 없이 끝까지 돈다.
- 새 실행에 `forkOf`(기준 실행 ID, 시작 단계)가 남는다. 점수표의 "앞 단계" 칸에 보이고, 호출·시간·토큰은 다시 돈 단계만 센다.
- API: `POST /api/lab/gen/:id/fork` `{ from: "design" | "author", models?, guideDir?, confirmed }`.

**모델·기준 비교는 앞으로 이 방식으로 한다.** 예: A 실행에서 "설계부터 다시"를 sol·medium으로 → A와 점수표·판정 비교. 개선 회차도 같은 기준 실행에서 `출제기준`과 `출제기준-후보`로 각각 고정 재실행해 비교한다.

## 9. 기준 후보 v2: 단답은 표기 하나일 때만, 나머지는 플래시카드 (2026-10-12, 사용자 결정)
- `출제기준-후보/`에 반영했다. 바뀐 규칙은 `출제기준-후보/변경기록.md` v2-후보에 있다. 원본 `출제기준/`은 그대로다.
- 점수표에 의심 신호 `short-wordy`(낱말로 된 단답, 예: `boolean 배열`)를 더했다. 플래시카드로 냈어야 할 단답을 센다.
- **비교 방법**: 같은 기준 실행(예: A `gen_13ca8b…`)에서 "앞 단계 고정 재실행 → 출제만 다시"를 두 번 돌린다. 하나는 `출제기준`, 하나는 `출제기준-후보`, 모델은 같게(출제 sol·medium 권장). 둘에 "평가 실행" 뒤 점수표로 비교한다. 볼 것: 형식 분포, `short-wordy`, 판정 실패·모호, 깊이.
