## 1. 작업 폴더와 git

- **클라우드 세션은 데스크톱 작업 폴더에서 git을 못 쓴다.** 데스크톱 작업 폴더는 git worktree이고, `.git` 파일이 Windows 경로(`…/CD0625/.git/worktrees/…`)를 가리킨다. 원격 셸에서는 그 경로가 안 보여서 `git status`부터 실패한다. 파일 읽기·쓰기·테스트는 된다.
- **그래서 데스크톱 폴더를 직접 고치고 다른 복사본에서 커밋하면, 데스크톱에는 "커밋 안 된 변경"이 남는다.** 내용은 원격 커밋과 같고 줄바꿈만 다르다. 데스크톱에서 `git restore src` → `git pull --ff-only` 하면 맞춰진다. 처음 보는 세션은 이걸 "모르는 변경 수십 개"로 본다.
- **데스크톱 파일은 CRLF, 저장소는 LF.** 내용이 같은지 볼 때는 줄바꿈을 빼고 비교한다: `tr -d '\r' < 파일 | sha256sum`.
- **`Recaller 시작.cmd`는 `git pull --ff-only`부터 한다.** 작업 폴더에 커밋 안 된 변경이 있으면 받기에 실패하고("코드를 받지 못했어요") 예전 코드로 켜진다.
- push 전에는 항상 `git pull --rebase origin claude/recaller2`. 여러 세션이 같은 브랜치에 올린다.
- 공개 저장소다. 강의 PDF·학습 기록·`.env.local`·ChatGPT 인증 정보는 커밋하지 않는다(학습 데이터는 비공개 RecallerData 저장소).

## 2. 로컬 앱과 데이터 폴더

- 앱은 `scripts/run-local-experiment.mjs`가 `next dev --hostname 127.0.0.1`로 띄운다. **코드를 고치면 바로 반영된다**(재시작 불필요). 공부 화면의 바닐라 앱(`dejipgi-app.js`)은 새로고침이 필요하다.
- 3000번 포트에 이미 서버가 있으면 `open-study-forge-local.mjs`는 그 서버를 끄지 않고 멈춘다.
- 데이터는 `.env.local`의 `STUDY_FORGE_DATA_DIR`(보통 RecallerData)에 있다. **`.env.local`을 바꾸면 next dev가 알아서 다시 읽는다**(재시작 불필요).
- **ChatGPT 로그인은 데이터 폴더와 따로 있다.** 토큰은 작업 폴더의 `.study-forge-data/chatgpt-auth`(`STUDY_FORGE_AUTH_DIR`), 암호화 키는 `%USERPROFILE%\.study-forge\chatgpt-token-key`. 데이터 폴더를 바꿔도 다시 로그인할 필요가 없다.
- **`Recaller 끝내기.cmd`는 데이터 폴더를 git으로 올린다.** 데이터 폴더를 테스트용으로 바꿔 둔 채 끝내기를 누르지 않는다.

## 3. 빈 데이터로 테스트하기

기존 공부 기록을 건드리지 않고 처음 상태에서 확인하는 방법.

1. 작업 폴더의 `tmp/`(gitignore됨) 아래에 빈 폴더를 만들고 `.env.local`을 복사해 둔 뒤 `STUDY_FORGE_DATA_DIR`만 그 폴더로 바꾼다.
2. PDF 등록은 파일 선택 창 없이 된다: `mcp-sources/src_<sha256>.pdf`와 `src_<sha256>.json`(`{"id","fileName","pageCount","sha256","createdAt"}`)을 넣으면 등록 PDF로 잡힌다. 몇 쪽만 쓰려면 `qpdf --empty --pages 원본.pdf 8-11 -- 작은.pdf`.
3. 화면에서 올리려면 `/api/mcp-runs/sources/<id>/pdf`로 받은 파일을 `DataTransfer`로 `input[type=file]`에 넣고 `change`를 보내면 된다(브라우저 자동화에 파일 올리기 도구가 없을 때).
4. **빈 데이터 폴더에도 예전 출제 문서 4개가 보인다**(기하변환 3개, 반도체 1개). 저장소의 `tools/problem-authoring-lab/runs`에서 오는 고정 자료라 데이터 폴더와 상관없다. 보관함(`POST /api/study-archive {action:"archive"}`)에 넣으면 안 보인다.
5. 기본 코드 문제 5개와 그 지식 7개는 처음 열 때 저절로 생긴다.
6. 4쪽 PDF 생성은 기본 엔진으로 2분쯤 걸린다(ChatGPT 계정 사용량).
7. 끝나면 `.env.local`을 원래대로 돌린다.

## 5. 지식창고·복습 (2026-10-26에 바뀐 것)

- **PDF 문제 결과가 지식으로 가는 길:** 공부 화면 `finishItem` → `env.onPractice` → `POST /api/knowledge/ref-event`. 문제의 `objectiveId`를 출제 문서의 지식층(`points.byObjective`)으로 지식에 잇는다. 지식층이 있는 새 엔진 자료만 이어지고, 그 전에 푼 기록은 지식에 없다.
- 읽은 직후 확인: 맞힘은 기억으로 치지 않고, **틀림은 몰랐음으로 보낸다.** "내 답도 맞아요"는 지식 쪽 틀림을 되돌린다(`takeBack`).
- **복습 간격은 두 곳에 같은 숫자로 있다:** 공부 화면 `INTERVALS`(`dejipgi-app.js`)와 지식창고 `REVIEW_BOXES`(`src/lib/knowledge/store.ts`). 10분·1·3·7·16·35일, 틀리면 첫 상자로 가서 다음 날. 하나를 바꾸면 다른 하나도 바꾼다.
- 예전 카드(덱)는 아직 FSRS(`src/lib/spaced-repetition.ts`)다. ts-fsrs는 이전 복습보다 앞선 시각을 넣으면 `FSRSValidationError: Invalid delta_t`로 죽는다.
- 서로 다른 3일 맞히면 졸업(복습에서 빠짐). 그래서 실제로는 3일 상자 근처에서 졸업한다.
- 복습할 게 없으면 문제를 안 낸다(예전엔 아무 지식이나 섞어 냈다). 보기는 같은 폴더·같은 자료에서만 고른다.
- 엔진 지식 본문의 `⟨받음: … / 냄: …⟩`은 지식끼리의 연결 표기다. 다른 지식 이름이 들어 있어서 문제에는 넣지 않는다.
- **예전 데이터 주의:** 족보(기출)에서 가져온 지식에 오답 보기가 지식으로 들어간 것, 본문이 `undefined`인 것, 같은 개념이 4~5번 중복된 것이 있다.

## 6. 코드 문제

- 문제 출처는 둘뿐: `src/lib/code/seeds.ts`의 기본 5개, "문제 만들기(AI)". 기대 출력은 AI가 아니라 JS 모범 풀이를 돌려서 만든다. 모범 풀이가 틀리면 틀린 기대 출력으로 채점된다(막는 장치 없음).
- **이번 풀이:** 힌트·질문·틀린 제출은 `code/attempts.json`에 모았다가 맞았을 때 / 문제를 나갈 때(`POST /api/code/problem/<id>/end`) / 2시간 지나면 지식 기록에 합친다. 바로 기록하면 AI가 방금 준 힌트를 "지난번에도"라고 말한다.
- "예제 실행"은 지식 기록에 안 남는다. 제출만 남는다.
- 화면 자동화로 코드를 넣을 때: `window.monaco.editor.getEditors()[0].setValue(…)`.

## 7. 수식 표시

- 지식 본문은 `$` 없이 `z_{vp}`, `P_0`, `n = N/|N|`처럼 저장된다. 지식 화면(`workspace/Rich.tsx`의 `mathify`)이 짧은 이름+아래첨자와 `=`·`×`가 들어간 식을 수식으로 바꿔 MathML로 그린다(스타일시트 불필요).
- `lower_bound` 같은 긴 이름, `$5` 같은 금액은 바꾸지 않는다. `/`는 분수로 바꾸지 않기로 했다(괄호·범위가 애매해서).

## 11. 데스크톱에 파일·패키지 반영하기 (2026-10-28, B)

- **데스크톱 셸(Linux VM)에서 `npm install`을 돌리지 않는다.** Windows에서 쓰는 패키지(`@next/swc-win32-x64-msvc`, `lightningcss-win32-x64-msvc`, `@img/sharp-win32-x64`)를 "맞지 않는 플랫폼"으로 보고 지울 수 있다. 새 패키지는 셸의 빈 폴더(`$HOME/qq/...`)에 따로 설치한 뒤, 데스크톱 `node_modules`에 **없는 것만** 복사한다. `onnxruntime-node`는 `bin/napi-v6/win32/x64`만 있으면 된다.
- 데스크톱 셸에서 `raw.githubusercontent.com`은 열린다. 올린 커밋의 파일을 `curl`로 받아 `sed 's/$/\r/'`(CRLF)로 쓰면 큰 파일도 쉽게 옮긴다. 쓰기 전에 데스크톱 파일이 바로 앞 커밋과 같은지(줄바꿈 빼고 sha256) 확인해서 남의 수정을 덮지 않는다.
- **서버 쪽만 옛 코드가 돌면 로그부터 본다.** `.next/dev/logs/next-development.log`에 `[Server HMR] Subscription error … TurbopackInternalError`가 1초마다 찍히면 서버 코드 갱신이 멈춘 것이다(화면은 바뀌고 API는 옛 코드, 에러 없이 404). 서버 창을 닫고 다시 켜야 한다. `Recaller 시작`은 3000번에 서버가 있으면 그냥 멈추므로, **먼저 기존 서버 창을 닫는다.** 로그 첫 줄의 `timestamp`가 `00:00:0x`로 다시 시작했는지로 재시작 여부를 확인한다.
- **새 패키지를 넣으면 next dev를 다시 켜야 한다.** 켜진 채로 패키지를 넣고 그 패키지를 부르는 경로 파일을 바꾸면, 화면(클라이언트)은 바뀌는데 그 API 경로는 옛 코드가 계속 돈다(에러 없이 404).
- Hugging Face(huggingface.co)는 클라우드 셸·데스크톱 셸에서 막혀 있다(403). 모델은 Windows에서 도는 앱 서버나 내장 브라우저에서만 받을 수 있다.
- 내장 브라우저 스크린샷은 클릭 직후 화면이 늦게 바뀐 상태로 찍힐 때가 있다. "반응 없음"으로 보이면 1~2초 뒤 다시 찍거나 네트워크 기록을 본다.
- 지식 테스트 데이터의 옛 복습 기록에는 FSRS 형식(`algorithm: "fsrs"`)이 섞여 있다. 이제 읽을 때 첫 상자로 바꾼다.
