# 작업지시 08: 생성 실험실 (`/lab`)

- **근거**: `docs/DECISIONS.md`의 "2026-09-30 · 생성 실험실"
- **브랜치**: `claude/local-state-20260928` (PR starvvolf/EasyMemory#1)
- **나눠 맡기**: 기획·화면 설계는 Claude가 했다(이 문서와 `협업/실험실/화면시안.html`). **구현은 GPT가 한다.**
- **화면 시안이 기준이다.** 배치, 문구, 색, 상태 표시는 시안을 따른다. 바꿔야 하면 결과보고에 이유를 적는다.
- **지켜야 할 것**
  - 실제 모델 호출은 사용자가 화면에서 확인을 누를 때만 한다. 개발과 확인은 가짜 모델로 한다.
  - 엔진 계약(5단계 규칙, 요청 기록 형식, 출제 패킷)은 이번에 바꾸지 않는다.
  - 토큰은 화면·기록에 남기지 않는다.
  - `/study`(되짚기) 화면과 동작은 바꾸지 않는다. 예외는 아래 5번의 "실험실 결과 제외" 하나다.

---

## 1. 왜 만드나

**현재**
- 생성은 분석 → 개념 구조 → 학습 설계 → 활동 설계 → 카드 → 출제의 6단계다. 앱 안 자동 실행기가 사람 없이 끝까지 돈다.
- 결과를 보려면 실행 기록 파일(JSON)을 직접 열어야 한다.

**문제**
- 실제 실행 두 번이 모두 실패했다. 원인은 두 번 다 기록을 뒤져서야 찾았다.
  - 한 번은 개념 구조에서 쪽 근거가 빠졌다.
  - 한 번은 44쪽 자료가 학습 목표 1개로 뭉치고 쪽이 0으로 저장됐다.
- 느린데 어느 단계가 느린지 모른다.
- 모델을 바꾸면 결과가 어떻게 달라지는지 비교할 방법이 없다.
- 기존 실험 도구(`tools/generation-lab`, `/mcp-runs`)는 옛 흐름 기준이거나 보기 불편하다.

**변경**
- 한 화면에서 다음을 한다.
  1. 단계별로 **어떻게 돌았는지** 본다: 상태, 걸린 시간, 모델, 재시도
  2. 단계별로 **무엇이 나왔는지** 사람이 읽기 좋은 모양으로 본다
  3. **모델을 단계마다 바꿔** 돌린다
  4. **한 단계씩** 멈추며 확인한다

**지금 안 하는 것**
- "나와야 할 목표" 기대 목록 만들기와 자동 채점
- 단계 구성 바꾸기(4·5단계 건너뛰기 등). 엔진 계약 변경이라 따로 정한다.
- 두 실행 나란히 비교, 중간부터 갈라 다시 돌리기. 2차에서 한다(맨 아래).

## 2. 어디에 두나

- 같은 Next 앱의 새 화면 `/lab`이다. **로컬 실험 모드에서만 열린다.**
- 자동 실행기, ChatGPT 로그인, PDF 등록, PDF 보기를 그대로 쓴다.
- 새 API는 `/api/lab/...` 아래에 둔다. `src/lib/local-experiment-mode.ts`의 `isLocalExperimentApiPath`에도 추가한다.
- 화면 파일은 `src/app/lab/` 아래에 둔다. 스타일은 `/study`와 같은 색·글꼴 토큰(`src/app/study/dejipgi.css`의 변수)을 쓰고, `.lab` 범위로 가둔다.

## 3. 실험실의 "실행"이란

**실행 1개 = 생성 요청 1개**다. 새 개념을 만들지 않는다.
- 자동 실행기가 다루는 요청과 같다. 기록도 같은 곳에 쌓인다.
- 실험실에서 만든 요청에만 **실행 설정**을 붙인다. 자동 실행기 상태 파일(`.study-forge-data/study-executor/<요청ID>.json`)에 `lab` 칸으로 둔다.

```jsonc
"lab": {
  "provider": "chatgpt",          // "chatgpt" | "fake"   이 실행에서 쓸 공급자
  "stepMode": true,                // 단계가 끝날 때마다 멈출지
  "stages": {                      // 단계별 모델·추론 강도. 비어 있으면 요청의 requestedStages를 쓴다
    "analyze":          { "model": "gpt-6-luna", "effort": "low" },
    "learning-design":  { "model": "gpt-6-sol",  "effort": "high" },
    "authoring":        { "model": "gpt-6-luna", "effort": "low" }
  },
  "note": "학습 설계만 무거운 모델"   // 사람이 붙이는 메모(선택)
}
```

- 멈춰 있는 동안에는 `stages`, `stepMode`, `note`를 바꿀 수 있다. 바뀐 값은 다음 단계부터 쓴다.
- 요청 기록에는 **실제로 쓴 모델**이 남는다(`actual.model`). 요청의 `requestedStages`는 만들 때 값 그대로 둔다.

## 4. 자동 실행기에 더할 것 (`src/lib/study/auto-executor.ts`)

모두 실험실 실행일 때만 달라진다. `/study` 실행의 동작은 그대로다.

1. **단계별 모델**
   - 호출마다 쓸 모델은 이 순서로 정한다: `lab.stages[단계]` → 환경변수 덮어쓰기(`STUDY_FORGE_EXECUTOR_MODEL`/`_EFFORT`) → 요청의 `requestedStages[단계]` → 기본값
   - 지금은 모든 단계가 `requestedStages.cards` 하나를 쓴다. 이것을 단계별로 고친다.
   - 이 수정은 `/study` 실행에도 그대로 적용한다. 버그 수정이기 때문이다.
2. **공급자 선택**
   - `callModel`에 선택 항목 `provider`를 더한다. 실험실 실행은 `lab.provider`를 넘긴다.
   - 넘기지 않으면 지금처럼 환경변수로 정한다.
3. **한 단계씩**
   - `stepMode`면 단계를 기록한 직후 상태를 `paused-step`으로 두고 멈춘다. 출제 단계도 한 단계로 친다.
   - 이어가기는 기존 "다시 시작"과 같은 경로(`enqueueStudyRequest`)를 쓴다.
4. **호출 기록**
   - 모델을 부를 때마다 파일 하나를 남긴다: `.study-forge-data/study-executor/<요청ID>/calls/<순번>.json`
   - 들어갈 것:
     ```jsonc
     { "n": 3, "purpose": "stage:learning-design", "attempt": 2,
       "model": "gpt-6-sol", "effort": "high", "startedAt": "…", "ms": 41230, "ok": false,
       "system": "…", "user": "…",            // 실제로 보낸 전문
       "reply": "…",                           // 받은 글 전문 (없으면 null)
       "error": "개념 '…'에 PDF 페이지 근거가 필요합니다.", // 검사·형식 오류 (없으면 null)
       "usage": { "inputTokens": 0, "outputTokens": 0 },
       "input": { "pagesSent": [1, 2, 3], "pagesCut": [31, 32], "charsSent": 60000 } }
     ```
   - 토큰·쿠키는 넣지 않는다. 상태 파일의 `timings`는 이 목록의 요약으로 남긴다.
5. **원문 잘림을 숨기지 않는다**
   - 지금은 쪽당 3,500자, 합계 60,000자를 넘으면 뒤쪽 쪽을 **말없이** 뺀다.
   - 뺀 쪽 번호를 호출 기록 `input.pagesCut`에 남긴다.
   - 모델에게 보내는 글에도 "p.31–44는 길이 제한으로 빠졌음"을 한 줄 적는다.
   - 제한값 자체는 이번에 바꾸지 않는다. 실험실에서 보고 정한다.

- "되짚기로 보내기"는 2차에서 한다.

## 6. 화면 설계

화면 시안: **`협업/실험실/화면시안.html`** (가짜 데이터, 브라우저로 바로 열림). 아래는 요점이다.

### 6-1. 전체 배치
```
┌ 머리줄: 생성 실험실 · ChatGPT 연결 상태 · [가짜 모델|실제 모델] ───────────────────┐
├ 실행 목록 (왼쪽, 좁게) ┬ 선택한 실행 ────────────────────────────────────────────┤
│ + 새 실행               │ 제목줄: 자료 · 범위 · 목적 · 메모 · 전체 시간·호출 수       │
│ 실행 카드들             │ 단계 줄: 6칸 (상태·시간·모델·재시도)                       │
│                         │ 단계 상세: [결과] [보낸 입력] [검사·재시도] [원본 JSON]     │
│                         │ 오른쪽 접이식: PDF 보기 (근거 누르면 그 쪽으로)             │
└─────────────────────────┴───────────────────────────────────────────────────────┘
```
- 좁은 화면(태블릿 이하)에서는 실행 목록이 위로 접히고, PDF 보기는 전체 화면 겹창으로 뜬다.

### 6-2. 실행 목록
- 카드마다 자료 이름, 범위, 상태 배지, 모델 요약("luna·low 외 1"), 전체 시간, 만든 시각, 메모 첫 줄을 보여 준다.
- 상태 배지: `진행 중`, `멈춤(단계 확인)`, `멈춤(한도)`, `멈춤(로그인)`, `멈춤(검사)`, `완료`, `실패`
- 가짜 모델 실행에는 `가짜` 표시를 붙인다.

### 6-3. 새 실행
- 겹창 하나로 받는다.
  - 자료: 등록된 PDF 고르기 또는 새로 올리기
  - 범위: 시작·끝 쪽
  - 목적 문장
  - 할 수 있어야 할 것: 다섯 칩
  - 메모
- **단계별 모델 표**
  - 6행(5단계와 출제) × [모델, 추론 강도]로 이루어진다.
  - 위에 "모두 같게" 한 줄을 두고, 바꾸면 전체에 적용한다.
  - 모델 목록은 로그인한 계정에서 쓸 수 있는 것만 보여 준다. 알 수 없으면 `gpt-6-sol`/`astra`/`luna`를 보여 준다.
- 옵션: `한 단계씩`(기본 켜짐), `가짜 모델`
- **실제 모델이면 시작 전에 확인창을 띄운다.**
  - 문구: "AI 호출 최소 6번, 최대 약 20번(재시도 포함). ChatGPT 플랜 사용량이 나가요."
  - [취소] [시작]

### 6-4. 단계 줄
- 6칸이 가로로 이어지는 줄이다. 칸마다 단계 이름, 상태 아이콘(대기·도는 중·완료·경고·실패·재사용), 걸린 시간, 모델·강도, 재시도가 있으면 `↻2`를 보여 준다.
- 칸을 누르면 아래 상세가 그 단계로 바뀐다. 도는 중인 칸은 경과 시간이 초 단위로 올라간다.
- 멈춤(단계 확인)이면 다음 칸에 **[다음 단계 실행]** 버튼과 그 단계의 모델 고르기가 붙는다.
- 전체 시간 중 단계별 비중을 칸 아래 얇은 막대로 보여 준다. 어디가 느린지 한눈에 보이게 한다.

### 6-5. 단계 상세: [결과] 탭 (단계마다 모양이 다르다)
- 맨 위에 **요약 줄**: 개수와 경고. 예: "목표 1개 · 쪽 근거 없음 1 · 범위 44쪽"
- 단계별 결과 모양은 이렇다.

| 단계 | 결과 모양 |
|---|---|
| 분석 | 목차 나무. 줄마다 쪽 배지. 원문 범위 중 목차에 안 잡힌 쪽이 있으면 경고 |
| 개념 구조 | 개념 나무. 개념마다 쪽 배지와 연결 목차 번호. 쪽 근거 없는 개념은 경고 |
| 학습 설계 | 목표 카드 목록: 목표, 학습내용, 성공기준, 근거 인용(누르면 PDF 그 쪽), 종류, 중요도, 쪽. 원문 인용 검사 결과(확인·글자 없음·불일치)를 카드에 표시 |
| 활동 설계 | 목표별 표: 보여줄 것, 감출 것, 응답, 채점, 문제방식, 이유 |
| 카드 | 질문·정답·해설 목록. 유형 배지 |
| 출제 | 문제를 정답 공개 전·후로 렌더링(기존 `renderInteractiveDocument`). 품질 검사 결과(오류·경고)를 문항 옆에 표시 |

**자동 경고** (요약 줄과 해당 항목에 노란 표시)
- 목표 수가 범위에 비해 너무 적음. 기준: 범위 쪽 수 ÷ 목표 수 > 8
- 쪽 근거 없음 또는 0쪽
- 원문 잘림(`pagesCut`)
- 원문 인용 불일치
- 재시도 발생, JSON 형식 오류
- 출제 품질 검사 오류

경고는 **점수가 아니라 사람이 볼 곳을 가리키는 표시**다.

### 6-6. 단계 상세: 나머지 탭
- **[보낸 입력]**
  - 그 단계의 호출 목록(시도별)을 보여 준다.
  - 시도를 고르면 지시문과 사용자 입력 전문이 나온다. 긴 원문 글자는 접어 두고 "p.1–30 보냄, p.31–44 잘림"으로 요약한다.
  - 글자 수, 입력·출력 토큰도 보여 준다.
- **[검사·재시도]**
  - 시도별로 검사 오류 문장을 보여 준다.
  - **이전 답과 고친 답의 차이**를 줄 단위로 색 표시한다.
- **[원본 JSON]**: 단계 산출물 원본. 접기와 복사를 넣는다.

### 6-7. 시각 규칙
- `/study`와 같은 색·글꼴 토큰, 밝은 바탕, 넉넉한 여백을 쓴다. 표는 줄무늬 없이 가는 구분선만 쓴다.
- 상태 색: 완료는 초록, 경고는 노랑, 실패는 빨강, 도는 중은 파랑, 재사용은 회색
- 숫자(시간·개수)는 고정폭 숫자로 쓴다.
- JSON이나 긴 원문을 기본으로 펼치지 않는다. 항상 사람이 읽는 모양을 먼저 보여 준다.

## 7. API (`/api/lab`)

| 경로 | 하는 일 |
|---|---|
| `GET /api/lab/runs` | 실험실 실행 목록. 요청, 실행기 상태, `lab` 설정 요약 |
| `POST /api/lab/runs` | 새 실행: 요청 만들기 → `lab` 설정 저장 → 대기열에 넣기. 실제 모델이면 본문에 `confirmed: true`가 있어야 함 |
| `GET /api/lab/runs/:id` | 실행 하나: 요청, 실행기 상태, 5단계 산출물과 검사 실패 내역(엔진 실행 기록), 호출 목록(요약), 출제 기록(있으면) |
| `GET /api/lab/runs/:id/calls/:n` | 호출 기록 전문 |
| `PATCH /api/lab/runs/:id` | 멈춰 있을 때 `lab.stages`·`stepMode`·`note` 바꾸기 |
| `POST /api/lab/runs/:id/continue` | 다음 단계 / 다시 시작 |

- 모든 경로는 로컬 실험 모드 전용이다.
- 단계 산출물은 엔진의 기존 저장본을 읽기만 한다.
- 화면 갱신은 2초 간격 조회로 충분하다. 스트리밍은 만들지 않는다.

## 8. 가짜 모델

- 화면 개발과 확인은 가짜 모델로 한다. 지금 가짜 공급자는 테스트 안에서만 응답을 넣을 수 있다.
- 실험실용 **고정 가짜 응답기**를 하나 둔다. `src/lib/study/auto-executor.test.ts`의 단계별 예시 응답을 옮겨 쓴다.
  - 등록 PDF `eval/corpus/user-test-pdfs/cornell-bfs-2pages.pdf`의 1쪽에서 끝까지 통과하게 한다.
  - 호출마다 0.5~2초 지연을 둔다. 화면의 "도는 중" 표시를 확인할 수 있게 하기 위함이다.
  - 재시도·경고 화면을 확인할 수 있게 **실패 시나리오 두 개**를 둔다. 예: 개념 구조 첫 답에 쪽 근거 누락, 학습 설계에 목표 1개만 참조
- 가짜 응답기는 로컬 실험 모드의 실험실 실행에서만 켜진다.
