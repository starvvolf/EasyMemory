## 작업 1. 풀기 전 "근거:" 줄 숨기기 (최우선)

**할 일**

- `sourceRange`와 `knowledgeContent`는 정답 공개 후에만 보인다.
  - 정적 `afterAnswerHtml`에서는 렌더 시점에 포함한다.
  - `interactive`에서는 "정답 공개"를 누를 때 표시한다. 텍스트를 미리 DOM에 숨겨 두지 말고, `answer-contract`처럼 공개 시점에 삽입한다.
- 개인화 화면(`src/app/mcp-personalization/`)이 같은 렌더러의 HTML을 쓰는지 확인하고, 다른 경로가 있으면 같은 규칙을 적용한다.

**완료 기준**
- [ ] 기하·반도체 `interactiveHtml`을 다시 렌더링했을 때, 공개 전 DOM 텍스트에 어떤 문제의 `sourceRange`·`knowledgeContent` 문자열도 없다(스크립트로 전수 확인).
- [ ] "정답 공개" 후에는 근거 문구가 보인다.
- [ ] 이 조건을 검사하는 테스트를 추가한다(`tools/problem-authoring-lab/problem-authoring-lab.test.ts` 또는 새 테스트).

## 작업 2. 채점 정규화 보강
**문제**: 정규화가 두 곳에 복사돼 있고(`renderer.ts` 115행 클라이언트, `contract.ts` 292행 `gradeResponse`), NFKC·대시·공백·소문자만 처리한다. 그래서 맞는 답이 오답으로 기록된다.

실측 사례(모두 현재 "오답"):
| 문제 | 입력 | 인정 답안 |
|---|---|---|
| 기하 7 | `-sinθ, sinθ` | `-sinθ,+sinθ` |
| 기하 11 | `75`, `75도` | `75°` |
| 기하 13 | `T(q)·R(θ)·T(-q)` | `T(q)R(θ)T(-q)` |
| 기하 15 | `R^-1(θ)SR(θ)` (PDF 13쪽 표기) | `R(-θ)S R(θ)` |
| 기하 21 | `x'=…` | `x′=…` |
| 기하 5 | `(x,y,1), h≠0` | `(x,y,1); h≠0` |

**할 일**
- 정규화 함수를 **한 곳에서 정의**하고, 서버 채점과 인터랙티브 HTML이 같은 코드를 쓰게 한다(HTML에는 빌드 시 문자열로 주입).
- 다음을 추가한다.
  - `'`·`´`·`` ` ``를 `′`로 통일
  - 곱셈 점 `·`, `*` 제거. `×`는 `3×3` 같은 크기 표기에 쓰이므로 건드리지 않는다.
  - `°`와 끝의 `도` 제거
  - 구분자 `,` `;` `、`를 하나로 통일. `/`는 `1/sx` 같은 나눗셈이므로 구분자로 취급하지 않는다.
  - 구분자 바로 뒤나 문자열 맨 앞에 붙은 `+` 부호 제거(`+sinθ` → `sinθ`)
  - `^-1`, `⁻¹`, `^{-1}` 표기 통일
- `R^-1(θ)`와 `R(-θ)`처럼 **의미는 같고 표기가 다른 경우는 정규화로 해결하지 않는다.** 작업지시 02의 "원문 표기를 인정 답안에 포함" 규칙으로 해결한다. 여기서는 표기 통일까지만 한다.

**완료 기준**
- [ ] 위 표에서 기하 15를 제외한 5개 사례가 "정답"이 된다(단위 테스트).
- [ ] 명백한 오답은 여전히 오답이다. 예: 기하 1 `(1,3)`, 기하 2 `(1,-2)`, 기하 7 `sinθ,-sinθ`. 순서가 바뀐 답이 정답이 되면 안 된다.
- [ ] 클라이언트 채점과 `gradeResponse`의 결과가 모든 기존 인정 답안에서 같다(동일성 테스트).

## 작업 3. 개인화·실행 기록 화면이 뜨게 하기
**A1. `src/lib/personalization-lab/artifacts.ts` `listArtifacts()`**: `Promise.all(... loadDescriptor ...)`라서 하드코딩된 `allowed` 4개 중 하나만 없어도 `/api/personalization-lab` 전체가 500이 된다.
- 항목별로 `Promise.allSettled`를 쓰고, 실패한 항목은 목록에서 "읽을 수 없음(사유)"으로 표시하거나 제외한다.

**A2. `src/lib/mcp-run-view.ts` `listMcpRunViews()`**: `local-data` 루트의 `ids: []`이고, 목록은 하드코딩된 run ID와 요청 저장소로만 만든다. 그래서 `.study-forge-data/mcp/chatgpt-runs/`의 최신 실행(`chatgpt-request-edffcc5c…`, `…ecdf7a39…`)이 보이지 않는다.
- `run.json`의 `config.files[0].sha256`이 등록된 원본(`mcp-source-catalog`)과 일치하는 실행은 요청 기록이 없어도 목록에 포함한다. 이 경우 "요청 기록 없음"이라고 표시한다.
- 하드코딩된 ID 목록은 테스트 고정값으로만 남긴다.

**A3. `src/lib/mcp-source-catalog.ts` 138–140행**: "기존 완료 실행의 문제 범위는 2~7쪽"이 고정 문자열이다. `runIds`와 `pages[].recordedRunId`에서 계산한 문구로 바꾼다.

**완료 기준**
- [ ] 산출물 폴더 하나를 임시로 지워도 `/api/personalization-lab`이 200을 반환하고, 남은 항목이 표시된다.
- [ ] 검토용 복사본 구성(요청 저장소 없음)에서도 `/mcp-runs`에 최신 두 실행이 표시된다.
- [ ] 쪽 안내 문구와 "연결된 쪽 N쪽"이 서로 모순되지 않는다.

## 작업 5. 공개 후 제출 문구
**문제**: 정답 공개 후 입력하고 제출하면 "정답"이 표시된다. 기록 규칙(`rule.ts`, `objective-checklist.ts`)은 이 경우를 올바르게 제외하지만, 화면 문구는 실력으로 오해하게 만든다.

**할 일**: 공개 이후 제출에는 "정답 확인 후 입력(기록에는 독립 풀이로 세지 않음)"처럼 표시한다.

**완료 기준**
