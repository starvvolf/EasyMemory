# 사용자 점검: PDF 공부 · 긴 글 공부 (2026-10-29 새벽, A)

실제 사용자라고 생각하고 PC 앱(3000)에서 처음부터 끝까지 눌러 봤다. 고친 것은 없다(목록만). 시간은 실측.
- PDF: 처음 넣는 32쪽 강의 자료 `02_Geometric Transformations`, 기본 설정 그대로.
- 긴 글: 위키백과 "상장지수 펀드" 13,817자 붙여 넣기 (B의 새 "글 지도" 흐름).

## 1. 누가, 왜, 어떻게 쓰나 (기능의 의도와 사용자 맞추기)

| | PDF 공부 | 긴 글 공부 |
|---|---|---|
| 사용자 | 시험을 앞둔 대학생 (전공 강의 PPT·교재) | 투자·기술 공부를 하는 직장인·학생 (칼럼·블로그·뉴스 해설) |
| 왜 쓰나 | "이 자료에서 시험에 나올 것을 빠짐없이 내 것으로 만들고, 시험일까지 잊지 않게" | "읽은 글의 핵심과 모르던 말을 남기고, 다음 글에서 다시 만나면 연결되게" |
| 언제·얼마나 | 시험 1~2주 전부터, 한 번에 30~60분, 강의 하나(30~50쪽)를 통째로 넣고 앞에서부터 읽음. 여러 과목을 번갈아 | 출퇴근·저녁에 5~15분, 하루 글 1~3개. 글은 브라우저에서 이미 읽는 중 |
| 기다림 참을성 | 넣자마자 읽기는 시작돼야 함. 읽는 속도(쪽당 30초~2분)보다 문제가 늦으면 안 됨 | 짧음. 글을 다 읽은 뒤 버튼 하나 → 수십 초 넘으면 이탈 |
| 성공 기준 | 끝까지 읽었을 때 모든 쪽에 문제가 있고, 틀린 것이 복습으로 돌아옴 | 핵심 3~5개를 말할 수 있고, 모르던 개념어만 복습에 남음 |

이 표 기준으로 보면: PDF는 "만들면서 바로 읽기"라는 의도가 맞지만 **긴 자료에서 문제가 중간에 끊긴다**. 긴 글은 "글 지도"가 의도에 잘 맞지만 **읽는 곳(브라우저)과 정리하는 곳(앱)이 떨어져 있고, PDF용 질문(시험·기한)이 섞여 있다**.

## 2. 실제로 기다린 시간

| 단계 | 시간 | 사용자가 하는 일 |
|---|---|---|
| PDF 올리고 "읽기 시작" | 바로 읽기 시작 | 1쪽부터 읽음 (좋음) |
| PDF 첫 문제 (3쪽) | **30~39초** | 1~2쪽 읽는 동안이라 거의 안 기다림 |
| PDF 생성 멈춤 1 | **65초**에 "호출 수(60)를 다 썼어요" | 위쪽 작은 줄로만 알림. 못 보면 뒤쪽에 문제가 없음 |
| PDF 다시 시작 후 멈춤 2 | **156초** (문제 33개, 11구역 중 일부) | 사용자가 다른 화면에 있으면 모른 채 멈춰 있음 |

| 핵심 확인 열기 | 3초 | — |

가장 긴(그리고 사용자가 모르는) 기다림은 **PDF가 호출 상한에서 멈춘 동안**이다. 사용자는 기다린다는 것조차 모르고, 뒤쪽 쪽에 문제가 안 붙는다.

## 3. 불편한 점과 어긋나는 흐름 (심한 순)

### PDF 공부

1. **긴 자료에서 문제가 중간에 멈춤 (가장 큼, C 영역).** 32쪽·44쪽 모두 호출 상한(60~62)에 두 번씩 걸림. 알림이 위쪽 회색 줄 하나뿐이고 "다시 시작"을 직접 눌러야 이어짐. 그사이 그림·수식 쪽은 그림으로 못 읽고 글자만 씀(10/28 확인). → 사용자는 "앱이 뒤쪽은 문제를 안 만든다"고 느낌.
2. **틀린 숫자 답을 사람에게 판정시키고, 강조 버튼이 "맞았어요".** 정답 1, 내 답 2인데 "자동 채점으로는 판단하지 못했어요. 정답과 같은 뜻인가요?" + 파란 "맞았어요"(Enter). 습관적으로 Enter를 누르면 틀린 것이 맞은 것으로 기록됨 → 복습에서 빠짐. 숫자·짧은 기호 답은 자동으로 틀림 처리하고, 애매할 때만 묻는 게 맞음 (PDF 화면, 주인 없음).
3. **"목표가 정리되면 확인을 부탁할게요"가 오지 않음.** 시작 안내와 실제 흐름이 다름(156초까지 확인 요청 없음). 오지 않을 거면 안내를 빼고, 올 거면 언제 오는지 보여야 함.
4. **진행 문구가 개발자 말.** "그림·수식 쪽 읽는 중 4/28 · 정리·기본 문제 1/11구역 · 호출 14번". 사용자에게 필요한 건 "지금 몇 쪽까지 문제가 준비됐는지(예: 12/32쪽)"와 "다 되면 알려 줌".
5. **시작 설정에서 판단 못 하는 선택지.** "그림·수식도 읽기 (약 4분 더)"가 기본으로 켜져 있음. 4분이 문제가 다 될 때까지인지, 첫 문제까지인지 알 수 없어 불안함. 실제로는 첫 문제가 30초 안에 와서 겁줄 필요 없음.
6. **"다시 시작" 옆 "지우기".** 무엇을 지우는지(문제? 자료?) 안 쓰여 있고 바로 옆이라 잘못 누르기 쉬움.
7. **"지식" 탭을 처음 누르면 문제 창만 닫힘**(두 번째에 넘어감, 10/28 확인).

### 긴 글 공부

8. **"주소(선택)" 칸이 주소만 넣으면 가져올 거란 기대를 줌.** 넣어도 글을 안 가져오고 본문을 따로 붙여 넣어야 함. 주소로 가져오기는 만들지 않음(사용자 10/29 "주소로 가져오긴 별로") → 칸 이름을 "출처 주소(선택, 원문 열기용)"로, 본문 칸을 위로.
9. **칼럼 읽은 사람에게 "시험이나 기한이 있나요?"** PDF용 질문이 그대로 나옴. 글 공부의 다음 행동은 "글 지도 보기"인데 그 앞을 막음.
10. **앱 안에 글 본문이 없음.** 붙여 넣은 글을 앱에서 다시 읽을 수 없고 "원문 열기 ↗"뿐(붙여 넣기만 한 글은 그것도 없음). 글 지도의 "흐름"을 보다가 해당 부분을 다시 보고 싶어도 못 봄.
11. **개념어 뜻이 마우스를 올려야만 보임.** 20개 중 모르는 걸 고르려면 하나씩 올려 봐야 하고, 태블릿에서는 아예 안 보임. 고른 뒤에야 아래에 뜻이 나옴.
12. **핵심 지식의 이름이 AI의 요약 제목.** "편의와 비용의 맞교환", "거래와 설정·환매의 분리" 같은 이름으로 카드 앞면이 나옴. 사용자가 글에서 본 말이 아니라 떠올릴 단서가 약하고, 지식창에서 검색하기도 어려움. 앞면을 "이 글에서 ETF의 장단점은?"처럼 질문으로 바꾸는 게 맞음.
13. **기다림 안내가 실제의 2배.** "47초쯤" → 실제 20초. 길게 말하는 건 나쁘지 않지만 계산식을 B의 새 실측(14~20초)에 맞출 것.

### 공통 (오늘 화면)

14. **들어갈 곳이 너무 많음.** "새 공부 시작 / 내 공부 보기 / 바로 복습 / 오늘 할 일 / 이어서 하기 / PDF 이어서 해요 / 과목 미지정 약점 6"이 한 화면. 시험 준비생에게 오늘 할 일은 "이어서 읽기"와 "복습" 둘이면 됨.
15. **"과목 미지정".** PDF를 넣을 때 과목·시험일을 묻지 않아서 "시험일까지 나눠 드려요"가 작동하지 않음(시작 흐름에서 기한을 물어야 할 곳은 PDF이고, 웹 글은 아님 — 9번과 반대로 되어 있음).

## 4. 잘 된 것 (유지)

- PDF: 넣자마자 읽기, 첫 문제 30초대, "읽은 직후 확인" 문구("방금 읽은 내용이라 기억 기록으로 세지 않아요")와 틀리면 "원문에서 다시 보기", 수식 표시.
- 긴 글: 글 지도(질문·흐름·핵심 5·개념어·생각해 볼 점) 구성, 13,817자를 20초에, 모르는 개념어만 몰랐음으로 넣는 방식, 확인 목표가 행동에 따라 열리는 것.
