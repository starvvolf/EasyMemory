# 작업지시 03: 재생성 1회와 앱 전체 흐름 검증

- **선행 조건**: 작업지시 01, 02 완료
- **대상**: 원본 개발 저장소
- **범위 제한**: MCP 재생성은 **두 PDF 각각 한 번**만 한다. 결과가 기준에 못 미치면 다시 돌리지 말고, 원인을 결과보고에 남긴 뒤 사용자 결정을 기다린다(`docs/handoff/START_HERE.md`의 "MCP 실험 → 결과 검수 → API 실험" 순서를 따른다).

## 할 일
1. **재생성**: 기하변환(32쪽)과 반도체(44쪽)를 01·02가 반영된 하네스와 검증기로 다시 생성한다. 검증된 기존 Analyze·목차 결과는 재사용해도 된다.
2. **등록**: authoring iteration 등록(`record_problem_iteration`)까지 끝내서 `/mcp-personalization`에 두 문서가 나타나게 한다. 현재 두 run에는 `source-packet.json`만 있고 iteration이 없다.
3. **자동 검사**: 새 문서에 `validateDocument`를 돌려 error 0건을 확인한다. warning은 목록으로 남긴다.
4. **앱 흐름 검증**: 사람이 하듯 앱 화면에서 직접 진행한다.
   - 목표 체크리스트에서 문제 열기 → 풀기 → 제출 → 복습 추천 확인
   - 정답 공개 → 같은 문제 제출 → **새로고침 후 다시 제출**: 독립 풀이로 세지는지 확인한다. 세션 경계가 새로고침에서 새로 생기면 결함으로 보고한다.
   - 오답 → 다른 세션에서 2회 성공 → 상태 회복 확인
   - 브라우저를 닫았다 다시 열어 기록이 유지되는지 확인
   - 모바일 폭(390px)에서 한 문제 끝까지 풀기
5. **원문 대조 표본 검수**: 새 문제 중 각 PDF에서 8문항 이상을 원문과 대조해 사실 오류, 정답 노출, 조건 부족을 확인한다.
