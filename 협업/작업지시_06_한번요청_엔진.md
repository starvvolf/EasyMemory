화면(`/study`) 쪽은 Claude가 끝냈다. 이 문서에는 **생성 엔진에서 해야 할 일만** 남겼다.

- **브랜치**: `claude/local-state-20260928` (PR starvvolf/EasyMemory#1)
- **근거**: `docs/DECISIONS.md`의 "2026-09-29 · 앱 전체 흐름"
- **지켜야 할 것**
  - 되짚기 화면(`src/app/study/`)의 문구·배치·기록 규칙은 바꾸지 않는다. 필요한 화면 변경은 결과보고에 제안으로 남긴다.
  - **유료 재생성(MCP·API)은 사용자 확인 없이 돌리지 않는다.** 확인은 기존 기록, 가짜 실행자, 테스트로 한다.
  - 공용 계약(요청 스키마, `src/lib/types.ts`, 출제 문서 형식)을 바꿔야 하면 바꾸기 전에 사용자에게 알린다.

## 화면이 이미 하는 일 (엔진이 맞춰야 할 입력·출력)
| 화면 동작 | 엔진에 들어가는 것 / 기다리는 것 |
|---|---|
| 새 자료: PDF → 질문 3개 → "이렇게 만들게요" → 읽기 시작 | PDF 등록(`/api/mcp-runs/sources`) 후 요청 **하나**: `stopAfterStage: "cards"`, 목표 선택 없음, `purpose` = 확인 문장. 질문 답은 화면이 `answers: { purpose, abilities }`로 들고 있지만 **아직 엔진에 넘기지 않는다**(아래 2번). |
| 진행 표시(5초마다) | 요청 상태: 대기 → 진행(`stages.length`/6) → **완료 후 출제 기록 대기** → 준비됨 |
| "준비됨" 판정 | `/api/personalization-lab` 목록에 `originRunId === 요청의 runId`인 문서가 나타남. 즉 `record_problem_iteration`까지 끝나야 한다. |
| 품질 검사에 걸린 문항 | `tools/problem-authoring-lab/quality.ts`의 error 문항은 화면에서 빼고 "빠진 문항 N"으로 표시 |
| "이 문제 이상해요" → 다시 만들기 | 원래 요청의 learning-design 결과를 `reuse`하고 신고한 문제의 목표만 `selectedObjectiveIds`로 요청 하나. 결과 문서는 **별도 자료**("… · 다시 만든 문제")로 붙는다. |
| 문제 화면 | 출제 문서의 블록을 그대로 그린다: 글, 수식, 표, 상자, 빈칸, 공통 지문, 생성 그래프(`generated-image`, 해시 확인 후 `/api/personalization-lab/run-asset`). **원문 그림(`image`)은 자리 표시만** 한다(아래 4번). |

## 할 일
1. **"처리해" 한마디로 끝까지**
   - 담당 AI가 대기 요청을 받으면 다음을 사람의 추가 지시 없이 이어서 하게 한다.
     - `study-forge-mcp`로 5단계 처리
     - 브리지로 source packet 만들기
     - `problem-authoring-lab`으로 작성, 검사(품질 검사 포함), `record_problem_iteration`
   - 절차는 MCP 서버 안내문(instructions), 도구 설명, 출제 지침 중 알맞은 곳에 고정한다.
   - 요청 "완료"와 출제 기록 사이의 공백을 없앨 방법이 있으면 제안한다. 예를 들어 출제 기록을 요청의 마지막 단계로 넣는 것인데, 계약 변경이라 먼저 보고한다.
   - `selectedObjectiveIds`가 있는 **다시 만들기 요청**도 같은 절차로 출제 기록까지 가는지 확인한다. 고른 목표만 담은 문서여야 한다.
2. **질문 답을 엔진 입력으로**
   - "할 수 있어야 할 것"(용어·정의 말하기 / 식·절차 쓰기 / 계산·적용하기 / 비슷한 것 구별하기 / 말로 설명하기)을 문제 설계 단계가 **형식을 고르는 근거**로 쓰게 한다.
   - 구조화된 칸으로 넘길지(계약 변경), `purpose` 문장에서 읽을지 정하고 이유를 남긴다. 칸으로 넘긴다면 화면 쪽 연결은 `src/app/study/DejipgiStudy.tsx`의 `builder.start`에서 `answers`를 요청 본문에 넣는 한 줄이다.
3. **단계별 검사 두 가지**
   - 학습 설계: 원문 구절이 **글자 그대로** 남는지 검사한다. 지금 `sourceText`는 "PDF 11쪽의 … 행렬식" 같은 요약이라 원문 표기(`T⁻¹`) 검사가 동작하지 않는다(`협업/결과보고_02_Claude_20260929.md`).
   - 문제 설계: 사용자가 고른 "할 수 있어야 할 것"과 형식이 맞는지 본다. 계산을 골랐는데 계산 문항이 없거나, 절차를 골랐는데 순서형이 없으면 경고한다.
4. **원문 그림 잘라내기 기준**
   - `SourceAssetRef.crop`의 단위(쪽 비율 0~1인지, PDF 포인트인지)가 어디에도 정해져 있지 않고 쓰는 문서도 없다.
   - 단위를 정해 계약·지침에 적는다. 정해지면 화면이 그 영역만 PDF에서 잘라 보여 줄 수 있다. 지금은 쪽 전체를 보여 주면 정답이 보일 수 있어서 자리 표시만 한다.
5. **작업지시 02 나머지**: 하네스 수정(오답 만들기, 답 형식, 원문 표기, 흐름 배치, 출처 칸 규칙)은 `협업/작업지시_02_검증기와하네스.md`와 결과보고 02를 따른다.
