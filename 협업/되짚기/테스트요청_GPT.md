# 테스트 요청: 되짚기 시제품 사용 평가

- **요청자**: 사용자(Recaller 개발자). 시제품 제작은 Claude.
- **대상 파일**: `협업/되짚기/되짚기.html` (파일 하나에 전부 들어 있음)
- **결과 제출**: 같은 폴더에 `결과보고_되짚기_작업자_YYYYMMDD.md`
- **하지 말 것**: `되짚기.html`을 수정하지 않는다. 고칠 점은 결과보고에 제안으로만 쓴다. Recaller 원본 저장소도 건드리지 않는다.

## 이게 무엇인가
Recaller의 핵심 아이디어("원문 → 학습목표 → 정답이 새지 않는 인출 문제 → 정직한 기록 → 복습")를 Claude가 처음부터 단순하게 다시 만든 비교용 시제품이다. Recaller를 대체하려는 것이 아니라, **같은 목표를 더 가벼운 구조로 만들면 무엇이 좋아지고 무엇이 빠지는지** 보려는 것이다. 배경은 `협업/검수결과_Claude_20260928.md`를 참고한다.

## 여는 방법과 이 환경의 한계
- 브라우저로 파일을 직접 연다(`file:///…/되짚기.html`). 서버는 필요 없다. Playwright를 쓰면 데스크톱(1000px)과 모바일(390px) 폭에서 모두 확인한다.
- 원래는 claude.ai 안에서 돌아가는 페이지다. 이 환경에서는 다음과 같다.
  - **문제 생성(자료 만들기)은 동작하지 않는다.** Claude 호출이 없어서다. 화면에 안내가 나오면 정상이다. 생성 품질은 이번 평가 범위가 아니다.
  - **기록은 그 브라우저의 localStorage(`dejipgi.v1` 키)에만 저장된다.** 새 브라우저 프로필에서는 초기화된다.
  - 예시 자료 "2D 기하 변환 (예시)" 8문제로 연습·채점·기록·복습 흐름은 전부 동작한다.
- 웹 폰트를 못 받으면 시스템 글꼴로 보인다. 이건 결함이 아니다.

## 해 볼 것
### A. 연습 흐름 (예시 8문제 전부)
1. "전체 연습 시작"으로 8문제를 끝까지 푼다. 형식은 네 가지다: 값 쓰기 3, 고르기 3, 순서 맞추기 1, 떠올리고 확인 1.
2. 다음 행동을 각각 한 번 이상 섞는다.
   - 정답 제출, 오답 제출, "모르겠어요"
   - **"정답 먼저 보기"** 후 다음 문제로 넘어가기. 같은 문제가 이번 연습 안에서 다시 나오면 그때 맞혀 본다.
   - 값 쓰기에서 표기만 다른 정답을 넣은 뒤 오답 처리되면 "내 답도 맞아요"를 누른다.
   - 떠올리고 확인 카드에서 "다 떠올림 / 일부만 / 못 떠올림"
3. 키보드만으로도 진행해 본다: Enter(제출·다음), 숫자 1~4(보기 선택).

### B. 채점이 맞는지
값 쓰기 문제에서 아래 입력이 **정답**으로 처리되는지 확인한다.

| 문제 | 정답으로 처리돼야 하는 입력 |
|---|---|
| (3,−2)를 (−1,5)만큼 이동 | `(2,3)`, `(2, 3)`, `( 2 , 3 )` |
| (0,4)를 양의 90도 회전 | `(-4,0)`, `(−4, 0)` (유니코드 마이너스) |
| S(2,4)의 역변환 인수 | `(1/2,1/4)`, `(0.5, 0.25)`, `S(1/2, 1/4)` |

그리고 아래는 **오답**으로 처리돼야 한다: `(3,2)`, `(4,0)`, `(0,-4)`, `(2,4)`, `(1/4,1/2)`.
채점이 기대와 다르면 입력과 결과를 표로 남긴다.

### C. 정답 노출
- 답을 내기 전 화면(문제 문장, 칩, 보기, 입력 안내 문구)에 정답이나 결정적 단서가 보이는지 확인한다.
- 학습목표 문장과 원문 근거는 **답을 낸 뒤에만** 보여야 한다.
- 고르기 문제에서 정답 보기의 위치가 매번 섞이는지 확인한다(같은 문제를 두 번 만났을 때).

### D. 기록의 정직성 (가장 중요)
연습을 마친 뒤 "기록" 탭에서 확인한다.
- "정답 먼저 보기"를 누른 문제는, 그 뒤에 맞혔어도 **"정답 보고 풂"**이어야 한다. "혼자 맞힘"으로 세면 결함이다.
- "모르겠어요"는 못 떠올림으로 기록돼야 한다.
- "내 답도 맞아요"로 인정한 풀이는 정답으로 바뀌지만, 이벤트에 `override: true`가 남아야 한다(localStorage에서 확인).
- 자기평가 카드는 자동 채점과 다른 색(파란색)으로 구분돼야 한다.
- 새로고침 후에도 기록과 다음 복습 시각이 유지되는지 확인한다.

### E. 복습 간격 (시간 조작 필요)
며칠을 기다릴 수 없으니 localStorage를 직접 고쳐서 확인한다.
- `dejipgi.v1` → `example` → `sched[<문제id>].due`를 과거 시각으로 바꾸고 새로고침하면, 홈 화면의 "복습 차례" 숫자가 늘고 그 문제가 먼저 나와야 한다.
- 혼자 맞힐 때마다 다음 복습까지의 간격이 1일 → 3일 → 7일 → 16일 → 35일로 늘고(`sched.box`가 1씩 증가), 틀리면 `box`가 0이 되며 10분 뒤로 돌아가야 한다. "일부만"은 `box`를 유지하고 1일 뒤다. 정답을 먼저 보고 푼 경우 `box`가 늘지 않고 10분 뒤로 잡혀야 한다.
- "정답 먼저 보기"의 효과는 **그 연습 세션 안에서만** 적용되는 설계다. 새로고침하거나 새 세션을 시작한 뒤 맞히면 혼자 맞힘으로 센다. 이 설계가 적절한지도 의견을 적는다.
- "3일 이상 혼자 맞힘"은 서로 다른 날짜 3일에 혼자 맞힌 경우에만 떠야 한다. 이벤트의 `t` 값을 서로 다른 날로 바꿔서 확인한다.

### F. 화면
- 데스크톱과 390px 폭에서 가로 스크롤, 잘린 글자, 겹침이 있는지 본다.
- 라이트/다크 모드(브라우저 `prefers-color-scheme` 에뮬레이션) 모두에서 글자가 읽히는지 본다.
- 처음 쓰는 사람이 설명 없이 연습 → 기록까지 갈 수 있는지, 헷갈린 문구가 있었는지 적는다.

### G. Recaller 미리보기와 비교 (선택)
같은 브라우저에서 `project/eval/local/full-study-20260928/r02/geometry-interactiveHtml.html`도 몇 문제 풀어 보고, 풀이 경험·채점·정답 노출·기록 측면에서 무엇이 나은지 짧게 비교한다. 문제 수와 내용이 달라서 품질 비교가 아니라 **경험 비교**다.
