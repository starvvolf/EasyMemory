한 판의 흐름

  1. 시작: 무엇을 만들지 말해요

    튜터가 몇 가지 묻고 로드맵(목표 여러 개)을 제안해요. 학습자가 고르면 첫 목표가 시작돼요.

    ① 튜터 대화목표 도구로만 상태 바꿈goals/<run>.json
  2. 만들면서 물어요

    튜터는 파일을 읽고, 작은 코드 조각을 돌려 보고(4초), 공식 문서 6곳에서 찾아 답해요. 답을 바로 주지 않고 어디를 볼지 짚어요.

    ① 튜터 대화 · 질문마다 1번agent-chat/
  3. 저장하면 저장본이 남아요

    나중에 "그때 코드"를 지어내지 않으려고 남겨요. 자동 확인이 켜져 있으면 튜터가 짧게 확인해요(①이 1번 더).

    저장본 · 앞뒤 차이goals/<run>.saves.jsonl
  4. 막히면 "막힌 순간"이 열려요

    명령 실패 · 틀림 판정 · [너무 어려워요]로 열리고, 같은 명령 성공 · 맞음으로 닫혀요. 몇 번 물었나, 튜터가 고쳤나, 어떻게 풀렸나(혼자 · 힌트 · 코드 보고 · 튜터가 고쳐 줌)는 코드가 세요.

    moments.tsmoments/<run>.json
  5. [해 봤어요] → 판정

    완료 조건과 학습자가 한 것(마지막 말 · 저장한 파일 · 터미널 결과)만 비교해요. 틀리면 부족함 원장에 올라가요.

    ② 판정원장 반영gaps/
  6. [다음으로] → 목표 정리

    이 목표 동안의 대화 · 저장본 차이 · 터미널 · 막힌 순간을 모아 AI가 한 번 정리해요. 배운 것 카드 · 메모리 바꿀 것 · 총정리(약점 카드)가 나와요. 코드는 기록에 있던 것만 남겨요.

    ③ 목표 정리코드 · 결과 대조 검사goals/<run>.records.json
  7. 하다가 나가면 "진행 중"

    손 놓고 15분 · 다른 실습으로 옮김 · 새 실습 시작 때 그때까지로 정리해요. 새 말이 없으면 다시 부르지 않아요. 기억에는 안 넣어요.

    ③ 목표 정리(진행 중)goals/<run>.ongoing.json
  8. 학습 종료 → 앱 기억으로

    실습 서버는 "아직 안 보낸 것"만 내주고, 앱이 기억 저장소에 넣은 뒤 넣은 열쇠를 돌려줘요. 실습 서버는 앱 데이터에 직접 쓰지 않아요.

    sync.tsknowledge/api.ts saveManysync/<run>.json
  9. 기억 도서관에서 다시 봐요

    목표마다 총정리, 만든 것(실행 결과), 장면 원문. 저장된 것을 보여 주기만 하고 AI를 부르지 않아요. 아래 채팅만 앱의 기억 묻기를 써요.

    library.tsLibrary.tsx

총정리는 이렇게 보여요

하려던 일
글을 띄어쓰기로 나눠 단어를 하나씩 살펴보려 했어요.
이렇게 하면 돼요
split()은 글을 공백 기준으로 잘라 단어 리스트를 돌려줘요.
공백으로 글을 나누는 방법을 몰라서 한 글자씩 살펴야 하는지 물었어요.
핵심 약점 글을 단어로 나누는 split
지금 내 상태 — 글자 하나하나를 돌며 공백을 찾아야 한다고 생각해요.
제대로 알아보기 — 왜 필요한지 · 작은 예 · 흔한 착각 · 이번 일에서 쓰는 법
text.split처럼 괄호 없이 썼다가 TypeError가 났어요.
for w in text.split: print(w)
TypeError: 'builtin_function_or_method' object is not iterable
메서드는 괄호로 부른다 — 이름만 쓰면 기능을 가리킬 뿐, text.split()처럼 불러야 실행돼요.
