## 2. 결정된 것 (모두 건희)
- 단계 완료는 **체험 기준 + 정직한 기록**: 단계는 해 보면 끝난 걸로 치고, 누가 고쳤는지는 그대로 기록

## 3. 남은 일
1. **진짜 AI로 확인**: 캐시 맥락 바꾼 뒤 한 단계에서 질문 2~3번 해서 답이 이상하지 않은지(VM에서는 OpenCode를 못 띄워 가짜 AI·단위 테스트로만 확인)
2. **Windows에서 자동 켜기 확인**: 실험 파일 안 누르고 앱에서 프로젝트 공부 열기 → "켜는 중" 뒤 코스가 뜨는지(건희 "봤어"라고 했으나 자세한 결과는 못 들음)
3. **버그**: 채팅에서 "고쳐 줘"로 튜터가 고치면 진도 기록은 힌트 3단계로 맞게 남지만, 수업 화면 상태(`State.hints`/`mode`)는 그대로라 통과 문구와 프로젝트 노트에 "직접 고침"으로 찍힘 (`lesson.ts` `runCheck`, `oc-engine.ts` `recordEdit`)
4. **튜터 맥락·프롬프트 다시 짜기**(건희가 "가장 어려운 문제"라고 함). 이 스레드에서 정리한 안:
   - 고정 규칙에 방식별 개입 수준(직접=짚기까지 / 같이=지금 조각만 / 만들어 줌=고친 이유 설명)
   - 학습자 기록 넣기: Recaller 지식(안다/헷갈림/물어봄)과 이번 단계 신호(같은 검사 실패 횟수, 마지막 저장 뒤 시간, 힌트 단계, 질문 수)
   - 코드는 파일 통째보다 단계 시작 뒤 바뀐 부분
   - "왜 불렸나": 코드가 정한 조건(예: 같은 검사 3번 실패)에서 튜터가 먼저 말 걸기. AI는 한두 문장과 선택지만
5. 막혔을 때 빠져나오는 길: 활동 하나만 되돌리기, 실패 종류별 안내, 3번 실패 규칙
6. 3단계 이후도 새 형식(지금 할 일·세 방식·now 문구)으로 옮기기 — 지금은 2단계만
