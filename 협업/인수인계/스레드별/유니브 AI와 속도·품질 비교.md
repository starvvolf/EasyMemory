# 인수인계: 유니브 AI와 속도·품질 비교 (10/31, Claude)

**파트: C (생성 엔진·PDF)** 중심. 웹 글 부분은 C의 `webtrial`, 플래시카드 앞면 질문형 제안은 B(지식 저장소).
이 스레드는 사용자 PC에서 원격으로 돌았고, AI 호출이 드는 실측은 PC 테스트 스레드가 대신 돌렸다(이 세션은 `.env.local`을 못 읽음). 코드는 이 스레드에서 고치지 않았다.

## 한 일

1. 유니브 AI(univai.co.kr)에 데드락 14쪽·그래픽스 03(44쪽)을 올려 속도·품질 실측(사용자가 로그인·파일 선택).
2. 유니브 공개 화면 코드(JS)와 저장 데이터로 품질 비결·모델 분석.
3. 같은 방식을 우리 엔진으로 실험: PDF 통째 요약(모델·추론 강도 4가지), 입력 방식 3가지, prep-2 그림 누락 점검, 요약→카드 구조 1~4차, 웹 글 적용.

## 결정된 것 (사용자)

| 무엇 | 결정 |
|---|---|
| 입력 방식 | PDF 통째 대신 **우리 전처리 결과를 이어 붙여** 보낸다 |
| prep-2 그림 누락 | 규칙 두 줄 보강: 글 300자 미만 && pathOps ≥ 20 → page / pictureCover ≥ 0.02 → figures. 저화질 안전망은 안 넣음 |
| 요약과 카드 | 요약을 먼저(유니브처럼 쪽 표시), 카드는 요약에서 만든다. 합격 기준은 `기준_요약카드_유니브급_20261031.md` |
| 요약→카드 구조 | **"1번"**: 뼈대(terra, 목차로 스트리밍) → 주제별 sol low 동시 요약 → 본문 끝나면 줄 2~3개씩 terra 카드 → 마무리(terra) |

구현은 글·PDF 루트 스레드에 넘겼다. 작업 트리에 그쪽 변경(`summary.ts`, `digest.ts`, `prep.ts` 보강 등)이 커밋 전으로 있다. DECISIONS.md 기록은 구현하는 쪽이 한다.

## 숫자 (데드락 14쪽 기준, 각 1회)

**유니브 실측**: 요약 첫 글자 약 10초·완성 57초(PDF 글 뽑기 9.5초 별도), 퀴즈 10문항 49초(버튼), 개념 8개 31초(버튼). 44쪽 퀴즈 약 50초. 같은 파일은 캐시로 복사(AI 0회).
**유니브 모델**: 퀴즈 OpenAI `gpt-6-luna`(저장 데이터 `paperGeneration`), 튜터 `gemini-3.1-flash-lite`/`gemini-3.8-flash`, 파일별 기본 Gemini → 실패 시 OpenAI.

**PDF 통째 요약 (우리)**
| | 첫 글자 / 완성 | 입력 / 출력 토큰 | 쪽 |
|---|---|---|---|
| terra low | 7.1 / 53.1초 | 13,640 / 2,536 | 12 |
| terra medium | 4.4 / 48.3초 | 13,640 / 2,421 | 12 |
| sol low | 5.5 / 119.7초 | 13,640 / 3,716 | 13 |
| sol medium | 7.5 / 114.6초 | 13,640 / 3,640 | 13 |
terra는 생각 토큰 0이라 low·medium이 같다. sol이 길고 비유가 낫다.

**입력 방식 (sol low)**: PDF 통째 5.5/120초·13,640 / 쪽 이미지만 3.9/119초·13,196 / **전처리 2.7/94초·5,070**.

**요약→카드 1~4차**
| | 첫 글자 | 카드 다 됨 | 전체 | 호출 / 입력 |
|---|---|---|---|---|
| 1차 sol 한 번 | 8.1초 | 134.6초 | - | 7 / 3.3만 |
| 2차 뼈대→주제별 | - | 54.6초 | - | 20 / 6.6만 |
| **3차 (채택 구조)** | 9.9초 | **49.7초** | 56.5초 | 16 / 5.9만 |
| 4차 sol 한 번(뼈대째) | 4.4초 | 82.5초 | 195초 | 13 / 5.4만 |
지금 쪽 카드 흐름: 첫 카드 약 11초, 지도 약 35초, 16호출, 입력 약 8.4만.
3차 품질: S1~S8·C1~C5 전부, 넘어서기 B2~B6 달성(그림 쪽 4/4, 직접 해 보기 4주제, 주제 연결·스스로 확인 7/7, 카드 27장 비유·오해 붙음). B7(첫 글자 ≤5초, 카드 ≤40초)만 미달.

**prep-2 점검 (4개 PDF, AI 0)**: 글자 층만 가는 19쪽 중 7쪽에서 그림·수식 빠짐. 보강 두 줄이 6쪽을 잡고 오판 0. 남은 1쪽(Geometric p.6, 그림 1% 미만).

**웹 글(프로세스 vs 스레드)**: 사용자가 말한 "입력 40만·출력 3.2만"은 A~D 네 방법 합계. 요약→카드 적용 시 31호출, 입력 13.3만(캐시 3.8만)·출력 2.2만, 첫 글자 2.2초, 전체 46.8초, 카드 52장, 기준 통과. 입력이 B(8.0만)보다 늘었다 — 카드 호출이 입력의 77%(22묶음마다 지시문·그림 재전송).

**비용(추정, gpt-5.6 단가표 적용)**: 데드락 1회 sol 통째 $0.180, sol 전처리 $0.116, terra 전처리 $0.052. 비용의 약 78%가 출력.

## 남은 일

1. (C) 채택 구조 구현 + 목표 달성: 뼈대 줄을 목차로 바로 보여 첫 글자 ≤5초, 카드 줄 2~3개씩으로 ≤40초. 주제 크기 기준(1~3쪽·본문 3~6줄) 코드로 나누기/합치기. 그래픽스 44쪽 재측정.
2. (C) 비유 다양성: 주제마다 코드가 생활 영역 배정(3차는 장면 7개 중 5개가 요리), "비유가 안 맞는 점" 구체화.
3. (C) 코드 검사: 요약 줄 쪽 ⊂ 그 호출 입력 쪽, 주제 사이 같은 용어·제목 카드 합치기(2·4차 "사이클과 데드락 판정" 겹침), 목록 카드 이름 두 번 찍힘.
4. (C, 웹 글) 카드 입력 줄이기 실험 대기 중(사용자 답 없음): 카드 호출에 그림 재전송 안 함 + 묶음을 주제 크기에 맞춤 + 카드 지시문 축약 → 전체 입력 약 6만 예상.
5. (공부 화면) "정리" 탭·문단 아래 카드 묶음은 큰 화면 변화라 시안 먼저.
6. (B) 플래시카드 앞면 질문형(개념 → "왜 ~인가?", 비교 → "A와 B는 ○○에서 어떻게 다른가?").
7. 아래 결과 문서 중 커밋 안 된 것 정리·커밋 여부는 사용자에게 아직 못 물음.

## 주의

- 유니브 무료 업로드는 사용자 계정에서 다 썼다. 같은 파일 재업로드는 캐시라 시간을 못 잰다.
- 유니브 요약 원문·문항 원문은 결과 문서에 싣지 않았다(구조·숫자만).
- AI 호출 실측은 `.env.local` 키가 필요하다. 원격 세션은 못 읽으니 PC 쪽에서 `node --env-file=.env.local …`로 돌린다.
- sol 한 호출에 다 쓰게 하면 출력이 한 줄로 나와 느리다(4차 195초). 주제별 동시가 원칙(루트 CLAUDE.md "통째로 한 번에 보내지 않는다").
