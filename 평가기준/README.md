# 평가기준 (판정단)

새 엔진이 만든 문제를 GPT 판정단이 대신 판정할 때 읽는 지시다. `출제기준/`과 같은 방식으로 규칙 ID를 붙이고, 고쳐서 판정 방식을 다듬는다.
코드: `src/lib/study/gen/judge.ts` · 실험실 `/lab/gen`의 점수표 → "평가 실행", "판정단 시험".

## 역할과 파일
| 파일 | 역할 | 받는 것 | 내는 것 |
|---|---|---|---|
| `맨손학습자.md` | 공부 안 한 학습자 | 정답 공개 전에 보이는 글만 | 답, 확신도 |
| `원문학습자.md` | 원문을 읽은 학습자(3명, 서로 독립) | 문제 + 그 목차 원문 (정답 없음) | 답 |
| `전문가.md` | 검토자 | 원문, 목표, 정답, 학습자들의 답 | 학습자 답 채점 + 문항 체크리스트 |

모델에는 규칙 줄(`- [ID] …`)만 들어간다.

## 판정 규칙(코드)
- **실패**: 정답이 원문과 다름, 질문의 조건이 원문과 다름, 원문 읽은 학습자 3명이 모두 틀림
- **의심**: 전문가가 화면에 정답·결정적 단서가 보인다고 함(노출), 단답에서 뜻은 맞는데 인정 답안에 없음(코드 채점과 전문가 채점 충돌), 원문 학습자 정오가 갈림(모호), 다른 답도 정답이 됨, 목표와 안 맞음, 객관식 오답이 티 남
- **통과**: 그 밖
- 객관식·단답은 코드가 채점하고, 자기 확인은 전문가가 채점한다.

## 판정단 시험(결함 심기)
판정에서 통과한 문제에 코드로 결함을 넣은 복제본을 만들어 다시 판정한다. 잡은 비율(검출률)과 원본을 잘못 걸러낸 비율(오탐률)이 판정단을 믿어도 되는지의 근거다.
- 정답 노출: 정답을 본문 끝에 덧붙인다
- 정답 바꾸기: 정답 키를 틀린 값으로 바꾼다(객관식은 다른 보기, 그 밖은 다른 문항의 답)
- 조건 바꾸기: 본문의 조건 낱말을 반대로 바꾼다(처음↔이미, 먼저↔나중 등). 바꿀 낱말이 없으면 건너뛴다

## 1차 실측 뒤 고친 점 (2026-10-12, `협업/결과보고_판정단1차_GPT_20261012.md`)
- 맨손 학습자가 확신하고 맞힌 것은 더는 의심 사유가 아니다. 모델이 원래 아는 기본 문제까지 걸렸다. 점수표에 "맨손 정답" 수로만 보인다. 노출은 전문가의 `answerVisible`(검토-8)로 판단한다.
- 단답에서 코드는 오답인데 전문가가 뜻으로 맞다고 하면 그 답을 맞음으로 치고 "인정 답안 누락"으로 센다. 원문 학습자가 다 틀렸다고 정답 오류로 떨어뜨리지 않는다.
- 판정단 시험의 "오탐"은 "원본 비통과"로 부른다. 실제 결함을 잡은 원본도 들어가므로 오탐률이 아니다.
- 판정은 자동으로 문제를 빼는 장치가 아니라 **검토할 문항과 이유를 모으는 도구**로 쓴다.
