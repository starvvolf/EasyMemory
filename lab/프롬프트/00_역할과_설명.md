# 프롬프트별 역할과 설명

프롬프트 원문은 같은 폴더의 번호 붙은 파일에 있다. 목록·흐름은 [README](README.md).

## 목차 · 지시문(system) — `PLAN_COMMON`
- 파일: [01_PLAN_COMMON.md](01_PLAN_COMMON.md)
- 단계: `rc-digest-plan` (목차·성격) · 기본 모델 gpt-6.1-terra low
- 역할: 목차 호출의 지시문(system). 자료 전체를 읽고 뒤에 붙는 [작업]만 하라는 틀과 쪽 번호 규칙.
- 받는 것: 자료 전체(쪽마다 [p.N] 글 + 쪽 그림)
- 내는 것: —(작업 지시가 정함)
- 쓰이는 때: 목차 → 바로 카드 / 목차 → 요약 → 카드 모두
- 주의: 짧은 공통 틀이라 여기보다 [작업] 쪽을 고친다.

## 목차 · 작업(항목까지) — `PLAN_TASK_CONCEPTS`
- 파일: [02_PLAN_TASK_CONCEPTS.md](02_PLAN_TASK_CONCEPTS.md)
- 단계: `rc-digest-plan` (목차·성격) · 기본 모델 gpt-6.1-terra low
- 역할: 목차 + 주제마다 배우는 항목(tN-cK)을 쓰게 하는 작업 지시. 앱 기본(목차 → 바로 카드)의 첫 호출.
- 받는 것: PLAN_COMMON과 같은 입력, 끝에 이 작업
- 내는 것: 개요|쪽, tN|큰 주제|제목|쪽|관련|성격, tN-cK|항목|쪽, <<<OUTLINE_END>>>
- 쓰이는 때: mapCards, conceptLines
- 주의: 항목까지 쓰느라 출력이 길다(데드락 18초, 52쪽 50초). 끝 표시까지 다 써야 카드가 시작된다. 항목 줄이 없으면 주제 제목 하나가 항목이 된다.

## 목차 · 작업(주제만) — `PLAN_TASK`
- 파일: [03_PLAN_TASK.md](03_PLAN_TASK.md)
- 단계: `rc-digest-plan` (목차·성격) · 기본 모델 gpt-6.1-terra low
- 역할: 목차 + 주제 성격만 쓰는 작업 지시(항목 없음).
- 받는 것: PLAN_COMMON과 같은 입력
- 내는 것: 개요|쪽, tN|큰 주제|제목|쪽|관련|성격, <<<OUTLINE_END>>>
- 쓰이는 때: 목차 → 요약 → 카드(digestStyle plan)
- 주의: 성격이 주제 요약 지시를 고른다.

## 목차 · 작업(학습 목표 포함) — `PLAN_TASK_GOALS`
- 파일: [04_PLAN_TASK_GOALS.md](04_PLAN_TASK_GOALS.md)
- 단계: `rc-digest-plan` (목차·성격) · 기본 모델 gpt-6.1-terra low
- 역할: PLAN_TASK 뒤에 학습 목표까지 쓰게 하는 작업 지시.
- 받는 것: 같음
- 내는 것: 목차 + 목표|oN|동사|문장|주제|핵심·보조
- 쓰이는 때: goalsInPlan(실험, 꺼짐)
- 주의: 목차가 5초 → 10초로 늦어져 기본은 학습 목표를 따로 부른다.

## 영어 자료 규칙 — `SOURCE_EN`
- 파일: [05_SOURCE_EN.md](05_SOURCE_EN.md)
- 단계: `(모든 글 쓰는 호출)` ((모든 글 쓰는 호출)) · 기본 모델 —
- 역할: 영어 자료일 때 글을 쓰는 모든 호출의 지시문 끝에 붙는 규칙.
- 받는 것: —

## 카드 · 공통 지시(맨 앞, 쪽당 장수 등) — `ORGANIZE`
- 파일: [06_ORGANIZE.md](06_ORGANIZE.md)
- 단계: `rc-digest-card` (줄 카드) · 기본 모델 gpt-6.1-terra low
- 역할: 카드 호출 지시문의 맨 앞 공통 부분: 카드 종류와 모양, 근거 인용, 오답 메모, 제목 규칙. 예전 쪽 단위 정리에서 쓰던 그대로다.
- 받는 것: —
- 내는 것: 카드 JSON
- 쓰이는 때: 모든 카드 호출(쪽 정리, 요약 줄 → 카드, 항목 → 카드)
- 주의: "쪽당 1~3장"이 여기 있다. MAP_CARD·DIGEST_CARD의 "쪽당 장수 제한 대신 이 규칙" 문장이 이것을 끈다.

## 카드 · 항목에서 바로 — `MAP_CARD`
- 파일: [07_MAP_CARD.md](07_MAP_CARD.md)
- 단계: `rc-digest-card` (줄 카드) · 기본 모델 gpt-6.1-terra low
- 역할: 항목(목차가 고른 이름과 쪽)마다 원문을 읽고 카드를 만들게 하는 지시. 앱 기본의 카드 호출.
- 받는 것: 주제, 항목 줄(id·이름·쪽), 그 쪽 원문·그림, 용어 목록
- 내는 것: 카드(covers = 항목 id)
- 쓰이는 때: mapCards
- 주의: 조건 이름은 용어 카드, 판정 규칙은 적용 범위를 condition에, 경계 칸은 원문에 있을 때만.

## 문제 재료(맞는 진술·오개념 쌍) — `Q_MATERIAL`
- 파일: [16_Q_MATERIAL.md](16_Q_MATERIAL.md)
- 단계: `rc-q-material` (문제 재료) · 기본 모델 gpt-6-luna medium
- 역할: 문제 재료: 맞는 진술 3개와 오개념 쌍 5개(한 단어만 다른 맞는/틀린 문장). OX·객관식·빈칸이 여기서 나온다.
- 받는 것: 카드, focus, ask(물을 지점·목표), 주제 줄과 흔한 오해, 이웃 카드, 원문
- 내는 것: truths, pairs
- 쓰이는 때: 문항마다(서술형 제외)
- 주의: 목차 → 바로 카드에서는 주제 줄 = 주제 카드 줄, 흔한 오해 = 카드 오답 메모.

## 객관식 — `Q_CHOICE`
- 파일: [17_Q_CHOICE.md](17_Q_CHOICE.md)
- 단계: `rc-q-choice` (객관식 재료) · 기본 모델 gpt-6-luna medium
- 역할: 객관식 문제 글, 정답, 오답 후보 6개. 상황형 우선, 판단이 두세 갈래면 "판단: 이유" 꼴.
- 받는 것: 재료 입력 + pairs
- 내는 것: stem, correct, candidates
- 쓰이는 때: 형식이 객관식일 때

## 객관식 보기 채점 — `Q_SCORE`
- 파일: [18_Q_SCORE.md](18_Q_SCORE.md)
- 단계: `rc-q-score` (오답 점수) · 기본 모델 gpt-6-luna medium
- 역할: 오답 후보마다 틀림 확실·그럴듯함·같은 꼴·같은 뜻을 매기고, 정답이 질문에 맞는지(fits)를 본다.
- 받는 것: 문제 글, 정답, 후보들, 원문
- 내는 것: fits, items
- 쓰이는 때: 객관식
- 주의: 코드가 틀림 확실 + 같은 꼴만 남겨 그럴듯한 순 3개를 고른다. 이 호출이 실패하면 그 카드는 객관식을 만들지 않는다.
